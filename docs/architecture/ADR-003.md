# ADR-003 - Native Performance Benchmarking Architecture

## Description

This document defines the structure and execution guidelines for native Go performance benchmarks in Toron.

## Decision

1. **Native Go Standard Library Benchmarks**:
   - Utilize `testing.B` harness without external benchmarking frameworks.
   - Separate benchmark logic into dedicated `*_bench_test.go` or `*_test.go` files per package.

2. **Metrics Tracked**:
   - Time per operation (`ns/op`).
   - Memory allocations per operation (`B/op` and `allocs/op`) via `b.ReportAllocs()`.

3. **Coverage Targets**:
   - `pkg/httpparser`: Streaming HTTP request parsing and response wire byte generation.
   - `pkg/router`: Route matching lookup performance (exact vs static prefix).
   - `pkg/reactor`: Socket buffer pool recycling (`sync.Pool`) vs heap allocation.
   - `pkg/server`: End-to-end request/response pipeline latency.

## Rationale

Built-in Go benchmarking (`go test -bench=.`) integrates seamlessly into CI/CD pipelines and developer workflows without third-party tool dependencies.

## Constraints

- Benchmarks must avoid real I/O blocking or external network calls wherever mock/pipe/memory buffers can be used to measure pure CPU and memory footprint.
