# SR-075 - Security Review of Concurrent Connection Dispatch in TCP Reactor

## Description

Security evaluation of the implementation for `TASK-077` / `SEC-17` (Connection starvation Denial of Service via persistent idle keep-alive socket monopolization).

## Scope

- Files reviewed:
  - `pkg/reactor/reactor.go`
  - `pkg/server/server.go`
  - `pkg/reactor/reactor_test.go`

## Security Evaluation & Analysis

1. **Elimination of Worker Starvation (CWE-400)**:
   - Previously, fixed-size worker pool loops synchronously blocked on persistent keep-alive connections during idle timeouts (up to 30s), causing task channel backlog and listener accept loop blockage.
   - Refactored `Reactor.Serve` to decouple connection acceptance from a static worker channel: each accepted socket is dispatched concurrently and tracked by `r.wg`.
   - The listener `ln.Accept()` is now completely unblocked by idle keep-alive sockets.
2. **Deterministic Lifecycle & Resource Cleanup**:
   - Active sockets are registered via `trackConn` into a thread-safe connection registry.
   - On `Shutdown(ctx)`, all active sockets are closed promptly, immediately unblocking any lingering reads.
   - In `pkg/server/server.go`, added `ctx.Done()` check at each iteration of `handleConn` to prevent socket reuse during shutdown.
3. **Exploit Verification**:
   - Verified that when 20 concurrent connections remain open and idle with keep-alive on a reactor configured with `WorkerPoolSize: 5`, connection 21 connects immediately and is processed without delay.
   - Verified that graceful shutdown terminates active sockets cleanly without hangs or goroutine leaks.

## Conclusion

`SEC-17` is fully mitigated. The edge gateway listener is resilient against worker exhaustion and keep-alive starvation attacks. Approved.
