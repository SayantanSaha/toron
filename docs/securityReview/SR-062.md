# SR-062 - Security Review of Upstream TLS Certificate Verification in WebSocket Proxy

## Description

Security evaluation of the implementation for `TASK-065` / `SEC-05` (Missing upstream TLS certificate validation in WebSocket reverse proxying).

## Scope

- Files reviewed:
  - `pkg/proxy/proxy.go`
  - `pkg/config/config.go`
  - `cmd/toron/main.go`
  - `pkg/proxy/proxy_test.go`

## Security Evaluation & Analysis

1. **Elimination of Hardcoded InsecureSkipVerify (CWE-295)**:
   - Previously, `serveWebSocketProxy` in `pkg/proxy/proxy.go` established upstream TLS dialer connections with a hardcoded `&tls.Config{InsecureSkipVerify: true}`. This rendered WebSocket reverse proxy connections susceptible to Man-in-the-Middle (MitM) interception or eavesdropping between Toron and backend origin servers.
   - The hardcoded bypass has been completely removed. By default, `InsecureSkipVerify` is `false`.
2. **Server Name Indication (SNI) & Hostname Validation**:
   - The outbound `tls.Config` explicitly populates `ServerName` with `outURL.Hostname()`, ensuring that SAN (Subject Alternative Name) and CN certificate checks match the target origin domain.
3. **Custom Root Certificate Authorities (CA Pools)**:
   - Added support for `TLSCACertPool *x509.CertPool` in `ProxyOptions` and `ReverseProxy`, allowing internal corporate PKI or private microservice CAs to be trusted without disabling verification globally.
4. **Controlled Insecure Override**:
   - `InsecureSkipVerify` can now only be enabled through explicit configuration (`ProxyRouteConfig.InsecureSkipVerify: true`), which is strictly intended for local development and non-production testing environments.

## Conclusion

`SEC-05` is completely resolved. Man-in-the-middle vulnerability on WebSocket proxying is eliminated. The implementation is approved.
