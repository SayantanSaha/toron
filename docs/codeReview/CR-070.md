# CR-070 - Code Review of Multiple & Conflicting Content-Length Rejection

## Description

Engineering code review of `TASK-074` implementation in `pkg/httpparser/request.go`, `pkg/httpparser/parser.go`, and `pkg/httpparser/parser_test.go`.

## Scope

- Files reviewed:
  - `pkg/httpparser/request.go`
  - `pkg/httpparser/parser.go`
  - `pkg/httpparser/parser_test.go`

## Key Observations & Review Findings

1. **Header API Enhancement**:
   - Added `(h Header) Values(key string) []string` to mirror standard library `http.Header.Values`, enabling inspection of all occurrences of any given header key.
2. **Deterministic RFC 7230 §3.3.2 Parsing**:
   - Loops through all `Content-Length` headers, splitting comma-separated tokens.
   - Rejects empty, negative, or unparseable values.
   - Enforces strict equality across all discovered integer values.
   - Normalizes valid duplicates into a single canonical integer header on the request.
3. **Smuggling Precedence with Transfer-Encoding**:
   - The check for `Transfer-Encoding` now correctly checks `len(clValues) > 0`, catching conflicting requests even when `Content-Length` is declared across multiple lines.
4. **Unit Test Verification**:
   - `TestParseRequest_ContentLengthMultiplicityAndConflict` validates conflicting headers, distinct comma-separated values, valid identical duplicate headers, valid comma-separated duplicates, and malformed inputs.
   - All tests pass cleanly under the race detector.

## Verdict

Approved. Ready for commit.
