# ADR-006 - Pluggable Upstream Load Balancing Architecture

## Context

Toron's reverse proxy module previously targeted a single upstream URL per route. To support high-availability microservice deployments, the proxy engine needs to balance incoming requests across a cluster of upstream servers.

## Decision

1. **`LoadBalancer` Interface**: Define a `LoadBalancer` interface in `pkg/proxy` (`Next(req) (*url.URL, error)`, `Algorithm() Algorithm`, `Targets() []*url.URL`) to isolate target selection logic from HTTP request forwarding.
2. **Round-Robin Default**: Implement `RoundRobinBalancer` using `sync/atomic` increment operations over a fixed slice of target URLs for zero lock contention and maximum performance under parallel event-loop workers.
3. **Configuration Schema**: Extend `ProxyRouteConfig` with `targets: []string` and `algorithm: string` while keeping `target: string` backwards-compatible.
4. **Router Methods**: Expose `r.ProxyBalancer` and `r.ProxyBalancerHeaders` on `pkg/router/router.go`.

## Consequences

- **Positive**: Enables multi-backend traffic distribution with minimal CPU overhead. Future algorithms (e.g. `random`, `least_connections`, `ip_hash`) can be plugged in without changing the core proxy loop.
- **Negative**: Adds target URL parsing and selection step to reverse proxy execution path.
