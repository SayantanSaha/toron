# TC-110 - Test Specification for Bounded Memory Buffer Optimization

## 1. Test Suite Objectives

Verify that Toron's HTTP parser and server utilize `sync.Pool` for bounded header line reading and request body ingestion, ensuring correct data delivery, memory recycling, double-free prevention, concurrency safety, and measurable allocation reduction.

## 2. Test Cases

### TC-110-01: Standard Payload Body Buffer Pooling
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_PooledBodyLifecycle`)
- **Methodology**: Parse a POST request with payload size $\le 64\text{ KB}$ (e.g. 1 KB, 32 KB, 64 KB). Read the entire payload from `req.Body`, verify integrity, and invoke `req.CloseBody()`.
- **Expected Outcome**:
  - Request body matches original bytes exactly.
  - `req.Body` implements `io.ReadCloser`.
  - Closing returns buffer safely to pool without error.

### TC-110-02: Large Payload Heap Allocation Fallback
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_LargeBodyFallback`)
- **Methodology**: Parse a POST request with payload size exceeding the 64 KB pool threshold (e.g. 128 KB).
- **Expected Outcome**:
  - Request parses successfully.
  - Full payload is readable via `io.ReadAll(req.Body)`.
  - `req.CloseBody()` executes cleanly without returning oversized slice into 64 KB pool.

### TC-110-03: Idempotent Close and Double-Free Prevention
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_IdempotentClose`)
- **Methodology**: Parse a pooled request and invoke `req.CloseBody()` multiple times in succession.
- **Expected Outcome**:
  - No panic occurs.
  - Return value is nil on all calls.
  - Underlying buffer is returned to `sync.Pool` exactly once.

### TC-110-04: Concurrent Pool Race Safety
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_ConcurrentPoolRace`)
- **Methodology**: Launch 50 concurrent goroutines executing rapid parse-read-close cycles against pooled requests.
- **Expected Outcome**:
  - Zero data races under `-race`.
  - No data corruption or crossed buffer contents across goroutines.

### TC-110-05: Allocation Reduction Microbenchmarks
- **Target**: `pkg/httpparser/parser_test.go` (`BenchmarkParseRequest_PooledBody`, `BenchmarkReadLineBounded_Pooled`)
- **Methodology**: Execute Go microbenchmarks measuring execution latency and allocation profile (`b.ReportAllocs()`).
- **Expected Outcome**:
  - `BenchmarkReadLineBounded_Pooled` shows dramatic reduction in allocation count.
  - `BenchmarkParseRequest_PooledBody` demonstrates reusable buffer recycling.
