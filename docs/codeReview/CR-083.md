  - Employs an atomic counter (`activeConns int64`) for $O(1)$, zero-lock concurrency gating.
  - Sockets rejected at capacity are closed immediately without dialing upstream backends or allocating heap memory.
  - Connection tracking ([`registerConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L151) / [`unregisterConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L168)) tracks open client and upstream sockets under a mutex-guarded registry.
  - Stream relaying replaces unbounded `io.Copy` with bidirectional deadline-aware transfer loops ([`p.relay`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L201)), refreshing read/write deadlines on activity and cleanly handling TCP half-close via `CloseWrite()`.
- **UDP Datagram Proxying ([`pkg/proxy/udp.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L91-L330))**:
  - Replaces unthrottled per-packet goroutines with a bounded worker pool consuming from a fixed-capacity channel `packetQueue chan udpPacketTask` of size `MaxWorkers`.
  - Queue saturation drops excess packets fail-safe without memory growth or panics.
  - Upstream session caching maps client endpoints to cached `*net.UDPConn` sockets with double-checked locking under `sessionMu sync.RWMutex`, eliminating per-packet socket dials and ephemeral port exhaustion.
  - Dedicated background sweeper routine ([`startSweeper`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L296)) evicts stagnant sessions after `IdleTimeout` of inactivity.

### 5. Resource Leak Prevention & Lifecycle Management

- **Normal Completion**:
  - [`handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L174) uses deferred unregistration, connection closure, and atomic decrement, guaranteeing that client and upstream sockets are closed and active counts decremented regardless of return path.
- **Idle Timeout**:
  - In [`TCPProxy.relay`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L201), `time.Since(lastActivity) >= p.idleTimeout` triggers `closeBoth("idle")`, severing both client and backend sockets and unblocking `copyDirection` goroutines.
  - In [`UDPProxy.sweepExpiredSessions`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L314), stagnant client sessions exceeding `IdleTimeout` are evicted and their upstream UDP sockets closed, freeing host ephemeral ports.
- **Capacity Drop**:
  - Saturated TCP connections exceeding `MaxConnections` are closed immediately upon `Accept()` with diagnostic log warnings, avoiding upstream dial or goroutine scheduling.
  - Saturated UDP worker queues drop packets non-blockingly, return buffers to `sync.Pool`, and log queue overflow warnings without memory accumulation.
- **Deterministic Shutdown (`Close()`)**:
  - [`TCPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L280) closes the listener, iterates over all tracked client and upstream connections, invokes `conn.Close()`, and clears the registry within $\le 500\text{ms}$.
  - [`UDPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L332) closes the listener socket, closes all cached session sockets, and drains worker goroutines.

## Actionable Recommendations

### 1. Darwin / macOS Ephemeral Port Pacing in Concurrency Tests (Non-Blocking)
- **Context**: In [`TestTCPProxy_ConcurrencyRaceSafety`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp_test.go#L433), 20 concurrent goroutines repeatedly dial and close TCP sockets. On Darwin/macOS, the default ephemeral port range is limited to 16,384 ports (`49152..65535`) and `TCP TIME_WAIT` defaults to 30 seconds (`net.inet.tcp.msl: 15000`).
- **Observation**: Calling `tc.SetLinger(0)` on client sockets and maintaining a minimum pacing sleep ($\ge 5\text{ms}$) avoids exhausting the host OS ephemeral port pool during rapid consecutive test executions.
- **Recommendation**: Retain `tc.SetLinger(0)` on client connections in high-throughput local dial tests to ensure predictable execution across CI runners with constrained port tables.

### 2. Scalability to >50,000 Concurrent UDP Sessions (Future Enhancement)
- **Context**: [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L105) utilizes a single `sessionMu sync.RWMutex` guarding `sessions map[netip.AddrPort]*udpSession`.
- **Observation**: Read locking provides high concurrency for steady-state packet forwarding. However, under extreme churn (>50,000 new client IPs per second), write lock acquisition during session creation may experience contention.
- **Recommendation**: As outlined in [`ADR-082 §4.2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md#L217-L232), adopt a 32-way striped session mutex map if future production monitoring indicates lock contention under massive distributed denial-of-service (DDoS) traffic.
