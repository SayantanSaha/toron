# TASK-106 - Strict TE: trailers Invariant & Metadata Preservation in Transcoder

## Overview

Ensure that outgoing HTTP/2 gRPC requests generated by [`Engine.HandleTranscode`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L89) enforce a strictly single-valued `TE: trailers` header conforming to [RFC 7540 §8.1.2.2](https://datatracker.ietf.org/doc/html/rfc7540#section-8.1.2.2), preventing client `TE` values from polluting or invalidating gRPC framing while preserving all legitimate end-to-end application metadata headers, mitigating [`SEC-29`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L402-L410).

## Scope & Implementation Breakdown

1. **Strict `TE: trailers` Guarantee**:
   - In [`HandleTranscode`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L89), after copying filtered client headers, ensure `grpcReq.Header.Set("TE", "trailers")` overrides and sets exactly the canonical `trailers` value.
   - Any client-supplied `TE` values (such as `gzip`, `deflate`, `chunked`) are stripped and never forwarded.

2. **Application Metadata Preservation**:
   - Verify that all legitimate end-to-end request headers pass through cleanly to `grpcReq`:
     - Authentication: `Authorization`, `Proxy-Authorization` (note: `Proxy-Authorization` is hop-by-hop, but standard application auth `Authorization` MUST be preserved).
     - Tracing & Telemetry: `X-Request-ID`, `Traceparent`, `Tracestate`, `X-B3-TraceId`, `X-B3-SpanId`.
     - Client Metadata: `User-Agent`, `Accept`, `Accept-Language`, custom `X-*` headers.

## Acceptance Criteria

- Outgoing `grpcReq.Header["Te"]` or `grpcReq.Header["TE"]` has exactly one element: `[]string{"trailers"}`.
- Legitimate metadata headers (`Authorization`, `X-Request-ID`, etc.) are forwarded intact.
- Zero external dependencies.
