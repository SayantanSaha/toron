# TC-111 - Test Specification for Bounded Worker Pool Connection Dispatching

## 1. Test Suite Objectives

Verify that `pkg/reactor/reactor.go` enforces bounded worker pool connection dispatching, bounds active worker concurrency to `WorkerPoolSize`, exerts backpressure on ingress queues, handles graceful shutdown without resource leakage or deadlocks, preserves HTTP/1.1 persistent connections, and improves connection scheduling predictability.

## 2. Test Cases

### TC-111-01: Bounded Concurrency Invariant Enforcement
- **Target**: `pkg/reactor/reactor_test.go` (`TestReactor_BoundedWorkerPoolEnforcement`)
- **Methodology**:
  - Configure `WorkerPoolSize = 4` and `MaxQueueSize = 16`.
  - Introduce an artificial delay in connection handler execution (or barrier synchronization).
  - Open 12 concurrent connections simultaneously.
  - Query `r.ActiveWorkers()` periodically across all connection lifetimes.
- **Expected Outcome**:
  - `r.ActiveWorkers()` never exceeds 4 at any point in time.
  - Concurrency is strictly bounded by `WorkerPoolSize`.
  - All 12 connections eventually complete successfully.

### TC-111-02: Task Queuing and Sequential Servicing
- **Target**: `pkg/reactor/reactor_test.go` (`TestReactor_WorkerPoolQueueBackpressure`)
- **Methodology**:
  - Configure `WorkerPoolSize = 2` and `MaxQueueSize = 8`.
  - Dial 6 concurrent clients sending sequenced payloads.
  - Verify that excess connections reside in `r.tasks` (assert `QueueLen() > 0`) and are processed in FIFO/fair order as workers become free.
- **Expected Outcome**:
  - Connections queue smoothly without drops or panics.
  - As earlier connections complete, queued connections are serviced without data corruption.

### TC-111-03: Graceful Shutdown with Active and Queued Tasks
- **Target**: `pkg/reactor/reactor_test.go` (`TestReactor_GracefulShutdownDrainsQueue`)
- **Methodology**:
  - Configure `WorkerPoolSize = 2`, `MaxQueueSize = 8`.
  - Connect 6 clients and initiate `r.Shutdown(ctx)` while connections are active and queued.
- **Expected Outcome**:
  - Shutdown returns without deadlock within timeout deadline.
  - All active and queued sockets are closed (`net.ErrClosed` observed on client).
  - Reactor terminates with zero leaked worker goroutines.

### TC-111-04: Keep-Alive Concurrency Compatibility
- **Target**: `pkg/reactor/reactor_test.go` (`TestReactor_KeepAliveConcurrencyAndShutdown`)
- **Methodology**:
  - Configure `WorkerPoolSize = 32` (adequate for concurrent persistent connections).
  - Connect 20 idle keep-alive clients, sending ping and receiving pong.
  - Connect 21st client and verify immediate ping-pong service without latency.
  - Execute graceful shutdown and assert `reactor.ErrServerClosed`.
- **Expected Outcome**:
  - All 20 idle connections remain open concurrently.
  - 21st connection is processed immediately.
  - Clean shutdown terminates all persistent sessions.

### TC-111-05: Connection Dispatch Microbenchmark
- **Target**: `pkg/reactor/reactor_bench_test.go` (`BenchmarkReactor_ConnectionDispatch`)
- **Methodology**:
  - Measure connection queueing and worker dispatch operations under `testing.B` with `b.ReportAllocs()`.
- **Expected Outcome**:
  - Sub-microsecond dispatch latency per connection.
  - Deterministic and minimal allocations per task dispatch.
