# SR-076 - Security Review of Hardened Path Exclusion Matching in Auth and WAF

## Description

Security evaluation of the implementation for `TASK-078` / `SEC-18` (Authentication and WAF bypass via root and empty string path exclusion misconfiguration).

## Scope

- Files reviewed:
  - `pkg/router/auth.go`
  - `pkg/waf/middleware.go`
  - `pkg/router/auth_test.go`

## Security Evaluation & Analysis

1. **Elimination of Global Security Bypass (CWE-285)**:
   - Previously, configuring an exclusion rule as `"/"` or `""` caused prefix evaluation against `"/"`, inadvertently matching every incoming path and disabling authentication or threat inspection globally.
   - Refactored exclusion loops in both `NewAuthMiddleware` and `NewWAFMiddleware`:
     - Empty exclusion strings (`pTrimmed == ""`) are strictly ignored.
     - Root exclusion (`pTrimmed == "/"`) requires strict path equality (`req.Path == "/"`). Child routes (`/admin`, `/api`) are not matched and remain protected.
     - Subpath rules (`pTrimmed != "/"`) match only the exact path or child paths prefixed with `pTrimmed + "/"`.
2. **Parity Across Auth and WAF Middlewares**:
   - Both security middleware modules now share identical hardened exclusion semantics, preventing configuration divergence.
3. **Exploit Verification**:
   - Verified that `excluded: ["/"]` permits unauthenticated requests to `/` (status 200) while `/admin/dashboard` is strictly rejected with `401 Unauthorized`.
   - Verified that `excluded: [""]` is safely ignored, rejecting unauthenticated requests to `/api/data` with `401 Unauthorized`.

## Conclusion

`SEC-18` is fully mitigated. Global authentication and WAF bypasses due to root/empty exclusion rules are eliminated. Approved.
