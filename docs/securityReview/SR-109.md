# SR-109 - Security Review for Header Field-Name Token Grammar Hardening

## 1. Security Evaluation Summary

- **Components**: `pkg/httpparser/parser.go`, `pkg/httpparser/parser_test.go`
- **Reviewed By**: Security Analyst
- **Status**: **APPROVED** (Zero Security Defects Identified)
- **Target Threat Invariants**:
  - RFC 7230 §3.2 / §3.2.6: Header Field-Name Token Grammar Specification
  - CWE-444: Inconsistent Interpretation of HTTP Requests (HTTP Request Smuggling / Parser Differential Attacks)
  - CWE-113: Improper Neutralization of CRLF Sequences in HTTP Headers ('HTTP Request/Response Splitting')
  - CWE-20: Improper Input Validation

## 2. Threat Vector Fidelity & Mitigation Verification

| Threat Vector / Attack Scenario | Security Verification & Invariant Analysis | Empirical Security Finding |
| :--- | :--- | :---: |
| **Parser Differential & Delimiter Smuggling (CWE-444)** | Attackers inject delimiters like `;`, `,`, `=`, or `?` into header names to exploit differences in header splitting between Toron and upstream engines (e.g. Node.js `llhttp`, NGINX). | **Mitigated**: All delimiters are rejected with `400 Bad Request`. Sockets fail fast and close immediately. |
| **Control Character Header Poisoning (CWE-113)** | Embedded NUL (`0x00`), ESC (`0x1B`), or DEL (`0x7F`) bytes in header names can truncate strings in C-based runtimes or escape log parsers. | **Mitigated**: All ASCII bytes `< 0x20` and `0x7F` are rejected by `validHeaderTokenTable`. |
| **Non-ASCII / High-Byte Smuggling** | High bytes (`0x80`-`0xFF`) or malformed UTF-8 in header keys can induce encoding desynchronization on multi-hop reverse proxy pipelines. | **Mitigated**: All bytes `0x80`-`0xFF` are blocked; only 7-bit ASCII `tchar` is accepted. |
| **Fail-Fast Socket Teardown** | Rejection emits `ErrBadRequest` which prompts `pkg/server/server.go` to emit `Connection: close` and sever the TCP transport socket. | **Verified**: Attack traffic cannot reuse the connection to attempt subsequent smuggling payloads. |
| **Academic Peer Review Mandate** | Fully resolves **`SRC-04`** from `ReviewTaskSummary.md` and Associate Editor Reports (`AER-001`, `AER-002`). | **Methodologically Sound**: Zero external dependencies; zero-allocation lookup table ensures wire-speed defense without DoS risk. |

## 3. Verdict

The static lookup table implementation of RFC 7230 §3.2.6 token grammar closes the semantic gap between Toron and backend HTTP runtimes, eliminating header differential injection vectors. Security review approval granted.
