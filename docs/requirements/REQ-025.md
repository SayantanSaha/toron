# REQ-025 - HTTP/2 WebSocket Support via Extended CONNECT Protocol (RFC 8441)

## Description

The Toron web server shall support bootstrapping WebSockets over HTTP/2 using the extended CONNECT method protocol (RFC 8441).

This includes advertising `SETTINGS_ENABLE_CONNECT_PROTOCOL = 1` in HTTP/2 settings, accepting `:method = CONNECT` requests with `:protocol = websocket` pseudo-headers, translating/forwarding HTTP/2 WebSocket streams through the router and reverse proxy gateway, and responding with HTTP status 200 OK upon successful stream establishment.

## Acceptance Criteria

- `pkg/httpparser`: `Request` supports detecting RFC 8441 HTTP/2 WebSocket requests (`:method = CONNECT`, `:protocol = websocket` or `:protocol` header parameter).
- `pkg/server`: `http2.Server` is configured with `EnableExtendedConnectProtocol: true` so HTTP/2 listeners advertise `SETTINGS_ENABLE_CONNECT_PROTOCOL` to clients.
- `pkg/server`: `http2AdapterHandler` supports streaming full-duplex HTTP/2 extended CONNECT requests through the router and proxy engine.
- `pkg/proxy`: `ReverseProxy` supports bridging HTTP/2 WebSocket streams to upstream target services.
- All Go unit tests pass cleanly.

## Rationale

RFC 8441 allows clients to run single-connection HTTP/2 multiplexing for both standard REST API calls and persistent WebSockets over the same TLS/TCP connection, avoiding connection overhead and enabling modern browser/gRPC features.
