# ADR-143 - Dual-Pane Analytics & Time-Window Filtered Paginated Request Explorer Architecture

## 1. Context & Problem Statement

As established in [`AN-003`](../analysis/AN-003.md) and defined in [`REQ-143`](../requirements/REQ-143.md), the Control Center dashboard Requests view ([`public/js/views/logs.js`](../../public/js/views/logs.js)) requires an architectural redesign to handle production traffic scalably.

Currently:
1. All requests in the memory buffer are rendered into a flat list, capped arbitrarily at 70 rows without pagination.
2. In real-time tailing, incoming requests push existing rows downward, causing layout thrashing and misclicks.
3. Operators lack macro-level visibility into throughput, status breakdown, and top endpoint performance.
4. Operators cannot filter requests by temporal operational windows (`1m`, `5m`, `1h`, custom timestamps) or sort by latency to isolate bottlenecks.

---

## 2. Decision & Component Architecture

Adopt **Option 1: Dual-Pane Analytics & Time-Window Filtered Paginated Request Explorer**:

```text
┌────────────────────────────────────────────────────────────────────────┐
│               Toron Control Center: Requests View (#log)               │
├────────────────────────────────────────────────────────────────────────┤
│ 1. TOP ANALYTICS & FACET STRIP                                         │
│  ┌───────────────────────────────┐  ┌───────────────────────────────┐  │
│  │ Mini Status Histogram (SVG)   │  │ Actionable Facet Cards:       │  │
│  │ [2xx green | 4xx amb | 5xx red│  │ • Top Endpoints (click filter)│  │
│  │  Time-bucketed distribution]  │  │ • P95 Latency & Slowest Route │  │
│  └───────────────────────────────┘  │ • Error % in window           │  │
│                                     └───────────────────────────────┘  │
├────────────────────────────────────────────────────────────────────────┤
│ 2. TEMPORAL & EXPRESSIVE FILTER TOOLBAR                                │
│  [ Search... ] [ Time: 1m|5m|1h|All|Custom▼ ] [ From.. To.. (if custom)│
│  [ 2xx ] [ 3xx ] [ 4xx ] [ 5xx ] [ Over SLO ] [ Exclude /health ]      │
│  [ Routes▼ ] [ ⏸ Pause / ▶ Tail ]                                      │
├────────────────────────────────────────────────────────────────────────┤
│ 3. PAGINATED & SORTABLE REQUEST STREAM                                 │
│  Header (Clickable Sort): Time ▼ | Status | Method+Path | Latency | IP  │
│  Rows: Max 25/50/100 (Default 25) · Freeze on Hover / Inspect          │
├────────────────────────────────────────────────────────────────────────┤
│ 4. PAGINATION FOOTER                                                   │
│  Showing 1–25 of 148 requests  [« First] [‹ Prev] [Page 1/6] [Next ›]  │
│  Page Size: [ 25 ▼ ]                                                   │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 State Management Extensions ([`public/js/state.js`](../../public/js/state.js))
Extend `state` with reactive fields for the redesigned Requests view:
- `state.ltime`: Time window mode (`'1m'`, `'5m'`, `'1h'`, `'all'`, `'custom'`), default `'all'`.
- `state.lfrom`: Custom range start timestamp in milliseconds (number or null).
- `state.lto`: Custom range end timestamp in milliseconds (number or null).
- `state.lnohealth`: Boolean flag to exclude `/health` requests (default `false`).
- `state.lsort`: Primary sort column (`'ts'`, `'status'`, `'ms'`, `'path'`), default `'ts'`.
- `state.lsortDir`: Sort direction (`'desc'` or `'asc'`), default `'desc'`.
- `state.lpage`: Current active page index (1-indexed, default `1`).
- `state.lpageSize`: Configurable page size (`25`, `50`, or `100`, default `25`).
- `state.lhover`: Boolean flag set true when mouse is over table or drawer is active, pausing visual DOM mutations.

### 2.2 SVG Mini-Histogram Generation
Instead of pulling in third-party chart libraries, generate a lightweight, responsive native SVG histogram within [`public/js/views/logs.js`](../../public/js/views/logs.js):
- Buckets the active filtered requests into 20–30 time intervals across the selected temporal window.
- Computes stacked bar segments for `2xx`, `3xx`, `4xx`, and `5xx` counts.
- Scales heights proportionally to the maximum bucket volume.

### 2.3 Interaction Freeze on Hover & Drawer
When an operator hovers over the table body (`mouseenter`) or opens the log inspection drawer, visual DOM replacement is suspended (`state.lhover = true`). New requests still populate `rawApiLogs` and the data model in the background, but the table rows stay stationary under the user's cursor. On `mouseleave` (with drawer closed), the table resumes updating.

---

## 3. Performance & Size Budget Compliance

1. **DOM Node Capping**: The table DOM renders at most `lpageSize` rows (default 25), reducing layout calculations from hundreds of nodes to 25.
2. **Zero Dependencies**: Pure standard vanilla JavaScript and native inline SVG.
3. **Footprint Guard**: Implementation is kept strictly within the existing $\le 100\text{ KB}$ JavaScript budget limit.
