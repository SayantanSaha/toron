## 2. Threat Modeling & Boundary Assessment

### 2.1 RFC 7230 §6.1 Conformance & Smuggling Prevention (CWE-444)
- **Invariant**: Raw hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Transfer-Encoding`, `Upgrade`) must never be forwarded blindly across proxy boundaries.
- **Analysis**: Instead of allowing operators to disable hop-by-hop stripping (which would have violated [`REQ-071 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-071.md) and enabled HTTP Request Smuggling), the architecture refined the feature into `PropagateUpstreamClose`.
- **Finding**: Hop-by-hop headers are stripped unconditionally. When `PropagateUpstreamClose: true`, Toron sets its own downstream `Connection: close` header to cleanly signal connection termination to the client loop, while raw origin headers remain sanitized. Zero smuggling risk.

### 2.2 Egress Forward Proxy Injection & SSRF Boundaries (CWE-918)
- **Invariant**: Operators configuring `proxy_url` must not be able to bypass URL validation or inject invalid transport protocols.
- **Analysis**: In `pkg/config/loader.go` and `pkg/proxy/proxy.go`, `ProxyURL` is validated using `url.Parse`, strictly requiring `http` or `https` schemes and a non-empty host. Direct dialing (`Proxy: nil`) remains the default, preventing unintended egress routing.

### 2.3 Denial of Service & Connection Starvation (CWE-400)
- **Invariant**: Fragile origins must be protectable from connection flooding.
- **Analysis**: Adding `MaxConnsPerHost` empowers operators to enforce backpressure limits on upstream targets, preventing connection bursts from overwhelming single-threaded WSGI, ASGI, or Node origins.

### 2.4 Upstream HTTP/2 Concurrency Safety (CWE-662)
- **Invariant**: Concurrent HTTP/2 upstream handshakes must not trigger data races on shared TLS configurations.
- **Analysis**: Transport creation maintains defensive cloning of `opts.TLSClientConfig` (verified in [`SR-099`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-099.md)), preventing unsynchronized concurrent read/write mutations on `NextProtos`. Verified race-free.
