## Description

This code review evaluates the changes implemented under [`TASK-116`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-116.md) and [`TASK-117`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-117.md) satisfying requirement specification [`REQ-094`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md), architectural decision record [`ADR-089`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-089.md), and test specification [`TC-094`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-094.md).

The change resolves four severe cascading failure modes in Toron Edge Gateway's core routing engine and Kubernetes Ingress Controller:
1. **Unbounded Route Table Memory Leaks**: Replaces unconditional slice appends during periodic and reactive resyncs with atomic source-partitioned batch replacement ([`ReplacePrefixRoutesBySource`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L307-L350)), bounding the routing table size strictly to $O(K)$ entries for $K$ active Ingress rules.
2. **Zombie Route Persistence**: Ensures routes deleted from the Kubernetes cluster are automatically excluded from the desired route batch, purging them immediately from the routing table and returning HTTP `404 Not Found`.
3. **Stale Endpoint Shadowing**: Removes obsolete route entries atomically upon endpoint modifications, preventing first-match linear scan interception by dead or decommissioned pod IPs.
4. **Multi-Pod Replica Starvation**: Consolidates multiple pod endpoint IPs sharing a `(Host, CleanPrefix)` into a single load-balanced reverse proxy configured with Toron's `RoundRobinBalancer`, restoring horizontal scaling and distributing traffic evenly across all pod replicas ($\approx 1/M$).
5. **Background Goroutine & Socket Leaks**: Integrates automatic [`proxy.Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L596-L600) invocation upon route eviction in `ReplacePrefixRoutesBySource`, `RemovePrefixRoute`, and `Reset`, terminating active health checker ticker goroutines and closing idle TCP probe sockets.

## Findings

### Finding 1: Telemetry Map Key Collision Risk on Multi-Path Single-Service Ingresses

- **Severity**: Low
- **Location**: [`pkg/ingress/translator.go:120-129`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go#L120-L129), [`pkg/ingress/controller.go:160`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go#L160)
- **Related Artifact**: [`REQ-094-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md#L120-L125), [`TASK-117 Step 1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-117.md#L71-L78)
- **Description**: In [`TranslateIngress`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go#L120-L129), `ContainerID` is generated using:
  ```go
  ContainerID: fmt.Sprintf("k8s-%s-%s-%s-%d", ing.Metadata.Namespace, ing.Metadata.Name, svcName, idx)
  ```
  If a single Kubernetes Ingress defines multiple path rules (or multiple host rules) pointing to the *same* backend Service (e.g. path `/v1` and path `/v2` both targeting service `api-svc`), the generated `ContainerID` for pod index `idx` is identical across both paths.
  In [`pkg/ingress/controller.go:160`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go#L160):
  ```go
  newRoutes[r.ContainerID] = r
  ```
  The second path's `DiscoveredRoute` overwrites the first path's entry in `newRoutes`.
- **Impact**:
  - **Routing Correctness**: Not impacted. Runtime routing uses `targetsByKey` and `keyOrder` keyed by `routeKey{host: host, prefix: cleanPrefix}`, which properly separates distinct paths.
  - **Telemetry / Observability**: Callers of [`ctrl.ActiveRoutes()`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go#L51-L60) or admin APIs inspecting discovered container routes will observe fewer routes than actual active paths when multiple paths target the same Service in one Ingress.
- **Recommendation**:
  Update `ContainerID` generation in `TranslateIngress` to incorporate the path prefix or path index, for example:
  ```go
  cleanIDPrefix := strings.Trim(strings.ReplaceAll(cleanPrefix, "/", "-"), "-")
  if cleanIDPrefix == "" {
      cleanIDPrefix = "root"
  }
  ContainerID: fmt.Sprintf("k8s-%s-%s-%s-%s-%d", ing.Metadata.Namespace, ing.Metadata.Name, cleanIDPrefix, svcName, idx)
  ```

### Finding 2: Unconditional Selection of First Port in Multi-Port Endpoint Subsets

- **Severity**: Low
- **Location**: [`pkg/ingress/translator.go:93-98`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go#L93-L98)
- **Related Artifact**: [`REQ-094-AC-05`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md#L151-L157), [`TASK-117 Step 1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-117.md#L71-L78)
- **Description**: In [`TranslateIngress`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go#L93-L98), subset port resolution executes as:
  ```go
  p := svcPort
  if len(subset.Ports) > 0 && subset.Ports[0].Port > 0 {
      p = subset.Ports[0].Port
  } else if p == 0 {
      p = 80
  }
  ```
  If a Kubernetes `Endpoints` subset defines multiple ports (e.g. `[{Name: "metrics", Port: 9090}, {Name: "http", Port: 8080}]`), and the Ingress Service backend specified `ServiceBackendPort{Number: 8080}` (or `Name: "http"`), the code unconditionally takes `subset.Ports[0].Port` (9090) rather than searching `subset.Ports` for the matching port.
- **Impact**:
  For typical Kubernetes services with a single endpoint port or homogeneous target ports, this works correctly. However, for multi-port services where the target port is not the first element in `subset.Ports`, traffic could be proxied to an auxiliary port (e.g., telemetry or admin) rather than the main application port.
- **Recommendation**:
  Match the endpoint port by name or number against `pathRule.Backend.Service.Port`:
  ```go
  p := svcPort
  if len(subset.Ports) > 0 {
      matched := false
      for _, epPort := range subset.Ports {
          if (svcPort > 0 && epPort.Port == svcPort) ||
             (pathRule.Backend.Service.Port.Name != "" && epPort.Name == pathRule.Backend.Service.Port.Name) {
              p = epPort.Port
              matched = true
              break
          }
      }
      if !matched && subset.Ports[0].Port > 0 {
          p = subset.Ports[0].Port
      }
  }
  if p == 0 {
      p = 80
  }
  ```

### Finding 3: Atomic Source-Tagged Prefix Route Replacement & All-or-Nothing Rollback

- **Severity**: Informational
- **Location**: [`pkg/router/router.go:307-350`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L307-L350), [`pkg/router/router.go:181-277`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L181-L277)
- **Related Artifact**: [`REQ-094-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md#L120-L125), [`REQ-094-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md#L126-L138), [`ADR-089 §1, §2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-089.md#L77-L195), [`TASK-116`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-116.md)
- **Description**: [`ReplacePrefixRoutesBySource`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L307-L350) provides an atomic batch route replacement primitive:
  1. Pre-compiles and pre-validates all route specifications outside of `r.mu.Lock()`.
  2. If any specification fails validation (invalid target type, unparseable rate limit, malformed upstream URL), all already-compiled proxies in the batch are immediately closed via `cpr.proxy.Close()` and an error is returned. The active routing table is untouched (all-or-nothing consistency).
  3. Under exclusive write lock (`r.mu.Lock()`), existing routes are partitioned into `retained` (routes from other sources) and `evicted` (routes matching the target source).
  4. The pre-compiled routes are appended to `retained`, and `r.prefixRoutes` is atomically reassigned.
  5. After releasing the write lock, all evicted reverse proxies are cleanly closed.
- **Verification**:
  - Validated by unit test `TestRouter_ReplacePrefixRoutesBySource` across Scenarios 1.1 through 1.5.
  - Preserves exact relative ordering of non-targeted sources (`"config"`, `"static"`).
- **Verdict**: Verified and Compliant.

## Positive Observations

1. **Clean Separation of Route Compilation & Write Lock Hold Time**:
   [`ReplacePrefixRoutesBySource`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L307-L350) compiles and validates all reverse proxies, rate limiters, and WAF middleware *before* acquiring `r.mu.Lock()`. Write lock hold time is reduced to nanoseconds (slice partitioning and pointer append), preventing lock contention and reader starvation in `ServeHTTP`.
2. **Leak-Free All-or-Nothing Rollback**:
   If pre-compilation of any spec fails midway through a batch, the engine loops over all previously pre-compiled routes in that batch and invokes `cpr.proxy.Close()` before returning the error. This prevents orphaned health check tickers and socket leaks when a partial configuration fails validation.
3. **Out-of-Lock Resource Teardown**:
   Invoking `pr.proxy.Close()` on evicted routes is performed *after* releasing `r.mu.Unlock()`. Network timeouts or balancer stops during route eviction do not block incoming HTTP traffic.
4. **Deterministic Route Ordering**:
   In [`pkg/ingress/controller.go:150-177`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go#L150-L177), `keyOrder` tracks the insertion order of unique `(Host, CleanPrefix)` keys, ensuring deterministic slice generation for `specs` rather than relying on Go's non-deterministic map iteration order.
5. **Strict Zero-Dependency Invariant**:
   All routing, serialization, synchronization, and balancing code strictly uses standard Go packages (`sync`, `net/http`, `net/url`, `time`, `context`, `strings`, `path`, `path/filepath`, `fmt`, `log`).

2. **Backward Compatibility**: `RoutePrefix` maintains identical signature and behavior, delegating to `RoutePrefixWithSource("config", ...)`. `c.ActiveRoutes()` preserves its exported method signature.
