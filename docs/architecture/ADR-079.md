# ADR-079 - Kubernetes Ingress Controller Non-Blocking Watch Stream and Debounced Event Consumer Architecture

## Context

In `pkg/ingress`, Toron connects to Kubernetes API server watch streams (`/apis/networking.k8s.io/v1/ingresses?watch=true`). Previously, watch events were piped into an unconsumed buffered channel (`c.events chan K8sWatchEvent`, cap=100) with naked channel writes. When more than 100 events arrived, the producer goroutine blocked permanently, rendering shutdown (`Stop()`) deadlocked forever on `c.wg.Wait()`.

## Decision

1. **Context-Guarded Channel Writes in `WatchIngresses`**:
   - Every send to `events` in `Client.WatchIngresses` MUST be wrapped in a non-blocking `select` with `case <-ctx.Done(): return ctx.Err()`.
   - This guarantees that client goroutines never block indefinitely on channel sends when the receiver is slow or stopping.

2. **Dual-Worker Pattern in `Controller`**:
   - The controller will maintain two dedicated workers tracked in `c.wg`:
     - `watchWorker(ctx)`: Connects to K8s API server and produces events into `c.events`.
     - `consumeEventsWorker(ctx)`: Drains `c.events` and triggers route updates.

3. **Debounced Resync Coalescing**:
   - To avoid triggering costly full route re-translations on high-churn clusters (where 50+ events may arrive in milliseconds), `consumeEventsWorker` uses a 25ms timer debounce window.
   - When multiple events arrive within 25ms, only a single `syncIngresses(ctx)` execution occurs.

4. **Coordinated Lifecycle Shutdown**:
   - `Controller.Stop()` cancels `c.cancel()`, which broadcasts `ctx.Done()` to both workers concurrently.
   - `watchWorker` exits immediately (unblocking on the `select` send or closing response body).
   - `consumeEventsWorker` stops its debounce timer and terminates.
   - `c.wg.Wait()` completes in <10ms with zero goroutine leaks.

## Consequences

- **Positive**: Eliminates SEC-23 channel deadlock completely.
- **Positive**: Enables real-time reactive route updates for Kubernetes Ingress additions, modifications, and deletions.
- **Positive**: Coalesces bursts of events, preventing route table computation thrashing.
- **Positive**: Preserves zero external dependencies and stdlib-only architecture.
