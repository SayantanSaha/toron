# ADR-108 - Persistent Connection bufio.Reader Preservation and Pipelining

## 1. Context & Problem Statement

Toron handles HTTP/1.1 persistent connections (`keep-alive`) within the connection worker loop `handleConn` in `pkg/server/server.go`. Prior to this decision:
1. `handleConn` invoked `httpparser.ParseRequest(conn, opts)` on every loop iteration, passing the raw `net.Conn`.
2. Inside `httpparser.ParseRequest` (`pkg/httpparser/parser.go`), every call allocated a fresh `bufr := bufio.NewReader(r)`.
3. Go standard library's `bufio.Reader` reads from the underlying stream into an internal 4 KB chunk buffer. When an HTTP/1.1 client sends pipelined requests (RFC 7230 §6.3.2) over a single TCP connection, `ParseRequest` parses the first request, but any additional pipelined requests or trailing bytes already read into the 4 KB buffer are discarded when `ParseRequest` returns.
4. On the subsequent loop iteration, `handleConn` passed `conn` again, creating another `bufio.NewReader(conn)`. Because the pipelined bytes had already been consumed from the kernel socket receive buffer, the server was desynchronized: it hung waiting for data or timed out.

## 2. Decision

We implement **Persistent `bufio.Reader` Preservation and Zero-Cost Type Assertion Reuse**:

### 2.1 Parser-Level Type Assertion Reuse (`pkg/httpparser/parser.go`)
Instead of unconditionally instantiating `bufio.NewReader(r)`, `ParseRequest` checks whether the provided `io.Reader` is already a `*bufio.Reader`:
```go
var bufr *bufio.Reader
if br, ok := r.(*bufio.Reader); ok {
    bufr = br
} else {
    bufr = bufio.NewReader(r)
}
```
This guarantees:
- Zero allocation and zero re-wrapping when callers pass an existing `*bufio.Reader`.
- Full backward compatibility when callers pass other `io.Reader` implementations (e.g. `*bytes.Buffer`, `*strings.Reader`).
- The existing function signature `ParseRequest(r io.Reader, opts ParserOptions) (*Request, error)` is preserved without breaking public APIs.

### 2.2 Server-Level Persistent Reader Lifecycle (`pkg/server/server.go`)
In `handleConn`, we allocate a single `*bufio.Reader` once before entering the request loop:
```go
br := bufio.NewReader(conn)
firstRequest := true
for {
    // ... deadline checks ...
    req, err := httpparser.ParseRequest(br, opts)
    // ... dispatch ...
}
```
The single reader instance `br` persists for the entire lifetime of the TCP connection session. All unconsumed pipelined bytes remain buffered in memory across consecutive request cycles.

### 2.3 Buffer-Aware Inactivity & Idle Deadline Management
When managing socket timeouts on persistent connections:
```go
timeout := s.config.ReadTimeout
if !firstRequest && br.Buffered() == 0 && s.config.IdleTimeout > 0 {
    timeout = s.config.IdleTimeout
}
if timeout > 0 {
    _ = conn.SetReadDeadline(time.Now().Add(timeout))
}
```
- If `br.Buffered() > 0`, unconsumed pipelined bytes are already buffered in user space; reading from `br` returns immediately without blocking on socket I/O. The connection is actively processing pipelined requests, so `IdleTimeout` is not triggered.
- If `br.Buffered() == 0`, the server is waiting for the client to transmit new packets over the persistent connection, so `IdleTimeout` applies.

### 2.4 Residual Buffer Preservation on Protocol Upgrades
If a request triggers a protocol upgrade (e.g., `101 Switching Protocols` or WebSocket proxying):
```go
if res.UpgradedConn != nil {
    var streamConn net.Conn = conn
    if br.Buffered() > 0 {
        unconsumed := make([]byte, br.Buffered())
        _, _ = io.ReadFull(br, unconsumed)
        streamConn = &prefixConn{Conn: conn, prefix: unconsumed}
    }
    // ... relay stream ...
}
```
Any frames sent by the client immediately following the upgrade handshake are not lost.

## 3. Considered Alternatives

- **Alternative 1: Passing `*bufio.Reader` directly in the signature of `ParseRequest`**:
  Rejected because changing `ParseRequest(r io.Reader, ...)` to `ParseRequest(r *bufio.Reader, ...)` would break every existing caller, test, and benchmark across the repository. Type assertion provides equivalent performance with zero API breakage.
- **Alternative 2: Returning the `*bufio.Reader` from `ParseRequest` in `*Request`**:
  Rejected because `*bufio.Reader` belongs to the connection transport layer, not the immutable HTTP request metadata.
- **Alternative 3: Resetting `bufio.Reader` with `br.Reset(conn)` on each iteration**:
  Rejected because `br.Reset(conn)` explicitly clears and discards the buffered unconsumed bytes, which is the exact failure mode being resolved.

## 4. Consequences

- **Positive**:
  - Full RFC 7230 §6.3.2 compliance for HTTP/1.1 request pipelining.
  - Complete elimination of socket desynchronization on persistent connections.
  - Zero allocation overhead for `bufio.Reader` recreation across request loops.
  - Safe handover of residual buffered bytes on protocol upgrades.
  - 100% backward-compatible API.
- **Negative / Operational Considerations**:
  - Requires careful management of `br.Buffered()` when inspecting connection idle status.
