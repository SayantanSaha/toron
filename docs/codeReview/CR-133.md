# CR-133 - Code Review of Inbound Chunked Transfer-Encoding Ingestion, Zero-Tolerance Wire Decoding, and Upstream Re-Framing Normalization (RFC 9112 §7.1)

> [!NOTE]
> This review document is also indexed chronologically in the repository sequence as [`CR-129.md`](file:///Users/sneha/Developer/toron-research/toron/docs/codeReview/CR-129.md). Both documents represent the identical authoritative review record for REQ-133 / TASK-156.

## 1. Executive Summary & Review Scope

### 1.1 Executive Summary

A comprehensive, senior-level code quality, security architecture, and protocol regression review was conducted on the changes implemented for [`REQ-133`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-133.md) and [`TASK-156`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-156.md), guided by architectural decisions in [`ADR-133`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-133.md) and verified against the 19 test cases in [`TC-133`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-133.md).

Historically, under [`ADR-056`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-056.md) (*Inbound Transfer-Encoding Rejection & Request Smuggling Defense*) and [`REQ-061`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-061.md), Toron maintained an uncompromising perimeter posture: all inbound HTTP/1.1 requests carrying `Transfer-Encoding: chunked` were immediately rejected with `HTTP/1.1 501 Not Implemented`, and the underlying TCP connection was severed. While this static posture immunized the early gateway against HTTP Request Smuggling ([CWE-444](https://cwe.mitre.org/data/definitions/444.html)), it created an operational barrier for modern cloud-native workloads (streaming uploads, SaaS webhooks, drop-in ingress replacement) and introduced protocol asymmetry with Toron's outbound streaming chunked responses ([`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md) / [`REQ-129`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-129.md)).

[`TASK-156`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-156.md) transitions Toron from static rejection into an **Active Ingress Smuggling Firewall**:
1. **Zero-Tolerance RFC 9112 §7.1 Wire Decoding**: A streaming finite-state machine (`ChunkedBodyReader` in [`pkg/httpparser/chunked.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go)) enforces strict `1*HEXDIG` chunk lengths, rejects signed hex, leading/embedded whitespace, bare LF delimiters, and clamps chunk extensions to $\le 256\,\text{B}$ and trailers to $\le 4\,\text{KB}$.
2. **Canonical Upstream Re-Framing Normalization**: In default `"normalize"` mode, Toron consumes and verifies chunked payloads at the edge, strips `Transfer-Encoding`, calculates the exact length, and forwards a clean `Content-Length` HTTP request upstream. Downstream origin microservices (Node.js, Python ASGI, Ruby Puma, Go `net/http`) are 100% insulated from chunk-level parsing vulnerabilities and desynchronizations.
3. **Canonical Passthrough Streaming Mode (`"passthrough"`)**: For high-throughput routes exceeding gateway buffering limits, Toron streams validated canonical chunks upstream, deploying an `earlyCancelingReader` that aborts upstream contexts immediately upon client disconnection or framing fault.
4. **Configurable Backward Compatibility (`"reject"`)**: The legacy [`ADR-056`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-056.md) perimeter defense is preserved as a configurable operational profile (`inbound_chunked_mode: "reject"`) with route-level override granularity.

## 3. Detailed Code Review by Subsystem

### 3.1 Streaming Zero-Tolerance Chunked Decoder ([`pkg/httpparser/chunked.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go) & [`chunked_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked_test.go))

#### 3.1.1 State Machine Architecture
`ChunkedBodyReader` implements a deterministic finite-state machine with five distinct states:
```go
const (
    stateChunkSize chunkedReaderState = iota
    stateChunkData
    stateChunkCRLF
    stateTrailerSection
    stateDone
)
```
- In [`chunked.go:86-223`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L86-L223), the `Read(p []byte)` loop manages transitions cleanly:
  - If caller passes a slice smaller than declared chunk size, the reader fulfills the available space from `stateChunkData` and preserves `chunkRemaining`.
  - When `chunkRemaining == 0`, it transitions to `stateChunkCRLF`.
  - When `stateDone` is reached, it returns accumulated bytes `(n, nil)` if `n > 0`, or `(0, io.EOF)` on terminal reads.
- **Evaluation**: The implementation conforms to Go's standard `io.Reader` contract and is decoupled from caller buffer slicing.

#### 3.1.2 Strict RFC 9112 §7.1 Hex Size Parsing (`1*HEXDIG`)
In [`chunked.go:226-333`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L226-L333) (`parseChunkSizeLine`):
- **Line Bounding**: Reads into `lineBuf [512]byte`. Lines exceeding 512 bytes return `ErrBadRequest`.
- **CRLF Delimiter**: Checks `idx < 2 || lineBuf[idx-2] != '\r'`, rejecting bare `\n` delimiters.
- **Empty Line**: Rejects `len(line) == 0`.
- **Leading Signs**: Explicit check `if hexBytes[0] == '+' || hexBytes[0] == '-'` returns `ErrBadRequest`.
- **Whitespace Checks**: Rejects leading space or tab (`hexBytes[0] == ' ' || hexBytes[0] == '\t'`). If no extension exists, trailing whitespace causes `isHexDigit` to fail, strictly enforcing zero trailing whitespace on bare hex sizes.
- **Character Grammar**: Loops over every character asserting `isHexDigit(c)` (`0-9`, `a-f`, `A-F`). Prefix notation (`0x10`, `0X1A`) fails on `'x'`.
- **Integer Bounds**: `strconv.ParseUint(trimmedHex, 16, 64)` rejects strings exceeding uint64. In addition, line 312 asserts `size > math.MaxInt64` to prevent signed 64-bit integer overflow.
- **Evaluation**: Zero-tolerance wire parsing is complete, uncompromising, and immune to integer overflow tricks.

#### 3.1.3 Bounded Chunk Extension Clamping ($\le 256\,\text{B}$)
In [`chunked.go:317-330`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L317-L330):
- Measures total extension length: `totalExtBytes := len(line) - len(trimmedHex)`.
- If `totalExtBytes >= MaxChunkExtensionBytes` (256 bytes), it aborts with `ErrBadRequest`.
- Inspects extension bytes for control characters: `(c < 0x20 && c != '\t') || c == 0x7F` triggers `ErrBadRequest`.
- Unrecognized extensions are ignored without string allocation.
- **Evaluation**: Completely eliminates chunk extension DoS ([CWE-400](https://cwe.mitre.org/data/definitions/400.html)).

#### 3.1.4 Strict CRLF Boundary Enforcement
In [`chunked.go:171-200`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L171-L200):
- In `stateChunkCRLF`, reads exactly 2 bytes via `io.ReadFull(cr.r, crlf[:])`.
- Asserts `crlf[0] == '\r' && crlf[1] == '\n'`.
- Any bare LF, bare CR, or garbage byte triggers `ErrBadRequest` and severs the underlying connection.
- Reader never advances to the next chunk before validating the CRLF boundary.
- **Evaluation**: Prevents delimiter confusion desynchronization between front-end and back-end parsers.

#### 3.1.5 Cumulative Payload Body Bounding (`opts.MaxBodyBytes` and HTTP 413)
In [`chunked.go:121-130, 143-150`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L121-L150):
- Tracks cumulative count: `cr.totalBodyRead += int64(readCount)`.
- If `cr.totalBodyRead > cr.maxBodyBytes`, sets `cr.err = ErrBodyTooLarge`, invokes `cr.closer.Close()`, and returns `ErrBodyTooLarge`.
- In `pkg/server/server.go`, `ErrBodyTooLarge` maps to `HTTP/1.1 413 Payload Too Large`.
- **Evaluation**: Guards against infinite streaming / zip bombs on ingress.

#### 3.1.6 RFC 9112 §7.1.2 Trailer Parsing & Forbidden Header Prohibitions
In [`chunked.go:336-422`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L336-L422) (`parseTrailers`):
- Clamps total trailer bytes to `MaxTrailerBytes = 4096` ($4\,\text{KB}$); returns `ErrHeaderTooLarge` (HTTP 431) if exceeded.
- Searches for colon `:` and trims key/value.
- Forbidden trailer blacklist in `isForbiddenTrailer` ([`chunked.go:475-494`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L475-L494)):
  - Rejects headers starting with `:` (HTTP/2 pseudo-headers).
  - Prohibits: `Transfer-Encoding`, `Content-Length`, `Connection`, `Host`, `Keep-Alive`, `TE`, `Trailer`, `Trailers`, `Upgrade`.
  - Rejection triggers `ErrBadRequest` (HTTP 400).
- Valid trailers are merged into `cr.reqHeader` and recorded in `cr.trailers http.Header`.
- **Evaluation**: Implements 100% compliance with RFC 9112 §7.1.2 prohibitions, closing secondary request smuggling through trailers.

#### 3.1.7 Socket Drainage on `Close()`
In [`chunked.go:425-469`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/chunked.go#L425-L469) (`Close`):
- If stream is already `stateDone`, returns `nil`.
- If `cr.err != nil`, calls `cr.closer.Close()` and returns error.
- Drains unread bytes up to `MaxDrainBytes = 65536` ($64\,\text{KB}$):
  - If stream reaches `stateDone` within 64KB, keep-alive connection reuse is preserved.
  - If stream cannot be drained within 64KB, calls `cr.closer.Close()` to forcefully sever the socket.
- **Evaluation**: Protects keep-alive connections from leftover byte pollution ([CWE-444](https://cwe.mitre.org/data/definitions/444.html)).

### 3.3 Canonical Upstream Normalization & Forwarding ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go))

#### 3.3.1 Canonical Normalization Mode (`"normalize"`, Default)
In [`proxy.go:1103-1134, 1189-1206`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1103-L1206):
1. Reads the inbound stream completely via `io.ReadAll(req.Body)`.
2. As bytes are consumed, `ChunkedBodyReader` validates all RFC 9112 invariants.
3. If error occurs, maps `ErrBodyTooLarge` -> 413, `ErrHeaderTooLarge` -> 431, default -> 400, and terminates.
4. Computes exact decoded length: `exactCL := int64(len(decodedBytes))`.
5. For payloads $\le 64\,\text{KB}$, copies into pooled buffer slice from `httpparser.GetBodyBuffer()` and defers recycling via `PutBodyBuffer`.
6. Sets `outReq.ContentLength = exactCL`.
7. Sets `outReq.Header.Set("Content-Length", strconv.FormatInt(exactCL, 10))`.
8. Unconditionally deletes `Transfer-Encoding` from upstream headers.
9. **Security Result**: Downstream origin microservices NEVER receive raw chunked streams from external untrusted clients. Request smuggling at origin is eliminated.

#### 3.3.2 Canonical Passthrough Streaming Mode (`"passthrough"`)
In [`proxy.go:1095-1102, 1190-1195`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1095-L1195):
- Deploys `earlyCancelingReader`:
  ```go
  type earlyCancelingReader struct {
      r      io.Reader
      cancel context.CancelFunc
  }

  func (e *earlyCancelingReader) Read(p []byte) (int, error) {
      n, err := e.r.Read(p)
      if err != nil && !errors.Is(err, io.EOF) {
          if e.cancel != nil {
              e.cancel()
          }
      }
      return n, err
  }
  ```
- If client aborts or transmits malformed chunks, `e.cancel()` cancels the upstream request context immediately, severing the upstream connection.
- Sets `outReq.ContentLength = -1` and `outReq.TransferEncoding = []string{"chunked"}`.

## 5. Findings & Architectural Observations

### Finding 1: Complete Neutralization of Upstream Request Smuggling via Edge Normalization
- **Severity**: Informational (Security Architecture Excellence)
- **Location**: [`pkg/proxy/proxy.go:1103-1134`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1103-L1134)
- **Related Artifact**: [`REQ-133 §1.2`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-133.md#L73-L84), [`ADR-133 §1.3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-133.md#L78-L120)
- **Description**: Converting client chunked requests into clean `Content-Length` requests at the edge fundamentally eliminates chunk-level desynchronization vulnerabilities ([CWE-444](https://cwe.mitre.org/data/definitions/444.html)) across upstream origin microservices.
- **Impact**: Upstream backends written in Node.js, Python, Ruby, or Go never receive raw chunk framing from untrusted external clients. Even if an upstream microservice contains known chunk parsing vulnerabilities, the attack is rendered completely inert.
- **Recommendation**: Maintain `"normalize"` as the unconditional default mode across all deployment profiles.

### Finding 4: Early Context Cancellation in Passthrough Streaming Mode
- **Severity**: Informational (Resource Leak Prevention)
