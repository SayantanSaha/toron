# ADR-048: Dynamic Upstream Health Probing & Zero-Hardcoding Dashboard Telemetry

## Context
Previous iterations of the Toron static dashboard (`public/index.html` and `public/app.js`) used hardcoded dummy arrays (ports 9001–9010) and static dropdown items to demonstrate dashboard capabilities. As Toron matured into a production edge gateway with dynamic OCI container discovery and pluggable load balancers, the dashboard must reflect real runtime state.

## Decision
1. **Dynamic Target Extraction**: The internal API endpoint `/internal/api/upstreams/health` will query `router.Router` prefix routing tables and `InternalAPIConfig.Routes` to dynamically compile a de-duplicated list of upstream target endpoints (`http://host:port`).
2. **Concurrent Target Probing**: Concurrently probe each target with a strict 1-second timeout using Go goroutines, reporting live availability, status code, and latency.
3. **Frontend Data Binding**: The dashboard frontend will strictly render upstream cards, route counts, version branding, and API tester options from the JSON payloads of `/internal/api/status`, `/internal/api/routes`, and `/internal/api/upstreams/health`.

## Consequences
- **Positive**: Real-time accuracy for any custom `routes.yaml` configuration or dynamically discovered Docker containers; zero stale mock data.
- **Negative**: Adds lightweight network probing when the dashboard actively queries `/internal/api/upstreams/health`.
