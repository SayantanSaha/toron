## Description

This code review evaluates the changes implemented under [`TASK-118`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-118.md) satisfying requirement specification [`REQ-095`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md), architectural decision record [`ADR-095`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md), header routing specification [`ADR-005`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-005.md), and test specification [`TC-095`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-095.md).

The change completely resolves five critical failure modes in Toron Edge Gateway's OCI container auto-discovery engine and core routing subsystem:

1. **Premature Route Deletion on Single Replica Scale-Down (CWE-662, CWE-284)**:
   Previously, stopping any single container replica invoked `m.router.RemovePrefixRoute(host, prefix)`, which indiscriminately purged all routes matching `(host, prefix)` from `r.prefixRoutes`, killing traffic to all remaining healthy replicas and causing a complete service outage (HTTP 404). The implementation transitions all lifecycle events to declarative target aggregation and atomic source replacement via `ReplacePrefixRoutesBySource("oci-discovery", desiredSpecs)`. Surviving replicas continue serving traffic with zero 404 errors.
2. **Horizontal Scaling Collapse & Single-Instance Starvation (CWE-400)**:
   Previously, multi-replica containers were registered as separate single-target routes. Because `router.ServeHTTP` scans prefix routes linearly and selects the first match, replica #1 received 100% of incoming requests while replicas #2..$M$ received 0% of traffic. The implementation groups all replicas matching an identical `CompositeRouteKey` into a unified multi-target `PrefixRouteSpec` configured with `RoundRobinBalancer`, distributing traffic evenly ($\approx 1/M$) across all active instances.
3. **Canary Variant Conflation & Routing Dimension Blindness**:
   Previously, discovery parsed only `toron.host` and `toron.prefix`. Canary containers (differentiated by `toron.header.X-Version: canary`) and baseline containers were conflated into the same route, leaking pre-release code to regular users. The implementation introduces `CompositeRouteKey = (Host, CleanPrefix, Method, CanonicalHeaders)`, keeping canary and baseline target pools strictly isolated.
4. **Route Shadowing via ADR-005 Specificity Sorting**:
   Prefix routes were previously evaluated in container discovery arrival order, allowing an unconstrained generic route (`/api`) registered earlier to shadow a more specific canary route (`/api` with `X-Version: canary`). The implementation enforces a 5-tier specificity hierarchy (Longest prefix $\to$ Specific host $\to$ Header constraint count $\to$ Method constraint $\to$ Deterministic tie-break), guaranteeing that canary routes are always evaluated before fallback routes.
5. **Declarative Method Matching & Proxy Resource Teardown**:
   `PrefixRouteSpec` now provides first-class `Method string` filtering, returning HTTP 405 Method Not Allowed or falling through to matching handlers on verb mismatches. Evicted reverse proxies cleanly invoke `proxy.Close()`, stopping active health check tickers and releasing idle TCP sockets.

## Findings

### Finding 1: Premature Method Mismatch Evaluation in `ServeHTTP` Before Host and Header Matching

- **Severity**: Medium
- **Location**: [`pkg/router/router.go:824-834`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L824-L834)
- **Related Artifact**: [`REQ-095-AC-07`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L174-L185), [`ADR-095 §5.1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md#L312-L333), [`TC-095-07`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-095.md#L372-L402)
- **Description**:
  In [`router.ServeHTTP`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L820-L850), the prefix routing loop evaluates method constraints *before* validating host and header constraints:
  ```go
  for i := range r.prefixRoutes {
      pr := &r.prefixRoutes[i]
      if pr.prefix == "" || strings.HasPrefix(req.Path, pr.prefix+"/") || req.Path == pr.prefix {
          if pr.method != "" && !strings.EqualFold(pr.method, req.Method) {
              methodMismatch = true
              continue
          }
          if pr.matcher != nil && !pr.matcher(req.Path) {
              continue
          }
          if headersAndHostMatch(reqHost, req, pr.host, pr.headers) {
              targetHandler = pr.handler
              break
          }
  ```
  If a prefix route is registered with an explicit method constraint (e.g. `POST`) on a specific host (e.g. `internal.corp.local`) or specific canary header (e.g. `X-Version: canary`), and an incoming `GET` request arrives for a *different* host (e.g. `public.example.com`) or without headers on that same path prefix:
  1. The prefix check matches.
  2. `pr.method != ""` is evaluated before `headersAndHostMatch`.
  3. Because `POST != GET`, `methodMismatch = true` is set, and the loop continues.
  4. If no subsequent route matches, the router evaluates lines 844-848:
     ```go
     if targetHandler == nil {
         if methodMismatch {
             targetHandler = r.MethodNotAllowed
         } else {
             targetHandler = r.NotFound
         }
     }
     ```
  5. The router returns HTTP `405 Method Not Allowed` to `public.example.com` instead of HTTP `404 Not Found`.
- **Impact**:
  Violates RFC 9110 §15.5.6. HTTP 405 Method Not Allowed indicates that the requested HTTP verb is not allowed for the *targeted resource*. However, because host and header constraints were never checked for that route, the request was never addressing that virtual host or canary resource in the first place.
- **Recommendation**:
  Evaluate `headersAndHostMatch` and `pr.matcher` *before* checking the method constraint:
  ```go
  if pr.prefix == "" || strings.HasPrefix(req.Path, pr.prefix+"/") || req.Path == pr.prefix {
      if !headersAndHostMatch(reqHost, req, pr.host, pr.headers) {
          continue
      }
      if pr.matcher != nil && !pr.matcher(req.Path) {
          continue
      }
      if pr.method != "" && !strings.EqualFold(pr.method, req.Method) {
          methodMismatch = true
          continue
      }
      targetHandler = pr.handler
      break
  }
  ```
  This ensures `methodMismatch = true` is recorded only when the incoming request's host and headers match the target route definition.

### Finding 2: Non-Deterministic Proxy Option Inheritance Under Conflicting Multi-Replica Labels

- **Severity**: Low
- **Location**: [`pkg/discovery/manager.go:226-242`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery/manager.go#L226-L242)
- **Related Artifact**: [`REQ-095-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L133-L147), [`ADR-095 §3.1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md#L238-L270)
- **Description**:
  In [`buildDesiredSpecsLocked`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery/manager.go#L179-L274), proxy configuration options (`StripPrefix`, `RewriteRedirects`, `RewriteCookiePath`, `HealthCheckPath`, `HealthCheckInterval`) are collected across replicas in `g.routes`:
  ```go
  for _, r := range g.routes {
      if stripPrefix == nil && r.StripPrefix != nil {
          stripPrefix = r.StripPrefix
      }
      if rewriteRedirects == nil && r.RewriteRedirects != nil {
          rewriteRedirects = r.RewriteRedirects
      }
      // ...
  }
  ```
  `g.routes` is populated by iterating over `m.activeRoutes` (`map[string]*DiscoveredRoute`). In Go, map iteration order is randomized. If two container replicas of the same service define conflicting label values (e.g., replica 1 has `toron.strip_prefix=true` while replica 2 has `toron.strip_prefix=false`), the selected option depends on map iteration order and may oscillate between reconciliation passes.
- **Impact**:
  For standard homogeneous container deployments, all replicas carry identical labels, so this produces identical results. However, in misconfigured or rolling update environments with divergent label values, proxy behavior could become non-deterministic across sync iterations.
- **Recommendation**:
  Sort `g.routes` deterministically (e.g. by `ContainerID` or `TargetURL`) before aggregating proxy options:
  ```go
  sort.Slice(g.routes, func(i, j int) bool {
      return g.routes[i].ContainerID < g.routes[j].ContainerID
  })
  ```

### Finding 3: Unreachable Dead Code in `router.ServeHTTP` (`fallbackPrefix`)

- **Severity**: Low
- **Location**: [`pkg/router/router.go:835-842`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L835-L842)
- **Related Artifact**: [`REQ-001`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-001.md), [`ADR-005`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-005.md)
- **Description**:
  In [`router.ServeHTTP`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L831-L842):
  ```go
  if headersAndHostMatch(reqHost, req, pr.host, pr.headers) {
      targetHandler = pr.handler
      break
  }
  if pr.host == "" && len(pr.headers) == 0 && fallbackPrefix == nil {
      fallbackPrefix = pr
  }
  ```
  If a route has `pr.host == ""` and `len(pr.headers) == 0`, `headersAndHostMatch(reqHost, req, "", nil)` *always* returns `true`. Consequently, the `if headersAndHostMatch(...)` branch on line 831 always triggers, assigning `targetHandler = pr.handler` and executing `break`.
  Line 835 can never be executed, `fallbackPrefix` is never assigned, and lines 840-842 (`if targetHandler == nil && fallbackPrefix != nil`) represent unreachable dead code.
- **Impact**:
  No functional defect or runtime failure occurs, but the dead code adds confusion to router path resolution logic.
- **Recommendation**:
  Remove the unused `fallbackPrefix` pointer and its associated unreachable check.

### Finding 4: Silently Discarded Error Return in `ReplacePrefixRoutesBySource` Calls

- **Severity**: Low
- **Location**: [`pkg/discovery/manager.go:301, 365, 384`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery/manager.go#L301)
- **Related Artifact**: [`REQ-095-AC-04`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L148-L159), [`TASK-118 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-118.md#L239-L274)
- **Description**:
  In `syncInitialContainers`, `handleContainerStart`, and `handleContainerStop`, calls to `m.router.ReplacePrefixRoutesBySource("oci-discovery", desiredSpecs)` discard the returned error:
  ```go
  if m.router != nil {
      _ = m.router.ReplacePrefixRoutesBySource("oci-discovery", desiredSpecs)
  }
  ```
  If a route specification fails compilation (e.g., malformed rate limit string, unparseable upstream target URL, or invalid route type), `ReplacePrefixRoutesBySource` rolls back and returns an error. Discarding the error hides configuration failures from gateway logs.
- **Impact**:
  Operational blindness in the event of upstream URL or option compilation failure.
- **Recommendation**:
  Capture and log the returned error:
  ```go

          log.Printf("[DISCOVERY] ERROR: failed to replace prefix routes: %v", err)

  }
  ```

### Finding 5: Specificity Ordering Architecture and Anti-Shadowing Validation

- **Severity**: Informational
- **Location**: [`pkg/router/router.go:205-368`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L205-L368), [`pkg/router/router_test.go:1192-1294`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router_test.go#L1192-L1294)
- **Related Artifact**: [`REQ-095-AC-07`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L174-L185), [`ADR-005`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-005.md), [`ADR-095 §5`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md#L308-L377), [`TC-095-06`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-095.md#L322-L370)
- **Description**:
  The implementation introduces a robust, mathematically deterministic 5-tier specificity hierarchy:
  1. **Tier 1 (Prefix Length)**: Longer prefixes strictly precede shorter prefixes (e.g. `/api/v1/auth` before `/api/v1` before `/api`).
  2. **Tier 2 (Host Specificity)**: Routes bound to explicit domain hosts strictly precede wildcard or unhosted routes (`host != ""` before `host == ""`).
  3. **Tier 3 (Header Specificity)**: Routes with header constraints strictly precede unconstrained routes (`len(headers) > 0` before `len(headers) == 0`, with higher constraint counts taking precedence).
  4. **Tier 4 (Method Specificity)**: Routes specifying an explicit HTTP verb strictly precede wildcard verb routes (`method != ""` before `method == ""`).
  5. **Tier 5 (Deterministic Tie-Break)**: Alphabetical comparison across host, canonical headers, method, prefix, and source ensures stable ordering across runtime runs.
- **Verification**:
  - Validated by `TestRouter_SpecificityOrdering_NoCanaryShadowing`.
  - Adverse registration test registers a generic `/api` route *before* a canary `/api` route (`X-Version: canary`). The router automatically sorts the canary route ahead of the generic route.
  - 6-route multi-tier test registers routes in reverse order; verifies exact rank order:
    `Rank 0: /api/v1/auth` $\to$ `Rank 1: /api/v1` $\to$ `Rank 2: /api (Host, Gold, POST)` $\to$ `Rank 3: /api (Host, Gold, Any)` $\to$ `Rank 4: /api (Host)` $\to$ `Rank 5: /api (Unhosted)`.
- **Verdict**: Verified and Compliant.

## Positive Observations

1. **Lock-Inversion-Free Orchestration**:
   The discovery manager strictly segregates discovery state lock `m.mu` from router state lock `r.mu`. Route specifications are computed under `m.mu.Lock()`, but `m.router.ReplacePrefixRoutesBySource` is called after releasing `m.mu.Unlock()`. This prevents any potential lock inversion deadlock between the two subsystems.
2. **Deterministic Multi-Tier Specificity Architecture (ADR-005)**:
   Implementing `comparePrefixRoutes` and `comparePrefixRouteSpecs` centrally inside `pkg/router` guarantees that all route entry points (`RoutePrefixWithSource`, `ReplacePrefixRoutesBySource`, `HandlePrefixWithMatcher`) enforce ADR-005 specificity ordering, ensuring that canary deployments and method-specific routes are never shadowed by generic routes regardless of caller registration order.
3. **Out-of-Lock Resource Teardown**:
   Invoking `pr.proxy.Close()` on evicted reverse proxies is deferred until *after* releasing `r.mu.Unlock()`. Network socket teardown and background health check halts do not block incoming HTTP request evaluation in `ServeHTTP`.
4. **Resilient Label Parsing**:
   `ParseContainerLabels` gracefully handles edge cases such as malformed JSON in `toron.headers` (falling back to comma-delimited key-value parsing without panicking), empty tokens, leading/trailing whitespace, and letter casing.
5. **Zero Third-Party Dependencies**:
   The entire feature is implemented using only the Go standard library, keeping binary size minimal, build times fast, and the supply chain attack surface zero.

## Constraints

1. **Standard Library Only**: Pure Go standard library packages only; zero third-party packages added (`go.mod` and `go.sum` remain untouched).
2. **Backward Compatibility**: `ActiveRoutes()` preserves its signature and semantics for administrative inspection and telemetry. `RoutePrefix` continues delegating cleanly to `RoutePrefixWithSource("config", ...)`.
3. **Zero Downtime Scale-Down**: Stopping a single container replica must never drop or interrupt traffic to surviving replicas.
4. **Thread Safety & Race-Freedom**: All operations must remain 100% data-race-free under `go test -race`.

## Open Questions & Recommendations

1. **Premature Method Mismatch Check (Finding 1)**:
   Recommend reordering the route evaluation in `router.ServeHTTP` to check `headersAndHostMatch` before `pr.method != ""`, ensuring that HTTP 405 Method Not Allowed is not returned for routes belonging to different virtual hosts or canary header sets.
2. **Deterministic Option Inheritance (Finding 2)**:
   Recommend sorting `g.routes` by `ContainerID` before extracting proxy options in `buildDesiredSpecsLocked`, guaranteeing deterministic option inheritance even if container replicas are misconfigured with conflicting labels.
3. **Dead Code Cleanup (Finding 3)**:
   Recommend removing the unreachable `fallbackPrefix` pointer and checks from `router.ServeHTTP`.
4. **Error Logging on Route Replacement (Finding 4)**:
   Recommend logging any errors returned by `m.router.ReplacePrefixRoutesBySource` in `syncInitialContainers`, `handleContainerStart`, and `handleContainerStop`.
