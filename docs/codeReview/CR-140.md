# CR-140 - Code Review for Dynamic Upstream Target Context Propagation, Route Tagging, and Telemetry Trace Fidelity

## 1. Executive Summary

This code review evaluates the implementation of dynamic upstream target context propagation, route identification, and telemetry trace fidelity across the Toron Edge Gateway reverse proxy ([`pkg/proxy/proxy.go`](../../pkg/proxy/proxy.go)), the HTTP router ([`pkg/router/router.go`](../../pkg/router/router.go)), the gateway entrypoint and telemetry middleware ([`cmd/toron/main.go`](../../cmd/toron/main.go)), and the Control Center dashboard ([`public/app.js`](../../public/app.js)).

The implementation resolves the defects specified in [`REQ-140`](../requirements/REQ-140.md), architected in [`ADR-140`](../architecture/ADR-140.md), decomposed in [`TASK-163`](../tasks/TASK-163.md), and verified by [`TC-140`](../testCases/TC-140.md):
1. **Elimination of Hardcoded `"gateway"` Upstream Values**: Upstream backend sockets selected by reverse proxy load balancers (e.g. `127.0.0.1:8080`) are now propagated via `req.Context()` and recorded dynamically into `server.GlobalTraceBuffer`.
2. **Static Route and In-Process Destination Classification**: Static directory routes are cleanly tagged with destination `static`, while internal engine endpoints (e.g. `/health`, `/metrics`, redirects) are tagged as `in-process`.
3. **Hierarchical Route Identification & Subpath Filtering**: `TraceLogEntry.Route` now reflects the matched canonical route prefix rather than raw subpaths, enabling dashboard route dropdown filters to match all subpath traffic cleanly.

## 2. Detailed Findings by Component

### 2.1 Reverse Proxy Upstream Target Propagation ([`pkg/proxy/proxy.go`](../../pkg/proxy/proxy.go))
- **Design & Safety**:
  - Implemented typed private context key `UpstreamTargetContextKey` and exported accessor functions `GetUpstreamTarget(ctx)` and `SetUpstreamTarget(req, target)`.
  - In `ServeHTTPWithPrefix`, when `targetNode` is resolved by the load balancer, `SetUpstreamTarget(req, targetNode.URL.Host)` is immediately invoked, storing the concrete backend socket in the request context.
  - Failures in load balancing (such as 502/503 errors) set target to `"unavailable"`, ensuring the trace buffer never records empty or misleading values.
- **Performance**: Zero heap allocations beyond standard `context.WithValue` pointer wrapping; thread-safe per-request boundary.

### 2.2 Router Route Identification & Destination Tagging ([`pkg/router/router.go`](../../pkg/router/router.go))
- **Design & Safety**:
  - Added typed context keys `MatchedRouteContextKey`, `RouteTypeContextKey`, and `DestinationContextKey` with public accessor functions (`GetMatchedRoute`, `GetRouteType`, `GetDestination`).
  - In `Router.ServeHTTP`:
    - Prefix routes match sets `MatchedRoute` to `pr.prefix` and `RouteType` to `pr.routeType`. For static file routes, `Destination` is tagged as `"static"`.
    - Exact routes match sets `MatchedRoute` to `req.Path`, `RouteType` to `"exact"`, and `Destination` to `"in-process"`.
    - Unmatched or internal handlers default to `Destination: "in-process"`.
- **Zero Allocations & Compiler Safety**:
  - Replaced unsafe function equality comparisons (`targetHandler != r.MethodNotAllowed`) with a boolean flag `matchedExact`, ensuring compiler adherence across Go releases.

### 2.3 Main Telemetry Middleware Ingestion ([`cmd/toron/main.go`](../../cmd/toron/main.go))
- **Execution Flow**:
  - Following `next(req, res)` execution:
    - Extracts `proxy.GetUpstreamTarget(req.Context())`. If absent, falls back to `router.GetDestination(req.Context())`, and defaults to `"in-process"`.
    - Extracts `router.GetMatchedRoute(req.Context())`, falling back to `req.Path` only if no route matched.
    - Records the enriched `TraceLogEntry` into `server.GlobalTraceBuffer`.
- **Data Integrity**: Trace entries now accurately distinguish between proxy upstreams, local filesystem static serving, and in-process responses.

### 2.4 Control Center Dashboard Live Tail & Filtering ([`public/app.js`](../../public/app.js))
- **Display & Filter Updates**:
  - `lgUpdate` renders `e.up` in the Upstream column and in the slide-over trace waterfall drawer.
  - Enhanced route filtering logic:
    ```javascript
    const matchRoute = (e.route === state.lroute) ||
                       (pfx && (e.route === pfx || (e.route && e.route.startsWith(pfx + '/')) || e.path === pfx || (e.path && e.path.startsWith(pfx + '/')))) ||
                       (e.short && (e.short === state.lroute || (selR && e.short === selR.short)));
    ```
    This enables seamless hierarchical matching for subpaths under a chosen route prefix.
