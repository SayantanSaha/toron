# REQ-014 - Upstream Health Check and Circuit Breaker

## Description

The Toron reverse proxy and load balancer engine shall support upstream health checks and circuit breaker state management. Each proxy route upstream target shall optionally configure an active health check endpoint (`health_check_path`), probe interval, consecutive failure threshold, and cooldown period. The circuit breaker shall automatically trip unhealthy upstreams out of the load balancing pool and attempt recovery after a cooldown period.

## Acceptance Criteria

- Optional `health_check_path`, `health_check_interval`, `consecutive_failures`, and `cooldown_period` configurable in `config.yaml` and programmatic proxy API.
- Implements 3-state Circuit Breaker: `StateClosed` (healthy), `StateOpen` (unhealthy/tripped), `StateHalfOpen` (probing recovery).
- Active background HTTP health checker probes specified `health_check_path` (e.g. `/health`).
- Passive failure detection trips circuit breaker to `StateOpen` after $N$ consecutive request/probe failures.
- Load balancer automatically skips `StateOpen` upstreams, forwarding traffic only to healthy targets.
- Transitions from `StateOpen` to `StateHalfOpen` after `cooldown_period`, recovering to `StateClosed` upon successful probe response.
- If all upstreams are `StateOpen`, proxy returns HTTP 503 Service Unavailable / 502 Bad Gateway with diagnostic JSON.

## Rationale

Prevents routing client requests to failing or offline upstream servers, reducing latency and cascading failure risks in microservice gateways.

## Constraints

- Active health checker goroutine must stop cleanly when proxy/server shuts down.
- Thread-safe state transitions across concurrent worker threads.
