# TC-084 - Verification of K8s Ingress Controller Watch Stream Concurrency, Consumer Draining, and Deadlock Prevention

## Objective

Verify that `pkg/ingress` handles high-frequency watch stream events without deadlocks, reliably drains events from `c.events`, dynamically triggers route synchronizations, and terminates cleanly in less than 100ms during `Stop()`.

## Test Specifications

### TC-084-01: Context-Aware Channel Send in `WatchIngresses`
- **Goal**: Verify that when `events` channel buffer is full and no receiver is reading, cancelling `ctx` immediately causes `WatchIngresses` to return `context.Canceled` without hanging.
- **Setup**: Start a mock HTTP server streaming watch events. Call `WatchIngresses(ctx, events)` where `events` has capacity 5 and no reader.
- **Assertion**: When `ctx` is cancelled after channel fills, `WatchIngresses` exits within 100ms returning `context.Canceled`.

### TC-084-02: Consumer Draining & Route Sync on >100 Events
- **Goal**: Verify that `Controller` continuously drains events via `consumeEventsWorker` even when more than 100 events (e.g. 150 events) are pushed through the stream.
- **Setup**: Launch `Controller` against a mock K8s API server that emits 150 consecutive `K8sWatchEvent` objects.
- **Assertion**: All 150 events are consumed from `c.events`. The buffer does not deadlock, and routes are updated.

### TC-084-03: Zero-Deadlock Shutdown with High-Volume Streaming
- **Goal**: Verify that calling `Controller.Stop()` while a high-frequency stream of watch events is actively saturating the network socket/channel shuts down cleanly in <100ms.
- **Setup**: Start `Controller` connected to an infinite event stream. After 50ms, invoke `ctrl.Stop()`.
- **Assertion**: `ctrl.Stop()` finishes without deadlock. Goroutines exit cleanly.
