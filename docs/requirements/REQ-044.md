# REQ-044 - WAF Telemetry, Prometheus Metrics, and Structured Security Audit Logging

## Description

The Toron web server and edge proxy gateway shall implement real-time security observability and structured security audit logging within the WAF subsystem (`pkg/waf`) and metrics registry (`pkg/metrics`) to provide SecOps and SRE teams with immediate visibility into Layer 7 attacks, protocol violations, anomaly scores, and inspection latency.

The system shall provide:

1. **Standardized Prometheus WAF Metrics (`pkg/metrics`)**:
   - **`toron_waf_blocked_requests_total{category="...",route="..."}`**: Counter tracking total blocked malicious requests categorized by threat vector (`sqli`, `xss`, `traversal`, `rce`, `protocol`, `ip_acl`) and matched route.
   - **`toron_waf_anomalies_detected_total{category="...",mode="detection"}`**: Counter tracking anomalies observed in `detection` mode.
   - **`toron_waf_inspection_duration_seconds`**: High-resolution latency histogram tracking WAF inspection processing duration across configured buckets (`0.0001` to `0.1` seconds).
   - Metrics shall be seamlessly exposed under the standard `/metrics` endpoint in Prometheus text exposition format (version 0.0.4) and aggregated in `/internal/api/metrics` JSON summary.

2. **Structured JSON Security Audit Logging (`pkg/waf`)**:
   - Every security event (WAF block, detection anomaly, IP ACL rejection, or protocol violation) shall produce a structured JSON log entry containing:
     - `timestamp`: RFC 3339 formatted UTC timestamp.
     - `event`: Event classification (`"waf_block"`, `"waf_detection"`, `"ip_acl_block"`, `"protocol_violation"`).
     - `client_ip`: Remote client IP address extracted safely.
     - `method`: HTTP method.
     - `path`: Request URL path.
     - `category`: Threat category (`"sqli"`, `"xss"`, `"traversal"`, `"rce"`, `"protocol"`, `"ip_acl"`).
     - `rule_id`: Matched rule ID (e.g. `"SQLI-001"`, `"XSS-001"`, or `""`).
     - `anomaly_score`: Calculated threat anomaly score.
     - `action`: Action taken (`"blocked"` or `"logged"`).
     - `location`: Matched request location (`"url"`, `"query"`, `"headers"`, `"body"`).
     - `payload_snippet`: Bounded payload excerpt triggering the violation (truncated to prevent log flooding).
   - **Configurable Output Destination**: Support output to `stdout`, `stderr`, or a dedicated log file (e.g. `./logs/security.log` or `/var/log/toron/security.log`) for direct SIEM ingestion (Splunk, Datadog, Elastic).

3. **Zero-Overhead & Non-Blocking Execution**:
   - Metrics collection shall be atomic or mutex-guarded with minimal lock contention.
   - Security logging shall operate safely without blocking downstream client response streams.

## Acceptance Criteria

- When a request is blocked by WAF (OWASP rule, IP ACL, or protocol guard), `toron_waf_blocked_requests_total` counter increments with correct category and route tags.
- In `detection` mode, `toron_waf_anomalies_detected_total` counter increments when threats are detected.
- `/metrics` exports all WAF counters and histogram buckets in valid Prometheus exposition format.
- Security audit events emit valid JSON entries containing client IP, rule ID, category, location, and payload snippet to the configured output sink.
- All Go unit tests pass cleanly across all packages (`go test ./...`).
