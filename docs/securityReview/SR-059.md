# SR-059 - Security Review of Management API Access Control, Subnet Restrictions, and SSRF Hardening

## Description

Security evaluation of the implementation for `TASK-062` / `SEC-02` (Management API authentication, CIDR subnet allowlisting, and loopback SSRF mitigation).

## Scope

- Files reviewed:
  - `pkg/config/config.go`
  - `pkg/server/internal_api.go`
  - `pkg/server/internal_api_test.go`
  - `cmd/toron/main.go`

## Security Evaluation & Analysis

1. **Authentication Token & Multi-Scheme Enforcement**:
   - In `pkg/server/internal_api.go`, `validateAdminAuth` supports `X-Toron-Admin-Key`, `Authorization: Bearer <token>`, and `Authorization: Basic <base64>`.
   - All secret comparisons utilize `crypto/subtle.ConstantTimeCompare` to eliminate timing side-channel attacks on secret tokens and API keys.
   - Unauthenticated requests correctly receive `401 Unauthorized` with `WWW-Authenticate: Bearer realm="Toron Management", Basic realm="Toron Management"`.
2. **Subnet Allowlisting & Network Isolation**:
   - `wrapHandler` validates client socket IP against parsed CIDR blocks in `AdminSubnets`.
   - Socket connection `RemoteAddr` is prioritized over request headers, preventing spoofed header-based IP bypasses when connected over raw TCP.
   - Unauthorized IPs receive `403 Forbidden`, preventing unauthorized reconnaissance of routing topology, upstream health, and incident logs.
3. **Loopback SSRF & Privilege Escalation Mitigation**:
   - `POST /internal/api/proxy-test` strictly rejects path schemes (`http://`, `https://`, `//`) and restrains targets to a safe diagnostic whitelist (`/health`, `/api/status`, and non-internal route prefixes).
   - Any path targeting `/internal/` is explicitly forbidden, preventing recursive privilege escalation.
   - Client requests attempting to inject sensitive identity headers (`X-Authenticated-User`, `X-Admin`, `x-user`, `x-remote-user`) are rejected with `400 Bad Request`.
   - Forwarded identity and hop-by-hop headers (`X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `Authorization`, `Cookie`) are stripped before probe dispatch.

## Conclusion

`SEC-02` is completely mitigated. The implementation is approved.
