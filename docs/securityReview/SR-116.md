## 2. Threat Modeling & Vulnerability Root Cause Analysis

### 2.1 The Pre-Implementation Failure State

In automated differential protocol security evaluations documented in [`benchmarks/results/differential_fuzz_report.md`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/results/differential_fuzz_report.md), Toron's differential protocol fuzzer reported an overall pass rate of **89.47% (17/19 tests)**, failing two critical directory traversal security tests:

```
| Test ID         | Attack / Invariant Vector                    | CWE    | Expected Status | Actual Status | Conn Closed | Result  |
| :---            | :---                                         | :---:  | :---:           | :---:         | :---:       | :---:   |
| `TRAVERSAL-001` | Raw Dot-Dot Path Traversal Sequence          | CWE-22 | `400/403`       | `404`         | `Open`      | ❌ FAIL |
| `TRAVERSAL-002` | Uppercase Percent-Encoded Traversal (%2E%2E) | CWE-22 | `400/403`       | `404`         | `Open`      | ❌ FAIL |
| `TRAVERSAL-003` | Double Percent-Encoded Traversal (%252e%252e)| CWE-22 | `400/403`       | `403`         | `Closed`    | ✅ PASS |
```

Both failed test vectors produced two unacceptable security failure modes:
1. **Defensive Masking & SIEM Blind Spot**: Returning `404 Not Found` misclassified deliberate attack vectors as innocuous cache or asset misses. WAF anomaly scoring was completely bypassed, and security audit logs registered zero threat events.
2. **Transport Keep-Alive Vulnerability**: The server maintained a persistent TCP socket (`Connection: Open`), directly violating the fail-fast transport teardown principle established in [`REQ-107`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-107.md) / [`ADR-107`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-107.md) and exposing the gateway to pipelined request smuggling (CWE-444) and connection descriptor exhaustion (CWE-400).

### 2.2 Root Cause Decomposition & The Dead-Code Contradiction

The vulnerability stemmed from two interrelated architectural anomalies:

```
[ Ingress Wire Request: "GET /internal/dashboard/../../canary_traversal.txt" ]
                                   │
                                   ▼
          ┌──────────────────────────────────────────────────┐
          │ router.go: cleanRequestPath(req.Path)            │
          │ Collapses path to: "/canary_traversal.txt"       │
          └──────────────────────────────────────────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
┌─────────────────────────────────┐       ┌─────────────────────────────────────┐
│ waf.go: InspectToron            │       │ router.go: Prefix Route Lookup      │
│ Inspects sanitized req.Path:    │       │ Searches for "/canary_traversal.txt"│
│ "/canary_traversal.txt"         │       │ Prefix "/internal/dashboard" fails  │
│ Rule TRAVERSAL-001 fails match  │       │ Dispatches to r.NotFound (404)      │
└─────────────────────────────────┘       └─────────────────────────────────────┘
         │                                                   │
         ▼                                                   ▼
  [ WAF Bypassed ]                        [ createStaticHandler Dead Code ]
  (score = 0)                             (filepath.Rel guard never reached!)
```

1. **Router Premature Path Canonicalization & Dead-Code Contradiction**:
   - In [`Router.ServeHTTP`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L789), the router unconditionally collapsed ingress path dot segments via `cleanRequestPath(req.Path)` *before* route lookup and middleware execution.
   - For a path targeting static mount `/internal/dashboard/../../canary_traversal.txt`, the path collapsed to `/canary_traversal.txt`.
   - The router prefix matcher checked whether `/canary_traversal.txt` started with `/internal/dashboard/`. Failing this, dispatch fell through to `r.NotFound` (`404 Not Found`).
   - **The Dead-Code Contradiction**: In [`Router.createStaticHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L643-L650), Toron already possessed an explicit `filepath.Rel` directory boundary escape guard designed to emit `403 Forbidden: Path Traversal Disallowed` with `Connection: close`. However, because pre-canonicalization altered the route before prefix matching, escaped requests never reached `createStaticHandler`. The security check inside the static handler was rendered unreachable dead code.

2. **WAF Layer 7 Raw Wire URI Blind Spot**:
   - In [`WAFEngine.InspectToron`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go#L327), the engine initialized `urlPath := req.Path`. Because `req.Path` had already been sanitized by `cleanRequestPath`, the WAF inspected `/canary_traversal.txt`.
   - The regex pattern in `TRAVERSAL-001` (`(?i)(\.\./|\.\.\\|%2e%2e/|%2e%2e%2f|%2e%2e\\|%2e%2e%5c)`) failed to match.
   - `InspectToron` only fell back to `req.RequestURI` if `urlPath == ""`, creating an inspection blind spot.

## 3. Security Evaluation of Implemented Defense Layers

The remediation specified in [`ADR-116`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-116.md) establishes a three-tier defense-in-depth model:

| Layer | Component | Defensive Responsibility | Failure Mode Resilience |
| :--- | :--- | :--- | :--- |
| **Layer 1** | [`pkg/waf/waf.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go) | Syntactic Raw Wire URI & Dual-Path Threat Inspection | Bypassed if WAF disabled or in detection-only mode |
| **Layer 2** | [`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go) | Semantic Route-Aware Static Prefix Escape Guard | Standalone enforcement; catches all prefix escapes |
| **Layer 3** | [`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go) | Filesystem Boundary (`filepath.Rel`) & Symlink Guard | Local filesystem containment within static directory |

### 3.1 Layer 1: Layer 7 WAF Raw Wire URI Inspection

#### 3.1.1 Wire URI Extraction and Sanitization
In [`WAFEngine.Inspect`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go#L288-L306) and [`WAFEngine.InspectToron`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go#L339-L356), the engine extracts the wire path directly from `req.RequestURI`:
- **Query String Separation**: Accurately truncates at the first `?` character (`rawWire[:idx]`) while preserving the extracted query string in `rawQuery` for subsequent `InspectQuery` evaluation.
- **Fragment Separation**: Accurately truncates at the first `#` character (`rawWire[:idx]`), neutralizing RFC 3986 fragment delimiter injection attacks.
- **Empty URI Fallback**: If `req.RequestURI` is empty (`""`), the engine gracefully falls back to `req.Path`, preventing nil-pointer dereferences or inspection bypasses.
- **Zero Allocations on Benign Paths**: Uses standard byte scanning (`strings.IndexByte`) and string reslicing, avoiding heap allocations on normal requests.

#### 3.1.2 Dual-Path Pattern Evaluation
In [`WAFEngine.inspectInternal`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go#L414):
```go
if (rule.Locations&InspectURL != 0) && ((normPath != "" && rule.Pattern.MatchString(normPath)) || (urlPath != "" && rule.Pattern.MatchString(urlPath))) {
    matchFound = true
}
```
The rule pattern is evaluated against both:
1. `urlPath`: The raw wire path preserving raw sequences (`../`, `..\`) and percent encodings (`%2e%2e`, `%2E%2E`).
2. `normPath`: The unescaped candidate computed via `url.PathUnescape(urlPath)`.

#### 3.1.3 Encoding Vector Neutralization Matrix
- **Raw Dot-Dot Sequences (`../`, `..\`)**: Matched immediately on `urlPath` by `TRAVERSAL-001`.
- **Uppercase Percent-Encoding (`%2E%2E/`, `%2E%2E%2F`)**: `TRAVERSAL-001` specifies case-insensitive matching `(?i)`, matching `urlPath` directly; additionally, `normPath` unescapes `%2E%2E` to `..`, matching `\.\./`.
- **Lowercase Percent-Encoding (`%2e%2e/`, `%2e%2e%2f`)**: Matched on both `urlPath` and `normPath`.
- **Double Percent-Encoding (`%252e%252e`)**: `url.PathUnescape` reduces `%252e` to `%2e`, which is evaluated against `TRAVERSAL-001` in `normPath` and matched.
- **Encoded Slashes (`%2f`, `%2F`, `%5c`, `%5C`)**: Evaluated both as raw patterns in `urlPath` and normalized slashes in `normPath`.

### 3.2 Layer 2: Route-Aware Static Prefix Escape Guard

#### 3.2.1 Standalone Defense-in-Depth When WAF is Disabled
The architectural core of [`ADR-116`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-116.md) is the router-level prefix boundary validation inside [`Router.ServeHTTP`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L848-L884). This logic executes within the router dispatch phase independently of whether WAF middleware is enabled, disabled, or configured in detection-only mode.

#### 3.2.2 Iterative Unescaping to Fixpoint
To prevent nested or multi-level encoding bypasses, `Router.ServeHTTP` iteratively unescapes the ingress wire path until a fixpoint is reached:
```go
unescaped = rawPath
for {
    u, err := url.PathUnescape(unescaped)
    if err != nil || u == unescaped {
        break
    }
    unescaped = u
}
```
This guarantees that deeply obfuscated vectors (e.g. `%25252e%25252e` -> `%252e%252e` -> `%2e%2e` -> `..`) are completely resolved before boundary testing.

#### 3.2.3 Formal Prefix Boundary Containment Invariant
For every static prefix route $P$ registered via `r.Static(P, dir)`:
1. Let $P_{norm} = \text{"/"} + \text{strings.Trim}(P, \text{"/"})$ and $P_{slash} = P_{norm} + \text{"/"}$.
2. **Targeting Predicate**:
   $$\text{Targeted}(P) \iff (rawPath = P_{norm} \lor \text{HasPrefix}(rawPath, P_{slash})) \lor (unescaped = P_{norm} \lor \text{HasPrefix}(unescaped, P_{slash}))$$
3. **Escaping Predicate**:
   $$\text{Escapes}(P) \iff (\neg\text{HasPrefix}(cleanRaw, P_{slash}) \land cleanRaw \neq P_{norm}) \lor (\neg\text{HasPrefix}(cleanUnesc, P_{slash}) \land cleanUnesc \neq P_{norm}) \lor (\neg\text{HasPrefix}(req.Path, P_{slash}) \land req.Path \neq P_{norm})$$
   where $cleanRaw = cleanRequestPath(rawPath)$ and $cleanUnesc = cleanRequestPath(unescaped)$.
4. **Enforcement Action**:
   If $\text{Targeted}(P) \land \text{Escapes}(P)$:
   - HTTP Status: `403 Forbidden` (`http.StatusForbidden`).
   - Response Headers: `Connection: close`, `Content-Type: application/json`.
   - Response Payload: `{"error":"403 Forbidden: Path Traversal Disallowed"}`.
   - Immediate dispatch termination: Does not fall through to `r.NotFound`.

#### 3.2.4 Dead-Code Elimination Verified
Because the static prefix escape check executes before `r.NotFound`, traversal probes targeted at static routes are arrested and returned as active 403 rejections. The structural dead-code contradiction is permanently eliminated.

### 3.3 Layer 3: Filesystem Containment & Physical Symlink Verification

In [`Router.createStaticHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L641-L665), for requests that legally remain within the static route prefix:
- `cleanRel := filepath.Clean(filepath.FromSlash(strings.TrimPrefix(fileRelPath, "/")))`
- Boundary check: `filepath.Rel(absDir, targetPath)` ensures relative resolution does not climb outside `absDir`.
- Symlink resolution: `filepath.EvalSymlinks(targetPath)` verifies that symbolic links do not resolve outside `realAbsDir`.
- On violation: Emits `403 Forbidden: Symlink Path Traversal Disallowed` with `Connection: close`.

## 4. Transport-Layer Socket Teardown Enforcement (`Connection: close`)

### 4.1 Threat Context: HTTP Smuggling (CWE-444) & Slowloris (CWE-400)
In an edge gateway, leaving a TCP connection open (`Connection: keep-alive`) after rejecting an attack request introduces two severe attack vectors:
1. **HTTP Desynchronization & Request Smuggling (CWE-444)**: An attacker can pipeline follow-up requests behind a traversal probe. If the gateway or intermediate proxy mishandles persistent stream boundaries, subsequent requests can be desynchronized, poison shared socket pools, or hijack victim sessions.
2. **Reactor Resource Exhaustion (CWE-400)**: Attackers can sustain open TCP connections across thousands of traversal probes, exhausting Toron's reactor file descriptors and connection pool tables.

### 4.2 Teardown Invariant Verification
The implementation strictly enforces transport socket teardown:
- In [`pkg/waf/middleware.go:159`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go#L159), blocked WAF responses explicitly set:
  ```go
  res.Header.Set("Connection", "close")
  ```
- In [`pkg/router/router.go:878`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L878), the static prefix escape handler explicitly sets:
  ```go
  res.Header.Set("Connection", "close")
  ```
- In `pkg/server/server.go`, the reactor event loop inspects `res.Header.Get("Connection")`:
  ```go
  if strings.EqualFold(res.Header.Get("Connection"), "close") {
      conn.Close()
      break
  }
  ```
  The physical TCP socket is closed immediately upon flushing the 403 response payload.
- In [`benchmarks/fuzzer/diff_fuzzer.go:209,219`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/fuzzer/diff_fuzzer.go#L209), the test oracle was updated to `ExpectClose: true` for `TRAVERSAL-001` and `TRAVERSAL-002`, aligning with `REQ-107` and `REQ-116`.

## 5. Invariant Preservation & False-Positive Analysis

A critical security requirement is ensuring that defensive hardening does not induce false positives on legitimate traffic or regress non-static routing contracts.

### 5.1 Non-Static Route Preservation (ADR-062 Alignment)
- **Exact API Routes (`r.GET`, `r.POST`, etc.)**:
  - In `Router.ServeHTTP`, exact route lookup (`r.routes[req.Path]`) occurs at lines 822–845.
  - Requests containing benign relative dot-segments targeting exact API routes (e.g. `GET /public/../internal` canonicalizing to `/internal`) match the exact route `/internal`.
  - Because `targetHandler != nil`, the static prefix escape guard (`if targetHandler == nil`) is completely bypassed.
  - The request dispatches cleanly to `/internal`, returning `200 OK` without triggering a false-positive rejection. Verified by [`TestRouter_ADR062_Canonicalization`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router_test.go#L1587).
- **Upstream Reverse Proxy Routes (`RouteTypeUpstream`)**:
  - In the prefix escape loop, non-static routes are filtered out immediately:
    ```go
    if pr.routeType != string(RouteTypeStatic) || pr.prefix == "" {
        continue
    }
    ```
  - Reverse proxy routes maintain their two-stage ADR-062 canonicalization and are not blocked by the static prefix escape guard.

### 5.2 Legitimate Static Subpath Access
- For legitimate requests within configured static mounts:
  - Example 1: `GET /internal/dashboard/index.html` -> $cleanRaw = \text{"/internal/dashboard/index.html"}$.
  - Example 2: `GET /internal/dashboard/assets/../index.html` -> $cleanRaw = \text{"/internal/dashboard/index.html"}$.
  - In both cases, $\text{HasPrefix}(cleanRaw, \text{"/internal/dashboard/"})$ evaluates to `true`.
  - The escape condition evaluates to `false`. The request is passed to `createStaticHandler` and served with `200 OK`. Verified by `TC-116-06`.
