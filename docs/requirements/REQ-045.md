# REQ-045 - User-Defined Custom WAF Regex Rules and Zero-Downtime Hot Reloading

## Description

The Toron Web Server & Reverse Proxy Gateway shall provide operators and security administrators with the capability to define organization-specific, user-defined regex security inspection rules in YAML configuration (`config.yaml` and `routes.yaml`) without requiring source code recompilation or application redeployment.

Furthermore, the system shall provide dynamic zero-downtime hot reloading of the server configuration and WAF rule sets using background `fsnotify` file system watching. When configuration files change, the WAF engine shall recompile and validate the rule sets, atomically swapping active inspection rules via thread-safe mutex operations without dropping active TCP, TLS, HTTP/1.1, HTTP/2, HTTP/3, or gRPC client connections.

### Key Capabilities

1. **User-Defined Regex Rules in YAML Configuration (`config.yaml` / `routes.yaml`)**:
   - Support `server.waf.custom_rules` and route-level `waf.custom_rules` lists containing:
     - `id`: Unique rule identifier (e.g. `"CUSTOM-001"`).
     - `category`: Threat category (e.g. `"bot"`, `"sqli"`, `"xss"`, `"rce"`, `"traversal"`, `"custom"`).
     - `description`: Human-readable summary of the security intent.
     - `pattern`: Valid regular expression string (e.g. `"(?i)(sqlmap|nikto|nmap|acunetix)"`).
     - `score`: Threat anomaly score weight contributed upon matching (e.g. `10`).
     - `locations`: Array of inspection target locations (`"url"`, `"path"`, `"query"`, `"headers"`, `"body"`). If omitted or empty, all locations are inspected by default.

2. **Validation and Pre-Compilation**:
   - Regular expressions must be pre-compiled and validated during initialization and dry-run validation (`-t` / `--test-config`).
   - Duplicate rule IDs or invalid regex patterns shall be flagged with clear diagnostic error messages.

3. **Zero-Downtime Hot Reloading via `fsnotify`**:
   - `ConfigWatcher` background worker monitors `config.yaml` for `Write` / `Create` / `Rename` events with debouncing.
   - On valid file update, the server parses the new configuration, compiles the new custom rule sets, and atomically swaps the active WAF rule sets via `WAFEngine.Reload(newConfig)` under write lock (`sync.RWMutex`).
   - If the newly edited configuration contains syntax or regex compilation errors, hot reload rejects the change and logs a descriptive warning while retaining the active in-memory rule set safely.
   - Active client requests and open long-lived connections (WebSockets, gRPC, HTTP/2 streams) proceed without interruption.

## Acceptance Criteria

- Custom rules defined in `config.yaml` and `routes.yaml` are loaded, compiled, and executed during request inspection.
- When an incoming request matches a custom regex rule at specified locations (e.g. `User-Agent: sqlmap`), the threat score increments and the request is blocked (`403 Forbidden` in `enforce` mode) or logged (in `detection` mode).
- WAF audit logging records custom rule violations with the custom `rule_id` and `category`.
- Editing `config.yaml` triggers atomic rule set recompilation and dynamic reload in memory via `fsnotify` without server restart or socket termination.
- Invalid configuration edits are rejected safely without crashing the server or discarding the last known valid rule set.
- All Go unit tests pass cleanly across all packages (`go test ./...`).
