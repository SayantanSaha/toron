# REQ-061 - HTTP Request Smuggling Prevention and Transfer-Encoding Protocol Enforcement

## Description

The Toron HTTP engine and request parser shall strictly enforce RFC 7230 transfer coding constraints to prevent HTTP Request Smuggling (CL.TE / TE.CL / TE desynchronization) and stream boundary confusion on persistent (keep-alive) TCP socket connections.

Whenever a client transmits a request containing a `Transfer-Encoding` header without a supported dechunking parser, or with malformed or conflicting length headers, Toron shall reject the request or immediately terminate the socket connection to guarantee that unread payload bytes cannot desynchronize subsequent requests on the connection.

## Acceptance Criteria

### 1. Rejection of Unsupported Transfer Coding
- Any incoming HTTP request declaring `Transfer-Encoding: chunked` (or any unsupported transfer coding) shall be rejected with HTTP `501 Not Implemented` or immediately closed with connection termination if the server runtime does not implement request body dechunking.
- The connection shall not be retained in keep-alive pool if unconsumed chunk bytes remain on the socket buffer.

### 2. Conflicting Length Header Enforcement
- Any request containing both `Content-Length` and `Transfer-Encoding` headers shall be rejected immediately with HTTP `400 Bad Request` prior to request processing.
- Requests declaring duplicate or conflicting `Content-Length` headers with mismatched values shall be rejected with HTTP `400 Bad Request`.

### 3. Socket Teardown on Protocol Violation
- In the event of a transfer coding violation or deserialization error, the server shall emit `Connection: close` in the response header and immediately close the underlying socket connection to prevent subsequent byte parsing from the unread stream.

## Rationale

Allowing unsupported `Transfer-Encoding: chunked` requests to proceed with `ContentLength = 0` leaves the chunked body on the TCP socket. On persistent keep-alive connections, the remaining body is parsed by the reactor as the next HTTP request, enabling classic request smuggling and unauthorized route execution.

## Constraints

- Compliance with RFC 7230 §3.3.1 and RFC 7230 §3.3.3.
- Minimal CPU overhead during header parsing.

## Open Questions

- Should native chunked request body parsing be implemented in `pkg/httpparser`, or should chunked request payloads remain rejected with 501 until a full streaming reactor dechunker is designed?
