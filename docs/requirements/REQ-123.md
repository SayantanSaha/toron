# REQ-123 - Configurable Upstream Reverse Proxy Transport Architecture (Raw Speed vs. Feature Flexibility)

## 1. Description & Problem Statement

### 1.1 Problem Context
In [`REQ-122`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-122.md), Toron achieved substantial performance gains (~3x throughput, reaching ~24.5k RPS and ~1.05ms P50 latency) by optimizing the reverse proxy upstream `http.Transport` with zero-allocation buffers, unconstrained persistent connection pooling, disabling automatic decompression, disabling environment proxy lookups, and enforcing RFC 7230 hop-by-hop header stripping.

However, these high-performance defaults inherently sacrifice several enterprise features and protective mechanisms:
1. **Outbound Egress Proxies**: Hardcoding `Proxy: nil` prevents Toron from routing upstream requests through corporate forward proxies (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`) or dedicated egress gateways.
2. **Upstream Overload Protection**: Setting `MaxConnsPerHost: 0` removes backpressure limits, creating a risk of exhausting file descriptors or overwhelming fragile upstream microservices under traffic spikes.
3. **Socket Resource Footprint**: Maintaining up to 1,000 idle sockets per host for 90 seconds ties up socket buffer memory and file descriptors across many target hosts.
4. **Payload Inspection / WAF Decompression**: Setting `DisableCompression: true` disables upstream response decompression, preventing downstream inspection or modification of compressed payloads.
5. **Upstream Keep-Alive Control**: Unconditionally stripping hop-by-hop headers isolates client keep-alive sockets, overriding backends that deliberately issue `Connection: close`.
6. **Upstream HTTP/2 Protocol Negotiation**: Hardcoding `ForceAttemptHTTP2: false` forces all upstream connections into HTTP/1.1, sacrificing upstream HTTP/2 stream multiplexing when proxying to HTTPS/h2 origins.

### 1.2 Objective
Toron must make all transport trade-offs—including connection pooling, egress routing, decompression, keep-alive isolation, and upstream HTTP/2 conversion—fully configurable at both the global server level (`config.yaml`) and the per-route level (`routes.yaml`), while maintaining default "raw speed" performance when configurations are omitted.

### 1.3 Prior Requirements & Standards Conflict Analysis
To guarantee system integrity, every configurable trade-off was formally cross-audited against previous requirement documents:
1. **RFC 7230 §6.1 & REQ-071 §3 (Hop-by-Hop Header Stripping)**:
   - *Audit Finding*: REQ-071 §3 mandates stripping hop-by-hop headers (`Connection`, `Keep-Alive`, `TE`, `Trailers`, `Upgrade`, `Transfer-Encoding`) to prevent HTTP Request Smuggling (CWE-444).
   - *Resolution*: Direct passthrough of raw hop-by-hop headers is strictly prohibited. The configurable parameter is refined to `PropagateUpstreamClose`: when enabled, Toron signals socket closure to the client loop while still strictly stripping RFC 7230 hop-by-hop headers from the response payload. Zero conflict with REQ-071, REQ-090, or REQ-112.
2. **REQ-034 & REQ-037 (Transparent Streaming Response Compression)**:
   - *Audit Finding*: REQ-034 §5 mandates bypassing compression for already-compressed payloads.
   - *Resolution*: Setting `DisableCompression: true` allows compressed upstream responses to pass through untouched directly to clients, fulfilling REQ-034 §5 and avoiding redundant double decompression/recompression cycles. Zero conflict.
3. **REQ-009 & REQ-087 (Upstream Routing & Connection Limits)**:
   - *Audit Finding*: REQ-009 mandates configurable upstream timeouts, and REQ-087 established `max_connections` and `idle_timeout` for Layer 4 proxies.
   - *Resolution*: Exposing `max_conns_per_host` and `idle_conn_timeout` for Layer 7 reverse proxy routes directly harmonizes Layer 7 with REQ-087 and extends REQ-009. Zero conflict.
4. **REQ-022 & REQ-112 (HTTP/2 Protocols & Translation Invariants)**:
   - *Audit Finding*: REQ-022 provides `server.http2.enabled` and `server.http2.allow_h2c`. REQ-112 enforces invariant checks on translated requests.
   - *Resolution*: Exposing `force_attempt_http2` in `http.Transport` for upstream connections preserves all REQ-112 pseudo-header stripping invariants while giving operators control over upstream ALPN multiplexing. Zero conflict.

## 2. Functional Requirements

### REQ-123.1: Declarative Transport Configuration Schema (`ProxyTransportConfig`)
Extend [`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) with a reusable `ProxyTransportConfig` struct:
- `MaxIdleConns` (`max_idle_conns`, int): Global maximum idle connections across all hosts (default: `10000`).
- `MaxIdleConnsPerHost` (`max_idle_conns_per_host`, int): Maximum idle connections per upstream host (default: `1000`).
- `MaxConnsPerHost` (`max_conns_per_host`, int): Total concurrent connections per host (default: `0` = unconstrained; $>0$ enables backpressure).
- `IdleConnTimeout` (`idle_conn_timeout`, duration): Maximum time an idle keep-alive socket remains in the pool (default: `90s`).
- `DisableCompression` (`disable_compression`, *bool): When `true` (default for raw speed), avoids decompression overhead; when `false`, enables transparent gzip decompression.
- `UseEnvProxy` (`use_env_proxy`, *bool): When `false` (default for raw speed), bypasses environment lookups (`Proxy: nil`); when `true`, honors `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`.
- `ProxyURL` (`proxy_url`, string): Explicit forward proxy URL (e.g., `http://egress-proxy:3128`) for dialing upstreams.
- `PropagateUpstreamClose` (`propagate_upstream_close`, *bool): When `false` (default for raw speed), isolates client keep-alive sockets from upstream `Connection: close`; when `true`, honors upstream origin termination by cleanly closing the client socket (while still stripping RFC 7230 hop-by-hop headers to prevent smuggling per REQ-071).
- `ForceAttemptHTTP2` (`force_attempt_http2`, *bool): When `false` (default for raw speed to HTTP/1.1 upstreams), prevents ALPN `h2` upgrade attempts; when `true`, enables HTTP/2 protocol negotiation and stream multiplexing to TLS upstream origins.
- `Profile` (`profile`, string): High-level preset: `"raw_speed"` (default) or `"balanced"` / `"standard"`.

### REQ-123.2: Hierarchical Scope (Global & Route-Level Inheritance)
1. **Global Configuration** (`config.yaml`):
   - Configurable under `proxy.transport`.
   - Establishes system-wide defaults for all reverse proxy routes.
2. **Route-Level Configuration** (`routes.yaml`):
   - Configurable per-route under `transport` in `ProxyRouteConfig`.
   - Route-level settings override global settings on a per-field basis (e.g., a specific route can set `max_conns_per_host: 50` while other routes remain unconstrained).

### REQ-123.3: Proxy Engine Dynamic Transport Instantiation
Extend [`ProxyOptions`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go) and `NewProxyWithOptions` in [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go):
- Initialize `http.Transport` using the resolved `ProxyTransportConfig`:
  - Dial proxy resolver:
    - If `ProxyURL` is specified $\rightarrow$ use `http.ProxyURL(...)`.
    - Else if `UseEnvProxy` is `true` $\rightarrow$ use `http.ProxyFromEnvironment`.
    - Else $\rightarrow$ `Proxy: nil` (direct zero-overhead dialing).
  - Connection pooling: Apply resolved `MaxIdleConns`, `MaxIdleConnsPerHost`, `MaxConnsPerHost`, `IdleConnTimeout`.
  - Compression: Apply resolved `DisableCompression`.
  - HTTP/2 Upstream: Apply resolved `ForceAttemptHTTP2` on `http.Transport`.
- In `ServeHTTPWithPrefix`: Strip RFC 7230 hop-by-hop headers unconditionally per REQ-071, and honor `PropagateUpstreamClose` to signal socket termination to the client loop when origin closes.

### REQ-123.4: Backward Compatibility & Zero-Regression Defaults
- Omitting transport configuration MUST preserve 100% of the raw speed behavior established in REQ-122 (~24.5k RPS, ~1.05ms P50 latency).
- Existing `routes.yaml` and `config.yaml` configurations without transport blocks must continue to operate without syntax errors or performance degradation.

## 3. Acceptance Criteria

- [ ] `ProxyTransportConfig` schema is integrated into `pkg/config/` and `pkg/proxy/`.
- [ ] YAML & JSON deserialization supports global `proxy.transport` and route-level `routes[].transport`.
- [ ] Explicit egress proxy resolution (`ProxyURL` and `UseEnvProxy: true`) functions correctly.
- [ ] Concurrency limiting (`MaxConnsPerHost > 0`) enforces backpressure on upstream requests.
- [ ] Transparent decompression toggle (`DisableCompression: false`) successfully decompresses upstream gzip responses.
- [ ] Upstream close propagation toggle (`PropagateUpstreamClose: true`) cleanly terminates client socket while preserving RFC 7230 sanitization.
- [ ] Upstream HTTP/2 toggle (`ForceAttemptHTTP2: true`) allows ALPN `h2` multiplexing to TLS origins.
- [ ] Preset profiles (`"raw_speed"` vs `"balanced"`) apply consistent configuration bundles.
- [ ] Unit tests in `pkg/proxy/` and `pkg/config/` pass with `-race` detection.
- [ ] Existing Docker comparative benchmark performance remains unaffected when using default settings.
