# TC-035 - In-Memory HTTP Response Caching Verification

## Test Objectives

1. Verify first GET request to a cacheable route sets `X-Cache: MISS` and caches the response.
2. Verify second GET request to the same route returns `X-Cache: HIT`, identical body, and valid `Age` header without re-invoking the handler.
3. Verify `Cache-Control: max-age=N` directive correctly sets expiration and entry expires after duration.
4. Verify `Cache-Control: no-store` prevents response from being cached.
5. Verify client `Cache-Control: no-cache` bypasses cached entry and fetches a fresh response (`X-Cache: MISS`).
6. Verify non-idempotent methods (POST, PUT, DELETE) bypass cache and do not store entries.
7. Verify WebSocket upgrade responses (`101 Switching Protocols`) are not cached.
8. Verify responses exceeding `max_payload_size` bypass caching.
9. Verify configuration loading under `config.yaml` parses `server.cache` properties.
