# SR-001 - Prototype 1 Security Review of Toron Web Server

## Description

Initial security analysis of the Toron event-driven Go HTTP server codebase focusing on socket handling, request header/body parsing limits, connection timeout guards, panic recovery, and memory exposure.

## Scope

- Files reviewed:
  - `pkg/reactor/reactor.go`
  - `pkg/httpparser/parser.go`
  - `pkg/httpparser/response.go`
  - `pkg/router/router.go`
  - `pkg/server/server.go`

## Findings

### Finding 1: Enforced Bounded Request Header and Body Allocation

- Severity: Informational
- Location: `pkg/httpparser/parser.go:40`
- Related requirement: `REQ-005`
- Description: The parser correctly enforces `MaxHeaderBytes` (default 8KB) and `MaxBodyBytes` (default 4MB) before memory allocation.
- Impact: Protects against memory exhaustion and OOM DoS attacks via unbounded HTTP request payloads.
- Recommendation: Maintain configurable limits via `server.Config`.

### Finding 2: Socket Read/Write Deadline Timeout Guards

- Severity: Low
- Location: `pkg/server/server.go:80`
- Related requirement: `REQ-005`
- Description: Read/Write deadlines are set per request iteration on active client sockets.
- Impact: Mitigates Slowloris and slow client connection holding attacks.
- Recommendation: Ensure idle connection timeout logic is added for persistent keep-alive connections in Prototype 2.

### Finding 3: Panic Recovery and Error Information Exposure

- Severity: Informational
- Location: `pkg/router/router.go:106`
- Related requirement: `REQ-005`
- Description: The `RecoveryMiddleware` intercepts panics, logs stack traces locally, and returns generic `500 Internal Server Error` to clients without leaking sensitive stack details.
- Impact: Prevents information disclosure vulnerabilities.

## Positive Observations

- Memory buffer pooling (`sync.Pool`) prevents heap fragmentation under load.
- Signal notification handling ensures graceful connection drain on server shutdown.
- All input validation failures return explicit, standard HTTP error status codes (`400`, `413`, `431`).

## Missing Security Tests

- Fuzzing HTTP parser with malformed UTF-8 and invalid HTTP method byte strings.

## Rationale

The baseline security controls satisfy Prototype 1 security expectations.

## Constraints

- TLS / HTTPS termination to be addressed in upcoming prototype iterations.
