# CR-122 - Code Review of Adaptive Socket Deadline Amortization and Activity-Refreshed Streaming Timeouts

## 1. Executive Summary

A comprehensive code review was conducted on the implementation of [`TASK-149`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-149.md), addressing [`REQ-126`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-126.md), [`ADR-126`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-126.md), and [`TC-126`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-126.md).

The change resolves the high-concurrency socket system call saturation problem (~49,000 socket deadline syscalls/sec at 24.5k RPS) by introducing an adaptive deadline amortization tracker ([`connDeadlineTracker`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L14-L23)) that elides redundant kernel socket deadline updates when more than half of the timeout window remains ($R > \tau/2$). Simultaneously, the implementation resolves the structural conflict between static write deadlines and long-lived streaming responses (SSE, chunked streams, and L4/L7 tunnels) by enforcing per-chunk activity-refreshed write deadlines in [`res.StreamBody`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L331-L363) and [`relayStreams`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L696-L770). Crucially, 100% compliance with Slowloris and Slow-Read Denial of Service ([CWE-400](https://cwe.mitre.org/data/definitions/400.html)) defenses is maintained via strict idle transition state machine synchronization ([`br.Buffered() == 0`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L215-L221)) and immediate socket termination upon send-buffer saturation.

**Verdict**: **APPROVED (0 Findings, 0 Regressions, 100% Test Pass Rate, Race Clean, Zero Third-Party Dependencies)**.

## 3. Detailed Review Findings by Review Area

### 3.1 Code Quality & Idiomatic Go
- **Formatting & Style**: All files adhere strictly to standard Go idioms and `gofmt` layout.
- **Encapsulation**: Struct fields in [`connDeadlineTracker`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L14-L23) are unexported. All state alterations are safely mediated by member methods.
- **Error Propagation & Wrapping**: Errors from socket operations are wrapped appropriately (`fmt.Errorf("...: %w", err)`) or handled cleanly for silent keep-alive teardown.
- **Resource Management**: Slices and pooled buffers are recycled properly with `defer` statements (e.g. `httpparser.PutCopyBuffer` in [`server.go:344`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L344)).
- **Panic Freedom**: Zero unchecked type assertions or nil pointer dereferences. Interface type assertions safely utilize the comma-ok idiom (`cw, ok := t.Conn.(interface{ CloseWrite() error })`).

### 3.2 Interface Wrapping & Forwarding
- **Audit Target**: Connections wrapped by [`connDeadlineTracker`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L14-L23) or [`prefixConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L35-L65) must transparently support optional standard library interfaces to avoid breaking lower-level socket optimizations or half-close propagation.
- **Verification**:
  - Both [`connDeadlineTracker`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L30-L50) and [`prefixConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L49-L65) implement:
    1. `Unwrap() net.Conn`: Returns the embedded underlying socket.
    2. `CloseWrite() error`: Delegates half-close if supported by the underlying connection, or returns an explicit error if unsupported.
    3. `SyscallConn() (syscall.RawConn, error)`: Forwards raw socket control if the underlying connection implements `syscall.Conn`, or returns `nil, syscall.EINVAL`.
  - In bidirectional upgraded tunneling ([`relayStreams`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L751)), half-close propagation (`dst.CloseWrite()`) traverses the wrapper chain directly to the raw socket, verified in [`TestDeadlineTracker_InterfacesAndUnwrap`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline_test.go#L296-L343).

### 3.3 Amortized Deadline Algorithm Correctness
- **Mathematical Invariant**:
  $$\text{SkipSyscall} \iff (\tau == \tau_{\text{last}}) \land (!D.\text{IsZero}()) \land (R(T_{\text{now}}) > \tau / 2)$$
- **Verification in [`deadline.go:66-74`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L66-L74)**:
  - If `!t.lastReadDeadline.IsZero() && timeout == t.lastReadTimeout`: The tracker checks `remaining := t.lastReadDeadline.Sub(now)`. If `remaining > timeout/2`, the kernel syscall is elided and `nil` is returned immediately.
  - When remaining time drops to $\le \tau/2$, or when `timeout != t.lastReadTimeout`, a fresh deadline $D' = T_{\text{now}} + \tau$ is dispatched to `t.Conn.SetReadDeadline(deadline)`.
  - **Error Safety**: The cached timestamp and duration are updated **only** when `err == nil` ([`deadline.go:77-81`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L77-L81)). If the underlying socket call fails, the cache remains unmodified.
  - **Concurrency Safety**: `t.mu.Lock()` and `defer t.mu.Unlock()` guard all reads and mutations of deadline timestamps, ensuring total race freedom.

### 3.4 Strict Idle Transition State Machine
- **Audit Target**: Prevent active request `ReadTimeout` (e.g. 5s or 10s) from bleeding into keep-alive idle wait periods, which must terminate connections within `IdleTimeout` (e.g. 200ms).
- **Verification in [`server.go:215-221`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L215-L221)**:
  ```go
  if !firstRequest && br.Buffered() == 0 && s.config.IdleTimeout > 0 {
      tracker.ResetReadAmortization()
      _ = tracker.ForceSetReadDeadline(time.Now().Add(s.config.IdleTimeout))
  } else if s.config.ReadTimeout > 0 {
      _ = tracker.SetAmortizedReadDeadline(s.config.ReadTimeout)
  }
  ```
  1. If `!firstRequest && br.Buffered() == 0`: Request is complete and no pipelined bytes exist in buffer. The tracker clears amortization (`ResetReadAmortization()`) and immediately sets `IdleTimeout` via `ForceSetReadDeadline`.
  2. If `br.Buffered() > 0`: Pipelined request data is queued; the connection remains active and applies amortized `ReadTimeout`.
  3. When idle timeout expires: Handled silently as keep-alive disconnect without returning HTTP 400 errors ([`server.go:230`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L230)).

### 3.5 Activity-Refreshed Streaming Write Deadlines
- **Audit Target**: Long-lived streams must survive indefinitely while actively transmitting chunks, but must terminate deterministically within `WriteTimeout` if a client stalls reading (CWE-400 Slow-Read defense).
- **Verification in [`server.go:347-363`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L347-L363)**:
  - For each chunk where `n > 0`, `tracker.ForceSetWriteDeadline(time.Now().Add(s.config.WriteTimeout))` refreshes the kernel socket write deadline immediately prior to `conn.Write(buf[:n])`.
  - If a client consumes data, the deadline is repeatedly pushed into the future, allowing active streams (SSE, telemetry feeds) to run for hours.
  - If a client stalls, closes its receive window, or reads at 1 byte/minute, the kernel TCP send buffer saturates. `conn.Write` blocks until the deadline expires, returning `os.ErrDeadlineExceeded`.
  - Toron catches `writeErr != nil`, exits the loop, triggers `defer res.StreamBody.Close()` to teardown upstream origin resources, and closes the client connection. Zero leaked goroutines.

### 3.6 Relaying Stream Amortization (`relayStreams`)
- **Audit Target**: Upgraded WebSocket and L4 tunnels must amortize read/write deadlines during bidirectional traffic bursts while strictly honoring inactivity disconnects.
- **Verification in [`server.go:696-770`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L696-L770)**:
  - Both connections are wrapped via `toDeadlineTracker(conn)`.
  - In `copyDirection`, `src.SetAmortizedReadDeadline(idleTimeout)` and `dst.SetAmortizedWriteDeadline(idleTimeout)` amortize system calls during high-rate bidirectional message exchanges.
  - Inactivity on both sockets triggers `netErr.Timeout()`, invoking `closeBoth()` to shut down both sockets cleanly.

### 3.7 Zero-Timeout Handling
- **Audit Target**: Setting `read_timeout: 0` and `write_timeout: 0` must completely eliminate deadline system calls for maximum benchmark throughput in trusted environments.
- **Verification in [`deadline.go:57-64`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/deadline.go#L57-L64)**:
  - When `timeout <= 0`, if an active deadline was previously set, `t.Conn.SetReadDeadline(time.Time{})` clears it once and resets cached state.
  - Subsequent invocations with `timeout <= 0` return `nil` immediately without issuing any syscalls.
  - In `handleConn`, guards `if s.config.ReadTimeout > 0` and `if s.config.WriteTimeout > 0` bypass deadline tracker invocations entirely.
  - In [`pkg/config/loader.go:188-202`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go#L188-L202), negative durations are rejected, but `0` durations are accepted and preserved without overwriting.
