# TC-058 - Verification of Config-Based Logging, Route Overrides, and Logrotate Reopen

## Objective

Verify that Toron correctly deserializes multi-stream logging configuration from `config.yaml`, applies per-route `access_log` and `security_log` overrides from `routes.yaml`, correctly directs server, access, and security logs to their respective destinations, and supports atomic file descriptor reopening upon `SIGHUP` (or `Reopen()` calls) for seamless system logrotate integration.

## Test Cases

### TC-058-01: Global Logging Configuration Deserialization & Defaults
- **Input**:
  ```yaml
  logging:
    level: "warn"
    format: "json"
    server_log: "logs/server.log"
    access_log: "logs/access.log"
    security_log: "logs/security.log"
  ```
- **Action**: Parse configuration through `config.LoadFromBytes`.
- **Expected Outcome**:
  - `cfg.Logging.Level` is `"warn"`.
  - `cfg.Logging.Format` is `"json"`.
  - `cfg.Logging.ServerLog` is `"logs/server.log"`.
  - `cfg.Logging.AccessLog` is `"logs/access.log"`.
  - `cfg.Logging.SecurityLog` is `"logs/security.log"`.
  - When omitted, `server_log`, `access_log`, and `security_log` default to empty/stdout.

### TC-058-02: Route-Level Overrides Deserialization
- **Input**:
  ```yaml
  routes:
    - type: "upstream"
      prefix: "/api"
      target: "http://localhost:9001"
      access_log: "logs/api_access.log"
      security_log: "logs/api_security.log"
    - type: "static"
      prefix: "/silent"
      dir: "./public"
      access_log: "off"
    - type: "static"
      prefix: "/default"
      dir: "./public"
  ```
- **Action**: Parse `routes.yaml` through `config.LoadRoutesFromBytes`.
- **Expected Outcome**:
  - First route specifies `AccessLog: "logs/api_access.log"`, `SecurityLog: "logs/api_security.log"`.
  - Second route specifies `AccessLog: "off"`.
  - Third route has empty `AccessLog` (inherits global default).

### TC-058-03: LogManager Sink Creation and Automatic Directory Creation
- **Setup**: Specify log path in a non-existent nested directory (e.g. `test_logs/nested/sub/access.log`).
- **Action**: Initialize `LogManager` with this path and write a log entry.
- **Expected Outcome**:
  - Directory `test_logs/nested/sub` is automatically created with appropriate permissions.
  - File `access.log` is created and entry is written.

### TC-058-04: Default Access Log Writing
- **Setup**: Route configured without override. Global `access_log` pointing to a file.
- **Request**: `GET /default HTTP/1.1`.
- **Expected Outcome**:
  - The request entry is recorded in the global access log file containing client IP, method, status code 200, and request path.

### TC-058-05: Route-Specific Access Log Override & Silencing
- **Setup**: Route `/api` with `access_log: "logs/api.log"`, Route `/silent` with `access_log: "off"`.
- **Request**:
  1. `GET /api/users HTTP/1.1`.
  2. `GET /silent/index.html HTTP/1.1`.
- **Expected Outcome**:
  - Request 1 is recorded in `logs/api.log` and NOT in the global access log.
  - Request 2 is NOT recorded in any access log file.

### TC-058-06: Security Log Recording on WAF / Auth Events
- **Setup**: Route `/secure` with `security_log: "logs/sec.log"` and WAF/Auth active.
- **Request**: Send request triggering WAF rule or invalid auth header.
- **Expected Outcome**:
  - An audit record is logged to `logs/sec.log` containing event timestamp, client IP, rule/violation details, and action taken (`blocked`).

### TC-058-07: SIGHUP / Logrotate Reopening Simulation
- **Setup**: Active log file with entries written.
- **Action**:
  1. Rename the active log file (simulating logrotate moving `access.log` -> `access.log.1`).
  2. Trigger `LogManager.Reopen()` (simulating `SIGHUP` signal).
  3. Write another log entry.
- **Expected Outcome**:
  - A new `access.log` file is created at the original path.
  - Subsequent log entry appears in the new file, while previous entries remain in the rotated file.
  - No errors or panic occurs during rotation.

### TC-058-08: High-Concurrency Thread Safety Verification
- **Setup**: 100 concurrent goroutines writing access and security log entries to the same log sinks.
- **Expected Outcome**:
  - No race conditions reported (`go test -race`).
  - No corrupted or interleaved log records in output files.
