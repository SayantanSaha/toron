# REQ-017 - Internal Management API Endpoints for Dashboard Observability

## Description

The Toron server shall expose a set of internal management endpoints starting with prefix `/internal/api/`. The frontend dashboard shall consume these endpoints for system metrics, proxy route configurations, server-side upstream health probing, and interactive proxy route testing without directly making HTTP calls to external upstream target ports from the browser.

## Acceptance Criteria

- Registered endpoints under `/internal/api/`:
  - `GET /internal/api/status`: Returns server runtime info, uptime, version, and active worker pool size.
  - `GET /internal/api/routes`: Returns active proxy route configurations, headers, load balancing algorithms, and target node URLs.
  - `GET /internal/api/upstreams/health`: Executes backend server-side HTTP probes against upstream targets and returns JSON status (`CLOSED`, `OPEN`, `UNREACHABLE`), latencies, and HTTP response status codes.
  - `POST /internal/api/proxy-test`: Executes internal test requests via Toron proxy routes and returns response status, latency, headers, and body payload.
- Frontend JavaScript (`public/app.js`) updated to query `/internal/api/...` endpoints exclusively, eliminating direct browser-to-upstream target requests.
- Full Go unit/integration test coverage for `/internal/api/` handlers.

## Rationale

Decouples frontend observability from direct browser-to-upstream networking, preventing CORS issues and enabling centralized server-side monitoring and proxy testing.
