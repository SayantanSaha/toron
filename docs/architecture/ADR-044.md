# ADR-044 - REST-to-gRPC Transcoding Architecture via Zero-Dependency Wire Framing

## Context

Frontend REST applications communicate using HTTP/1.1 JSON (e.g. `GET /v1/users/123`), whereas internal microservices expose binary Protobuf gRPC RPCs (e.g. `POST /user.UserService/GetUser`). Importing protobuf compiler code generators and C-gRPC runtimes adds massive binary bloat. Toron requires a native, zero-dependency REST-to-gRPC transcoder in `pkg/transcoder`.

## Decision

1. **gRPC Wire Framer (`pkg/transcoder/framer.go`)**:
   - Implement gRPC 5-byte header prefix encoder: `[1-byte compression (0x00)][4-byte payload length (big-endian)] + payload`.
2. **REST Parameter Extractor (`pkg/transcoder/transcoder.go`)**:
   - Extract URL path placeholders (`/v1/users/:id` -> `{"id": "123"}`) and query string params, merging them with body JSON.
3. **gRPC Status Mapper**:
   - Map `grpc-status` trailer integer values to standard HTTP status codes:
     - `0` (OK) -> `200 OK`
     - `3` (InvalidArgument) -> `400 Bad Request`
     - `5` (NotFound) -> `404 Not Found`
     - `7` (PermissionDenied) / `16` (Unauthenticated) -> `401 / 403`
     - `14` (Unavailable) -> `503 Service Unavailable`

## Consequences

- **Positive**: Zero external dependencies. Works out of the box for JSON-over-gRPC endpoints.
- **Positive**: Preserves Toron's sub-30MB binary size and instant boot times.
- **Negative**: Dynamic field tags require explicit mapping rules in configuration.
