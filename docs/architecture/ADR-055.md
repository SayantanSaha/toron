# ADR-055 - Universal Query Parameter Preservation and Ingress Adapter Normalization

## Context

In modern web applications and API gateways, URL query parameters (`?key=val&flag&page=1`) carry critical execution state, such as API authentication tokens, pagination offsets, search filters, and webhook signatures.

In Toron, requests ingress through multiple pathways:
1. Native raw TCP reactor / socket parser (`pkg/httpparser/parser.go`) for HTTP/1.1 cleartext.
2. Standard library TLS + Go `http2.Server` for HTTP/2 (`h2` ALPN).
3. `quic-go/http3.Server` for HTTP/3 over UDP.
4. Sidecar transparent proxy handlers (`pkg/sidecar/proxy.go`).

In pathways 2, 3, and 4, the ingress engine adapted `*http.Request` into `*httpparser.Request` manually. However, `QueryParams` was omitted, remaining `nil`.

When `pkg/proxy/proxy.go` constructed the upstream request URL, it serialized query parameters using:
```go
outURL.RawQuery = req.QueryParams.Encode()
```
Since `req.QueryParams` was `nil` in HTTP/2 and HTTP/3, `outURL.RawQuery` evaluated to `""`, stripping all query parameters from client requests. Furthermore, relying on `url.Values.Encode()` instead of the raw client query string stripped parameter ordering, altered percent-encoding, and stripped flag parameters without explicit values.

## Decision

We decide to:

1. **Standardize Request Adaptation (`NewRequestFromStd`)**:
   Implement a centralized adapter function in `pkg/httpparser/request.go` (`NewRequestFromStd(r *http.Request) *Request`) that extracts `URL`, `Path`, `RequestURI`, `Header`, and `QueryParams` (`r.URL.Query()`), ensuring all ingress adapters produce uniform `Request` instances.

2. **Add Lazy Query Fallback (`req.Query()`)**:
   Provide a lazy accessor `Query()` on `*httpparser.Request` that transparently parses `URL.Query()` if `QueryParams` is nil.

3. **Prefer Verbatim `URL.RawQuery` During Upstream Proxying**:
   In `pkg/proxy/proxy.go`, resolve client query parameters by checking:
   ```go
   clientQuery := ""
   if req.URL != nil && req.URL.RawQuery != "" {
       clientQuery = req.URL.RawQuery
   } else if len(req.QueryParams) > 0 {
       clientQuery = req.QueryParams.Encode()
   } else if req.Query() != nil && len(req.Query()) > 0 {
       clientQuery = req.Query().Encode()
   }
   ```
   This guarantees that the exact query string as sent by the client over the wire is forwarded to the upstream server.

4. **Support Target Query Merging**:
   If the upstream `target` URL defined in `routes.yaml` includes pre-configured query parameters, client query parameters are merged with an `&` separator instead of overwriting the target's parameters.

5. **Enhance Access Log Telemetry**:
   Record `req.RequestURI` in `AccessLoggerMiddleware` so that full query parameters are visible in `/var/log/toron/access.log`.

## Consequences

### Positive
- Query parameters are fully and reliably forwarded across HTTP/1.1, HTTP/2, and HTTP/3.
- Parameter ordering, non-value flags, and percent-encoding are preserved verbatim.
- Target pre-configured query parameters are preserved and merged cleanly.
- Full observability in access logs.

### Negative / Trade-offs
- None. Minimal overhead and full backward compatibility.
