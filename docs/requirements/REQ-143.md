# REQ-143 - Dual-Pane Analytics & Time-Window Filtered Paginated Request Explorer for Control Center Dashboard

## 1. Description & Problem Statement

### 1.1 Context & Background
As detailed in [`AN-003`](../analysis/AN-003.md), the Toron Control Center Requests & Logs view ([`public/js/views/logs.js`](../../public/js/views/logs.js)) provides live visibility into HTTP transactions processed by the gateway.

In high-throughput environments, the current implementation exhibits critical operational limitations:
1. **Unbounded Visual Growth & Firehose Jitter**: Rendering incoming requests into an unpaginated flat table pushes rows continuously downward, causing operators to misclick or lose visual tracking while debugging.
2. **Noise vs Signal Drowning**: Frequent automated health probes (e.g. `GET /health`) overwhelm the view, burying critical 4xx/5xx errors or latency degradation.
3. **Absence of Aggregation**: Operators have no macro-level visibility into traffic distributions, status breakdowns, or top endpoints.
4. **Lack of Temporal Filtering & Sorting**: Operators cannot scope logs to specific operational incident windows (e.g. `1 min`, `5 min`, `1 hr`, or custom datetime boundaries), nor can they sort by duration to pinpoint slow requests.

### 1.2 Objective & Scope
Redesign the Requests view (`#log`) into a **Dual-Pane Analytics & Time-Window Filtered Request Explorer** adhering to Option 1 of [`AN-003`](../analysis/AN-003.md) with custom temporal windowing:
1. **Top Analytics Strip**: Compact SVG status-code distribution mini-histogram and actionable facet summary cards (Top Routes, P95 Latency / Slowest Endpoints, Error Rate).
2. **Time-Window Filtering**: Dedicated temporal scoping supporting `1m`, `5m`, `1h`, `All Buffer`, and a `Custom` range picker with start/end boundaries.
3. **Enhanced Filter Toolbar**: Search query, status category chips (`2xx`, `3xx`, `4xx`, `5xx`), `Over SLO` toggle, `Exclude /health` noise filter, route selector, and live tail toggle.
4. **Paginated & Sortable Request Ledger**: Configurable page sizes (25, 50, 100), page navigation controls, sortable column headers (Time, Status, Duration, Path), and interaction freeze (hover/drawer lock).
5. **Zero External Dependencies**: Implemented strictly with vanilla ES modules, complying with the $\le 100\text{ KB}$ JavaScript budget.

## 2. Functional Requirements

### 2.1 Top Analytics & Facet Strip
- **REQ-143.1: Status Distribution Mini-Histogram**:
  - The view MUST render an SVG spark-histogram visualizing request volume across time buckets in the active buffer.
  - Bars MUST be color-coded by status class: `2xx` (green/ok), `3xx` (blue/info), `4xx` (amber/warn), `5xx` (red/err).
  - The histogram MUST update dynamically as new requests arrive or when filters change.
- **REQ-143.2: Actionable Facet Cards**:
  - The view MUST display quick summary metric pills:
    - **Top Routes by Volume**: Top 2–3 endpoints with highest request counts. Clicking a pill MUST automatically set the route filter.
    - **Latency Facet**: Current P95 latency and the slowest request endpoint.
    - **Error Rate Facet**: Overall error percentage across the active filtered window.

### 2.2 Temporal & Expressive Filtering
- **REQ-143.3: Predefined Time-Window Filtering**:
  - The toolbar MUST include a time-window filter selector with preset intervals:
    - `1m` (Last 1 minute)
    - `5m` (Last 5 minutes)
    - `1h` (Last 1 hour)
    - `all` (All requests in buffer)
    - `custom` (Custom timestamp range)
  - Filtering MUST evaluate request timestamps (`ts`) against the selected interval relative to current time or absolute timestamps.
- **REQ-143.4: Custom Time Range Scoping**:
  - When `custom` is selected, the view MUST reveal inline start (`from`) and end (`to`) datetime/time inputs.
  - The request table and histogram MUST restrict records to $from \le \text{record.ts} \le to$.
- **REQ-143.5: Noise Reduction (Exclude Health Probes)**:
  - The toolbar MUST provide an `Exclude /health` chip or checkbox.
  - When active, all requests matching `/health` MUST be suppressed from the table and facet aggregations.
- **REQ-143.6: Multi-Field Search & Status Filters**:
  - The search input MUST match case-insensitively across: Path, Upstream socket, Trace ID, Client IP, and Route identifier.
  - Status chips (`2xx`, `3xx`, `4xx`, `5xx`) and `Over SLO` MUST remain fully functional.

### 2.3 Paginated & Sortable Request Stream Table
- **REQ-143.7: Configurable Pagination**:
  - The request stream MUST be paginated with configurable page sizes: `25`, `50`, or `100` rows per page (default: `25`).
  - The pagination bar MUST display current page, total pages, record counts (e.g. `Showing 1–25 of 180 requests`), and navigation controls (`First`, `Prev`, `Next`, `Last`).
- **REQ-143.8: Multi-Column Sorting**:
  - Table headers MUST be interactive and sortable:
    - **Time** (`ts` desc/asc)
    - **Status** (HTTP code desc/asc)
    - **Duration** (`ms` desc/asc)
    - **Path** (alphabetical desc/asc)
  - An active sort indicator (arrow icon or symbol) MUST indicate the current primary sort column and direction.
- **REQ-143.9: Interaction Freeze on Hover & Drawer Inspection**:
  - When the cursor hovers over `#lgBody` or when a log trace drawer is open, live updates to the DOM table MUST be paused so rows do not jump.
  - Tail updates continue accumulating in the data model without displacing the operator's view.

### 2.4 Inspector Drawer Trace Parity
- **REQ-143.10: Detail Drawer Integration**:
  - Clicking any row MUST continue to open the inspector drawer ([`public/js/components/drawer.js`](../../public/js/components/drawer.js)) displaying the span waterfall, trace ID, headers, upstream address, client IP, and response byte count.

## 3. Non-Functional Requirements & Invariants

- **NFR-143.1: Zero External Dependencies**:
  All histogram rendering, pagination, sorting, and time window calculations MUST be written in vanilla ES6+ without third-party libraries.
- **NFR-143.2: Performance & Bundle Footprint**:
  The total JavaScript asset footprint in `public/js/` MUST remain $\le 100\text{ KB}$ (currently $99.8\text{ KB}$, requiring compact, efficient code).
- **NFR-143.3: Strictly Relative Links**:
  All project documents, requirements, and test suites MUST adhere strictly to relative linking rules with zero absolute machine paths.
- **NFR-143.4: Complete Automated Verification**:
  All new capabilities MUST be covered by dedicated verification test cases in `tests/dashboard_telemetry_test.js`.
