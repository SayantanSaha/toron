# REQ-031 - Prometheus Metrics Endpoint (/metrics) and W3C Traceparent Context Propagation

## Description

The Toron web server shall expose a standardized `/metrics` HTTP endpoint in Prometheus text exposition format and support OpenTelemetry W3C `traceparent` distributed tracing header propagation.

The `/metrics` endpoint shall export server observability counters, gauges, and latency histograms including:
- `toron_http_requests_total{method, status, route}` (Counter)
- `toron_http_request_duration_seconds` (Histogram buckets: 0.005s to 10s)
- `toron_active_quic_streams` (Gauge)
- `toron_circuit_breaker_trips_total{target}` (Counter)
- `toron_tcp_connections_active` (Gauge)
- `toron_udp_packets_total` (Counter)

Toron's request router and reverse proxy engine shall automatically parse W3C `traceparent` headers (`00-<trace_id>-<parent_id>-<flags>`) from client requests, inject missing trace contexts, and propagate `traceparent` headers to upstream backend target microservices.

## Acceptance Criteria

- `pkg/metrics`: Implements `MetricsRegistry` producing valid Prometheus exposition text format (`text/plain; version=0.0.4`).
- `pkg/router`: Exposes `/metrics` endpoint returning Prometheus metric counters, latency histograms, QUIC stream gauges, and circuit breaker trip metrics.
- `pkg/proxy`: Reverse proxy propagates incoming W3C `traceparent` headers or generates valid 32-hex trace ID / 16-hex span ID headers for upstream requests.
- Automated unit and integration tests in `pkg/metrics`, `pkg/proxy`, and `pkg/router` pass cleanly.

## Rationale

Prometheus metrics and W3C distributed tracing context propagation provide essential enterprise observability, monitoring, and tracing across microservice mesh architectures.
