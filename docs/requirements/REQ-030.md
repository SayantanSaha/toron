# REQ-030 - Sticky Session Load Balancing Algorithms (sticky_cookie and ip_hash)

## Description

The Toron reverse proxy load balancer shall support session affinity ("sticky sessions") through two load balancing algorithms: `sticky_cookie` (cookie-based session affinity) and `ip_hash` (client IP hash affinity).

When `algorithm: "sticky_cookie"` is configured on a route in `routes.yaml`, the load balancer shall inspect client requests for a sticky cookie (default `TORON_STICKY`). If a valid cookie mapping to a healthy target backend is present, the request shall be routed to that target. If absent or if the target is unhealthy, a new target shall be assigned and a `Set-Cookie` header injected on the response.

When `algorithm: "ip_hash"` is configured, the load balancer shall hash the client's remote IP address to map requests consistently to the same healthy target node.

## Acceptance Criteria

- `pkg/config`: `ProxyRouteConfig` supports `algorithm: "sticky_cookie"` and `algorithm: "ip_hash"`, and optional `sticky_cookie_name` parameter.
- `pkg/proxy`: `StickyCookieBalancer` injects `Set-Cookie` headers for initial requests and routes subsequent requests with matching cookies to the pinned target backend.
- `pkg/proxy`: `IPHashBalancer` hashes client IP addresses consistently to select backend targets.
- Circuit breaker / health check integration: If a pinned sticky target becomes unhealthy (`Open` state), the load balancer falls back to an available healthy target seamlessly.
- Automated unit and integration tests in `pkg/proxy` pass cleanly.

## Rationale

Sticky sessions are essential for stateful web applications, shopping carts, authenticated user sessions, and WebSockets that require persistent binding to specific backend service instances.
