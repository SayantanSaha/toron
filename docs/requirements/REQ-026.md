# REQ-026 - TCP and UDP Layer 4 Transport Layer Proxying and Listener Support

## Description

The Toron server shall support Layer 4 transport-layer TCP and UDP proxying and listening capabilities.

This requirement introduces dual transport-layer proxy engines (`TCPProxy` and `UDPProxy`) and configuration schema extensions in `routes.yaml` (`type: "tcp"` and `type: "udp"`), allowing Toron to handle raw TCP socket stream forwarding and connectionless UDP packet proxying to configured upstream targets with configurable load balancing and timeouts.

## Acceptance Criteria

- `pkg/config`: `RouteConfig` supports `type: "tcp"` and `type: "udp"` routes with dedicated listener ports (`listen_port` or `port`), `target` / `targets` endpoints, `algorithm` selection, and network timeouts.
- `pkg/proxy`: `TCPProxy` implementation supports handling incoming raw TCP net.Conn streams and bi-directionally copying bytes between client sockets and upstream TCP targets.
- `pkg/proxy`: `UDPProxy` implementation supports receiving incoming UDP datagrams (`net.UDPConn`) and forwarding datagrams to/from upstream UDP targets.
- `pkg/server`: `Server` infrastructure supports starting and managing concurrent TCP and UDP listeners alongside existing HTTP listeners.
- Automated Go unit tests in `pkg/config`, `pkg/proxy`, and `pkg/server` pass cleanly without regressions.

## Rationale

Supporting raw TCP and UDP transport protocols enables Toron to serve as a versatile unified gateway for non-HTTP microservice workloads (such as gRPC raw TCP, database proxies, DNS, IoT protocols, and custom socket services).
