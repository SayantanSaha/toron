# TC-105 - Verification Suite for HTTP Parser Microbenchmarks and Latency Profiling

## 1. Test Suite Objectives

Verify that `pkg/httpparser/parser_test.go` provides comprehensive, in-process Go microbenchmarks (`testing.B`) evaluating pure state machine execution latency, ensuring zero-allocation reader resetting, validating fail-fast error assertions, and generating nanosecond-resolution metrics for RFC 7230 §3.2.4 whitespace rejection, RFC 7230 §3.3.2 multiple Content-Length rejection, and valid baseline requests.

## 2. Test Cases

### TC-105-01: Header Whitespace Rejection Microbenchmark
- **Objective**: Execute `BenchmarkParseRequest_WhitespaceRejection` and verify that `ParseRequest` rejects the payload on each iteration with an error wrapping `ErrBadRequest`.
- **Expected Outcome**: Benchmark runs cleanly for $N$ iterations without error; state machine execution latency reported in $\text{ns/op}$ ($< 1\,\mu\text{s}$).

### TC-105-02: Conflicting Content-Length Rejection Microbenchmark
- **Objective**: Execute `BenchmarkParseRequest_MultipleCL` and verify that `ParseRequest` rejects the request containing duplicate conflicting `Content-Length` headers.
- **Expected Outcome**: Benchmark runs cleanly for $N$ iterations without error; fail-fast rejection latency reported in $\text{ns/op}$.

### TC-105-03: Valid HTTP/1.1 Baseline Microbenchmark
- **Objective**: Execute `BenchmarkParseRequest_ValidBaseline` and verify that `ParseRequest` successfully parses the well-formed request into a valid `*Request` struct without error.
- **Expected Outcome**: Benchmark runs cleanly for $N$ iterations; outputs baseline parsing latency and memory allocation statistics (`B/op`, `allocs/op`).

### TC-105-04: Zero-Allocation Harness Verification
- **Objective**: Confirm that reader instantiation occurs strictly outside `b.ResetTimer()`, and `r.Reset(payload)` inside the loop introduces 0 additional harness heap allocations.
- **Expected Outcome**: Memory profile under `go test -bench=. -benchmem` confirms that allocations reflect solely internal parser allocations.

### TC-105-05: Race Detector Cleanliness
- **Objective**: Execute the test package with race detection enabled (`go test -v -race -count=1 ./pkg/httpparser/...`).
- **Expected Outcome**: All unit tests and benchmarks compile and pass with zero race warnings.
