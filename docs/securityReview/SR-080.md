# SR-080 - Security Review of Mandatory exp Claim Enforcement in JWT Verification

## Description

Security evaluation of the implementation for `TASK-082` / `SEC-22` (Missing expiration `exp` claim enforcement causing indefinite token replay risk).

## Scope

- Files reviewed:
  - `pkg/router/auth.go`
  - `pkg/router/auth_test.go`

## Security Evaluation & Analysis

1. **Elimination of Permanent Credential Replay (CWE-613)**:
   - Previously, `VerifyJWT` checked the `exp` claim only if present in the claims payload, allowing non-expiring tokens to remain valid indefinitely.
   - Enhanced `VerifyJWT` to mandate the presence and future expiration of the `exp` claim by default (`requireExp := true`).
   - If a token is presented without an `exp` claim (or with `exp <= 0`), verification immediately aborts with `token missing required exp claim`.
2. **Backward-Compatibility & Opt-Out Support**:
   - Added `RequireExpiration` and `AllowNoExpiration` fields to `JWTConfig`.
   - In `NewAuthMiddleware`, `requireExp` defaults to `true` unless `AllowNoExpiration: true` is explicitly opted into.
   - `VerifyJWT` supports variadic opt-out (`requireExpOpt ...bool`) for legacy systems where non-expiring tokens are intentional.
3. **Exploit Verification**:
   - TC-082-01 verified: Token lacking `exp` claim is rejected with `token missing required exp claim`.
   - TC-082-02 verified: Token with future `exp` claim is accepted.
   - TC-082-03 verified: Token with past `exp` claim is rejected with `token has expired`.
   - Opt-out verified: When `requireExp=false`, non-expiring tokens pass validation.

## Conclusion

`SEC-22` is fully mitigated. Permanent token replay risks are eliminated. Approved.
