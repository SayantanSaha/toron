# SR-052 - Security Review of SPA HTML5 History Fallback Support in Static Router

## Executive Summary

The Security Analyst (AGENT-007) has conducted an in-depth security review and vulnerability assessment of the Single Page Application (SPA) HTML5 History Fallback implementation for static routes in Toron ([`pkg/router/router.go`](file:///Users/sneha/Developer/toron/pkg/router/router.go), [`pkg/config/config.go`](file:///Users/sneha/Developer/toron/pkg/config/config.go), and [`cmd/toron/main.go`](file:///Users/sneha/Developer/toron/cmd/toron/main.go)), addressing [`TASK-056`](file:///Users/sneha/Developer/toron/docs/tasks/TASK-056.md) and verifying [`REQ-056`](file:///Users/sneha/Developer/toron/docs/requirements/REQ-056.md) in accordance with [`ADR-051`](file:///Users/sneha/Developer/toron/docs/architecture/ADR-051.md).

The evaluation focused on four primary threat vectors and security controls:
1. **Path Traversal & Directory Escape Defenses (CWE-22 / CWE-59)**: Validating containment for both incoming relative request paths and configured fallback filenames (`filepath.Base`, `filepath.Clean`, `filepath.Rel`, and symlink escape verification via `filepath.EvalSymlinks`).
2. **Asset Masking & MIME-Confusion / XSS Prevention (CWE-430 / CWE-79)**: Ensuring non-existent physical static assets with extensions (`.js`, `.css`, `.png`, `.json`, `.svg`, etc.) reliably return HTTP 404 Not Found and cannot be manipulated into returning HTML documents that trigger browser script/style execution anomalies or MIME-confusion vulnerabilities.
3. **Information Disclosure & Error Sanitization (CWE-200 / CWE-209 / CWE-548)**: Verifying that internal filesystem structures, system error traces, or directory listings are never leaked to clients when files are absent, unreadable, or invalid.
4. **Denial of Service (DoS) & Resource Boundedness (CWE-400 / CWE-770)**: Auditing file I/O operations, memory allocation ceilings during file reads, HTTP method restrictions (`HEAD` / `GET`), and integration with Toron's pre-routing Rate Limiter and WAF.

Based on thorough static analysis, threat modeling, and test verification, the SPA HTML5 History Fallback implementation incorporates robust multi-layered defensive controls and is **APPROVED**.

## Detailed Security Evaluation & Threat Modeling

### 1. Path Traversal & Directory Escape Defenses (CWE-22 / CWE-59)

#### Threat Vector
Attackers can supply path traversal sequences (`../`, `..%2f`, `%2e%2e/`, null bytes) in the request URI to escape the designated static root directory (`absDir`) and read sensitive operating system files (e.g., `/etc/passwd`, private keys, application secrets). Additionally, if operators configure a malicious or parameterized fallback path, or if symbolic links inside the document root point to external directories, an attacker could traverse out of the sandbox.

#### Implementation & Defensive Analysis
Toron establishes multi-tiered lexical and physical containment boundaries:

1. **Requested Relative Path Sanitization**:
   ```go
   cleanRel := filepath.Clean(filepath.FromSlash(strings.TrimPrefix(fileRelPath, "/")))
   targetPath := filepath.Join(absDir, cleanRel)

   relFromDir, err := filepath.Rel(absDir, targetPath)
   if err != nil || strings.HasPrefix(relFromDir, "..") || (strings.HasPrefix(relFromDir, ".") && len(relFromDir) > 1 && relFromDir[1] == '.') {
       res.SetStatus(http.StatusForbidden)
       res.Header.Set("Content-Type", "application/json")
       _, _ = res.WriteString(`{"error":"403 Forbidden: Path Traversal Disallowed"}`)
       return
   }
   ```
   - All input paths are normalized with `filepath.FromSlash` and canonicalized via `filepath.Clean`.
   - Lexical boundary validation using `filepath.Rel(absDir, targetPath)` strictly asserts that the target does not resolve to an ancestor path (`..`).
   - Any violation triggers an immediate `403 Forbidden` response with an opaque JSON error.

2. **Symlink Escape Mitigation**:
   ```go
   realAbsDir, err := filepath.EvalSymlinks(absDir)
   if err != nil {
       realAbsDir = absDir
   }
   if evalTarget, err := filepath.EvalSymlinks(targetPath); err == nil {
       relFromReal, err := filepath.Rel(realAbsDir, evalTarget)
       if err != nil || strings.HasPrefix(relFromReal, "..") || (strings.HasPrefix(relFromReal, ".") && len(relFromReal) > 1 && relFromReal[1] == '.') {
           res.SetStatus(http.StatusForbidden)
           res.Header.Set("Content-Type", "application/json")
           _, _ = res.WriteString(`{"error":"403 Forbidden: Symlink Path Traversal Disallowed"}`)
           return
       }
   }
   ```
   - Before any file access, symlink targets are resolved using `filepath.EvalSymlinks` against the evaluated canonical document root (`realAbsDir`).
   - Even if a symlink exists inside the static directory pointing outside (e.g., `assets/root -> /`), Toron catches the breakout and rejects it with `403 Forbidden: Symlink Path Traversal Disallowed`.

3. **Fallback Filename Boundary Enforcement**:
   ```go
   fallbackName := filepath.Base(opts.Fallback)
   if fallbackName == "." || fallbackName == ".." || fallbackName == "" {
       fallbackName = "index.html"
   }
   fallbackPath := filepath.Join(absDir, fallbackName)
   ```
   - `filepath.Base` forcefully strips any directory path separators (`/` or `\`) or relative directory components (`../../`).
   - Traversal tokens such as `.` or `..` or empty inputs default safely to `"index.html"`.
   - The resolved `fallbackPath` undergoes the identical lexical `filepath.Rel` and symlink `filepath.EvalSymlinks` checks as the primary target path.
   - Verified by `TestRouter_SPA_SecurityPathTraversal` in [`pkg/router/router_test.go`](file:///Users/sneha/Developer/toron/pkg/router/router_test.go#L523-L567), confirming that both URI-level traversal attempts and malicious `Fallback: "../../../../etc/passwd"` configurations fail safely with 403 or 404 without leaking file contents.

### 2. Asset Masking & MIME-Confusion / XSS Prevention (CWE-430 / CWE-79)

#### Threat Vector
In naive Single Page Application fallback configurations (such as global rewrites or wildcard `try_files` that route any missing path to `index.html`), requesting non-existent static assets (e.g. `/assets/main.c83a1.js` or `/theme.css`) returns an HTTP 200 OK containing HTML markup.
- **MIME Confusion & Script Execution Errors**: When `<script src="/missing.js">` receives HTML, browsers fail with `Uncaught SyntaxError: Unexpected token '<'`, breaking the SPA execution pipeline.
- **XSS & Style Injection Vector**: In certain legacy clients or embed scenarios, masking asset errors behind HTML responses can allow attackers to abuse script/stylesheet inclusion points or trigger unexpected document execution.
- **Observability Degradation**: Deployment errors, broken links, and missing assets are obscured from client-side monitoring tools (e.g., Sentry, Datadog), hindering security and operations incident response.

#### Implementation & Defensive Analysis
Toron introduces strict deterministic asset segregation before invoking the fallback mechanism:

```go
spaMode := opts.SPA || strings.TrimSpace(opts.Fallback) != ""
if spaMode && filepath.Ext(relPath) == "" {
    // Client-side virtual navigation: serve fallback document
} else {
    // Missing asset with file extension or SPA disabled: return 404
    r.NotFound(req, res)
}
```

1. **Deterministic Extension Filtering**:
   - `filepath.Ext(relPath)` examines the requested URL relative path.
   - If `filepath.Ext(relPath) != ""` (e.g., `.js`, `.css`, `.json`, `.png`, `.map`, `.svg`), Toron treats the request as a physical static asset.
   - If that physical asset does not exist on disk, Toron immediately invokes `r.NotFound(req, res)`, returning HTTP 404 Not Found.
   - The fallback document is **never served** for missing asset requests with file extensions.

2. **Strict Content-Type & Charset Enforcement**:
   - For valid fallback serving, Toron explicitly sets `Content-Type: text/html; charset=utf-8` on line 351 of `pkg/router/router.go`.
   - Explicit declaration of `charset=utf-8` prevents UTF-7 XSS and MIME sniffing attacks.

3. **Verification**:
   - Verified by `TestRouter_SPA_AssetProtection404` in [`pkg/router/router_test.go`](file:///Users/sneha/Developer/toron/pkg/router/router_test.go#L430-L457), ensuring that missing `.js`, `.css`, `.png`, and `.json` requests return HTTP 404 and never return HTML fallback content.

### 3. Information Disclosure & Error Sanitization (CWE-200 / CWE-209 / CWE-548)

#### Threat Vector
Web servers commonly expose internal architecture details through:
- Automatic directory indexing (listing directory contents when `index.html` is absent).
- Detailed operating system error messages (e.g., leaking root filesystem paths or permission codes upon disk I/O errors).
- Distinct error signatures revealing whether a file exists but is unreadable versus non-existent.

#### Implementation & Defensive Analysis

1. **Zero Directory Listing Exposure (CWE-548)**:
   - In `pkg/router/router.go` lines 372–379:
     ```go
     if fileInfo.IsDir() {
         targetPath = filepath.Join(targetPath, "index.html")
         fileInfo, err = os.Stat(targetPath)
         if err != nil || fileInfo.IsDir() {
             serveFallback()
             return
         }
     }
     ```
   - Directory listings are completely prohibited in Toron. If a directory does not contain an `index.html`, Toron never generates a directory listing; instead, it delegates directly to `serveFallback()`.
   - If SPA fallback is active and the route has no file extension, it safely serves the root SPA entry document (`index.html`). If not, it invokes `r.NotFound(req, res)`.

2. **Opaque Error Responses (CWE-209)**:
   - If `os.Stat(targetPath)` fails with any error other than `os.IsNotExist(err)` (e.g. permission denied `EACCES`), Toron returns a generic `res.SetStatus(http.StatusInternalServerError)` without echoing the OS error string or internal filepath.
   - Path traversal and symlink violations return standardized JSON messages (`{"error":"403 Forbidden: Path Traversal Disallowed"}` and `{"error":"403 Forbidden: Symlink Path Traversal Disallowed"}`) that do not include server directories, internal paths, or user names.
   - If the fallback file itself is unreadable or missing, Toron cleanly invokes `r.NotFound(req, res)`.

### 4. Denial of Service (DoS) & Resource Boundedness (CWE-400 / CWE-770)

#### Threat Vector
Uncontrolled disk operations, large unbuffered file reads, or unbounded memory allocations on client-controlled paths can exhaust server memory, thread pools, or disk I/O channels.

#### Implementation & Defensive Analysis

1. **HTTP Method Restriction (CWE-650)**:
   - In `pkg/router/router.go` lines 272–275:
     ```go
     if req.Method != "GET" && req.Method != "HEAD" {
         r.MethodNotAllowed(req, res)
         return
     }
     ```
   - State-changing or body-carrying methods (`POST`, `PUT`, `DELETE`, `PATCH`) are rejected at the very entrance of the static handler with `405 Method Not Allowed`, preventing request body buffering or abuse.

2. **Zero Body Transfer on HEAD Requests**:
   - In `pkg/router/router.go` lines 352–354 and lines 413–415:
     ```go
     if req.Method != "HEAD" {
         _, _ = res.Write(fbData)
     }
     ```
   - `HEAD` requests execute metadata lookup and status headers but omit response body generation, saving network socket buffers and avoiding unnecessary transmission.

3. **Bounded Filesystem Lookups**:
   - Fallback execution is reactive: it triggers only when `os.IsNotExist(err)` is returned from the initial `os.Stat(targetPath)`.
   - Physical hits experience zero overhead.
   - The fallback logic executes at most one single `os.Stat` and one `os.ReadFile` for the root fallback document, avoiding recursion, unbounded directory loops, or regex backtracking.

4. **Integration with Rate Limiting & WAF**:
   - As implemented in `pkg/router/router.go` lines 189–213, static routes are fully wrapped by Toron's pre-routing Rate Limiter middleware (`opts.RateLimit`) and WAF middleware (`opts.WAF`).
   - Volumetric request flooding or path probing targeting static/fallback routes can be rate-limited and filtered by IP/CIDR or OWASP rules before reaching disk I/O routines.

## Positive Observations & Security Controls Verified

1. **Robust Defense-in-Depth against Directory Traversal**: Employs both lexical path checking (`filepath.Clean`, `filepath.Rel`) and real filesystem symlink validation (`filepath.EvalSymlinks`) for both requested routes and fallback filenames.
2. **Strict Non-Masking of Missing Assets**: Missing `.js`, `.css`, `.json`, `.png`, and other files with extensions return 404 Not Found, preventing browser syntax errors and asset masking vulnerabilities.
3. **Information Disclosure Prevention**: Directory listings are never generated, and OS error traces are never leaked to clients.
4. **Complete Backward Compatibility**: Non-SPA static routes maintain existing 404 behavior, and implicit activation (`fallback != ""`) behaves safely.
5. **Concurrency & Thread Safety**: All router configurations and handlers execute with read/write mutex synchronization, with zero race conditions identified during `go test -race ./...`.

## Rationale & Constraints

- **Rationale**: Single Page Applications require server-side support for HTML5 History routing when deep links are accessed or refreshed. Toron's implementation ensures native high-performance SPA hosting without risking asset masking or path traversal vulnerabilities.
- **Constraints**:
  - Only `GET` and `HEAD` requests are served by the static handler and its fallback; other HTTP methods receive `405 Method Not Allowed`.
  - Fallback document lookup executes only upon initial `os.IsNotExist` misses.
  - The fallback document must reside within the designated static directory root.
