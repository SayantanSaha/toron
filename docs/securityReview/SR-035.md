# SR-035 - Security Review of CORS Policies & Enterprise Security Headers Middleware

## Scope

Security assessment of CORS origin pattern validation, preflight `OPTIONS` short-circuiting, credential reflection security, and browser security header injection in [`pkg/router/cors.go`](file:///D:/Work/server/pkg/router/cors.go) and [`pkg/router/security_headers.go`](file:///D:/Work/server/pkg/router/security_headers.go).

## Findings

1. **CORS Credentials Security (No Insecure `*` with Credentials)**: `NewCORSMiddleware` strictly avoids reflecting wildcard `*` with `Access-Control-Allow-Credentials: true` (which would violate RFC 6454 and browser security models). When credentials are enabled, only matched valid origins are reflected.
2. **Vary: Origin Integrity**: Correctly adds `Vary: Origin` whenever CORS headers are attached, preventing intermediate proxy cache poisoning.
3. **OWASP Security Headers**: Injects baseline protection against MIME confusion attacks (`X-Content-Type-Options: nosniff`), clickjacking (`X-Frame-Options: DENY`), insecure protocol downgrades (`Strict-Transport-Security`), and referrer leakage.
4. **Preflight Interception**: Disallowed preflight requests are rejected with `403 Forbidden` and do not reach downstream upstreams.

## Conclusion

Approved. Hardens edge security across all public and internal web routes.
