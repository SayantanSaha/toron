# REQ-114 - High-Concurrency Saturation Stress Testing with Background Traffic (BMK-04)

## 1. Description

Academic peer reviews of Paper 2 (`AER-002` lines 288–291, `MSR-002` lines 239–245 & 298–301, and `ReviewTaskSummary.md` item `BMK-04`) identified a critical empirical evaluation gap regarding wire-rate performance and tail latency under saturation:

1. **The Sequential Single-Socket Evaluation Limitation**:
   In prior security benchmarking (`benchmarks/fuzzer/diff_fuzzer.go`), invariant violation probes were transmitted sequentially over isolated single sockets one at a time. Reviewers criticized this methodology as failing to model production edge conditions:
   > *"The evaluation relies on sequential raw-socket probes issued one-at-a-time via `diff_fuzzer.go`. This harness does not generate sustained load, cannot induce socket queueing, and cannot measure latency distributions under concurrency. To measure true wire-rate overhead, the authors should have used their wrk2 harness (`benchmarks/wrk2/loadgen.go`) transmitting adversarial payloads amidst high-concurrency background traffic."* (`MSR-002`, lines 239–245)

2. **Absence of Proof for Zero-Starvation Under Saturation**:
   When an edge gateway is bombarded with malformed, malicious, or desynchronization attack vectors, an architectural concern is whether active defense mechanisms (deep header inspection, WAF regexes, transport socket termination) consume excessive CPU or lock event loops, starving concurrent legitimate requests and inflating tail latencies ($p95, p99, p99.9$). The manuscript reported mean rejection latencies in Table 3 but lacked tail latency distributions under concurrent load.

3. **Mandatory Remediation (`BMK-04`)**:
   Toron must establish a high-concurrency saturation benchmarking harness by extending `benchmarks/wrk2/loadgen.go` (and providing a dedicated stress harness):
   - Sustain 5,000+ requests per second (RPS) of background legitimate traffic across dozens of concurrent connections.
   - Concurrently interleave malformed protocol attack vectors (conflicting `Content-Length`/`Transfer-Encoding`, whitespace-obfuscated headers, invalid token characters, CRLF injection, oversized headers, path traversal) at a configurable injection ratio (e.g. 10% adversarial traffic).
   - Decouple telemetry into two independent streams:
     1. **Legitimate/Benign Traffic Stream**: Verifies zero-starvation, throughput (MB/s), and tail latency percentiles ($p50, p75, p90, p95, p99, p99.9, \text{Max}$).
     2. **Adversarial Attack Stream**: Verifies 100% active defense enforcement ($400\text{ Bad Request}$ or $403\text{ Forbidden}$) and sub-millisecond fast-fail rejection latency percentiles.
   - Output publication-grade evaluation artifacts (`benchmarks/results/saturation_stress_report.json` and `benchmarks/results/saturation_stress_report.md`).

## 2. Acceptance Criteria

### AC-1: High-Concurrency Background Load Generation (5,000+ RPS)
- In `benchmarks/wrk2/loadgen.go`:
  1. Support sustained constant-rate load generation up to and exceeding 10,000 RPS (calibrated default $\ge 5,000$ RPS).
  2. Support configurable concurrency levels (`-c`, default: 50–100 persistent connections).
  3. Support configurable execution durations (`-d`, e.g. 10s, 30s, 60s).
  4. Implement coordinated-omission-free rate pacing using token bucket / ticker scheduling.

### AC-2: Concurrent Adversarial Protocol Attack Injection
- In `benchmarks/wrk2/loadgen.go`:
  1. Support a configurable attack injection ratio via flag `-attack-ratio <float>` (default: `0.10`, meaning 10% of generated traffic consists of malformed protocol probes, with 90% benign background traffic).
  2. Maintain a rich catalog of live attack vectors derived from literature and peer reviews:
     - `ADV-01`: Conflicting `Content-Length` and `Transfer-Encoding: chunked` (CWE-444 / CL.TE).
     - `ADV-02`: Obfuscated whitespace preceding colon in `Transfer-Encoding : chunked` (RFC 7230 §3.2.4).
     - `ADV-03`: Invalid token character in header field name (`X-Header@Bad: val`, RFC 7230 §3.2).
     - `ADV-04`: CRLF header injection attempting response splitting (`X-Inject: test\r\nInjected: evil`).
     - `ADV-05`: Multiple conflicting `Content-Length` headers (`Content-Length: 10` and `Content-Length: 20`).
     - `ADV-06`: Path traversal probe attempting canary escape (`GET /../../canary_traversal.txt`).
     - `ADV-07`: Oversized request header block exceeding 8 KB limit (CWE-400 resource exhaustion).
     - `ADV-08`: Null byte injection in URI path (`GET /health%00evil`).
  3. Workers randomly sample from the attack catalog when assigned an adversarial slot.

### AC-3: Decoupled Dual-Stream Telemetry & Tail Latency Profiling
- The load generator must partition metrics into two distinct streams:
  1. **Benign Traffic Stream**:
     - Total requests, successful requests ($200\text{ OK}$), failed/error requests.
     - Actual achieved RPS and throughput (MB/s).
     - High-precision latency distribution ($p50, p75, p90, p95, p99, p99.9, \text{Max}$) in milliseconds.
     - **Zero-Starvation Invariant**: $p99$ tail latency of benign traffic under 5,000+ RPS with 10% adversarial injection must not exceed 50.0 ms (target $< 10.0$ ms over local loopback).
  2. **Adversarial Attack Stream**:
     - Total attack probes transmitted.
     - Invariant rejection count ($400\text{ Bad Request}$, $403\text{ Forbidden}$, or $413\text{ Payload Too Large}$).
     - Bypass / Leakage count: MUST be strictly `0` (100.0% invariant enforcement rate).
     - Adversarial fast-fail rejection latency distribution ($p50, p90, p99, \text{Max}$) in milliseconds.

### AC-4: Automated Execution Scripting
- Provide `benchmarks/wrk2/run_saturation_stress.sh`:
  1. Compiles or invokes `loadgen.go`.
  2. Supports target flags (`-u`, `-c`, `-d`, `-r`, `-a` for attack ratio).
  3. Seamlessly launches and manages background Toron edge gateway if `-auto-start` is passed.
  4. Automatically outputs structured reports to `benchmarks/results/`.

### AC-5: Publication-Grade Structured Artifacts
- In `benchmarks/results/`:
  1. **`saturation_stress_report.json`**: Machine-readable telemetry containing decoupled benign and adversarial metrics, percentiles, status code breakdowns, and starvation verification verdicts.
  2. **`saturation_stress_report.md`**: Publication-grade GitHub-flavored markdown report featuring:
     - Executive summary answering `AER-002` lines 288–291 and `MSR-002` lines 239–245.
     - Side-by-side performance table (Benign vs. Adversarial Streams).
     - Comprehensive latency distribution table ($p50, p75, p90, p95, p99, p99.9, \text{Max}$).
     - Invariant rejection verification table across all 8 attack vectors.

### AC-6: Zero-Dependency & Race-Clean Invariant
- The enhanced load generator and stress harness must strictly use the Go standard library (`net`, `net/http`, `context`, `sync`, `sync/atomic`, `time`, `encoding/json`, `encoding/csv`, `math/rand`, `flag`, `fmt`).
- 100% clean under `go test -race -count=1 ./benchmarks/wrk2/...`.

---

## 3. Rationale

Evaluating invariant enforcement purely under single-shot, sequential fuzzer runs leaves Toron vulnerable to reviewer skepticism regarding wire-rate throughput and tail latency under saturation. By interleaving active protocol attacks into 5,000+ RPS background traffic and measuring high-order tail latencies ($p95, p99, p99.9$) alongside invariant rejection rates, Toron empirically proves that its fail-fast architecture, worker pool dispatching (`REQ-111`), and zero-allocation parser guards (`REQ-109`, `REQ-110`) operate without starving legitimate traffic or inducing unbounded latency amplification.

---

## 4. Constraints

- Pure Go standard library (zero external dependencies).
- Zero data races under `go test -race`.
- Coordinated-omission-free measurement loop.
- Decoupled metric tracking to avoid conflating 400 rejection latencies with legitimate 200 OK service latencies.
