# ADR-022 - HTTP/3 Protocol Engine & QUIC Transport Architecture

## Context

HTTP/3 relies on QUIC (UDP) for multiplexed, low-latency transport without TCP head-of-line blocking. Modern browsers discover HTTP/3 endpoints via `Alt-Svc` headers returned over HTTP/1.1 or HTTP/2 TLS connections.

## Decision

1. **Configuration Integration**:
   - Add `HTTP3Config` struct to `pkg/config/config.go` under `ServerConfig.HTTP3`.
   - Default `http3.enabled: true` and `http3.port: 8443` (or mirror server HTTPS port).

2. **HTTP/3 QUIC Engine (`pkg/server/server.go`)**:
   - Integrate `github.com/quic-go/quic-go/http3` server engine.
   - Bind `http3.Server` to the configured UDP address using TLS certificate & key credentials generated by `auto_dev_cert` or configured TLS files.

3. **Protocol Upgrade Advertising (`Alt-Svc`)**:
   - On HTTPS TLS connection responses, automatically set `Alt-Svc: h3=":port"` header (e.g. `Alt-Svc: h3=":8443"; ma=2592000`).
   - Enables compliant HTTP clients to upgrade subsequent connections seamlessly to HTTP/3 QUIC.

4. **Handler Pipeline Uniformity**:
   - Map `http3.Server.Handler` directly to Toron's core `router.Router` so static routes, upstream proxies, and management APIs serve HTTP/3 requests identically to HTTP/1.1 and HTTP/2.

## Consequences

- **Positive**: Enables zero-RTT HTTP/3 connections over QUIC, providing top-tier protocol capabilities.
- **Interoperability**: Dual TCP (HTTP/1.1, HTTP/2) and UDP (HTTP/3 QUIC) listeners ensure 100% backward compatibility for all clients.
