# REQ-019 - Decoupled Dual-File YAML Configuration (config.yaml and routes.yaml)

## Description

The Toron server configuration shall be split into two distinct YAML configuration files:
1. `config.yaml`: Contains server runtime limits, static asset hosting configuration, and logging settings.
2. `routes.yaml`: Contains reverse proxy routing rules, header matching conditions, load balancing algorithms, target upstreams, and circuit breaker parameters.

The configuration loader (`pkg/config`) shall support loading both files independently or via CLI flags (`-config` and `-routes`), defaulting to `config.yaml` and `routes.yaml` in the working directory when available.

## Acceptance Criteria

- `config.yaml` updated to retain `server`, `static`, and `logging` configuration sections.
- `routes.yaml` created containing all reverse proxy route definitions (`proxy: enabled: true`, `routes: [...]`).
- `pkg/config` updated with `LoadFromFiles(configPath, routesPath string)` helper.
- CLI flags `-config` (`-c`) and `-routes` (`-r`) supported in `cmd/toron/main.go`.
- All Go unit tests pass cleanly.

## Rationale

Separates infrastructure runtime concerns from routing rules, enabling independent deployment and updating of proxy routes without mutating server infrastructure configuration.
