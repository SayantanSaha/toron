# ADR-012 - Server-Side Internal Management API and Proxy Test Architecture

## Context

To enhance security, maintainability, and network isolation, the frontend dashboard must not attempt direct cross-origin browser connections to backend upstream ports (`9001-9010`). Instead, Toron should expose centralized `/internal/api/` endpoints.

## Decision

1. **Internal API Namespace**: Reserve path prefix `/internal/api/` for Toron control plane endpoints.
2. **Backend Health Probing**:
   - `GET /internal/api/upstreams/health` executes concurrent HTTP GET probes from Go routines with 2s timeouts against configured target nodes (`9001-9010`).
   - Evaluates HTTP response status code ($200 \rightarrow \text{CLOSED}$, $\ge 500 \rightarrow \text{OPEN (500 ERR)}$, timeout/error $\rightarrow \text{UNREACHABLE}$).
3. **Internal Proxy Testing**:
   - `POST /internal/api/proxy-test` accepts JSON request payload (`path`, `method`, `headers`), dispatches internal request via Toron's HTTP client/router, and returns structured execution metrics (`status_code`, `latency_ms`, `headers`, `body`).
4. **Frontend Integration**:
   - `public/app.js` updates fetch endpoints to `/internal/api/upstreams/health` and `/internal/api/proxy-test`.

## Consequences

- **Positive**: Eliminates browser CORS dependency, protects internal network topology, and standardizes control plane observability.
