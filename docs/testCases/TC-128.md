# TC-128 - Test Specification for Streaming Response Middleware Exemptions and RFC 7234 Origin Cache-Control Enforcement

## 1. Test Suite Overview & Architectural Objectives

### 1.1 Executive Summary & Problem Context
During comprehensive end-to-end architectural audits and streaming performance benchmarks of Toron's reverse proxy and middleware pipeline ([`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md), [`TASK-151`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md), [`ADR-128`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md)), three severe root causes were identified that corrupted real-time streaming connections (specifically Server-Sent Events / SSE `text/event-stream`) and dynamic HTTP endpoints:

1. **Root Cause 2: In-Memory Cache Stores Origin `no-cache` and Freezes SSE Feeds (RFC 7234 §5.2.2.2 Violation)**:
   - In [`pkg/router/cache.go:250-254`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L250-L254), `CacheMiddleware` evaluated response cacheability directives:
     ```go
     resCC := ParseCacheControl(res.Header.Get("Cache-Control"))
     if resCC.NoStore || resCC.Private {
         return
     }
     ```
   - While `no-store` and `private` were inspected, **`resCC.NoCache` was completely ignored**.
   - Under **RFC 7234 §5.2.2.2**:
     > *"The `no-cache` response directive indicates that the response MUST NOT be used to satisfy a subsequent request without successful validation on the origin server."*
   - Because Toron's shared response cache does not implement conditional origin revalidation (i.e. issuing conditional `GET` requests with `If-None-Match` or `If-Modified-Since` upon cache hit), storing responses marked `no-cache` directly violates RFC 7234.
   - When an upstream origin emits a dynamic response or Server-Sent Events stream with `Cache-Control: no-cache` without specifying `max-age`, Toron fell back to `ttl := cfg.DefaultTTL` (default: 60 seconds). Toron cloned the body snapshot into `ResponseCache`, effectively freezing the live stream.
   - Any subsequent client connecting to the streaming endpoint received a static, dead snapshot with `X-Cache: HIT` and `Age: N`. The client never received live updates, resulting in severe real-time feed corruption and Web Cache Deception ([CWE-524](https://cwe.mitre.org/data/definitions/524.html)).
   - Furthermore, `CacheMiddleware` did not systematically guard against `Content-Type: text/event-stream` or `X-Accel-Buffering: no`, allowing streaming responses to be captured as static cache entries.

2. **Root Cause 3: Transparent Compression Traps `text/event-stream` via Wildcard `text/*`**:
   - In [`pkg/router/compression.go:42`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go#L42), `DefaultCompressionConfig.Types` includes `"text/"` to compress HTML, plain text, and CSS assets.
   - In `isMIMECompressible(contentType, allowedTypes)`, `strings.HasPrefix(ct, "text/")` matched `text/event-stream`.
   - When a client sent standard browser headers (`Accept-Encoding: gzip, deflate, br, zstd`), `CompressionMiddleware` intercepted the live stream, buffered the streaming payload in RAM until stream completion, compressed it into a single block, and updated `Content-Length` and `Content-Encoding`.
   - This completely destroyed streaming delivery: clients experienced event starvation and received **zero events** until the stream terminated or disconnected.
   - Additionally, upstream responses signaling `X-Accel-Buffering: no` (the standard reverse proxy directive requesting unbuffered streaming) were ignored and subjected to intermediate buffering and compression.

3. **Proxy Fast-Path Disqualification (`canStream` Disqualification)**:
   - In [`pkg/proxy/proxy.go:1105`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1105), `ReverseProxy` evaluated streaming eligibility as:
     ```go
     canStream := p.streamResponse && (!p.routeHasCompression && !p.routeHasCache)
     ```
   - If a route configured compression or caching globally (e.g. for a mixed API prefix `/api/v1/*`), `canStream` evaluated to `false` for **all** responses on that route. Consequently, SSE responses were forced into the buffered fallback path (`io.CopyBuffer(res.Body, outResp.Body)`), blocking until upstream stream termination and risking memory exhaustion ([CWE-400](https://cwe.mitre.org/data/definitions/400.html)).

### 1.2 The Unified Streaming Middleware Exemption Architecture
To eliminate stream freezing, event starvation, and memory buffering while maintaining full backward compatibility with standard cached assets and compressed REST responses, [`ADR-128`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md) and [`TASK-151`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md) establish a four-part architectural resolution:

1. **RFC 7234 §5.2.2.2 Origin Cache-Control Enforcement (`pkg/router/cache.go`)**:
   - Strictly exclude any response from cache admission if `resCC.NoCache == true`, `resCC.NoStore == true`, or `resCC.Private == true`.
   - In the absence of conditional origin revalidation, `no-cache` strictly overrides `max-age`.
   - All bypassed responses emit `X-Cache: MISS` and strictly omit the `Age` header.
2. **Streaming Response Cache Exemption (`pkg/router/cache.go`)**:
   - Systematically exclude any response with `Content-Type: text/event-stream` (case-insensitive, with or without parameters) or `X-Accel-Buffering: no` (case-insensitive) from cache admission.
   - Zero byte cloning and zero entries stored in `ResponseCache`.
3. **Streaming Response Compression Exemption (`pkg/router/compression.go`)**:
   - Implement an early pre-compression inspection guard checking for `text/event-stream` and `X-Accel-Buffering: no`.
   - Bypass compression writer checkout from pools (`gzipPool`, `zstdPool`, `brotliPool`, `deflatePool`).
   - Leave `Content-Encoding` unmodified (empty for uncompressed origin feeds), emitting raw chunks immediately.
4. **Content-Aware Reverse Proxy Fast-Path Activation (`pkg/proxy/proxy.go`)**:
   - Refine `canStream` evaluation to activate the direct socket streaming fast-path (`res.StreamBody = outResp.Body`) whenever `isStreamingMIME || isUnbuffered` evaluates to `true`, even if compression or caching are enabled on the route.

### 2.3 Mathematical Model, Physical Invariants & Latency Physics

#### 1. Compression Event Starvation Latency Equation
Let $T_{\text{emit}}(k)$ denote the timestamp when the origin emits streaming event chunk $k \in \{1, 2, \dots, N\}$.
Let $T_{\text{close}}$ denote the timestamp when the upstream stream terminates or the client disconnects.
Let $T_{\text{recv}}(k)$ denote the timestamp when the client receives event chunk $k$.

Under the legacy implementation where wildcard `"text/"` trapped `text/event-stream`:
$$\forall k < N: \quad T_{\text{recv}}(k) \ge T_{\text{close}}$$
The buffering starvation delay $\Delta T_{\text{starvation}}(k)$ experienced by event $k$ was:
$$\Delta T_{\text{starvation}}(k) = T_{\text{close}} - T_{\text{emit}}(k)$$
For open-ended streams where $T_{\text{close}} \to \infty$, $\Delta T_{\text{starvation}} \to \infty$, causing complete communication failure.

Under `ADR-128` compression exemption:
$$\forall k: \quad T_{\text{recv}}(k) = T_{\text{emit}}(k) + \tau_{\text{transit}} \quad \text{where } \tau_{\text{transit}} < 1.0\text{ms}$$
Event delivery occurs in real time with zero intermediate buffering delay.

#### 2. RFC 7234 §5.2.2.2 Cache Admission Boolean Formula
Let $C_{\text{admit}}$ denote the boolean condition under which an upstream response is admitted to `ResponseCache`.
Let $S$ denote the HTTP status code ($S \in \{200, 301, 404\}$).
Let $L$ denote the response body length in bytes.
Let $M_{\text{max}}$ denote `cfg.MaxPayloadSize`.
Let $\text{CC}$ denote the parsed `CacheControl` directives.
Let $\text{CT}$ denote the lowercased `Content-Type` header string.
Let $\text{XAB}$ denote the `X-Accel-Buffering` header string.

The strict RFC 7234 §5.2.2.2 compliant admission predicate is:
$$C_{\text{admit}} \iff (S \in \{200, 301, 404\}) \land (0 < L \le M_{\text{max}}) \land \neg \text{CC.NoStore} \land \neg \text{CC.NoCache} \land \neg \text{CC.Private} \land \neg \text{HasPrefix}(\text{CT}, \text{"text/event-stream"}) \land \neg \text{EqualFold}(\text{XAB}, \text{"no"}) \land (\text{res.StreamBody} == \text{nil}) \land (\text{res.UpgradedConn} == \text{nil})$$

If $\text{CC.NoCache} \equiv \text{True}$, then $C_{\text{admit}} \equiv \text{False}$, regardless of whether $\text{CC.MaxAge} > 0$. In the absence of conditional revalidation, `no-cache` strictly overrides `max-age`.

#### 3. Reverse Proxy Streaming Fast-Path Predicate
The streaming fast-path activation condition `canStream` in [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go) is defined as:
$$\text{canStream} = p.\text{streamResponse} \land \Big( (\neg p.\text{routeHasCompression} \land \neg p.\text{routeHasCache}) \lor \text{isStreamingMIME} \lor \text{isUnbuffered} \Big)$$
where:
$$\text{isStreamingMIME} \iff \text{strings.HasPrefix}(\text{strings.ToLower}(\text{outResp.Header.Get}(\text{"Content-Type"})), \text{"text/event-stream"})$$
$$\text{isUnbuffered} \iff \text{strings.EqualFold}(\text{outResp.Header.Get}(\text{"X-Accel-Buffering"}), \text{"no"})$$

### Test Suite 1: Cache Middleware Unit Verification (`pkg/router/cache_test.go`)

#### TC-128.1: RFC 7234 §5.2.2.2 Origin Cache-Control: no-cache Bypass
- **Identifier**: `TC-128.1`
- **Target Subsystem**: In-Memory Response Cache ([`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go))
- **Test Implementation**: `TestCache_RFC7234_OriginNoCache_Bypass` in [`pkg/router/cache_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache_test.go)
- **Objective**: Verify that when an upstream origin returns `Cache-Control: no-cache`, `CacheMiddleware` strictly adheres to RFC 7234 §5.2.2.2 by refusing to store the response in `ResponseCache`, emitting `X-Cache: MISS`, omitting the `Age` header, keeping the cache registry size at 0, and invoking the downstream handler on every repeated request.
- **Traceability**: [`REQ-128 §2.1`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md#L93-L112), [`TASK-151 WP-1.1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md#L121-L133), [`TASK-151 WP-4.1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md#L242-L246), [`ADR-128 §2.1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md#L176-L197).
- **Setup & Preconditions**:
  - Toron router initialized with `NewCacheMiddleware(cfg)` where `cfg.DefaultTTL = 60 * time.Second`.
  - Atomic handler counter `handlerHits int64`.
  - Handler endpoint `GET /api/dynamic` returns `200 OK`, `Content-Type: application/json`, `Cache-Control: no-cache`, body `{"timestamp": 123456789}`.
- **Action**:
  1. Construct initial request `req1`: `GET /api/dynamic HTTP/1.1`.
  2. Dispatch `r.ServeHTTP(req1, res1)`.

  1. Record baseline goroutine count via `runtime.NumGoroutine()`.
  2. Launch 50 goroutines requesting `/events` (streaming).
  3. Concurrently launch 50 goroutines requesting `/api/data` (cacheable & compressible).

## 5. Invariants, Standards Compliance & Security Audit

### 5.1 RFC 7234 §5.2.2.2 Compliance
Responses containing origin `Cache-Control: no-cache` are strictly excluded from proxy cache storage. All bypassed requests emit `X-Cache: MISS` and omit the `Age` header.

### 5.2 RFC 7230 §6.1 Hop-by-Hop Cleanliness
Hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Transfer-Encoding`, `Upgrade`) are stripped prior to stream relay.

### 5.3 Security & Vulnerability Mitigations
1. **Mitigation of Shared Cache Information Exposure ([CWE-524](https://cwe.mitre.org/data/definitions/524.html))**: Enforcing origin `no-cache` prevents private, real-time user updates (notifications, LLM tokens, trading ticks) from being served to secondary clients.
2. **Web Cache Deception Mitigation**: Dynamic API responses are immune to cache admission tricks.
3. **Denial of Service via Memory Exhaustion ([CWE-400](https://cwe.mitre.org/data/definitions/400.html))**: Infinite SSE streams bypass `res.Body` buffering, preventing process out-of-memory crashes.

### 5.4 Zero Third-Party Dependencies
Implementation uses exclusively Go standard library packages (`strings`, `net/http`, `sync`, `time`, `io`).
