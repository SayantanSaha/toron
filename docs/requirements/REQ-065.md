# REQ-065 - Upstream TLS Certificate Verification and Trust Management in WebSocket Proxy

## Description

The Toron reverse proxy gateway shall enforce rigorous TLS certificate validation on all outbound encrypted WebSocket connections (`wss://` and `https://`) to upstream backend targets.

The dialer shall verify server certificates against the host system's root CA trust pool or a user-configured Certificate Authority bundle, eliminating hardcoded `InsecureSkipVerify: true` settings and preventing Man-in-the-Middle (MitM) attacks.

## Acceptance Criteria

### 1. Mandatory Upstream TLS Verification by Default
- The WebSocket proxy dialer in `pkg/proxy/proxy.go` shall enforce strict TLS certificate validation (`InsecureSkipVerify: false`) by default for all upstream connections over TLS.
- Connections presenting invalid, expired, or hostname-mismatched certificates shall fail with an error and return HTTP `502 Bad Gateway` to the client.

### 2. Custom CA & Trust Store Configuration
- Toron shall allow route-level or global proxy configuration to specify a custom CA certificate file (`ca_file`) for verifying upstream backend certificates signed by private or enterprise PKI authorities.

### 3. Explicit Insecure Verification Override
- Disabling certificate verification (`insecure_skip_verify: true`) shall only be permitted if explicitly enabled by the user in `config.yaml` or `routes.yaml` for specific development environments.
- When an insecure override is active, Toron shall log a prominent warning at server startup.

### 4. SNI & Hostname Propagation
- The TLS dialer shall supply the correct Server Name Indication (SNI) corresponding to the upstream target hostname during the TLS handshake.

## Rationale

Hardcoding `InsecureSkipVerify: true` allows any attacker positioned between the reverse proxy and upstream services (e.g. on shared cloud VPC networks) to intercept and tamper with WebSocket data streams without detection.

## Constraints

- Compliance with standard Go `crypto/tls` verification mechanics.
- Zero disruption to existing HTTP proxying configurations.

## Open Questions

- Should Toron support mutual TLS (mTLS) client certificates when connecting to upstream WebSocket backends?
