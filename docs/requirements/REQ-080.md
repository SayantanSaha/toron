# REQ-080 - Case-Insensitive Percent-Encoding Hardening in WAF Path Traversal Rule

## Description

The Toron Web Application Firewall default rule `TRAVERSAL-001` (`pkg/waf/rules.go`) shall enforce case-insensitive matching across all percent-encoded path traversal sequences, preventing evasion via uppercase hex digits in headers, queries, or body payloads.

## Acceptance Criteria

### 1. Case-Insensitive Traversal Pattern Matching
- The regex pattern for `TRAVERSAL-001` shall include the `(?i)` flag.
- The pattern shall match all casing permutations of dot-dot-slash:
  - Standard relative sequences: `../` and `..\`
  - Lowercase percent-encoding: `%2e%2e/` and `%2e%2e%2f`
  - Uppercase percent-encoding: `%2E%2E/`, `%2E%2e/`, `%2e%2E%2F`
  - Encoded backslash variations: `%2e%2e\\`, `%2e%2e%5c`, `%2e%2e%5C`

### 2. Header and Body Detection
- WAF inspection across raw request headers and body payloads shall successfully trigger on uppercase encoded traversal payloads.

### 3. Verification
- Transmitting `%2E%2E/etc/passwd` in a request header or JSON body shall trigger `TRAVERSAL-001` and increment the anomaly score.

## Rationale

Without `(?i)`, attackers easily evade the WAF filter by submitting uppercase hex percent-encoding (`%2E%2E/`), which passes through to vulnerable downstream backend services.

## Constraints

- Pure Go standard library `regexp`.
- No regression in existing WAF rule performance.
