# REQ-040 - Configurable CORS Policies and Enterprise Security Headers Middleware

## Description

The Toron web server and reverse proxy shall support **Cross-Origin Resource Sharing (CORS)** and **Enterprise HTTP Security Headers** middleware to protect applications from browser-based vulnerabilities (XSS, Clickjacking, MIME-sniffing, cross-origin data leakage) and enable seamless cross-origin API interactions.

The subsystem shall provide:
1. **Configurable CORS Policies**:
   - `allow_origins`: List of allowed origin domains (supports `*`, exact domain `https://example.com`, and wildcards `https://*.domain.com`).
   - `allow_methods`: Allowed HTTP methods (`GET`, `POST`, `PUT`, `DELETE`, `OPTIONS`, `PATCH`, `HEAD`).
   - `allow_headers`: Allowed request headers (`Content-Type`, `Authorization`, `X-Requested-With`, etc.).
   - `expose_headers`: Allowed response headers exposed to browser scripts (`X-Cache`, `Content-Length`, etc.).
   - `allow_credentials`: Boolean flag controlling `Access-Control-Allow-Credentials: true`.
   - `max_age`: Preflight cache duration in seconds (`Access-Control-Max-Age`).
   - **Automatic Preflight Resolution**: Intercepts `OPTIONS` requests containing `Access-Control-Request-Method`, validating origin and short-circuiting with `204 No Content` and CORS headers without dispatching to backend upstreams.
2. **Enterprise Security Headers**:
   - `Strict-Transport-Security` (HSTS): Enforces HTTPS connections (e.g. `max-age=31536000; includeSubDomains; preload`).
   - `X-Content-Type-Options`: Prevents MIME-type sniffing (`nosniff`).
   - `X-Frame-Options`: Mitigates clickjacking attacks (`DENY`, `SAMEORIGIN`).
   - `Referrer-Policy`: Controls referrer leakage (`strict-origin-when-cross-origin`, `no-referrer`, etc.).
   - `Content-Security-Policy` (CSP): Restricts resource loading vectors.
   - `Permissions-Policy`: Restricts browser hardware features (camera, microphone, geolocation).
3. **Global and Route-Level Overrides**:
   - Supports global definition in `config.yaml` (`server.cors`, `server.security_headers`) and granular route-level overrides in `routes.yaml`.

## Acceptance Criteria

- Preflight `OPTIONS` requests from valid origins receive `204 No Content` with appropriate `Access-Control-Allow-*` headers.
- Preflight requests from unauthorized origins do not receive CORS allow headers.
- Actual cross-origin requests receive `Access-Control-Allow-Origin` and `Vary: Origin`.
- Outgoing responses include configured security headers (`HSTS`, `nosniff`, `DENY`, `CSP`, `Referrer-Policy`).
- All Go unit tests pass cleanly (`go test ./...`).
