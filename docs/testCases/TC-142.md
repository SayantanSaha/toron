# TC-142 - Verification Test Cases for Dashboard Security, Multi-Scheme Authentication & Access Controls

## 1. Overview & Objectives

Verify that the defense-in-depth authentication, credential management, and access controls designed under [`REQ-142`](../requirements/REQ-142.md), [`TASK-165`](../tasks/TASK-165.md), and [`ADR-142`](../architecture/ADR-142.md) satisfy all security, functional, and operational requirements. Ensure the gateway management APIs (`/internal/api/*`) strictly enforce authentication, that the dashboard client handles HTTP 401 challenges cleanly with an interactive modal, and that credentials are securely scoped without leaks.

## 3. Detailed Verification Procedures

### TC-142-01 to TC-142-05: Backend API Security Verification
1. Configure `InternalAPIConfig` with `AdminAuthEnabled: true`, `AdminToken: "test-token"`, and `AdminSubnets: ["127.0.0.1/32"]`.
2. Send request to `GET /internal/api/status` without headers: verify HTTP 401 and `WWW-Authenticate: Bearer realm="Toron Management", Basic realm="Toron Management"`.
3. Send request with `X-Toron-Admin-Key: test-token`: verify HTTP 200.
4. Send request with `Authorization: Bearer test-token`: verify HTTP 200.
5. Send request with `Authorization: Basic <base64(admin:pass)>`: verify HTTP 200.
6. Simulate request from remote IP `192.168.1.100`: verify HTTP 403 Forbidden.

### TC-142-06 & TC-142-07: Frontend 401 Interception & Credential Injection
1. In simulated DOM test runner, mock `fetch()` to return HTTP 401 for `/internal/api/status`.
2. Verify that `fetchBackendData()` invokes the registered 401 challenge callback.
3. Call `setAuthToken('token-123')`.
4. Execute `authenticatedFetch('/internal/api/status')`: verify that request headers contain `X-Toron-Admin-Key: token-123` and `Authorization: Bearer token-123`.

### TC-142-08: Session Storage Hygiene & Lockout
1. Verify `setAuthToken()` writes to `sessionStorage` and does NOT write to `localStorage`.
2. Call `clearAuth()`: verify `sessionStorage` token is removed, auth state resets to unauthenticated, and polling pauses.

### TC-142-10: Strictly Relative Links Invariant
Scan `docs/requirements/REQ-142.md`, `docs/tasks/TASK-165.md`, `docs/architecture/ADR-142.md`, `docs/testCases/TC-142.md`, and verify zero absolute paths.
