# REQ-116 - Layered Route-Aware Path Traversal Defense Architecture (CWE-22)

## 1. Description & Problem Statement

In automated protocol security evaluations documented in `benchmarks/results/differential_fuzz_report.md`, Toron's differential fuzzer reported an overall pass rate of **89.47% (17/19 tests)**, failing two critical directory traversal security tests:
- `TRAVERSAL-001`: Raw Dot-Dot Path Traversal Sequence (`GET /internal/dashboard/../../canary_traversal.txt HTTP/1.1`)
- `TRAVERSAL-002`: Uppercase Percent-Encoded Traversal (`GET /internal/dashboard/%2E%2E/%2E%2E/canary_traversal.txt HTTP/1.1`)

Both test cases returned **`404 Not Found` with an open TCP keep-alive connection (`Conn: Open`)** instead of the required active defensive security response (**`403 Forbidden` or `400 Bad Request` with `Connection: close`**).

```
| Test ID         | Attack / Invariant Vector                    | CWE    | Expected Status | Actual Status | Conn Closed | Result  |
| :---            | :---                                         | :---:  | :---:           | :---:         | :---:       | :---:   |
| `TRAVERSAL-001` | Raw Dot-Dot Path Traversal Sequence          | CWE-22 | `400/403`       | `404`         | `Open`      | ❌ FAIL |
| `TRAVERSAL-002` | Uppercase Percent-Encoded Traversal (%2E%2E) | CWE-22 | `400/403`       | `404`         | `Open`      | ❌ FAIL |
| `TRAVERSAL-003` | Double Percent-Encoded Traversal (%252e%252e)| CWE-22 | `400/403`       | `403`         | `Closed`    | ✅ PASS |
```

### 1.1 Root Cause Analysis

A thorough architectural and code trace identified two interrelated structural flaws across the routing and security inspection pipeline:

1. **Router Premature Path Canonicalization & Dead-Code Contradiction (`pkg/router/router.go:789`)**:
   - In `Router.ServeHTTP`, the router unconditionally executes `req.Path = cleanRequestPath(req.Path)` at the very beginning of request processing before route matching and before middleware execution.
   - For an ingress path like `/internal/dashboard/../../canary_traversal.txt`, `cleanRequestPath` collapses the dot-dot segments, mutating `req.Path` to `/canary_traversal.txt`.
   - When the router subsequently searches its route table:
     - No exact route exists for `/canary_traversal.txt`.
     - Prefix routes registered under `/internal/dashboard` fail to match because `/canary_traversal.txt` does not possess the prefix `/internal/dashboard/`.
   - Consequently, the router dispatches to `r.NotFound` (`404 Not Found`).
   - **The Dead-Code Contradiction**: In `Router.createStaticHandler` (`pkg/router/router.go:643-650`), Toron possesses an explicit path traversal and directory boundary escape guard designed to emit `403 Forbidden: Path Traversal Disallowed` with `Connection: close`. However, because the router collapsed the path prior to prefix dispatch, any traversal escaping outside the static mount prefix never reaches `createStaticHandler`. The security check inside the static handler is effectively rendered dead code.

2. **WAF Layer 7 Inspection Blind Spot (`pkg/waf/waf.go:313`)**:
   - In `WAFEngine.InspectToron`, the engine assigns `urlPath := req.Path`. Because `req.Path` was already stripped of its dot-dot traversal sequences by `cleanRequestPath`, the WAF inspects the sanitized string `/canary_traversal.txt`.
   - The active WAF traversal rule `TRAVERSAL-001` (`(?i)(\.\./|\.\.\\|%2e%2e/|%2e%2e%2f|%2e%2e\\|%2e%2e%5c)`) finds no match in `/canary_traversal.txt`.
   - Although the raw wire URI is preserved in `req.RequestURI` (e.g. `/internal/dashboard/../../canary_traversal.txt` or `/internal/dashboard/%2E%2E/%2E%2E/canary_traversal.txt`), `InspectToron` only consults `req.RequestURI` if `urlPath == ""`, creating an inspection bypass.
   - (Note: `TRAVERSAL-003` succeeded only because double-encoding `%252e` bypassed the initial `url.ParseRequestURI` and `cleanRequestPath`, which left `%2e%2e` in `req.Path` to be unescaped later in `inspectInternal`.)

### 1.2 The Approved Architectural Solution: Layered / Route-Aware Defense

To resolve this issue with defense-in-depth, Toron shall implement a two-layered defense architecture:
1. **Layer 7 WAF Raw Wire URI Inspection**: Inspect the uncleaned raw wire URI path from `req.RequestURI` against URL-scoped WAF threat rules, actively blocking traversal attempts with `403 Forbidden`, `Connection: close`, and structured security audit logging.
2. **Route-Aware Static Prefix Escape Guard**: In the router prefix matching and dispatch layer, detect when an ingress uncleaned request path targets a static route prefix, but canonicalizes to a path escaping that prefix boundary. Actively reject with `403 Forbidden: Path Traversal Disallowed` and `Connection: close`. This eliminates the dead-code contradiction and guarantees active security even if the WAF middleware is disabled or omitted.

## 2. Functional Requirements

### FR-1: WAF Raw Wire URI Extraction and Inspection (`pkg/waf/waf.go`)
- **Extraction**: In `WAFEngine.InspectToron(req *httpparser.Request)`, the engine shall determine the wire request path directly from `req.RequestURI` if present:
  - Strip any query string (starting from `?`) and fragment (starting from `#`) from `req.RequestURI` to isolate the raw wire path component.
  - If `req.RequestURI` is empty, fallback to `req.Path`.
- **Dual-Path Pattern Evaluation**:
  - In `WAFEngine.inspectInternal`, for all rules where `Locations & InspectURL != 0`, the engine shall evaluate rule patterns against both:
    1. The raw wire URL path (preserving `%2e%2e`, `/..`, etc.).
    2. The unescaped / normalized URL path (`url.PathUnescape(urlPath)`).
- **Active Defense Enforcement**:
  - If rule `TRAVERSAL-001` or any URL-scoped rule matches, increment anomaly score.
  - In `enforce` mode (default), when anomaly score meets or exceeds `AnomalyThreshold`, actively block the request:
    - Status code: `403 Forbidden`.
    - Response header: `Connection: close`.
    - Response header: `Content-Type: application/json`.
    - Response payload: Structured JSON (`FormatBlockedResponse`).
    - Audit log: Record `waf_block` event with rule ID, category, client IP, and URI snippet.

### FR-2: Route-Aware Static Prefix Escape Guard (`pkg/router/router.go`)
- **Prefix Boundary Validation**:
  - During request dispatching in `Router.ServeHTTP`, before delegating to `r.NotFound`, the router shall inspect all registered static prefix routes (`RouteTypeStatic`).
  - The router shall extract the incoming uncleaned path from `req.RequestURI` (stripping query string) or use the pre-canonicalized `req.Path`.
  - Also evaluate unescaped path variants (`url.PathUnescape`) to detect encoded traversals (`%2E%2E`, `%2e%2e`).
- **Escape Detection Logic**:
  - For any configured static route with prefix $P$ (e.g. `/internal/dashboard`):
    - If the incoming uncleaned path begins with $P + "/"` or equals $P$;
    - BUT the canonicalized path `cleanRequestPath(rawPath)` does NOT begin with $P + "/"` and does NOT equal $P$;
    - The router shall immediately identify this request as a **Static Route Prefix Boundary Escape Attempt**.
- **Active Defensive Rejection**:
  - The router shall immediately reject the request without dispatching to `r.NotFound`:
    - Status code: `403 Forbidden`.
    - Response header: `Connection: close`.
    - Response header: `Content-Type: application/json`.
    - Response body: `{"error":"403 Forbidden: Path Traversal Disallowed"}`.
  - This eliminates the dead-code contradiction in `createStaticHandler` and provides standalone defense-in-depth even when WAF is disabled.

### FR-3: Upstream Proxy and API Route Canonicalization Invariant
- Non-static routes (such as reverse proxy routes configured via `RoutePrefix(RouteTypeUpstream, ...)` and standard exact routes registered via `r.GET`, `r.POST`, etc.) shall continue to adhere to ADR-062 two-stage canonicalization.
- Clean canonicalization for legitimate non-escaping routes (e.g. `/public/../internal` dispatching cleanly to `/internal` API handler) shall be strictly preserved without regression.

## 3. Non-Functional Requirements

### NFR-1: Zero External Dependencies
- All enhancements shall strictly utilize the Go standard library (`net/url`, `path`, `path/filepath`, `strings`, `bytes`).
- No external third-party dependencies shall be introduced.

### NFR-2: Performance & Sub-Microsecond Fail-Fast Latency
- The prefix escape check and raw URI extraction shall perform zero heap allocations on common benign paths.
- Rejection latency for traversal probes shall remain within existing benchmarks (Mean latency $< 300\ \mu\text{s}$, Median latency $< 70\ \mu\text{s}$).

### NFR-3: Concurrency Safety & Race-Clean Execution
- All access to routing tables and WAF rule sets shall respect `sync.RWMutex` reader locks.
- Must execute cleanly with zero data race warnings under `go test -race -count=1 ./...`.

### NFR-4: Auditability & Telemetry
- Blocked traversal attempts at both Layer 7 (WAF) and Layer 4/7 (Router) shall record appropriate metrics in `metrics.DefaultRegistry` and write structured security log events when logging is enabled.

## 4. Security & CWE-22 Threat Analysis

### CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')
- **Vulnerability Description**: An edge gateway that canonicalizes paths before verifying route boundaries may allow an attacker to either bypass access control filters or cause routing desynchronization. Returning `404 Not Found` masks an attack attempt as a benign missing resource and leaves persistent keep-alive connections vulnerable to pipeline attacks.
- **Threat Vectors Mitigated**:
  1. `TRAVERSAL-001`: Raw dot-dot climbing (`/internal/dashboard/../../canary_traversal.txt`).
  2. `TRAVERSAL-002`: Uppercase percent-encoded dot-dot climbing (`/internal/dashboard/%2E%2E/%2E%2E/canary_traversal.txt`).
  3. Mixed case and double percent-encoded climbing (`%252e%252e`, `%2e.`, `.%2e`).
  4. Null-byte and control character injections combined with traversal sequences.
- **Defense-in-Depth Matrix**:
  | Threat Vector | Layer 1: WAF (Raw Wire URI) | Layer 2: Router (Prefix Escape Guard) | Layer 3: Static Handler (`filepath.Rel`) |
  | :--- | :--- | :--- | :--- |
  | Raw dot-dot (`/../`) | Blocked (`403 Forbidden`, `conn:close`) | Blocked (`403 Forbidden`, `conn:close`) | Blocked (`403 Forbidden`, `conn:close`) |
  | Encoded (`%2E%2E`) | Blocked (`403 Forbidden`, `conn:close`) | Blocked (`403 Forbidden`, `conn:close`) | Blocked (`403 Forbidden`, `conn:close`) |
  | WAF Disabled | *Bypassed* | Blocked (`403 Forbidden`, `conn:close`) | Blocked (`403 Forbidden`, `conn:close`) |

## 5. Verification Criteria & Acceptance Oracle

### AC-1: Differential Protocol Security Fuzzer (19/19 Tests, 100.0% Pass Rate)
- In `benchmarks/fuzzer/diff_fuzzer.go`:
  - `TRAVERSAL-001`: Must actively reject with `403 Forbidden` and `Connection: close` (`ExpectClose: true`). Result: `PASS`.
  - `TRAVERSAL-002`: Must actively reject with `403 Forbidden` and `Connection: close` (`ExpectClose: true`). Result: `PASS`.
  - `TRAVERSAL-003`: Must continue to actively reject with `403 Forbidden` and `Connection: close` (`ExpectClose: true`). Result: `PASS`.
  - Overall fuzzer pass rate must reach **100.0% (19/19 tests)**.

### AC-2: Layer 7 WAF Wire URI Verification
- Dedicated unit tests in `pkg/waf/waf_test.go` and `pkg/waf/custom_rules_test.go` verifying that `InspectToron` with `req.RequestURI` containing dot-dot sequences triggers rule `TRAVERSAL-001` and returns `blocked = true`, `score >= 5`.

### AC-3: Route-Aware Static Prefix Escape Guard Verification
- Unit tests in `pkg/router/router_test.go` (including standalone test `TestRouter_RouteAwareStaticPrefixEscapeGuard` and `TestRouter_ADR062_Canonicalization`):
  - Request to `/internal/dashboard/../../canary_traversal.txt` without WAF returns `403 Forbidden: Path Traversal Disallowed` with `Connection: close`.
  - Request to `/internal/dashboard/%2E%2E/%2E%2E/canary_traversal.txt` without WAF returns `403 Forbidden: Path Traversal Disallowed` with `Connection: close`.
  - Valid subpath requests (e.g. `/internal/dashboard/index.html` or `/internal/dashboard/assets/app.js`) are served normally without false rejections.

### AC-4: Zero Regression on Existing Router Test Suite
- Existing tests in `pkg/router/router_test.go` (`TestRouter_PathCanonicalizationAndTraversalGuards`, `TestRouter_SPA_SecurityPathTraversal`, etc.) must pass with zero regression.

### AC-5: Full Race-Clean Build
- The full test suite must pass cleanly with zero race warnings under `go test -race -count=1 ./...`.
