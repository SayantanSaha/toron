# REQ-034 - Transparent HTTP Response Compression (Gzip and Deflate)

## Description

The Toron web server shall provide high-performance, transparent streaming HTTP response compression middleware for responses delivered from static file handlers, internal API endpoints, and reverse proxy upstreams.

The compression engine shall:
1. Inspect the client's `Accept-Encoding` request header and negotiate supported encodings (`gzip`, `deflate`).
2. Transparently compress response payloads exceeding a configurable minimum size threshold (e.g. 512 bytes).
3. Selectively compress eligible text and data MIME types (e.g., `text/*`, `application/json`, `application/javascript`, `application/xml`, `image/svg+xml`) while bypassing incompressible binary payloads (e.g. JPEG, PNG, ZIP, WOFF2, video, audio).
4. Set the `Content-Encoding: gzip` (or `deflate`) and `Vary: Accept-Encoding` response headers, and update `Content-Length` accordingly.
5. Bypass compression for WebSocket upgrades (101 Switching Protocols), HTTP/2 Extended CONNECT streams, and already compressed responses.
6. Support global configuration in `config.yaml` (`server.compression`).

## Acceptance Criteria

- `pkg/router`: `CompressionMiddleware` compresses HTTP response payloads when `Accept-Encoding: gzip` or `Accept-Encoding: deflate` is present in request headers.
- Responses smaller than `min_length` (default 512 bytes) or already encoded (`Content-Encoding` present) pass through uncompressed.
- WebSocket handshakes (`101 Switching Protocols` / `UpgradedConn != nil`) are bypassed without modification.
- Compression writer instances are pooled (`sync.Pool`) for memory and allocation efficiency.
- `config.yaml` supports `server.compression` settings (`enabled`, `min_length`, `level`, `encodings`, `types`).
- All Go unit tests pass cleanly (`go test ./...`).

## Rationale

Streaming response compression significantly reduces bandwidth consumption, improves page load latency over WAN connections, and brings Toron to feature parity with modern edge gateways like Caddy, NGINX, and Traefik.
