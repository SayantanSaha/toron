# CR-078 - Code Review of Mandatory exp Claim Enforcement in JWT Verification

## Description

Engineering code review of `TASK-082` implementation in `pkg/router/auth.go` and `pkg/router/auth_test.go`.

## Scope

- Files reviewed:
  - `pkg/router/auth.go`
  - `pkg/router/auth_test.go`

## Key Observations & Review Findings

1. **Configurable Default-Secure Expiration**:
   - `JWTConfig` struct extended with `RequireExpiration bool` and `AllowNoExpiration bool`.
   - `VerifyJWT` defaults to `requireExp := true` if no boolean is passed, requiring explicit opt-out to bypass.
   - Robustly checks that `exp` is present, parsed into `int64`, strictly greater than 0, and greater than current Unix time.
2. **Backward-Compatible Signature**:
   - `VerifyJWT(tokenString string, secret []byte, expectedIssuer, expectedAudience string, requireExpOpt ...bool)` maintains full source compatibility with existing 4-argument call sites across the codebase.
3. **Automated Unit Testing**:
   - `TestVerifyJWT_ExpirationEnforcement` validates rejection of tokens without `exp`, acceptance of future `exp`, rejection of expired tokens, and explicit opt-out behavior.
   - All tests pass under race detection.

## Verdict

Approved. Ready for commit.
