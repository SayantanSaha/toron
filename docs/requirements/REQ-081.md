# REQ-081 - Request Body Preservation in Sidecar Proxy Engine

## Description

The Toron sidecar proxy engine (`pkg/sidecar/proxy.go`) shall properly preserve and forward the incoming HTTP request body when adapting Go standard library `http.Request` instances to Toron `httpparser.Request` models.

## Acceptance Criteria

### 1. Retention of Mutating Request Payloads
- When `r.Body` contains payload data on `POST`, `PUT`, `PATCH`, or other methods, the sidecar proxy engine shall populate `toronReq.Body` so that the downstream reverse proxy transmits the complete payload to the upstream destination.
- `toronReq.Body` shall not be instantiated as an empty reader (`bytes.NewReader(nil)`) when `r.Body` is non-empty.

### 2. Bounded Memory Allocation
- The payload transfer shall respect standard body size limits to prevent memory exhaustion.

### 3. Verification
- A POST request containing JSON or binary data routed through the sidecar engine shall arrive at the target service with 100% payload byte fidelity.

## Rationale

Previously, `NewRequestFromStd(r)` defaulted `Body` to an empty reader. Because the sidecar proxy did not populate `toronReq.Body` from `r.Body`, all mutating requests had their bodies silently dropped, breaking upstream microservices.

## Constraints

- Pure Go standard library.
- Zero unnecessary allocations for empty GET/HEAD requests.
