# REQ-011 - Upstream Reverse Proxy Load Balancing

## Description

The Toron reverse proxy module shall support load balancing incoming client HTTP requests across multiple upstream target servers. The default load balancing algorithm shall be Round-Robin, with an extensible architecture allowing future algorithms (e.g., Random, Least Connections, IP Hash) to be added without breaking API compatibility.

## Acceptance Criteria

- Reverse proxy supports multiple target URLs per proxy route (e.g., `targets: ["http://backend1:8080", "http://backend2:8080"]`).
- Round-Robin (`round_robin`) is the default selection strategy across configured upstreams.
- An extensible `LoadBalancer` interface is defined in `pkg/proxy` to accommodate future balancing algorithms.
- Configurable via `config.yaml` (`proxy.routes[].targets` and `proxy.routes[].algorithm`).
- Maintains backward compatibility with single-target routes (`target: "http://..."`).
- Programmatic router helper methods added (`r.ProxyBalancer` and `r.ProxyBalancerHeaders`).

## Rationale

High-availability web applications and gateway proxies require distributing traffic across multiple backend instances for scalability and fault tolerance.

## Constraints

- Target selection must be thread-safe for high concurrency (`atomic.AddUint64`).
- Non-breaking changes to existing `proxy.NewReverseProxy` and `r.Proxy` APIs.
