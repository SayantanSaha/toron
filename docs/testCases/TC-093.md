# TC-093 - Test Suite for Fail-Closed WAF IP Access Control on Unidentifiable Client IP

## 1. Test Suite Objectives & Scope

Verify that the Toron Web Application Firewall ([`pkg/waf`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf)) and CIDR IP Access Control List engine ([`pkg/waf/ip_acl.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go)) strictly enforce **fail-closed** access control when an incoming client IP cannot be determined under an active IP allowlist, while preserving **fail-open** pass-through when only IP denylists are configured.

This test specification validates the complete remediation of security vulnerability [`SEC-32`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L439-L447) and security review finding [`SR-091 Finding 2`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L102-L127) ([CWE-284: Improper Access Control](https://cwe.mitre.org/data/definitions/284.html), [CWE-1188: Insecure Default Initialization of Resource](https://cwe.mitre.org/data/definitions/1188.html), [CWE-693: Protection Mechanism Failure](https://cwe.mitre.org/data/definitions/693.html)), verifying that:

1. [`IPAccessList.CheckIP(nil)`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L76-L87) denies access fail-closed when an allowlist (`allowedSubnets` or `allowedIPs`) is configured, returning `allowed == false` and the exact reason `"client IP could not be determined and allowed IP list is enforced"`.
2. [`IPAccessList.CheckIP(nil)`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L76-L87) permits access fail-open when only denylists (`deniedSubnets` or `deniedIPs`) are configured, returning `allowed == true` and `reason == ""`.
3. The WAF middleware ([`pkg/waf/middleware.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go)) rejects requests with missing or unidentifiable client IP with HTTP `403 Forbidden`, `Content-Type: application/json`, and the exact JSON payload `{"error":"Forbidden","message":"client IP could not be determined and allowed IP list is enforced"}` when an allowlist is enforced.
4. The WAF middleware allows requests with unidentifiable client IP to pass through the IP ACL stage to downstream handlers when only denylists are configured.
5. Malformed, corrupt, or non-IP inputs (e.g. `"unknown"`, `"localhost"`, `"999.999.999.999"`, `"not-an-ip:9999"`) in `req.RemoteAddr`, `X-Forwarded-For`, or `X-Real-IP` evaluate to `nil` and are rejected fail-closed under an active allowlist.
6. Structured audit logging ([`pkg/waf/audit.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/audit.go)) emits an `ip_acl_block` [`SecurityEvent`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/audit.go#L28-L43) with `ClientIP: ""` upon denial, executing safely with zero panics or nil-pointer dereferences.
7. The middleware performs single-pass extraction via [`ExtractClientIP`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L181-L207) exactly once per request lifecycle, eliminating redundant parsing and maintaining strict telemetry parity across logging and access control.
8. Concurrent execution across parallel goroutines is 100% race-clean under `go test -race ./pkg/waf/...`.

- **Test Data Matrix**:

- **Preconditions**:

    - `Mode = "enforce"`
    - `Enabled = true`
    - `AllowedIPs = []string{"10.0.0.0/8"}`
    - `DeniedIPs = []string{"198.51.100.0/24"}`
  - WAF middleware constructed via `mw := NewWAFMiddleware(engine)`.
  - Next handler tracker `nextCalled := false`.
- **Action & Test Steps**:
  1. Construct synthetic [`httpparser.Request`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L58-L70):

## 5. Security, Performance & Architectural Invariants

1. **Fail-Closed Perimeter Invariant**:
   Whenever an allowlist is configured, any request whose client IP cannot be positively resolved and verified against that allowlist MUST be rejected fail-closed with HTTP `403 Forbidden`. No request may pass an allowlist by obscuring or stripping its source address.
2. **Denylist-Only Fail-Open Preservation**:
   Denylists are purely exclusionary filters intended to block known hostile peers. When only denylists are present, unidentifiable client IPs MUST NOT be blocked by the IP ACL layer, preventing disruption to legitimate synthetic test harnesses or proxy topologies.
3. **Single-Pass Extraction Invariant**:
   The WAF middleware must perform client IP resolution ([`ExtractClientIP`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L181-L207)) exactly once per request. The resolved `net.IP` is cached in local scope and reused for both security policy checks and telemetry logging.
4. **Audit Trail Integrity & Panic Safety**:
   Audit logging must handle empty or unidentifiable client IPs without panicking or producing invalid JSON output (`client_ip: ""`).
5. **Zero Third-Party Dependencies Invariant**:
   All IP parsing, CIDR matching, and JSON error formatting must strictly utilize Go standard library packages (`net`, `net/http`, `strings`, `bytes`, `testing`).
6. **Thread Safety & Immutability**:
   `IPAccessList` and `WAFEngine` configurations are immutable during request processing. All access checks must be safe for concurrent execution across arbitrary goroutines.
