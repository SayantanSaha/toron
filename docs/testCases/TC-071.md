# TC-071 - Verification of Connection State Integrity and Hop-by-Hop Stripping for Forwarded Ingress Headers

## Objective

Verify that `pkg/proxy/proxy.go` correctly removes RFC 7230 §6.1 hop-by-hop headers and custom tokens listed in `Connection`, grounds `X-Forwarded-Proto` and `X-Forwarded-For` in physical connection state (`req.RawConn`), overwrites spoofed client headers from untrusted connections, and safely appends trusted proxy chains when originating from configured `TrustedProxies`.

## Test Cases

### TC-071-01: Hop-by-Hop and Connection-Specific Header Stripping
- **Setup**: Create `ReverseProxy` forwarding to a test backend server.
- **Action**: Client sends request with hop-by-hop headers (`Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Connection: close, X-Custom-Hop`) and `X-Custom-Hop: sensitive`.
- **Expected Outcome**:
  - Upstream backend receives the request without `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, or `X-Custom-Hop`.
  - Non-hop-by-hop headers remain intact.

### TC-071-02: Untrusted Ingress Header Anti-Spoofing
- **Setup**: Create `ReverseProxy` with no trusted proxies configured.
- **Action**: Client connects from untrusted IP `198.51.100.25` via cleartext socket, sending `X-Forwarded-Proto: https`, `X-Forwarded-For: 203.0.113.195`, and `X-Real-IP: 203.0.113.195`.
- **Expected Outcome**:
  - `X-Forwarded-Proto` is overridden to `"http"` based on physical cleartext socket state.
  - `X-Forwarded-For` and `X-Real-IP` are overridden to `"198.51.100.25"`.
  - Spoofed client values are discarded.

### TC-071-03: Trusted Proxy Preservation and Header Chaining
- **Setup**: Create `ReverseProxy` configured with `TrustedProxies: ["10.0.0.0/8"]`.
- **Action**: Client connects from trusted internal proxy `10.0.1.5` sending `X-Forwarded-Proto: https` and `X-Forwarded-For: 203.0.113.50`.
- **Expected Outcome**:
  - `X-Forwarded-Proto` preserves `"https"` as trusted upstream declaration.
  - `X-Forwarded-For` appends the connection peer: `"203.0.113.50, 10.0.1.5"`.
  - `X-Real-IP` preserves original client IP `"203.0.113.50"`.
