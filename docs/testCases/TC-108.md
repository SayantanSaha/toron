# TC-108 - Test Specification for HTTP/1.1 Pipelining and Buffered Reader Reuse

## 1. Test Suite Objectives

Verify that Toron retains unconsumed pipelined bytes across persistent HTTP/1.1 keep-alive connections by preserving `*bufio.Reader` across `handleConn` iterations and transparently reusing it inside `httpparser.ParseRequest`. Ensure zero-allocation reader reuse, strict FIFO ordering of pipelined requests, correct body isolation, connection close termination, and residual byte handover during protocol upgrades.

## 2. Test Cases

### TC-108-01: Dual and Multi-Request GET Pipelining
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP1PipelinedGETRequests`)
- **Methodology**:
  - Establish a single TCP connection to the Toron server.
  - Send two or more complete HTTP/1.1 GET requests in a single atomic `conn.Write()` call:
    ```http
    GET /pipe1 HTTP/1.1\r\nHost: localhost\r\n\r\nGET /pipe2 HTTP/1.1\r\nHost: localhost\r\n\r\n
    ```
  - Read responses consecutively from the socket.
- **Assertions**:
  - Server returns HTTP 200 for `/pipe1` with correct response body.
  - Server returns HTTP 200 for `/pipe2` with correct response body.
  - Responses are received in strict FIFO order without connection reset or hang.

### TC-108-02: Pipelined POST with Content-Length Body Followed by GET
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP1PipelinedPOSTAndGET`)
- **Methodology**:
  - Send a POST request with an explicit `Content-Length` and body payload, followed immediately by a GET request in the same TCP buffer:
    ```http
    POST /upload HTTP/1.1\r\nHost: localhost\r\nContent-Length: 11\r\n\r\nhello-worldGET /status HTTP/1.1\r\nHost: localhost\r\n\r\n
    ```
- **Assertions**:
  - POST handler receives exactly `"hello-world"` in its request body.
  - Server does not bleed POST body bytes into the GET request line.
  - GET handler receives `/status` and returns HTTP 200 without parsing error.

### TC-108-03: Pipelined Request with Connection Close Termination
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP1PipelinedConnectionClose`)
- **Methodology**:
  - Transmit two pipelined requests in one write, where the first request specifies `Connection: close`:
    ```http
    GET /first HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\nGET /second HTTP/1.1\r\nHost: localhost\r\n\r\n
    ```
- **Assertions**:
  - Server serves `/first` with `Connection: close`.
  - Server immediately terminates the TCP connection (`io.EOF` observed by client on subsequent read).
  - The second request `/second` is never parsed or processed.

### TC-108-04: Protocol Upgrade Handover with Residual Buffered Frames
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP1PipelinedUpgradeResidualBytes`)
- **Methodology**:
  - Send an HTTP/1.1 protocol upgrade request followed immediately by payload frames in the same TCP write buffer.
- **Assertions**:
  - The server extracts any residual buffered bytes from `br.Buffered()`.
  - The residual bytes are cleanly wrapped in `prefixConn` and forwarded to the upstream/relay stream without byte loss.

### TC-108-05: Parser Zero-Allocation `*bufio.Reader` Reuse
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_BufioReaderReuse`)
- **Methodology**:
  - Create a `*bufio.Reader` wrapping a byte buffer containing two pipelined HTTP requests.
  - Call `httpparser.ParseRequest(br, opts)` twice consecutively with the exact same `*bufio.Reader`.
- **Assertions**:
  - The first call parses request 1 and leaves unconsumed bytes in `br`.
  - The second call immediately parses request 2 from `br` without returning an error.
  - `ParseRequest` called with non-`*bufio.Reader` (e.g. `*bytes.Buffer`) continues to work identically for backward compatibility.
