# REQ-048 - Service Mesh Sidecar Mode for Pod-to-Pod mTLS and Traffic Splitting

## Description

Toron Edge Gateway MUST provide a native, zero-dependency **Service Mesh Sidecar Mode** package (`pkg/sidecar`). In Sidecar Mode, Toron acts as a lightweight pod-level proxy intercepting ingress/egress traffic, enforcing pod-to-pod Mutual TLS (mTLS) encryption, and supporting dynamic weighted traffic splitting (e.g. 80/20 canary releases) with zero external service mesh dependencies.

## Acceptance Criteria

1. **Zero External Dependencies**: The sidecar proxy MUST implement mTLS certificate verification and weighted traffic splitting using Go stdlib `crypto/tls`, `net/http`, and `net` packages only.
2. **Pod-to-Pod Strict mTLS**: The sidecar MUST support strict mutual TLS client certificate verification (`client_auth: "require_and_verify"`) using root CA certificate pools.
3. **Weighted Traffic Splitting**: The sidecar MUST support splitting request traffic across multiple backend endpoints according to user-defined integer weights (e.g. 80% to v1, 20% to v2).
4. **Ingress & Egress Modes**: The sidecar MUST operate in `ingress` mode (protecting local app container), `egress` mode (encrypting outbound requests), or `dual` mode.
