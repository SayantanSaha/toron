# SR-125 - Security Review of Conditional Direct Socket Streaming Fast-Path, Transport Timeout Decoupling, and Buffer Pooling

## 1. Executive Summary

A comprehensive security analysis was conducted on the implementation of [`TASK-148`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-148.md) and [`ADR-125`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-125.md).

The review evaluated threat vectors introduced by decoupling upstream response body streaming from `Client.Timeout`, direct wire streaming without intermediate buffering, memory slab pooling, and bypass guards in caching and compression middlewares.

**Verdict**: **APPROVED (0 Vulnerabilities, 0 Security Regressions, Mitigations Verified)**.

---

## 2. Threat Modeling & Vulnerability Analysis

### 2.1 CWE-400: Uncontrolled Resource Consumption (Slow-Read / Slowloris DoS)
- **Threat**: Setting `p.Client.Timeout = 0` to decouple body streaming could enable malicious clients or slow upstreams to tie up server goroutines and file descriptors indefinitely.
- **Analysis**:
  1. Connection dial remains strictly bounded by `tr.DialContext` using `opts.Timeout` (10s default).
  2. Time-to-first-byte (response headers) remains strictly bounded by `tr.ResponseHeaderTimeout` (10s default), verified by `TC-125.2`.
  3. During active stream relaying, `Server.handleConnection` sets socket write deadlines refreshed on every chunk: `conn.SetWriteDeadline(time.Now().Add(idleTimeout))`.
  4. If a slow client halts or stalls reading, the write deadline expires, the server terminates the relay loop, and `defer res.StreamBody.Close()` immediately tears down the upstream connection (`TC-125.7`).
- **Verdict**: Fully mitigated.

### 2.2 CWE-200: Information Exposure Through Shared Recycled Memory Slabs
- **Threat**: `sync.Pool` buffer slabs (`bufferPool`, `copyBufferPool`) could inadvertently leak sensitive tokens or payload fragments across unrelated requests if unreset buffers are reused.
- **Analysis**:
  1. `PutBuffer` strictly executes `buf.Reset()` prior to returning the `*bytes.Buffer` to the pool.
  2. `GetBuffer` returns clean buffers with `Len() == 0`.
  3. In `pkg/httpparser/response_test.go`, Subtest 8A specifically asserts that sensitive bytes written to a pooled buffer are completely erased upon pool recycling.
- **Verdict**: No cross-tenant information disclosure risk.

### 2.3 RFC 7234 §5.2.2.2 Cache Deception & Stale Stream Exposure
- **Threat**: Caching unbuffered live streams (`text/event-stream` or `X-Accel-Buffering: no`) can freeze live feeds and cause cache deception vulnerabilities.
- **Analysis**:
  1. `CacheMiddleware` explicitly checks `res.StreamBody != nil`, `text/event-stream`, and `X-Accel-Buffering: no`, immediately bypassing the cache registry.
  2. Subtest 5B verifies that subsequent streaming requests yield `X-Cache: MISS` and are never cached.
- **Verdict**: Strict compliance with RFC 7234 and REQ-128.

### 2.4 CWE-113: HTTP Response Splitting & Hop-by-Hop Header Leakage
- **Threat**: Direct wire streaming could leak RFC 7230 hop-by-hop headers (`Transfer-Encoding`, `Connection`, `Upgrade`) from upstream to client.
- **Analysis**:
  1. In `ReverseProxy.ServeHTTPWithPrefix`, upstream headers pass through `hopByHopHeaders` filtering before being committed to `res.Header`.
  2. Hop-by-hop headers (`Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Transfer-Encoding`, `Upgrade`) are strictly stripped, verified in `TestProxy_WebSocketAlignedStreamHandOff` (`TC-125.4`).
- **Verdict**: Clean protocol isolation.

## 3. Verification & Conclusion

Automated test execution with the Go race detector (`go test -race ./pkg/...`) confirms clean synchronization and thread safety. All security controls and DoS defenses are fully verified.
