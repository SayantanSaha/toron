# CR-034 - Code Review of Per-Host Dynamic SNI Certificate Mapping & mTLS Client Auth

## Scope

Engineering review of [`pkg/server/sni.go`](file:///D:/Work/server/pkg/server/sni.go), [`pkg/server/tls.go`](file:///D:/Work/server/pkg/server/tls.go), [`pkg/server/server.go`](file:///D:/Work/server/pkg/server/server.go), [`pkg/config/config.go`](file:///D:/Work/server/pkg/config/config.go), and unit test suite ([`sni_test.go`](file:///D:/Work/server/pkg/server/sni_test.go)).

## Findings

1. **Clean Integration with Go `crypto/tls`**: Leveraged standard library `tls.Config.GetConfigForClient` hook, avoiding custom socket wrapper hacks.
2. **Wildcard & Exact Matching**: Supports both exact host matching (`api.example.com`) and wildcard matching (`*.example.com`) with fallback to the server default / auto dev certificate.
3. **mTLS & Version Customization**: Allows configuring `client_auth` modes (`no_client_cert`, `request_client_cert`, `require_any_client_cert`, `verify_client_cert_if_given`, `require_and_verify`) and `min_version` (`tls1.2`, `tls1.3`) per host.
4. **Comprehensive Test Suite**: Tested multi-domain SNI certificate routing, valid and invalid mTLS handshakes, and TLS 1.3 protocol enforcement with 100% pass rate.

## Conclusion

Approved. Implementation ready for production.
