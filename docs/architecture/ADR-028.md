# ADR-028 - ACME HTTP-01 & TLS-ALPN-01 Zero-Touch SSL Provisioning Architecture

## Context

Production deployments require valid SSL/TLS certificates issued by trusted certificate authorities (Let's Encrypt, ZeroSSL). Manual renewal introduces operational overhead and downtime risk.

## Decision

1. **ACME Manager Core (`pkg/acme/acme.go`)**:
   - Manages ACME account registration, order creation, domain validation challenges, certificate issuance, and disk caching (`cache_dir`).

2. **HTTP-01 Challenge Responder**:
   - Intercepts requests matching `GET /.well-known/acme-challenge/{token}`.
   - Computes key authorization thumbprint `token + "." + base64url(sha256(account_key))` and returns string with `Content-Type: text/plain`.

3. **TLS-ALPN-01 Challenge Responder**:
   - Intercepts TLS Client Hello negotiating ALPN `acme-tls/1`.
   - Generates a transient self-signed X.509 certificate containing critical extension OID `1.3.6.1.5.5.7.1.31` (`id-pe-acmeIdentifier`) containing the SHA-256 digest of key authorization.

4. **TLS Handshake Callback (`GetCertificate`)**:
   - Integrated into `tls.Config.GetCertificate`. If cached certificate exists and is valid, serves certificate; if expiring or missing, triggers ACME challenge flow.

## Consequences

- **Positive**: Zero-touch, fully automated production SSL certificate issuance and background renewals.
- **Standards Compliance**: Full adherence to RFC 8555 (ACME) and RFC 8737 (TLS-ALPN-01).
