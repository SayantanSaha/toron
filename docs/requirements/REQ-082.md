# REQ-082 - Mandatory Expiration (exp) Claim Enforcement in JWT Verification

## Description

The Toron JWT authentication engine (`pkg/router/auth.go`) shall support configurable and default enforcement of the `exp` (Expiration Time) claim, preventing non-expiring tokens from remaining valid indefinitely.

## Acceptance Criteria

### 1. Verification of exp Claim Presence
- In `VerifyJWT`, when `RequireExpiration` is enabled (or by default in secure mode), the presence of the `exp` claim shall be mandatory.
- If a JWT token does not declare an `exp` claim, verification shall fail with an error indicating missing expiration claim (`"missing required exp claim"`).

### 2. Backward Compatibility Configuration
- `JWTConfig` shall expose an optional boolean `RequireExpiration` (defaulting to `true` or configurable) to accommodate legacy environments where non-expiring tokens are explicitly permitted.

### 3. Immediate Token Rejection on Expiry
- Tokens whose `exp` timestamp is less than or equal to current Unix time shall continue to be rejected with `HTTP 401 Unauthorized`.

## Rationale

Without mandatory expiration checking, a token issued without an `exp` claim never expires, creating a persistent window of vulnerability if the token is ever leaked, logged, or intercepted.

## Constraints

- Pure Go standard library.
- Zero impact on tokens with valid `exp` claims.
