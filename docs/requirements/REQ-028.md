# REQ-028 - Dynamic Hot Reloading of Routes via File-Watch Worker (fsnotify)

## Description

The Toron web server shall support dynamic zero-downtime hot reloading of routing configuration (`routes.yaml`) using a background file-watch worker powered by `fsnotify`.

When modifications to `routes.yaml` are saved, the file watcher worker shall automatically validate the updated route syntax, re-parse static site and upstream target definitions, and atomically update active router rules and proxy targets without dropping active client TCP/UDP/QUIC connections or restarting the server listener.

## Acceptance Criteria

- `pkg/config`: `ReloadRoutesFromFile(filePath string)` re-reads, validates, and returns newly parsed `ProxyRouteConfig` rules.
- `pkg/router`: `Router` supports thread-safe atomic swapping of active routing tables via `sync.RWMutex` or `atomic.Pointer`.
- `pkg/config`: `RouteWatcher` struct utilizes `fsnotify` to monitor changes to `routes.yaml`, debounce rapid write events, and trigger hot reload.
- Active TCP socket streams, WebSocket channels, and QUIC streams are preserved without dropping client connections during a route reload.
- Automated unit and integration tests in `pkg/config` and `pkg/router` pass cleanly.

## Rationale

Dynamic route hot-reloading allows operators to add, remove, or modify upstream proxy targets, static site locations, domain matching, and versioning rules in production environments without service interruption.
