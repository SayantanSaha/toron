# TC-086 - Verification of Service Mesh Sidecar Request Body Limiting and 413 Rejection

## Objective

Verify that [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) in [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go) enforces configurable request body limits via [`SidecarConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L103), rejects declared and streaming overflows with HTTP `413 Request Entity Too Large` (`http.StatusRequestEntityTooLarge`), forwards in-limit mutating requests with 100% byte fidelity, bypasses non-mutating/empty requests without buffer allocations, and maintains thread safety under high concurrency with zero race conditions, resolving [`SEC-25`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L366-L374) (CWE-436, CWE-400).

## Target Test Suite

- **Test Suite Location**: [`pkg/sidecar/sidecar_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go)
- **Target Implementation**: [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go), [`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go), and [`pkg/config/loader.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go)
- **Dependencies**: Zero external / third-party dependencies (strictly Go standard library: `testing`, `net/http`, `net/http/httptest`, `io`, `bytes`, `sync`, `sync/atomic`).

## Test Specifications

### TC-086-01: Declared Content-Length Fast-Fail Rejection
- **Objective**: Verify that when an incoming mutating request declares a `Content-Length` header exceeding [`SidecarConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L103), the proxy immediately rejects the request with HTTP 413 (`http.StatusRequestEntityTooLarge`), closes the request body, and terminates proxying without reading the payload stream or dispatching any request to the upstream target.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 2), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Stage 1), [`TASK-091`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-091.md), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream HTTP server instantiated via `httptest.NewServer` tracking total received requests using `atomic.Int64`.
  - [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) configured with `MaxBodyBytes: 1024` (1 KB), `Mode: "ingress"`, `IngressPort: 16001`, `AppPort: mockServerPort`.
  - Engine started with a 2-second timeout context.
- **Action**:
  - Client issues `POST http://127.0.0.1:16001/api/data` with header `Content-Length: 2048` and a 2048-byte payload (`bytes.Repeat([]byte("A"), 2048)`).
- **Verifiable Assertions**:
  1. Response status code MUST equal `http.StatusRequestEntityTooLarge` (`413`).
  2. Response body contains `"Request Entity Too Large"`.
  3. Upstream request counter MUST equal `0` (upstream application receives zero requests, zero partial data).
  4. Proxy body reading is aborted fast-path prior to allocating body memory.

### TC-086-02: Bounded Stream Over-Read Rejection
- **Objective**: Verify that when an incoming request uses chunked transfer encoding (`Transfer-Encoding: chunked`) or omits an oversized declared `Content-Length` (`r.ContentLength <= 0`), [`ProxyEngine.proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L189) bounds stream ingestion using `io.LimitReader(r.Body, MaxBodyBytes + 1)`. When the consumed stream exceeds `MaxBodyBytes`, the engine aborts reading, closes `r.Body`, discards buffered bytes, returns HTTP 413, and guarantees upstream receives 0 requests.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 2), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Stage 2), [`TASK-091`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-091.md), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream HTTP server tracking received requests and raw payload bytes.
  - [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) running with `MaxBodyBytes: 512` bytes, `Mode: "ingress"`, `IngressPort: 16002`, `AppPort: mockServerPort`.
- **Action**:
  - Client constructs an HTTP `POST http://127.0.0.1:16002/api/stream` with `req.ContentLength = -1` (triggering chunked transfer encoding in Go HTTP client) and an `io.Reader` streaming 1024 bytes.
  - Dispatch request via `http.DefaultClient.Do(req)`.
- **Verifiable Assertions**:
  1. Response status code MUST equal `http.StatusRequestEntityTooLarge` (`413`).
  2. Response body contains `"Request Entity Too Large"`.
  3. Upstream mock server receives `0` requests (counter == 0).
  4. Memory consumption is strictly bounded to `MaxBodyBytes + 1` (513 bytes), preventing unconstrained allocation (CWE-400).
  5. Zero partial or corrupted frames reach the upstream application.

### TC-086-03: Default 10MB Fallback Enforcement
- **Objective**: Verify that when [`SidecarConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L103) is unset (`0`) or non-positive (`<= 0`), [`NewProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L37) and [`validateConfigDefaults`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go#L153) default to exactly 10 MB (`10 * 1024 * 1024` = 10,485,760 bytes). Verify exact boundary enforcement: an exact 10 MB payload is accepted and forwarded, whereas 10 MB + 1 byte is rejected with HTTP 413.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 1, AC 2), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Section 1), [`TASK-090`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-090.md), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream server recording received body size and returning HTTP 200 OK.
  - Construct [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) with `SidecarConfig{MaxBodyBytes: 0}` and verify fallback.
  - Construct [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) with `SidecarConfig{MaxBodyBytes: -1}` and verify fallback.
  - Start engine on `IngressPort: 16003`.
- **Action**:
  - **Subtest 3A (Config Struct Defaults)**: Verify `engine.cfg.MaxBodyBytes == 10485760`.
  - **Subtest 3B (Exact 10MB Boundary Accepted)**: Dispatch `POST http://127.0.0.1:16003/api/upload` with exactly `10 * 1024 * 1024` bytes (10,485,760 bytes).
  - **Subtest 3C (10MB + 1 Byte Boundary Rejected)**: Dispatch `POST http://127.0.0.1:16003/api/upload` with `10 * 1024 * 1024 + 1` bytes (10,485,761 bytes).
- **Verifiable Assertions**:
  1. `engine.cfg.MaxBodyBytes` is normalized to `10485760` for both 0 and negative initial values.
  2. Subtest 3B yields HTTP `200 OK`; upstream server receives all 10,485,760 bytes intact.
  3. Subtest 3C yields HTTP `413 Request Entity Too Large`; upstream server receives 0 requests for this submission.

### TC-086-04: Full-Fidelity In-Limit Body Forwarding
- **Objective**: Verify that mutating requests (`POST`, `PUT`, `PATCH`) whose payload size is less than or equal to `MaxBodyBytes` are forwarded to the upstream destination intact with 100% byte fidelity, preserving exact byte sequences and accurate `ContentLength`.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 3), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Stage 3), [`TASK-091`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-091.md), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream HTTP server recording method, headers (`Content-Length`, `Content-Type`), and body bytes.
  - [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) running with `MaxBodyBytes: 8192` (8 KB), `Mode: "ingress"`, `IngressPort: 16004`.
- **Action**:
  - Subtest 4A: Send `POST /api/records` with 1024-byte structured JSON payload `{"id":"101","data":"..."}`.
  - Subtest 4B: Send `PUT /api/records/101` with 2048-byte binary payload (`crypto/rand` or sequential byte pattern).
  - Subtest 4C: Send `PATCH /api/records/101` with 512-byte text payload.
- **Verifiable Assertions**:
  1. Client receives HTTP `200 OK` with upstream response body for each request.
  2. Upstream receives matching HTTP methods (`POST`, `PUT`, `PATCH`).
  3. Upstream payload matches sent payload byte-for-byte (`bytes.Equal(receivedBytes, sentBytes) == true`).
  4. Upstream `Content-Length` header strictly matches `int64(len(sentBytes))` (zero truncation, zero corruption).

### TC-086-05: Non-Mutating and Empty Request Bypass
- **Objective**: Verify that non-mutating requests (`GET`, `HEAD`) and requests without bodies (`r.Body == nil` or `ContentLength == 0`) bypass request body buffering and `LimitReader` pipelines, allocating zero body buffers and avoiding false-positive 413 rejections.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 4), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Stage 0), [`TASK-091`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-091.md), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream HTTP server returning HTTP 200 OK for `GET` (with response body `{"status":"ok"}`), HTTP 200 OK for `HEAD` (with empty body and custom headers), and HTTP 200 OK for empty `POST`.
  - [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) configured with a minimal limit: `MaxBodyBytes: 32` bytes, `Mode: "ingress"`, `IngressPort: 16005`.
- **Action**:
  - Send `GET http://127.0.0.1:16005/api/status` with nil body.
  - Send `HEAD http://127.0.0.1:16005/api/status` with nil body.
  - Send `POST http://127.0.0.1:16005/api/empty` with `http.NoBody` and `Content-Length: 0`.
- **Verifiable Assertions**:
  1. `GET` returns HTTP `200 OK`; response body equals `{"status":"ok"}`; upstream receives 0-byte body.
  2. `HEAD` returns HTTP `200 OK`; response body is empty; response headers preserved.
  3. `POST` with `Content-Length: 0` returns HTTP `200 OK` without triggering 413.
  4. Zero buffer allocation overhead; zero false-positive rejections.

### TC-086-06: High-Concurrency & Race-Condition Safety
- **Objective**: Verify that [`ProxyEngine.proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L189) handles concurrent client workloads mixing valid in-bounds requests, declared oversized requests, chunked stream oversized requests, and non-mutating requests across multiple goroutines without deadlocks, memory corruption, or race conditions under `go test -race ./pkg/sidecar/...`.
- **Traceability**: [`REQ-086`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-086.md) (AC 6), [`ADR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-081.md) (Section 3), [`TASK-092`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-092.md).
- **Setup & Preconditions**:
  - Mock upstream server tracking request counts using atomic counters (`validPostCount`, `getCount`, `oversizedLeakCount`).
  - [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) configured with `MaxBodyBytes: 1024` bytes, `Mode: "ingress"`, `IngressPort: 16006`.
  - `sync.WaitGroup` managing `N = 100` concurrent requests across 4 distinct worker categories (25 goroutines each):
    1. Valid in-bounds `POST` requests (256 bytes).
    2. Declared oversized `POST` requests (2048 bytes with `Content-Length: 2048`).
    3. Chunked oversized `POST` requests (1500 bytes with `ContentLength = -1`).
    4. Non-mutating `GET` requests.
- **Action**:
  - Concurrently launch 100 goroutines against `http://127.0.0.1:16006`.
  - Collect client-side response codes and verify assertions in parallel.
  - Wait for all goroutines to complete via `wg.Wait()`.
  - Verify upstream server statistics.
  - Stop engine and verify graceful termination.
- **Verifiable Assertions**:
  1. All 25 valid POST requests return HTTP `200 OK`.
  2. All 25 declared oversized requests return HTTP `413 Request Entity Too Large`.
  3. All 25 chunked oversized requests return HTTP `413 Request Entity Too Large`.
  4. All 25 GET requests return HTTP `200 OK`.
  5. Upstream `oversizedLeakCount` MUST equal `0` (zero oversized requests ever hit the backend).
  6. Test execution passes cleanly under `go test -v -race ./pkg/sidecar/...` with zero data races detected.
