# TC-119 - Verification of Benchmark Result Retention, Directory Isolation, and Manifest Integrity (REQ-119)

## 1. Test Objectives & Scope

Validate the Dual-Path Benchmark Result Retention and Historical Manifest architecture specified in [`REQ-119`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-119.md), [`TASK-142`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-142.md), and [`ADR-119`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-119.md).

## 2. Test Case Specifications

### TC-119-01: Historical Directory Provisioning and Formatting
- **Objective**: Verify that timestamped directories are created under `benchmarks/results/history/<timestamp>/` adhering to `YYYY-MM-DD_HH-MM-SS`.
- **Preconditions**: `benchmarks/results/history/` exists or is created automatically.
- **Actions**:
  1. Trigger archival helper or benchmark runner.
  2. Inspect generated directory name with regex `^[0-9]{4}-[0-9]{2}-[0-9]{2}_[0-9]{2}-[0-9]{2}-[0-9]{2}(_[0-9]+)?$`.
- **Pass Criteria**: Directory is created with correct permissions (`0755`) and timestamp format.

### TC-119-02: Dual-Path Replication & Canonical Synchronization
- **Objective**: Verify that benchmark artifacts are written to both the historical snapshot directory and the canonical `benchmarks/results/` root.
- **Actions**:
  1. Run a benchmark task (e.g. differential fuzzer or microbenchmarks).
  2. Compare byte content and SHA256 of `benchmarks/results/<artifact>` with `benchmarks/results/history/<timestamp>/<artifact>`.
- **Pass Criteria**: Both files are byte-for-byte identical; canonical path is updated without breakage.

### TC-119-03: Manifest Schema & Append Atomicity
- **Objective**: Verify that `benchmarks/results/history/manifest.json` conforms to schema and supports atomic append across consecutive runs.
- **Actions**:
  1. Execute two consecutive benchmark runs.
  2. Parse `manifest.json` using Go JSON decoder.
  3. Validate `schema_version`, `total_runs >= 2`, and array length matches `total_runs`.
  4. Verify run metadata fields: `run_id`, `timestamp`, `directory`, `suite`, `git_commit`, `status`, and `artifacts`.
- **Pass Criteria**: `manifest.json` is syntactically valid JSON with two distinct chronologically ordered run entries.

### TC-119-04: Master Suite Consolidated Archiving (`run_all.sh`)
- **Objective**: Verify that `run_all.sh` consolidates all 6 stages into a single master session directory and logs a single consolidated suite entry or linked stage entries.
- **Actions**:
  1. Execute `run_all.sh` (or a mock multi-stage execution).
  2. Check that a single historical session directory receives artifacts from all executed stages.
- **Pass Criteria**: All generated files reside in that session directory and `manifest.json` records the master suite.

### TC-119-05: Standalone Runner Independent Archiving
- **Objective**: Verify that standalone runner scripts (`run_wrk2.sh`, `run_saturation_stress.sh`, `run_fuzzer.sh`, `run_multihop.sh`, `run_ablation.sh`) archive independently when run without `run_all.sh`.
- **Actions**:
  1. Unset `TORON_BENCHMARK_SESSION_DIR`.
  2. Invoke a runner directly.
  3. Verify a new timestamp directory is created and `manifest.json` is updated.
- **Pass Criteria**: Standalone execution creates historical entry and updates canonical root.

### TC-119-06: Equation 1 DAG Contract Invariant
- **Objective**: Verify that all tasks, requirements, and ADRs in the repository strictly satisfy Equation 1 gating invariants.
- **Action**: Run `python3 scripts/validate_dag.py`.
- **Pass Criteria**: Exit code 0, 100% compliant.
