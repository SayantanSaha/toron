# TC-087 - Verification of Layer 4 TCP and UDP Proxy Hardening, Concurrency Limits, Socket Reuse, and Idle Deadline Enforcement

## Objective

Verify that Layer 4 transport proxies—[`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) in [`pkg/proxy/tcp.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go) and [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) in [`pkg/proxy/udp.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go)—enforce bounded concurrency limits, bidirectional idle deadline tracking, upstream socket and session reuse, datagram buffer pooling, and clean deterministic teardown. This test specification validates the remediation of critical vulnerability [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html)) and [`SR-081 Finding 4`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L130-L140), preventing denial of service, ephemeral port exhaustion (`bind: address already in use`), socket file descriptor starvation (`EMFILE`), memory exhaustion (OOM), and Slowloris connection hangs.

## Test Specifications

### TC-087-01: TCP Concurrency Gating & Over-Capacity Fast Rejection
- **Objective**: Verify that [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) enforces bounded connection concurrency via atomic counter tracking. When active client connections reach `MaxConnections` (`MaxConnections = 2`), any subsequent incoming connection is immediately rejected and closed on acceptance without dialing the upstream backend, allocating buffers, or leaking resources. Once an active connection terminates, the atomic counter decrements and subsequent incoming connections are accepted and proxied normally.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 2), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 2.1), [`TASK-094`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-094.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestTCPProxy_MaxConnections(t *testing.T)` in [`pkg/proxy/tcp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server started on loopback (`127.0.0.1:0`), tracking total accepted backend connections with an atomic counter `backendConnCount`.
  - [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) instantiated targeting the mock backend with options `WithTCPMaxConnections(2)` and `WithTCPIdleTimeout(5 * time.Second)`.
  - TCP proxy listener started on loopback (`127.0.0.1:0`).
- **Action**:
  1. Client dials connection 1 (`conn1 = net.Dial("tcp", proxyAddr)`), transmits `"client1-hello"`, and verifies receipt of `"echo: client1-hello"`. `conn1` is kept open.
  2. Client dials connection 2 (`conn2 = net.Dial("tcp", proxyAddr)`), transmits `"client2-hello"`, and verifies receipt of `"echo: client2-hello"`. `conn2` is kept open.
  3. Verify `backendConnCount` equals `2`.
  4. Attempt connection 3 (`conn3 = net.Dial("tcp", proxyAddr)`):
     - Attempt to read from `conn3` with a 1-second timeout.
  5. Close `conn1` (`conn1.Close()`). Wait briefly (up to 50ms) for the proxy counter to decrement.
  6. Attempt connection 4 (`conn4 = net.Dial("tcp", proxyAddr)`), transmit `"client4-hello"`, and read response.
  7. Close remaining open connections (`conn2`, `conn4`).
- **Verifiable Assertions**:
  1. `conn1` and `conn2` concurrently establish and maintain full-duplex proxying.
  2. `conn3` is immediately rejected by the proxy upon acceptance; client read on `conn3` yields `io.EOF` or a closed connection error.
  3. `backendConnCount` remains at `2` when `conn3` is attempted; the upstream backend receives zero connection attempts for `conn3`.
  4. Closing `conn1` decrements active connection tracking, allowing `conn4` to be accepted.
  5. `conn4` successfully communicates with the mock backend and receives `"echo: client4-hello"`.

### TC-087-02: TCP Bidirectional Idle Deadline Enforcement (Slowloris Mitigation)
- **Objective**: Verify that [`TCPProxy.handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L78-L109) enforces `IdleTimeout` (`IdleTimeout = 150ms`) across bidirectional data streams between client and upstream sockets. If an established connection produces zero data transfers in either direction for longer than `IdleTimeout`, both the client socket and upstream backend socket are forcibly closed by the proxy, unblocking goroutines and freeing file descriptors. Verify that active bidirectional traffic repeatedly refreshes the deadline and keeps connections alive.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 3), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 2.2), [`TASK-094`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-094.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestTCPProxy_IdleTimeout(t *testing.T)` in [`pkg/proxy/tcp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server running on `127.0.0.1:0`.
  - [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) configured with a short idle timeout: `WithTCPIdleTimeout(150 * time.Millisecond)`.
  - Proxy listener running on `127.0.0.1:0`.
- **Action**:
  - **Subtest 2A (Idle Timeout Expiration)**:
    1. Client connects to proxy (`conn, _ := net.Dial("tcp", proxyAddr)`).
    2. Client sends `"ping"`, verifies response `"echo: ping"`.
    3. Client ceases all transmission and sleeps for `250ms` (`> IdleTimeout`).
    4. Client attempts to read from `conn` with a 500ms timeout (`conn.SetReadDeadline(time.Now().Add(500 * time.Millisecond))`).
  - **Subtest 2B (Active Stream Deadline Refreshing)**:
    1. Client connects via a second connection `connActive`.
    2. Over a duration of `450ms` (3x `IdleTimeout`), client transmits payloads every `50ms` (`< IdleTimeout`), reading the corresponding echo responses.
- **Verifiable Assertions**:
  1. In Subtest 2A, the proxy detects idle deadline expiration on the stagnant connection and closes both client and upstream sockets.
  2. Client read on `conn` returns `io.EOF` or an OS closed connection error.
  3. Upstream backend observes socket closure, confirming zero leaked backend sockets.
  4. In Subtest 2B, `connActive` remains open and healthy throughout the 450ms period, proving that each data transfer successfully refreshes the idle deadline.

### TC-087-03: UDP Bounded Worker Pool & Saturation Backpressure
- **Objective**: Verify that [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) limits concurrent datagram processing to `MaxWorkers` (`MaxWorkers = 2`) through a bounded worker queue. When subjected to a burst of datagrams that exceeds worker capacity, the proxy applies fail-safe backpressure by dropping excess datagrams without unbounded goroutine growth, memory exhaustion (OOM), or panics.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 4), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 3.1), [`TASK-095`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-095.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestUDPProxy_WorkerPoolSaturation(t *testing.T)` in [`pkg/proxy/udp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp_test.go).
- **Setup & Preconditions**:
  - Mock UDP backend server that artificially pauses for `50ms` during datagram processing before replying.
  - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) configured with `WithUDPMaxWorkers(2)` and a bounded packet queue capacity of 2.
  - Record baseline goroutines using `runtime.NumGoroutine()`.
- **Action**:
  1. Concurrently blast 40 datagrams from distinct UDP client endpoints to the proxy within a 5ms window.
  2. Sample `runtime.NumGoroutine()` during burst processing.
  3. Wait 300ms for active workers to complete in-flight tasks and drain the queue.
  4. Send a single subsequent datagram within capacity from a new client and verify echo reply.
- **Verifiable Assertions**:
  1. Goroutine count remains strictly bounded: runtime goroutines during the burst increase by at most $O(\text{MaxWorkers})$ (e.g., $\Delta \text{goroutines} \le 8$), never spawning 40 individual goroutines.
  2. Unprocessed packets exceeding queue capacity are dropped fail-safe; proxy does not panic, deadlock, or crash with OOM.
  3. After worker queue drains, subsequent datagrams are accepted and forwarded normally.

### TC-087-04: UDP Upstream Socket Reuse Across Datagrams
- **Objective**: Verify that [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) maintains an active session registry caching upstream sockets (`*net.UDPConn`) indexed by client endpoint. Multiple datagrams originating from the same client session MUST reuse the established upstream socket, eliminating per-packet `net.DialUDP` calls, preventing ephemeral port exhaustion (`bind: address already in use`), and avoiding socket descriptor starvation (`EMFILE`).
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 5), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 3.3), [`TASK-095`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-095.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestUDPProxy_SocketReuse(t *testing.T)` in [`pkg/proxy/udp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp_test.go).
- **Setup & Preconditions**:
  - Mock UDP echo backend server running on `127.0.0.1:0`.
  - The mock backend records the source port (`addr.Port`) of every received packet into a thread-safe slice `receivedSourcePorts`.
  - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) initialized and serving on loopback.
- **Action**:
  1. Client creates a persistent UDP socket (`net.DialUDP("udp", nil, proxyAddr)`).
  2. Client transmits 10 sequential datagrams (`"packet-0"` through `"packet-9"`) spaced 10ms apart.
  3. Client receives and verifies echo responses for each datagram.
  4. Inspect `receivedSourcePorts` recorded by the mock backend.
- **Verifiable Assertions**:
  1. All 10 datagrams are successfully echoed and received by the client.
  2. The mock backend records the **exact same upstream source port** across all 10 packets (`receivedSourcePorts[0] == receivedSourcePorts[i]` for all $i \in [1, 9]$).
  3. Exactly one upstream UDP socket was created for this client session; subsequent packets reused the cached socket without additional socket descriptor allocations.

### TC-087-05: UDP Session Idle Timeout & Eviction
- **Objective**: Verify that [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) runs a background session sweeper that evicts inactive client sessions whose `lastActivity` timestamp exceeds `IdleTimeout` (`IdleTimeout = 200ms`). Eviction MUST close the upstream socket and release host ephemeral ports. Subsequent datagrams sent from the same client after eviction establish a brand-new session with a newly allocated upstream socket.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 5), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 3.3), [`TASK-095`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-095.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestUDPProxy_SessionIdleTimeout(t *testing.T)` in [`pkg/proxy/udp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp_test.go).
- **Setup & Preconditions**:
  - Mock UDP echo backend server recording upstream source ports.
  - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) configured with `WithUDPIdleTimeout(200 * time.Millisecond)`.
  - Sweeper ticker configured to sweep at `IdleTimeout / 2` (100ms).
- **Action**:
  1. Client sends datagram 1 (`"session-packet-1"`) from local port $C$; backend records upstream port $P_1$. Client receives echo.
  2. Client pauses transmission for `350ms` (`> IdleTimeout + sweeper interval`).
  3. Verify that the session for client $C$ is evicted from the proxy session registry.
  4. Client transmits datagram 2 (`"session-packet-2"`) from the same local port $C$; backend records upstream port $P_2$. Client receives echo.
- **Verifiable Assertions**:
  1. Datagram 1 creates an initial active session using upstream port $P_1$.
  2. After 350ms of inactivity, the proxy background sweeper evicts the session and closes socket $P_1$.
  3. Datagram 2 successfully establishes a new session; backend records a new upstream port ($P_2 \ne P_1$), confirming that the expired socket was terminated and a fresh socket was bound.
  4. Memory and socket count return to baseline after idle eviction.

### TC-087-06: UDP Buffer Pooling (Zero Heap Churn)
- **Objective**: Verify that [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) recycles 64 KB datagram buffers (`make([]byte, 65535)`) via `sync.Pool`. During steady-state datagram processing, verify that buffers are returned to the pool and reused across packets, preventing massive heap allocation churn and GC pauses.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 4), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Section 3.2), [`TASK-095`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-095.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md), [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383).
- **Target Function**: `TestUDPProxy_BufferPooling(t *testing.T)` in [`pkg/proxy/udp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp_test.go).
- **Setup & Preconditions**:
  - Mock UDP echo backend server.
  - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) initialized with buffer pool.
- **Action**:
  1. Send 10 warmup datagrams to prime the buffer pool and establish sessions.
  2. Measure allocations using `testing.AllocsPerRun(100, ...)` transmitting datagrams through the proxy.
- **Verifiable Assertions**:
  1. Buffers are recycled using `sync.Pool` for both inbound reads and upstream responses.
  2. Steady-state heap allocations per datagram do not allocate new 65,535-byte slices (`allocs/op <= 2` for minimal task metadata).
  3. Total memory allocated during continuous datagram forwarding remains flat without GC thrashing.

### TC-087-07: Deterministic Graceful Shutdown
- **Objective**: Verify that calling [`Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L112-L127) on [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) and [`Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L111-L126) on [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22) while concurrent client traffic is underway immediately stops accepting new connections/datagrams, closes all tracked active client and upstream sockets, terminates background session cleaner routines and worker pools, and returns cleanly within 500ms without hangs, deadlocks, or socket descriptor leaks.
- **Traceability**: [`REQ-087`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-087.md) (AC 6), [`ADR-082`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-082.md) (Sections 2.3, 3.4), [`TASK-094`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-094.md), [`TASK-095`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-095.md), [`TASK-096`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-096.md).
- **Target Functions**:
  - `TestTCPProxy_GracefulShutdown(t *testing.T)` in [`pkg/proxy/tcp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp_test.go).
  - `TestUDPProxy_GracefulShutdown(t *testing.T)` in [`pkg/proxy/udp_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend and UDP backend servers running.
  - Active TCP and UDP proxies running on dynamic loopback ports.
- **Action**:
  - **Subtest 7A (TCP Proxy Shutdown)**:
    1. Establish 5 concurrent TCP client connections streaming continuous data to the proxy.
    2. While streams are in-flight, call `tcpProxy.Close()`.
    3. Measure elapsed time for `Close()` completion.
    4. Verify all client connections receive read/write errors.
    5. Attempt a new connection to proxy; verify connection is refused.
  - **Subtest 7B (UDP Proxy Shutdown)**:
    1. Transmit continuous UDP datagram streams across 5 concurrent client sessions.
    2. Concurrently invoke `udpProxy.Close()`.
    3. Measure elapsed time for `Close()` completion.
    4. Verify listener socket, worker pool, sweeper routine, and all cached upstream session sockets are closed.
- **Verifiable Assertions**:
  1. Both `tcpProxy.Close()` and `udpProxy.Close()` return cleanly within $\le 500\text{ms}$ without deadlocking.
  2. All tracked active TCP client connections and upstream connections are closed immediately.
  3. All cached UDP upstream session sockets are closed, and worker/sweeper goroutines terminate.
  4. Post-shutdown socket dial attempts fail immediately.
  5. Zero goroutine leaks or socket file descriptor leaks remain after shutdown.
