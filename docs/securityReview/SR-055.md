# SR-055 - Security Review of Config-Based Multi-Stream Logging and System Logrotate Support

## Description

Security assessment of the multi-stream logging implementation in `pkg/logging`, routing integration in `pkg/router`, and configuration in `pkg/config`. The review evaluates file path handling, permission boundaries, log injection defenses, client IP extraction security, concurrency safety, and signal handling during logrotate reopening.

## Scope

- Files reviewed:
  - `pkg/logging/manager.go`
  - `pkg/logging/manager_test.go`
  - `pkg/config/config.go`
  - `pkg/config/config_test.go`
  - `pkg/router/router.go`
  - `pkg/router/router_test.go`
  - `cmd/toron/main.go`
  - `etc/logrotate.d/toron`

## Findings

### Finding 1: File Permissions on Log Creation
- Severity: Low / Informational
- Location: `pkg/logging/manager.go:67`
- Description: `os.OpenFile` uses mode `0644` with `O_CREATE|O_WRONLY|O_APPEND`. On shared multi-user systems, world-readable log files could expose request paths or headers to other local unprivileged users.
- Impact: In standard containerized or dedicated cloud VMs, `0644` is standard and safe. However, in sensitive shared host setups, `0640` with group access is preferred.
- Recommendation: The `etc/logrotate.d/toron` config sets `create 0640 root root`, mitigating exposure for rotated logs.

### Finding 2: Safe Client IP Extraction
- Severity: Informational
- Location: `pkg/logging/manager.go:497`
- Description: `ExtractClientIP` checks `req.RawConn.RemoteAddr()` first if available before falling back to `X-Forwarded-For` or `X-Real-IP`.
- Impact: Prevents remote spoofing of IP addresses when directly connected over raw sockets.

### Finding 3: Log Injection and CRLF Sanitization
- Severity: Informational
- Location: `pkg/logging/manager.go:370`
- Description: In JSON format, strings are safely escaped by `encoding/json.Marshal`, neutralizing CRLF injection. In Combined text format, path and method inputs from `httpparser` have already undergone strict RFC 7230 header and path sanitization.

## Positive Observations

- **Append Mode Concurrency (`O_APPEND`)**: All file sinks use OS-level `O_APPEND`, preventing file pointer clobbering across concurrent worker goroutines and ensuring safe operation with `copytruncate`.
- **Atomic Reopening (`SIGHUP`)**: The `Reopen()` method locks the sink mutex, closes the active descriptor, and re-opens the file handle without race conditions or memory leaks.
- **Per-Route Silencing**: Routes can specify `access_log: "off"`, preventing logging of sensitive internal token exchanges or health checks.

## Missing Security Tests

- None. Concurrency and race-safety are verified with `go test -race`.

## Constraints & Rationale

No third-party logging packages were introduced, preserving Toron's zero-dependency baseline.
