# REQ-036 - Multi-Scheme Authentication Middleware (JWT HS256, API Key, and HTTP Basic Auth)

## Description

The Toron web server shall provide a modular, high-performance authentication middleware supporting multiple authentication schemes for protecting routes, static assets, and upstream reverse proxy targets.

The authentication engine shall support:
1. **JSON Web Token (JWT) Verification (RFC 7519)**:
   - Extract Bearer tokens from `Authorization: Bearer <token>` header.
   - Verify cryptographic signatures using standard HMAC-SHA256 (`HS256`, `HS384`, `HS512`) secrets without third-party dependencies.
   - Enforce standard claim validations: expiration (`exp`), not-before (`nbf`), issuer (`iss`), and audience (`aud`).
   - Extract subject (`sub`) and user context, injecting `X-User-Id` / `X-Authenticated-User` headers into upstream reverse proxy requests.
2. **API Key Authentication**:
   - Extract API keys from `X-API-Key` header, `Authorization: ApiKey <key>`, or `?api_key=` query parameter.
   - Validate against configured key allowlists using constant-time string comparison (`crypto/subtle`).
3. **HTTP Basic Authentication (RFC 7617)**:
   - Extract `Authorization: Basic <base64(user:pass)>` credentials.
   - Validate username/password against configured user tables using constant-time comparison.
   - Return `401 Unauthorized` with `WWW-Authenticate: Basic realm="Toron"` header upon failure.
4. **Rejection & Error Handling**:
   - Reject unauthenticated or invalid requests with `401 Unauthorized` status and structured JSON error payload.
5. **Configuration Flexibility**:
   - Support route-level authentication in `routes.yaml` and global settings in `config.yaml`.

## Acceptance Criteria

- `pkg/router`: `AuthMiddleware` verifies JWT tokens (HMAC-SHA256), API keys, and HTTP Basic credentials.
- Valid requests pass through to the target handler with authenticated identity headers forwarded to upstreams.
- Missing, expired, malformed, or unauthorized requests return HTTP `401 Unauthorized` and `Content-Type: application/json`.
- Signature verification uses standard library `crypto/hmac` and `crypto/sha256`.
- `routes.yaml` and `config.yaml` support configuring authentication types and credentials.
- All Go unit tests pass cleanly (`go test ./...`).

## Rationale

Authentication is a fundamental requirement for edge reverse proxies and API gateways, ensuring microservices are protected from unauthorized access at the network edge.
