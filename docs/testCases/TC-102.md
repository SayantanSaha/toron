# TC-102 - Verification Suite for Tightened Path Traversal Test Oracles and Deterministic Canary Defense

## 1. Test Suite Objectives

Verify that `benchmarks/fuzzer/diff_fuzzer.go` test oracles for path traversal attacks (`TRAVERSAL-001..003`) strictly reject HTTP 404 responses, accept only active defense status codes (`400 Bad Request` or `403 Forbidden`), fail on canary leakage (`200 OK`), and deterministically evaluate traversal protection against an established canary file.

## 2. Test Cases

### TC-102-01: Rejection of HTTP 404 False-Positive Pass
- **Objective**: Confirm that a server returning HTTP 404 to traversal payloads is marked as FAILED by `executeRawTest`.
- **Expected Outcome**: `res.Passed == false`, `res.FailureReason` details received status 404 while expecting 400 or 403.

### TC-102-02: Acceptance of HTTP 403 Active Guard Rejection
- **Objective**: Confirm that a server returning HTTP 403 (Toron's static traversal guard or WAF policy) is marked as PASSED.
- **Expected Outcome**: `res.Passed == true`, `res.ActualStatus == 403`.

### TC-102-03: Acceptance of HTTP 400 Canonicalization Rejection
- **Objective**: Confirm that a server returning HTTP 400 (pre-routing path canonicalization rejection) is marked as PASSED.
- **Expected Outcome**: `res.Passed == true`, `res.ActualStatus == 400`.

### TC-102-04: Rejection of HTTP 200 Canary Leakage
- **Objective**: Confirm that a vulnerable mock server serving the canary file with HTTP 200 OK is marked as FAILED.
- **Expected Outcome**: `res.Passed == false`, `res.FailureReason` details received status 200.

### TC-102-05: Live Target Traversal Invariant Enforcement
- **Objective**: Execute traversal test cases against live Toron instance and verify that all three vectors (`TRAVERSAL-001..003`) pass with strictly 400 or 403.
- **Expected Outcome**: `res.Passed == true`, `res.ActualStatus` $\in \{400, 403\}$.
