# REQ-085 - Kubernetes Ingress Route Hijacking and Administrative Route Shadowing Prevention

## Description

The native Kubernetes Ingress Controller (`pkg/ingress`) MUST enforce route prefix scoping, path canonicalization, and sensitive route shadowing protections in `TranslateIngress`, preventing untrusted cluster tenants from hijacking edge gateway root traffic or intercepting administrative, health, and telemetry endpoints.

## Problem Statement

In `pkg/ingress/translator.go`, `TranslateIngress` maps Kubernetes Ingress rules into `DiscoveredRoute` objects without validation against unhosted roots or reserved system paths.
1. An Ingress declaring an unhosted root (`host: ""` and `path: "/"`) captures 100% of unrouted or default host gateway traffic.
2. An Ingress declaring `/internal` or `/api/status` shadows the Toron administrative dashboard and telemetry APIs.
3. An Ingress declaring unhosted `/health` or `/metrics` can intercept Kubernetes container liveness probes or Prometheus metric scrapers.
4. Untrusted tenants sharing a multi-tenant Kubernetes cluster can leverage these gaps to execute cross-tenant traffic interception and phishing against edge gateway administrators.

## Acceptance Criteria

1. **Path Canonicalization**:
   - Every Ingress rule path MUST be canonicalized using `path.Clean` prior to validation and route translation, resolving dot-segments (`..`) and duplicate slashes (`//`).

2. **Unhosted Root Protection**:
   - An Ingress path rule evaluating to root (`""` or `"/"`) with an empty host (`host == ""`) MUST be rejected.
   - Root path rules are ONLY permitted if an explicit, non-empty `host` (e.g. `app.example.com`) is declared.

3. **Reserved Administrative Path Protection**:
   - Any Ingress rule matching or prefixing `/internal` (e.g. `/internal`, `/internal/*`) or `/api/status` (e.g. `/api/status`, `/api/status/*`) MUST be rejected unconditionally, regardless of declared host.

4. **Gateway Telemetry & Health Protection**:
   - Any Ingress rule with an empty host (`host == ""`) matching `/health` or `/metrics` MUST be rejected to preserve Kubernetes probes and telemetry scrapers.

5. **Security Audit Telemetry**:
   - When an Ingress rule is rejected due to security policy violations, a structured warning MUST be logged indicating the Ingress namespace, name, host, and rejected prefix.
   - Valid rules within the same Ingress object MUST continue to be processed without failing the entire Ingress unless all rules are invalid.

6. **Regression Invariants**:
   - Valid hosted Ingress rules (`host: "app.example.com"`, `path: "/"` or `path: "/api"`) MUST continue to translate and route properly.
   - All tests must pass race-clean with zero external dependencies.
