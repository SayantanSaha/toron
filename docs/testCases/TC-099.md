# TC-099 - Verification of Thread-Safe ReverseProxy Caching, Transport Teardown, and Client mTLS Lifecycle Management in Service Mesh Sidecar Proxy

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's Service Mesh Sidecar Proxy ([`pkg/sidecar/`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/)) enforces **thread-safe, origin-normalized reverse proxy caching, active TCP connection pooling, comprehensive transport socket teardown, and seamless client mutual TLS (mTLS) configuration propagation**, completely eliminating the critical resource exhaustion, socket descriptor leak, and security bypass vulnerabilities identified in security audit [`SR-091 Finding 7`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md) and vulnerability assessment [`SEC-37`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L492-L500) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html) and [CWE-772: Missing Release of Resource after Effective Lifetime](https://cwe.mitre.org/data/definitions/772.html)).

This test specification validates the architectural remediations defined in [`REQ-099`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md), [`ADR-099`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md), and [`TASK-122`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md) across [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go), [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go), [`pkg/sidecar/sidecar_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go), and [`pkg/proxy/proxy_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy_test.go), confirming that:

1. **Transport Singleton & TCP Connection Reuse per Origin (CWE-400 / CWE-772)**: Sequential and concurrent HTTP requests targeting the same destination origin reuse a single cached [`proxy.ReverseProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L36) and its underlying `*http.Transport` connection pool, enabling HTTP keep-alive connection reuse and completely eliminating per-request transport allocation.
2. **Multi-Target Backend Isolation**: Distinct target origins maintain independent cached reverse proxy instances with isolated connection pools and load balancer states.
3. **Canonical Origin Normalization ($O(U)$ Bounded Memory)**: Target URLs are normalized to their canonical origin (`scheme://host[:port]`), stripping path segments, query strings, and fragments. Diverse request paths targeting the same upstream service map to the exact same cache entry, preventing cache key explosion.
4. **Comprehensive Transport Teardown on Proxy Closure & Engine Shutdown**: Invoking `ReverseProxy.Close()` or `ProxyEngine.Stop()` explicitly closes all idle keep-alive connections on the transport via `tr.CloseIdleConnections()`, immediately terminating lingering sockets and preventing file descriptor exhaustion (`EMFILE`).
5. **Egress Client mTLS Configuration Plumbing**: `ProxyOptions` accepts a pre-compiled `TLSClientConfig *tls.Config` which is assigned to the transport in `NewProxyWithOptions`. Cached proxies in `ProxyEngine` inherit the engine's pre-compiled `p.clientTLS`, preserving client identity certificates, custom CA root pools, and minimum TLS 1.2 enforcement in compliance with [`REQ-097`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md) / `SEC-35`.
6. **Zero External Dependencies**: All locking, origin normalization, proxy caching, connection pooling, and lifecycle teardown strictly use the Go standard library (`net/http`, `crypto/tls`, `sync`, `net/url`, `io`, `fmt`, `time`, `strings`).
7. **Thread Safety & Race-Freedom**: Double-checked locking and proxy routing execute with 100% thread safety under `go test -race ./pkg/sidecar/... ./pkg/proxy/...`.

## 3. Detailed Test Case Specifications

### TC-099-01: Transport Singleton & Socket Descriptor Reuse across Sequential Requests

- **Objective**: Verify that when `ProxyEngine.proxyToURL` processes multiple sequential requests targeting the same destination origin with differing paths (e.g. `/users/1`, `/users/2`, `/orders/884`), exactly one `ReverseProxy` and underlying `*http.Transport` instance is created and cached in `p.proxies`, and that HTTP keep-alive connections are pooled and reused across requests.
- **Traceability**: [`REQ-099-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L127-L141), [`REQ-099-AC-05`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L150-L155), [`ADR-099 §3, §5`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L163-L254), [`TASK-122 §2, §3`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md#L163-L257), [`SEC-37`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L492-L500).
- **Target Function**: `TestProxyEngine_ProxyCaching_SingletonPerOrigin(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Upstream HTTP test server running on a local TCP listener recording remote TCP client addresses (`RemoteAddr`).
  - `ProxyEngine` initialized with a valid `SidecarConfig`.
- **Test Setup & Execution Steps**:
  1. Launch mock upstream HTTP server:
     ```go
     var mu sync.Mutex
     remoteAddrs := make(map[string]int)
     upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         mu.Lock()
         remoteAddrs[r.RemoteAddr]++
         mu.Unlock()
         w.WriteHeader(http.StatusOK)
         _, _ = w.Write([]byte(`{"status":"ok"}`))
     }))
     defer upstream.Close()
     ```
  2. Initialize `ProxyEngine`:
     ```go
     cfg := config.SidecarConfig{Enabled: true, Mode: "egress", EgressPort: 0}
     engine, err := NewProxyEngine(cfg)
     if err != nil { t.Fatalf("failed to create engine: %v", err) }
     defer engine.Stop()
     ```
  3. Execute 50 sequential requests through `proxyToURL` across varying paths:
     ```go
     for i := 0; i < 50; i++ {
         targetURL := fmt.Sprintf("%s/resource/%d?param=%d", upstream.URL, i, i*2)
         rec := httptest.NewRecorder()
         req := httptest.NewRequest("GET", targetURL, nil)
         engine.proxyToURL(rec, req, targetURL)
         if rec.Code != http.StatusOK {
             t.Fatalf("request %d failed with status %d", i, rec.Code)
         }
     }
     ```
  4. Inspect engine proxy cache:
     - Acquire `engine.mu.RLock()`.
     - Assert `len(engine.proxies) == 1`.
     - Retrieve cached proxy: `px := engine.proxies[canonicalOrigin]`.
     - Assert `px != nil`.
     - Release `engine.mu.RUnlock()`.
  5. Inspect upstream connection reuse:
     - Check `len(remoteAddrs)`.
     - With connection pooling active, `len(remoteAddrs)` MUST be $\le 2$ (typically exactly 1), proving that multiple requests reused the same underlying keep-alive TCP socket rather than creating 50 separate connections.
- **Verifiable Assertions**:
  1. `len(engine.proxies)` equals exactly 1 for 50 distinct request URLs.
  2. The cached `*proxy.ReverseProxy` pointer remains identical across all 50 invocations.
  3. Distinct client connection addresses `len(remoteAddrs)` is $\le 2$, confirming HTTP keep-alive connection reuse.
  4. Per-request allocation of `ReverseProxy`, `http.Client`, and `http.Transport` is completely eliminated.

### TC-099-02: Multi-Target Backend Isolation & Dedicated Origin Pools

- **Objective**: Verify that when `ProxyEngine` handles egress requests targeting multiple distinct upstream origins (e.g. `http://service-a:8081` and `http://service-b:8082`), the engine caches exactly one isolated `ReverseProxy` instance per origin in `p.proxies`, ensuring dedicated transport connection pools and independent load balancers.
- **Traceability**: [`REQ-099-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L127-L141), [`ADR-099 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L163-L254), [`TASK-122 §2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md#L163-L235).
- **Target Function**: `TestProxyEngine_MultiOrigin_Isolation(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Three distinct mock upstream servers running on different local ports (`upstream1`, `upstream2`, `upstream3`).
- **Test Setup & Execution Steps**:
  1. Initialize 3 mock upstream servers returning distinct identifiers:
     ```go
     srv1 := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Write([]byte("backend-1"))
     }))
     defer srv1.Close()
     srv2 := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Write([]byte("backend-2"))
     }))
     defer srv2.Close()
     srv3 := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Write([]byte("backend-3"))
     }))
     defer srv3.Close()
     ```
  2. Initialize `ProxyEngine` and send 10 requests to each server across varied paths.
  3. Verify responses match each backend's payload (`"backend-1"`, `"backend-2"`, `"backend-3"`).
  4. Inspect `engine.proxies`:
     - Assert `len(engine.proxies) == 3`.
     - Verify keys match canonical origins of `srv1.URL`, `srv2.URL`, and `srv3.URL`.
     - Verify proxy pointers `px1 != px2`, `px2 != px3`, `px1 != px3`.
- **Verifiable Assertions**:
  1. `len(engine.proxies)` equals exactly 3.
  2. Each origin maintains its own distinct `*proxy.ReverseProxy` instance.
  3. Traffic destined for `srv1` never routes through `srv2`'s transport or load balancer.

### TC-099-03: High-Concurrency Thread Safety & Race Freedom

- **Objective**: Verify that high-concurrency execution of `proxyToURL` and `getOrCreateProxy` across multiple origins and varied paths operates with 100% thread safety and zero data races under `go test -race`.
- **Traceability**: [`REQ-099-AC-09`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L172-L175), [`ADR-099 §5`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L500-L507), [`TASK-122 §5`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md#L280-L309).
- **Target Function**: `TestProxyEngine_HighConcurrency_RaceClean(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Two mock upstream HTTP servers running concurrently.
  - Test executed under Go's race detector (`go test -race`).
- **Test Setup & Execution Steps**:
  1. Launch 2 mock upstream servers.
  2. Instantiate `ProxyEngine`.
  3. Spawn 50 concurrent worker goroutines.
  4. Each worker issues 20 requests (total 1,000 requests) alternating between the two upstreams and generating random path/query arguments.
  5. Coordinate via `sync.WaitGroup`:
     ```go
     var wg sync.WaitGroup
     workers := 50
     requestsPerWorker := 20
     for w := 0; w < workers; w++ {
         wg.Add(1)
         go func(workerID int) {
             defer wg.Done()
             for i := 0; i < requestsPerWorker; i++ {
                 target := srv1.URL
                 if (workerID+i)%2 == 0 { target = srv2.URL }
                 targetURL := fmt.Sprintf("%s/path/%d/%d?token=xyz", target, workerID, i)
                 rec := httptest.NewRecorder()
                 req := httptest.NewRequest("GET", targetURL, nil)
                 engine.proxyToURL(rec, req, targetURL)
                 if rec.Code != http.StatusOK {
                     t.Errorf("worker %d request %d failed: %d", workerID, i, rec.Code)
                 }
             }
         }(w)
     }
     wg.Wait()
     ```
  6. Verify outcome:
     - All 1,000 requests complete with HTTP 200 OK.
     - `len(engine.proxies)` equals exactly 2.
     - Zero race warnings detected.
- **Verifiable Assertions**:
  1. Double-checked locking in `getOrCreateProxy` is 100% race-free.
  2. Exactly 2 `ReverseProxy` instances are instantiated despite 50 concurrent goroutines racing on cache misses during initialization.
  3. Zero panics, memory corruption, or map concurrent read/write errors.

### TC-099-04: Clean Teardown on `ProxyEngine.Stop()` & Idle Socket Release

- **Objective**: Verify that calling `ProxyEngine.Stop()` iterates over all cached `ReverseProxy` instances in `p.proxies`, invokes `px.Close()` on each (closing idle connections via `tr.CloseIdleConnections()`), clears `p.proxies`, and leaves zero lingering socket descriptors or goroutines.
- **Traceability**: [`REQ-099-AC-06`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L156-L161), [`ADR-099 §6`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L324-L364), [`TASK-122 §4`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md#L258-L277), [`SEC-37`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L492-L500).
- **Target Function**: `TestProxyEngine_Stop_CleansUpAllProxies(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Two mock upstream servers.
  - Active keep-alive connections established to both upstreams.
- **Test Setup & Execution Steps**:
  1. Start 2 upstream servers.
  2. Instantiate `ProxyEngine` and send requests to both servers to populate `p.proxies`.
  3. Verify `len(engine.proxies) == 2`.
  4. Record baseline goroutine count: `initialGoroutines := runtime.NumGoroutine()`.
  5. Invoke `engine.Stop()`.
  6. Inspect `engine.proxies`:
     - Acquire `engine.mu.RLock()`.
     - Assert `len(engine.proxies) == 0`.
     - Release `engine.mu.RUnlock()`.
  7. Allow transient connections to close (`time.Sleep(100 * time.Millisecond)`).
  8. Assert goroutines return to baseline ($\pm 2$ runtime background threads).
  9. Verify calling `engine.Stop()` a second time is safe and idempotent (no panics).
- **Verifiable Assertions**:
  1. `p.proxies` is completely emptied on `Stop()`.
  2. `px.Close()` is invoked on every cached proxy.
  3. All idle connections across all cached transports are terminated.
  4. Subsequent calls to `engine.Stop()` are idempotent and panic-free.

### TC-099-06: Canonical Target URL Origin Normalization ($O(U)$ Bounded Memory)

### TC-099-07: `ReverseProxy.Close()` Idle Transport Connection Closure

- **Objective**: Unit test verifying that `ReverseProxy.Close()` invokes `tr.CloseIdleConnections()` on the underlying HTTP transport (`p.Client.Transport.(*http.Transport)`), immediately terminating all idle TCP connections.
- **Traceability**: [`REQ-099-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L101-L112), [`ADR-099 §1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L103-L128), [`TASK-122 §1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-122.md#L150-L160), [`SEC-37`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L492-L500).
- **Target Function**: `TestReverseProxy_Close_ClosesIdleConnections(t *testing.T)` in `pkg/proxy/proxy_test.go`.
- **Preconditions**:
  - Mock upstream server that logs active connection closure.
- **Test Setup & Execution Steps**:
  1. Launch upstream test server.
  2. Instantiate `ReverseProxy` using `NewProxyWithOptions(ProxyOptions{Targets: []string{upstream.URL}})`.
  3. Dispatch an HTTP request using `px.ServeHTTP` to establish an active keep-alive connection in the transport pool.
  4. Verify the transport has an idle connection:
     ```go
     tr, ok := px.Client.Transport.(*http.Transport)
     if !ok { t.Fatalf("expected *http.Transport") }
     ```
  5. Call `px.Close()`.
  6. Verify outcome:
     - `p.Balancer.Stop()` has been called (balancer stopped).
     - `tr.CloseIdleConnections()` has been executed.
     - Sockets transition to closed state without lingering.
     - Calling `px.Close()` when `p.Client == nil` or `p.Client.Transport` is nil does not panic.
- **Verifiable Assertions**:
  1. `ReverseProxy.Close()` executes without panic when `p.Client` or `p.Balancer` are nil/mocked.
  2. Idle transport connections are cleanly terminated upon invocation.
  3. Socket descriptors are promptly released back to the operating system.
