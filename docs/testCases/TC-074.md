# TC-074 - Verification of Multiple & Conflicting Content-Length Rejection (RFC 7230 §3.3.2)

## Objective

Verify that `httpparser.ParseRequest` rejects requests containing multiple distinct `Content-Length` headers or comma-separated lists with `HTTP 400 Bad Request`, preventing CL.CL desynchronization attacks.

## Test Cases

### TC-074-01: Conflicting Multiple Content-Length Headers
- **Setup**: Raw HTTP client connection.
- **Action**: Transmit `POST /api HTTP/1.1\r\nHost: example.com\r\nContent-Length: 0\r\nContent-Length: 45\r\n\r\n`.
- **Expected Outcome**:
  - Request is rejected with `HTTP 400 Bad Request`.
  - Socket does not leave unread body bytes for subsequent keep-alive loops.

### TC-074-02: Comma-Separated Distinct Content-Length
- **Setup**: Raw HTTP client connection.
- **Action**: Transmit `POST /api HTTP/1.1\r\nHost: example.com\r\nContent-Length: 10, 20\r\n\r\n0123456789`.
- **Expected Outcome**:
  - Request is rejected with `HTTP 400 Bad Request`.

### TC-074-03: Duplicate Identical Content-Length Headers
- **Setup**: Raw HTTP client connection.
- **Action**: Transmit `POST /api HTTP/1.1\r\nHost: example.com\r\nContent-Length: 10\r\nContent-Length: 10\r\n\r\n0123456789`.
- **Expected Outcome**:
  - Request is accepted; body of exactly 10 bytes is read.
