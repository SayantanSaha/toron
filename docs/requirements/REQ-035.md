# REQ-035 - In-Memory HTTP Response Caching Middleware and Cache Control Engine

## Description

The Toron web server shall provide a thread-safe in-memory HTTP response caching engine and middleware. The caching engine will store and serve repeated idempotent GET and HEAD requests directly from RAM, reducing latency to sub-millisecond speeds and drastically decreasing load on upstream microservices and static asset storage.

The caching engine shall:
1. Cache responses for idempotent HTTP methods (`GET`, `HEAD`) indexed by request URI, domain Host, and HTTP method.
2. Honor standard RFC 7234 HTTP caching semantics:
   - Parse `Cache-Control` response directives (`max-age=N`, `no-store`, `no-cache`, `private`, `public`).
   - Fall back to a configurable default TTL (e.g. 60 seconds) when `Cache-Control` header is omitted on eligible 200 OK responses.
   - Respect client request cache bypass directives (`Cache-Control: no-cache`, `Pragma: no-cache`).
3. Add telemetry and diagnostics headers on responses:
   - `X-Cache: HIT` or `X-Cache: MISS`.
   - `Age: <seconds>` indicating the elapsed time since response was originally cached.
4. Protect against memory bloat using a thread-safe cache store with:
   - Maximum entry count limits (`max_entries`).
   - Maximum cached payload size limits (`max_payload_size`).
   - Active background expiration and passive on-read eviction of expired entries.
5. Bypass caching for:
   - Non-cacheable HTTP methods (POST, PUT, DELETE, PATCH, CONNECT).
   - WebSocket upgrades (`101 Switching Protocols` / `UpgradedConn != nil`).
   - Responses containing `no-store` or `private` (when Authorization is present).
   - Responses with uncacheable error status codes (e.g. 500, 502, 503).
6. Support global configuration in `config.yaml` (`server.cache`).

## Acceptance Criteria

- `pkg/router`: `CacheMiddleware` and `ResponseCache` provide thread-safe storage, retrieval, and eviction of HTTP responses.
- Repeated GET requests to a cacheable endpoint return `X-Cache: HIT` with identical status, headers, and body, along with a calculated `Age` header.
- Responses with `Cache-Control: no-store` or `no-cache` are not stored in cache.
- Requests with `Cache-Control: no-cache` or `Pragma: no-cache` bypass the cache and fetch fresh responses (`X-Cache: MISS`).
- Cached items automatically expire after their `max-age` or `default_ttl` duration.
- Memory usage is bounded by `max_entries` and `max_payload_size`.
- `config.yaml` supports `server.cache` properties (`enabled`, `default_ttl`, `max_entries`, `max_payload_size`).
- All Go unit tests pass cleanly (`go test ./...`).

## Rationale

HTTP response caching is essential for API gateways and web servers, reducing backend compute load, saving network bandwidth, and delivering fast response times for static assets and repeated API queries.
