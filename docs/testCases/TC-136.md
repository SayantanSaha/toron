# TC-136 - Verification Suite for Native Dynamic 2-Stage WAF Auto-Ban Engine and Persistent Storage

## 1. Test Suite Overview

This test suite verifies:
1. **Strike Tracking & Sliding Window**: Verifies that violations within the sliding window trigger a temporary ban once `max_violations` is reached, and expired strikes fall outside the window.
2. **Stage 1 Temporary Ban**: Verifies that a temporarily banned IP is immediately rejected with HTTP 403, and automatically becomes unbanned after `ban_duration` expires.
3. **Stage 2 Permanent Ban Escalation**: Verifies that an IP accumulating $\ge \text{max\_temporary\_bans}$ escalates to permanent ban status (never expiring).
4. **Fast-Path Rejection**: Verifies that banned IP requests are dropped before AST/regex inspection.
5. **CIDR Allowlist Immunity**: Verifies that whitelisted IPs/subnets (e.g. `127.0.0.1`, `::1`) never accumulate strikes or get banned.
6. **Atomic State File Persistence**: Verifies that bans and strike records are saved to JSON disk storage using atomic file replacement and correctly reloaded across manager reinstantiations.
7. **Management APIs**: Verifies `/internal/api/security/banned-ips`, `/internal/api/security/unban`, and `/internal/api/security/ban` endpoints.
8. **Concurrency & Thread Safety**: Verifies that concurrent strike records and ban checks operate without race conditions (`go test -race`).

---

## 2. Test Cases

### TC-136-01: Sliding Window Strike Accumulation and Temporary Ban Trigger
- **Action**: Emit `max_violations` (e.g. 3) WAF violations for IP `198.51.100.1` within the sliding window (e.g. 60s).
- **Expected Outcome**: On the 3rd violation, `IsBanned("198.51.100.1")` returns `true` with `Type: "temporary"`, `TempBanCount: 1`, and `ExpiresAt` set to `time.Now().Add(banDuration)`.

### TC-136-02: Stage 2 Permanent Ban Escalation
- **Action**: Simulate temporary ban expiration, re-strike to trigger temporary ban 2, expire, and re-strike to reach `max_temporary_bans` (e.g. 3).
- **Expected Outcome**: On reaching the 3rd temporary ban threshold, the IP escalates to `Type: "permanent"`, with `ExpiresAt` zero/nil, never expiring.

### TC-136-03: CIDR Whitelist Immunity
- **Action**: Emit 20 consecutive violations for `127.0.0.1` and `10.0.0.5` (matching configured whitelists `127.0.0.1/32`, `10.0.0.0/8`).
- **Expected Outcome**: `IsBanned()` returns `false`; zero strikes or bans are recorded.

### TC-136-04: Atomic State File Persistence & Reload
- **Action**: Populate ban table with 1 temporary ban and 1 permanent ban. Call `SaveState()`. Instantiate a new `AutoBanManager` with the same `persistence_file` path.
- **Expected Outcome**: The new manager immediately loads the permanent ban and unexpired temporary ban with intact metadata and escalation counts.

### TC-136-05: Manual Ban & Unban API Operations
- **Action**: Call `Unban("198.51.100.1")` via manager and API.
- **Expected Outcome**: Ban entry is deleted from memory, strikes are cleared, and state file is atomically updated. `IsBanned("198.51.100.1")` returns `false`.

### TC-136-06: High-Concurrency Multi-Threaded Stress Test
- **Action**: Run 50 parallel goroutines recording strikes and verifying bans simultaneously.
- **Expected Outcome**: Zero data races or deadlocks detected under `go test -race`.
