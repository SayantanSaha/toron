# REQ-125 - Conditional Direct Socket Streaming Fast-Path and Response Buffer Pooling Architecture

## 1. Description & Problem Statement

### 1.1 Problem Context
Profiling in [`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md) and [`REQ-124`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-124.md) demonstrated that Toron's reverse proxy throughput (~24.5k RPS) is competitive with Traefik (~24.0k RPS) and superior to Caddy (~18.3k RPS). However, Traefik achieved a ~0.19ms lower median latency (P50 0.97ms vs Toron's 1.16ms).

In Toron's proxy response path:
1. In [`pkg/proxy/proxy.go:1037`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1037), `io.Copy(res.Body, outResp.Body)` reads the entire upstream HTTP response payload into `res.Body` (`*bytes.Buffer`).
2. In [`pkg/httpparser/response.go:97`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/response.go#L97), `res.Serialize(conn)` allocates a second `bytes.Buffer`, serializes status line and headers, copies `res.Body.Bytes()`, and issues `conn.Write(buf.Bytes())`.

This pipeline incurs **two full in-memory body copies** and dynamic heap allocations per request. In contrast, Traefik and Caddy utilize direct streaming models (`io.CopyBuffer` from upstream response stream directly into the client connection writer) with zero intermediate payload buffering.

Furthermore, architectural analysis identified a critical transport timeout flaw:
In [`pkg/proxy/proxy.go:551`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L551) and [`line 654`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L654), Toron configures `p.Client.Timeout = 10 * time.Second`. In Go's `net/http.Client`, `Timeout` specifies an absolute aggregate deadline for the entire request lifecycle, including dial, TLS handshake, redirects, and reading `Response.Body`. Consequently, any long-lived streaming connection—such as Server-Sent Events (SSE, `text/event-stream`), live telemetry, or chunked transfer streams lasting longer than 10 seconds—is abruptly aborted by `http.Client.Timeout`. Upstream body streaming must be decoupled from monolithic client timeouts by relying on `ResponseHeaderTimeout` and activity-aware deadlines.

### 1.2 Prior Requirements & Standards Cross-Audit (Conflict Analysis)

A direct, unconditional streaming implementation from upstream into the client socket introduces critical architectural and protocol conflicts:

1. **Conflict with [`REQ-017`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-017.md) / [`ADR-017`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-017.md) & [`REQ-034`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-034.md) / [`ADR-029`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-029.md) (Transparent Response Compression)**:
   - `CompressionMiddleware` (`pkg/router/compression.go`) runs after the downstream handler completes. It evaluates `res.Body.Len()`, verifies MIME compressibility, compresses `res.Body.Bytes()` using Zstd/Brotli/Gzip/Deflate, swaps `res.Body`, and updates `Content-Length`.
   - *Conflict*: If `ReverseProxy` flushes bytes directly to `net.Conn`, `CompressionMiddleware` cannot compress the body or update `Content-Length`, corrupting downstream compression.
2. **Conflict with [`REQ-019`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-019.md) / [`REQ-035`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-035.md) / [`ADR-030`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-030.md) (In-Memory Response Caching)**:
   - `CacheMiddleware` (`pkg/router/cache.go`) inspects `res.StatusCode`, evaluates payload limits, and clones `res.Body.Bytes()` into the cache registry.
   - *Conflict*: If `ReverseProxy` streams directly to the socket, `CacheMiddleware` cannot capture payloads for caching.
3. **Conflict with [`REQ-004`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-004.md) / [`ADR-004`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-004.md) (Header & Cookie Rewriting)**:
   - If response bytes are streamed before status and headers are fully committed, subsequent cookie path rewriting or 3xx redirect rewriting is impossible.
4. **Resolution via [`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md) (Streaming Middleware Exemptions)**:
   - Under `REQ-128`, unbuffered streaming responses (`text/event-stream` or `X-Accel-Buffering: no`) are explicitly exempt from both caching and compression. Therefore, the streaming fast-path MUST NOT be blocked merely because caching or compression are globally enabled on the route when the upstream response indicates an unbuffered or streaming MIME type.

### 1.3 Safe Non-Conflicting Path
To achieve the latency benefits of direct socket streaming without breaking compression, caching, or header rewriting:
1. **Conditional Direct Streaming Fast-Path**: Enable zero-copy socket streaming when:
   - Compression is disabled AND caching is disabled on the route AND streaming is permitted (`stream_response: true` or "raw_speed" profile); OR
   - The upstream response is identified as an unbuffered streaming response (e.g. `Content-Type: text/event-stream` or `X-Accel-Buffering: no`), which bypasses caching and compression per `REQ-128` regardless of route-level defaults.
2. **Transport Timeout Decoupling**: Decouple upstream response body streaming from `p.Client.Timeout = 10s`. Bound connection dial and response header receipt via `ResponseHeaderTimeout` (10s) and `DialContext` timeout, while setting `p.Client.Timeout = 0` (or leaving response body read decoupled) so that persistent event streams remain active indefinitely.
3. **Response Buffer Memory Pooling (`sync.Pool`)**: When buffering is required for compression or caching, eliminate heap allocation churn by replacing arbitrary dynamic `bytes.Buffer` instantiation with a recycled buffer pool slab.
4. **Zero-Copy Dual-Write Serialization**: In `res.Serialize`, avoid copying the payload into an intermediate serialization buffer; serialize headers directly and stream `res.Body` via `res.Body.WriteTo(w)` or multi-part write.

## 2. Functional Requirements

### 2.1 Transport Streaming Knob and Timeout Decoupling
1. Extend [`ProxyTransportConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L258) with:
   ```go
   StreamResponse        *bool         `yaml:"stream_response,omitempty" json:"stream_response,omitempty"`
   ResponseHeaderTimeout time.Duration `yaml:"response_header_timeout,omitempty" json:"response_header_timeout,omitempty"`
   ```
2. Profile defaults in `DefaultProxyTransportConfig`:
   - **`profile: "raw_speed"`**: `StreamResponse = &true`, `ResponseHeaderTimeout = 10 * time.Second`.
   - **`profile: "balanced"`**: `StreamResponse = &false`, `ResponseHeaderTimeout = 10 * time.Second`.
3. Support global transport (`config.yaml`: `proxy.transport.stream_response`) and per-route transport (`routes.yaml`: `routes[].transport.stream_response`) overriding.
4. **Upstream Body Streaming Decoupling**:
   - In `pkg/proxy/proxy.go`, configure upstream `http.Transport.ResponseHeaderTimeout` to bound time-to-first-response-header.
   - Decouple `p.Client.Timeout` from body reading: set `p.Client.Timeout = 0` (or utilize a non-body-bounding transport) so that long-lived response bodies (e.g., SSE) are not terminated after 10s. Connection establishment continues to be guarded by `Dialer.Timeout`.

### 2.2 Route-Aware & Content-Aware Streaming Eligibility Guard
1. `ReverseProxy` shall determine streaming eligibility upon inspecting the route configuration and upstream response headers:
   ```go
   contentType := strings.ToLower(outResp.Header.Get("Content-Type"))
   isStreamingMIME := strings.HasPrefix(contentType, "text/event-stream")
   isUnbuffered := strings.EqualFold(outResp.Header.Get("X-Accel-Buffering"), "no")
   
   // Direct streaming applies if route has no compression/cache, OR if the response
   // is an unbuffered/streaming response that bypasses them per REQ-128.
   canStream := p.streamResponse && (!p.routeHasCompression && !p.routeHasCache || isStreamingMIME || isUnbuffered)
   ```
2. If `canStream == true`:
   - Commit any header/cookie rewriting (e.g., sticky cookies, 3xx redirect Location rewriting) to the header collection.
   - Serialize status line and filtered headers (stripping RFC 7230 hop-by-hop headers) directly to client `net.Conn`.
   - Stream upstream `outResp.Body` directly to client `net.Conn` using a pooled 32KB/64KB copy buffer (`io.CopyBuffer`).
   - Flush bytes immediately upon arrival, eliminating intermediate `res.Body` buffering.
3. If `canStream == false`:
   - Buffer upstream response payload into `res.Body` to allow downstream `CompressionMiddleware` and `CacheMiddleware` to process and modify the payload before final wire transmission.

### 2.3 Buffer Recycling (`sync.Pool`) for Buffered Responses
1. Implement a thread-safe `sync.Pool` for `bytes.Buffer` in `pkg/httpparser` or `pkg/proxy`.
2. Ensure recycled buffers are reset (`buf.Reset()`) prior to reuse, avoiding cross-request data leaks.
3. In `res.Serialize`, serialize headers into a recycled header buffer, then write `res.Body` directly to the socket without allocating a combined memory buffer.

## 3. Non-Functional Requirements

### 3.1 Latency & Allocation Reduction
- Reduce median proxy latency by ~0.10ms on streaming-eligible routes.
- Eliminate heap memory allocations for payload buffering during streaming fast-path execution.
- Maintain real-time event delivery latency without client-side timeout cutoffs.

### 3.2 Protocol & Security Invariants
- Strict compliance with RFC 7230 §6.1 hop-by-hop header stripping must be enforced on streamed responses before the first byte is transmitted.
- Status codes $\ge 500$ must continue to register failure telemetry in circuit breakers and health trackers.
- RFC 7234 compliance: streaming and unbuffered responses must not be cached per [`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md).

### 3.3 Zero Third-Party Dependencies
- All streaming pipelines, buffer pools, transport configurations, and copying routines must rely solely on Go standard library (`io`, `net`, `net/http`, `sync`, `bytes`).

## 4. Acceptance Criteria

1. **`pkg/config`**:
   - `ProxyTransportConfig` includes `StreamResponse *bool `yaml:"stream_response,omitempty" json:"stream_response,omitempty"`` and `ResponseHeaderTimeout time.Duration `yaml:"response_header_timeout,omitempty" json:"response_header_timeout,omitempty"``.
   - `DefaultProxyTransportConfig("raw_speed")` sets `StreamResponse = &true` and `ResponseHeaderTimeout = 10s`.
   - `DefaultProxyTransportConfig("balanced")` sets `StreamResponse = &false` and `ResponseHeaderTimeout = 10s`.
   - Route-level `stream_response` overrides cascade correctly over global settings.
2. **`pkg/proxy`**:
   - Upstream client transport enforces `ResponseHeaderTimeout` for header receipt, but decouples response body streaming from a hard 10s `p.Client.Timeout`.
   - `ReverseProxy` executes direct streaming when `canStream == true`, including on routes with compression/cache enabled if the response is `text/event-stream` or `X-Accel-Buffering: no`.
   - When standard non-streaming responses occur on routes with compression or caching active, reverse proxy falls back to buffered `res.Body` with zero functional regressions.
3. **Automated Unit & Integration Tests**:
   - Unit tests verify streaming fast-path byte delivery, immediate flushing, and header preservation.
   - Long-lived streaming integration tests verify that persistent streams (e.g. SSE lasting $> 10\text{s}$) stream chunks continuously without being terminated by client timeouts.
   - Integration tests verify that routes with `compression: true` or `cache: true` correctly compress and cache standard responses without corruption, while bypassing unbuffered streams.
4. **Race Safety**:
   - All tests pass cleanly under `go test -race ./pkg/config/... ./pkg/proxy/...`.
