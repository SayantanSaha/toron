# TC-098 - Verification of Bounded Request Ingestion, Configurable Upstream Response Buffering, and Safe Connection Draining in Internal API Proxy Test Probe

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's administrative internal API endpoint `POST /internal/api/proxy-test` ([`pkg/server/internal_api.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go)) enforces **strictly bounded memory consumption, configurable response payload clamping with truncation signaling, and safe transport connection lifecycle management**, completely eliminating the critical resource exhaustion and socket descriptor leak vulnerabilities identified in security audit [`SR-091 Finding 6`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L197-L212) and vulnerability assessment [`SEC-36`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L483-L491) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html), [CWE-770: Allocation of Resources Without Limits or Throttling](https://cwe.mitre.org/data/definitions/770.html), and [CWE-775: Missing Release of File Descriptor or Handle after Effective Lifetime](https://cwe.mitre.org/data/definitions/775.html)).

This test specification validates the end-to-end architectural remediations defined in [`REQ-098`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md), [`ADR-098`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-098.md), and [`TASK-121`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-121.md) across [`pkg/server/internal_api.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go) and [`pkg/server/internal_api_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api_test.go), confirming that:

1. **Inbound Request Ingestion Capped at 64 KB (CWE-400)**: Inbound request payloads exceeding 64 KB (`65536` bytes) are rejected immediately with HTTP `400 Bad Request` (`"Request body exceeds maximum allowed size of 64KB"`) without initiating any upstream probe request.
2. **Configurable Upstream Response Limiting**: Upstream probe response body buffering is constrained by `InternalAPIConfig.MaxProxyTestResponseBytes`, defaulting strictly to **1 MB** (`1048576` bytes) when omitted, set to `0`, or configured with a negative integer.
3. **Deterministic Clamping & Truncation Signaling**: When an upstream response exceeds the configured byte ceiling, the payload is clamped to exactly `maxBytes`, the upstream HTTP status code and headers are preserved intact, and `Truncated: true` is populated in `ProxyTestResponse`. Responses within the limit preserve the complete body and report `Truncated: false`.
4. **Infinite Stream Bounded Termination & Memory Safety**: Probing an infinite or multi-gigabyte upstream stream (such as a chunked infinite generator or `/dev/urandom` stream) consumes no more than $O(\text{maxBytes})$ heap memory, terminates promptly within bounded time, and releases sockets without hanging.
5. **Safe Residual Draining & Clean Socket Teardown (CWE-775)**: Unread stream remnants are safely drained up to 64 KB into `io.Discard` before invoking `httpResp.Body.Close()`, ensuring HTTP/1.1 transport connection reuse in Go's keep-alive connection pool without socket leaks (`EMFILE`).
6. **Zero External Dependencies**: All streaming limits, bounded readers, truncations, and JSON serializations strictly utilize Go standard library primitives (`io`, `net/http`, `encoding/json`, `fmt`, `time`, `strings`).
7. **Thread Safety & Race-Freedom**: All bounded read and probe dispatch operations operate concurrently without race conditions under `go test -race ./pkg/server/...`.

## 3. Detailed Test Case Specifications

### TC-098-01: Normal Upstream Response Under Default Limit (`truncated: false`, full body intact)

- **Objective**: Verify that when an upstream service returns a response with a body size strictly within the default limit (1 MB, e.g. 512 bytes or 64 KB), `POST /internal/api/proxy-test` reads and returns the complete body without modification, sets `Truncated: false`, and accurately conveys the upstream HTTP status code and response headers.
- **Traceability**: [`REQ-098-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L93-L105), [`ADR-098 §2.2, §3.2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-098.md#L146-L192), [`TASK-121 §3, §5`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-121.md#L182-L257).
- **Target Function**: `TestProxyTest_NormalResponse_UnderLimit(t *testing.T)` in `pkg/server/internal_api_test.go`.
- **Preconditions**:
  - Mock upstream server running on local TCP listener returning a known payload of 512 bytes with HTTP 200 OK and custom header `X-Upstream-Header: healthy`.
  - Internal API router initialized with default `InternalAPIConfig` (`MaxProxyTestResponseBytes: 0`).
- **Test Setup & Execution Steps**:
  1. Initialize mock upstream server:
     ```go
     upstreamPayload := strings.Repeat("A", 512)
     upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Header().Set("Content-Type", "text/plain")
         w.Header().Set("X-Upstream-Header", "healthy")
         w.WriteHeader(http.StatusOK)
         _, _ = w.Write([]byte(upstreamPayload))
     }))
     defer upstream.Close()
     ```
  2. Parse port from upstream server URL and configure `InternalAPIConfig{Port: upstreamPort, AllowedProxyTestPaths: []string{"/health"}}`.
  3. Register internal API routes on router: `r := router.NewRouter(); RegisterInternalAPIRoutes(r, cfg)`.
  4. Dispatch test request to router:
     ```go
     reqBody := `{"path":"/health","method":"GET"}`
     req, _ := httpparser.NewRequest("POST", "/internal/api/proxy-test", "HTTP/1.1")
     req.Body = bytes.NewBufferString(reqBody)
     res := httpparser.NewResponse()
     r.ServeHTTP(req, res)
     ```
  5. Assert router response status is HTTP 200 OK.
  6. Unmarshal response body into `ProxyTestResponse`:
     - Assert `resOut.StatusCode == http.StatusOK` (200).
     - Assert `resOut.StatusText == "OK"`.
     - Assert `resOut.Headers["X-Upstream-Header"] == "healthy"`.
     - Assert `len(resOut.Body) == 512`.
     - Assert `resOut.Body == upstreamPayload`.
     - Assert `resOut.Truncated == false`.
- **Verifiable Assertions**:
  1. `resOut.StatusCode` strictly equals 200.
  2. `resOut.Body` matches the full 512-byte payload byte-for-byte.
  3. `resOut.Truncated` is strictly `false`.
  4. Upstream response headers are correctly mapped and returned in JSON output.

### TC-098-02: Oversized Upstream Response Truncation & Clamping (clamped to exactly 1 MB, `truncated: true`)

- **Objective**: Verify that when an upstream service returns a response exceeding the default 1 MB limit (e.g. 2.5 MB or 5 MB), `POST /internal/api/proxy-test` uses `io.LimitReader` to clamp the ingested body to exactly 1 MB (`1048576` bytes), populates `Truncated: true`, preserves the original upstream HTTP status code (e.g. 200 OK or 206 Partial Content), and avoids unbounded heap memory allocation.
- **Traceability**: [`REQ-098-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L93-L105), [`REQ-098-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L106-L114), [`ADR-098 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-098.md#L159-L192), [`TASK-121 §3, §5`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-121.md#L182-L257), [`SEC-36`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L483-L491).
- **Target Function**: `TestProxyTest_OversizedResponse_Truncated(t *testing.T)` in `pkg/server/internal_api_test.go`.
- **Preconditions**:
  - Mock upstream server configured to serve a 2.5 MB payload (`2621440` bytes) of pseudo-random or repetitive ASCII characters.
  - Internal API router initialized with default config (`MaxProxyTestResponseBytes: 0`, defaulting to 1 MB).
- **Test Setup & Execution Steps**:
  1. Initialize upstream test server:
     ```go
     const payloadSize = 2500 * 1024 // 2.5 MB
     upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Header().Set("Content-Type", "text/plain")
         w.WriteHeader(http.StatusOK)
         buf := make([]byte, 32*1024)
         for i := range buf { buf[i] = 'X' }
         written := 0
         for written < payloadSize {
             n := len(buf)
             if payloadSize - written < n { n = payloadSize - written }
             _, _ = w.Write(buf[:n])
             written += n
         }
     }))
     defer upstream.Close()
     ```
  2. Configure router with upstream port and path `/health`.
  3. Dispatch proxy test probe: `POST /internal/api/proxy-test` with `{"path":"/health","method":"GET"}`.
  4. Parse resulting JSON `ProxyTestResponse`:
     - Assert `resOut.StatusCode == http.StatusOK` (200).
     - Assert `resOut.Truncated == true`.
     - Assert `len(resOut.Body) == 1048576` (exactly 1 MB).
     - Assert `strings.HasPrefix(resOut.Body, "XXXX")`.
- **Verifiable Assertions**:
  1. Body length in response is strictly clamped to `1048576` bytes (`1 * 1024 * 1024`).
  2. `Truncated` boolean is strictly `true`.
  3. Upstream HTTP status code is 200 (not masked or converted to 502).
  4. Zero heap expansion beyond the 1 MB buffer window.

### TC-098-03: Infinite Streaming Upstream Probe Termination & Clean Socket Teardown

- **Objective**: Verify that probing an infinite streaming upstream (e.g. continuous `/dev/urandom` stream, unending chunked generator, or infinite SSE stream) terminates promptly within bounded memory, clamps the response body to 1 MB with `Truncated: true`, drains up to 64 KB of residual data, and closes the TCP socket without process hang, memory leak, or goroutine leak.
- **Traceability**: [`REQ-098-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L93-L105), [`REQ-098-AC-05`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L128-L136), [`ADR-098 §4`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-098.md#L194-L210), [`TASK-121 §4, §5`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-121.md#L212-L257), [`SEC-36`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L483-L491).
- **Target Function**: `TestProxyTest_InfiniteStream_BoundedTermination(t *testing.T)` in `pkg/server/internal_api_test.go`.
- **Preconditions**:
  - Mock upstream server configured to write an endless stream of bytes using `http.Flusher` until the client disconnects.
  - Internal API configured with default 1 MB limit.
- **Test Setup & Execution Steps**:
  1. Initialize infinite streaming server:
     ```go
     serverDone := make(chan struct{})
     upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         w.Header().Set("Content-Type", "application/octet-stream")
         w.WriteHeader(http.StatusOK)
         flusher, ok := w.(http.Flusher)
         chunk := bytes.Repeat([]byte("0123456789abcdef"), 4096) // 64 KB chunk
         for {
             select {
             case <-r.Context().Done():
                 close(serverDone)
                 return
             default:
                 _, err := w.Write(chunk)
                 if err != nil {
                     close(serverDone)
                     return
                 }
                 if ok { flusher.Flush() }
                 time.Sleep(1 * time.Millisecond)
             }
         }
     }))
     defer upstream.Close()
     ```
  2. Measure baseline goroutine count: `initialGoroutines := runtime.NumGoroutine()`.
  3. Dispatch probe request: `POST /internal/api/proxy-test` with `{"path":"/health","method":"GET"}` within a strict 3-second test timeout context.
  4. Parse `ProxyTestResponse`:
     - Assert probe completes in $< 2.0\text{ seconds}$ (no hang).
     - Assert `resOut.StatusCode == http.StatusOK`.
     - Assert `resOut.Truncated == true`.
     - Assert `len(resOut.Body) == 1048576` (clamped to 1 MB).
  5. Wait for upstream handler context cancellation:
     ```go
     select {
     case <-serverDone:
         // Successfully notified that client closed connection
     case <-time.After(2 * time.Second):
         t.Fatalf("upstream server did not receive socket closure from client")
     }
     ```
  6. Verify goroutine count returns to baseline ($\pm 2$ transient runtime workers).
- **Verifiable Assertions**:
  1. The proxy test terminates promptly after reading 1 MB + bounded drain without waiting for stream completion.
  2. `Truncated` is set to `true`.
  3. Upstream server context is canceled upon `httpResp.Body.Close()`, proving the TCP connection stream was severed.
  4. No lingering background read goroutines remain alive.

### TC-098-06: Inbound Client Request Payload Limit Enforcement (64 KB Cap Rejection)

- **Objective**: Verify that incoming HTTP request bodies sent to `POST /internal/api/proxy-test` are strictly bounded to 64 KB (`65536` bytes) via `io.LimitReader(req.Body, 64*1024+1)`, rejecting oversized requests with HTTP `400 Bad Request` before making any upstream call. Additionally verify that empty request bodies and invalid JSON payloads are rejected with HTTP 400.
- **Traceability**: [`REQ-098-AC-04`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-098.md#L115-L127), [`ADR-098 §2.1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-098.md#L125-L144), [`TASK-121 §2, §5`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-121.md#L141-L180), [`SEC-36`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L483-L491).
- **Target Function**: `TestProxyTest_OversizedRequestBody_Rejection(t *testing.T)` in `pkg/server/internal_api_test.go`.
- **Preconditions**:
  - Upstream server tracking received request count in an atomic integer counter `upstreamCalls`.
- **Test Scenarios Matrix**:

| Scenario ID | Inbound Request Payload Description | Size in Bytes | Expected HTTP Status | Expected Error / Message | Upstream Called? |
| :--- | :--- | :--- | :--- | :--- | :--- |

### TC-098-07: Safe Residual Stream Draining & Keep-Alive Connection Pool Reuse

- **Objective**: Verify that after reading up to `maxBytes + 1` from `httpResp.Body`, the handler safely drains pending residual bytes up to 64 KB into `io.Discard` and invokes `httpResp.Body.Close()`, allowing Go's `http.Transport` to reuse the underlying TCP socket in its keep-alive pool without socket descriptor leaks (`EMFILE`).

- **Target Function**: `TestProxyTest_SocketDrainAndConnectionReuse(t *testing.T)` in `pkg/server/internal_api_test.go`.
- **Preconditions**:
  - Upstream server tracking distinct remote TCP connection addresses (`RemoteAddr`).
- **Test Setup & Execution Steps**:
  1. Initialize upstream server that logs client connection addresses:
     ```go
     var connMutex sync.Mutex
     activeConns := make(map[string]int)
     upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
         connMutex.Lock()
         activeConns[r.RemoteAddr]++
         connMutex.Unlock()
         w.Header().Set("Content-Type", "text/plain")
         w.WriteHeader(http.StatusOK)
         // Serve 1.05 MB payload (slightly exceeds 1 MB default, triggering truncation and drain)
     ```

  3. Verify each response is truncated: `resOut.Truncated == true` and `len(resOut.Body) == 1048576`.
  4. Verify connection reuse:
     - Check the number of distinct `r.RemoteAddr` keys in `activeConns`.
     - With HTTP keep-alive reuse enabled by clean draining, multiple requests reuse the same underlying client connection rather than creating 10 fresh TCP sockets.
- **Verifiable Assertions**:
  1. Residual stream draining successfully clears socket buffers without blocking.
  2. `httpResp.Body.Close()` is invoked on every execution path.
  3. Zero socket descriptor leakage (`EMFILE`) across repeated oversized requests.
