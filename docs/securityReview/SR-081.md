# SR-081 - Complete Codebase Security Audit (Post-Remediation Assessment)

## Description

A complete, comprehensive security audit of the Toron Web Server and Edge Gateway codebase (`toron_v3`) following the successful remediation, verification, and commit of all 10 post-remediation security tasks (`TASK-073` through `TASK-082`). This audit evaluates the integrity of previous fixes and analyzes the entire codebase—including HTTP protocol parsing, server reactors, TLS/mTLS, routers, reverse proxies, WAF engines, container discovery, Kubernetes ingress controllers, service mesh sidecars, gRPC transcoders, and logging pipelines.

## Executive Summary & Prior Fix Verification

The prior 22 identified vulnerabilities (`SEC-01` through `SEC-22`) were audited and confirmed **100% Resolved**:
1. **SEC-13 (DOM XSS)**: `escapeHTML()` applied cleanly across all dynamic HTML insertions in `public/app.js`.
2. **SEC-14 (Header Whitespace Smuggling)**: `strings.ContainsAny(k, " \t\r\n")` strictly rejects illegal header field-name whitespace with HTTP 400.
3. **SEC-15 (Multiple Content-Length Desync)**: Multiple and conflicting `Content-Length` headers are rejected with HTTP 400; identical values are canonicalized.
4. **SEC-16 (HTTP/2 Body Bounding)**: `io.LimitReader(r.Body, maxBodyBytes+1)` returns HTTP 413 on payload overflow.
5. **SEC-17 (Reactor Keep-Alive Starvation)**: Non-blocking concurrent connection dispatch with `sync.Map`/connection tracking prevents worker pool starvation.
6. **SEC-18 (Root Path Exclusion Bypass)**: Exact-path equality and prefix slash delimiters prevent global auth/WAF bypasses.
7. **SEC-19 (Container Route Hijacking)**: Unhosted root routes and `/internal` prefix registrations from Docker labels are rejected.
8. **SEC-20 (WAF Traversal Pattern)**: `(?i)` case-insensitivity prevents uppercase percent-encoding bypasses in `TRAVERSAL-001`.
9. **SEC-21 (Sidecar Request Body Retention)**: Bounded body buffering preserves payload when proxying requests through `ProxyEngine`.
10. **SEC-22 (JWT exp Claim Enforcement)**: Missing `exp` claims fail validation by default unless explicitly opted into via `AllowNoExpiration`.

During this audit of peripheral and newly integrated subsystems (Kubernetes Ingress Controller, Layer 4 Proxies, gRPC Transcoding, Service Mesh Sidecar, WebSocket Upgrades), **8 new findings** (`SEC-23` through `SEC-30`) were identified.

## Findings

### Finding 1 (SEC-23): K8s Ingress Controller Watch Stream Unconsumed Channel Deadlock & Goroutine Leak
- **Severity**: **High** (CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H - Score 7.5)
- **Location**: `pkg/ingress/controller.go:44, 159-164`, `pkg/ingress/client.go:209`
- **CWE**: CWE-400, CWE-833
- **Description**:  
  `Controller` initializes an unconsumed events channel `events: make(chan K8sWatchEvent, 100)` and invokes `c.client.WatchIngresses(ctx, c.events)`. `WatchIngresses` reads streaming JSON events from the Kubernetes API server and performs `events <- evt`. Because no worker goroutine ever reads from `c.events`, the channel buffer fills up after 100 events. Once full, `events <- evt` blocks indefinitely. Because `ctx.Done()` is only evaluated at loop start, blocking on the unbuffered channel write prevents the goroutine from ever reading from `ctx.Done()`. During graceful shutdown, `c.Stop()` invokes `c.wg.Wait()`, which deadlocks forever waiting for `watchWorker` to terminate, causing server shutdown to hang. Furthermore, real-time Ingress create/update/delete events are never processed.
- **Impact**: Process shutdown deadlock, goroutine resource leak, and failure to process Kubernetes Ingress lifecycle events.
- **Recommendation**: Launch an event consumer worker `consumeEventsWorker(ctx)` in `Controller.Start` that continuously drains `c.events` and invokes `c.syncIngresses(ctx)` or event handlers, and ensure `WatchIngresses` selects on `ctx.Done()` when sending to `events`:
  ```go
  select {
  case events <- evt:
  case <-ctx.Done():
      return ctx.Err()
  }
  ```

### Finding 2 (SEC-24): Ingress Route Hijacking & Sensitive Route Shadowing in Kubernetes Ingress Controller
- **Severity**: **Medium** (CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:L/A:L - Score 6.3)
- **Location**: `pkg/ingress/translator.go:40-48`, `pkg/ingress/controller.go:146-154`
- **CWE**: CWE-284, CWE-285
- **Description**:  
  `TranslateIngress` converts Kubernetes Ingress rules into `DiscoveredRoute` entries. Unlike `pkg/discovery/parser.go` (hardened in `TASK-079`), `TranslateIngress` does not enforce route prefix scoping or root shadowing guards. Any Kubernetes tenant with permission to create an Ingress in their namespace can define an unhosted root route (`host: ""` and `path: "/"`) or shadow administrative management routes (`path: "/internal"` or `path: "/api/status"`). When `c.syncIngresses` executes, `c.router.RoutePrefix` registers these routes on the router, hijacking inbound gateway traffic and shadowing internal security telemetry APIs.
- **Impact**: Ingress traffic hijacking, tenant cross-namespace route collision, and administrative route shadowing.
- **Recommendation**: Add validation in `TranslateIngress` to reject unhosted root paths (`(prefix == "" || prefix == "/") && host == ""`) and reserved management prefixes (`prefix == "/internal" || strings.HasPrefix(prefix, "/internal/") || prefix == "/api/status"`).

### Finding 3 (SEC-25): Silent Request Body Truncation in Service Mesh Sidecar Proxy
- **Severity**: **Medium** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N - Score 5.3)
- **Location**: `pkg/sidecar/proxy.go:201-210`
- **CWE**: CWE-436, CWE-400
- **Description**:  
  In `ProxyEngine.proxyToURL`, incoming request payloads are read using `io.LimitReader(r.Body, maxSidecarBody+1)`. If an incoming payload exceeds `maxSidecarBody` (10 MB), the excess bytes are discarded, but the proxy does **not** return `HTTP 413 Payload Too Large`. Instead, it sets `toronReq.Body = bytes.NewReader(bodyBytes)` and updates `toronReq.ContentLength = int64(len(bodyBytes))`, silently forwarding a truncated, incomplete payload upstream.
- **Impact**: Upstream data corruption, unexpected JSON/payload truncation, and desynchronization vulnerabilities.
- **Recommendation**: Check if `int64(len(bodyBytes)) > maxSidecarBody`. If so, abort proxying and return `http.StatusRequestEntityTooLarge` (413) immediately.

### Finding 4 (SEC-26): Unbounded Goroutine & Socket Allocation in Layer 4 UDP/TCP Proxies
- **Severity**: **High** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H - Score 7.5)
- **Location**: `pkg/proxy/udp.go:76-108`, `pkg/proxy/tcp.go:74-109`
- **CWE**: CWE-400
- **Description**:  
  - In `UDPProxy.Serve`, each incoming UDP datagram spawns a new unthrottled goroutine (`go p.handleDatagram`), which opens a new outbound UDP socket via `net.DialUDP` and allocates a 64 KB response buffer. Under a high-frequency UDP packet flood, this rapidly exhausts available file descriptors, depletes memory, and triggers process termination (OOM).
  - In `TCPProxy.Serve`, accepted connections are dispatched without read/write/idle deadlines, and without tracking active connections. A client can establish idle TCP streams that block in `io.Copy` indefinitely, monopolizing network descriptors and leaking goroutines.
- **Impact**: Complete denial of service via Layer 4 socket starvation and memory exhaustion.
- **Recommendation**: Enforce a worker pool or maximum concurrent connection limit on Layer 4 proxies, reuse upstream sockets or track sessions for UDP proxying, and enforce idle timeouts on TCP proxy streams.

### Finding 5 (SEC-27): Missing Maximum Idle Deadlines on Upgraded Protocol Connections (WebSockets)
- **Severity**: **Medium** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:M - Score 5.3)
- **Location**: `pkg/server/server.go:273-294`
- **CWE**: CWE-400
- **Description**:  
  When an HTTP connection upgrades to WebSocket or a raw bidirectional tunnel (`101 Switching Protocols`), the server clears all connection deadlines (`conn.SetDeadline(time.Time{})`). If both endpoints stop transmitting without closing the TCP socket, the two `io.Copy` goroutines remain blocked indefinitely. Attackers can open thousands of idle WebSocket upgrade handshakes and abandon them, consuming server file descriptors and memory.
- **Impact**: Slowloris-style resource exhaustion on WebSocket/tunnel endpoints.
- **Recommendation**: Support a configurable `TunnelIdleTimeout` or periodically verify connection liveness through TCP keep-alive probes.

### Finding 6 (SEC-28): Unbounded Request Body Ingestion in REST-to-gRPC Transcoder
- **Severity**: **Medium** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L - Score 5.3)
- **Location**: `pkg/transcoder/transcoder.go:93-103`
- **CWE**: CWE-400, CWE-770
- **Description**:  
  In `transcoder.HandleTranscode`, `io.ReadAll(req.Body)` is invoked directly on `req.Body` without bounding the read via `io.LimitReader`. While standard HTTP/1.1 requests parsed by Toron have body limits enforced, requests arriving from custom sources or HTTP/2 stream handlers can trigger unbounded memory allocation if a client streams an arbitrarily large body.
- **Impact**: Memory exhaustion (OOM) when transcoding malicious large JSON requests.
- **Recommendation**: Bounded read: wrap `req.Body` with `io.LimitReader(req.Body, maxTranscodeBody+1)` (e.g. 4 MB) and reject oversized bodies with HTTP 413.

### Finding 7 (SEC-29): Hop-by-Hop Header Leakage to Upstream in REST-to-gRPC Transcoder
- **Severity**: **Low** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N - Score 3.7)
- **Location**: `pkg/transcoder/transcoder.go:153-161`
- **CWE**: CWE-444, CWE-436
- **Description**:  
  In `transcoder.HandleTranscode`, incoming headers are forwarded to the gRPC backend using:
  ```go
  for k, vv := range req.Header {
      if !strings.HasPrefix(strings.ToLower(k), "content-") {
          for _, v := range vv {
              grpcReq.Header.Add(k, v)
          }
      }
  }
  ```
  Standard RFC 7230 §6.1 hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Transfer-Encoding`, `Upgrade`) are forwarded verbatim to the gRPC server, potentially confusing upstream HTTP/2 frame parsers.
- **Impact**: Minor protocol confusion or rejection by strict upstream HTTP/2 gRPC servers.
- **Recommendation**: Filter out `hopByHopHeaders` before appending headers to `grpcReq`.

### Finding 8 (SEC-30): Subpath Routing Interception & 502 Denial via Empty Prefix Proxy in REST-to-gRPC Transcoder
- **Severity**: **Medium** (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:M - Score 5.3)
- **Location**: `pkg/transcoder/transcoder.go:83-85`
- **CWE**: CWE-284, CWE-400
- **Description**:  
  In `Engine.registerRoutes()`, the engine registers:
  ```go
  _ = e.router.RoutePrefix("upstream", "", cleanPrefix, nil, "", proxy.ProxyOptions{})
  e.router.Handle(rRule.HTTPMethod, cleanPrefix, handler)
  ```
  `RoutePrefix` registers an upstream proxy with empty `ProxyOptions` (no targets) for `cleanPrefix`. Meanwhile, `e.router.Handle` registers `handler` only for the exact path `cleanPrefix`. When a request for a subpath like `/v1/users/usr-123` arrives:
  1. Exact path match in `r.routes["/v1/users/usr-123"]` fails.
  2. Router falls back to `r.prefixRoutes`, which matches the empty `RoutePrefix`.
  3. The empty proxy executes and immediately returns `502 Bad Gateway: No upstream target available`.
  The actual transcoder `handler` is never invoked for parameterized paths.
- **Impact**: Parameterized REST-to-gRPC routes are unreachable and return 502 Bad Gateway.
- **Recommendation**: Register a prefix route whose handler directly dispatches to `e.HandleTranscode`, rather than registering a dummy upstream reverse proxy with empty targets.

## Positive Observations

- **RFC 7230 Strictness**: HTTP parser strictly adheres to RFC 7230 §3.2.4 (whitespace before colon rejected) and RFC 7230 §3.3.2 (multiple/conflicting Content-Length rejected).
- **DOM XSS Elimination**: `public/app.js` now contextually escapes all dynamic table and log data.
- **Path Exclusion Hardening**: Authentication and WAF middlewares enforce exact matching for root paths and require delimiter slashes for subpaths.
- **JWT Claim Validation**: Mandatory `exp` claim enforcement prevents eternal token acceptance.
- **Data Race Cleanliness**: Entire codebase passes `go test -count=1 -race ./...` with zero data races.
