# ADR-021 - TCP and UDP Layer 4 Transport Layer Proxying Architecture

## Context

Toron previously supported L7 application layer HTTP/1.1, HTTP/2, and WebSocket routing. Users require raw L4 transport layer TCP and UDP socket listener and proxy forwarding support to enable unified routing for non-HTTP microservices, database connections, and datagram-based protocols.

## Decision

1. **Configuration Schema Extensions**:
   - Update `RouteConfig` in `pkg/config/config.go` to recognize `type: "tcp"` and `type: "udp"`.
   - Add `ListenPort int` (`listen_port` / `port`) field to specify dedicated listener ports for L4 stream and datagram routes.

2. **TCP Layer 4 Proxy Engine (`pkg/proxy/tcp.go`)**:
   - `TCPProxy` accepts raw incoming `net.Conn` client sockets.
   - Selects an upstream target backend using configured load balancing strategy (`round_robin` or `random`).
   - Dials upstream TCP target via `net.DialTimeout("tcp", targetAddr, timeout)`.
   - Spawns goroutines for full-duplex byte stream relaying via `io.Copy(upstreamConn, clientConn)` and `io.Copy(clientConn, upstreamConn)`.

3. **UDP Layer 4 Proxy Engine (`pkg/proxy/udp.go`)**:
   - `UDPProxy` binds a listener socket via `net.ListenUDP("udp", listenAddr)`.
   - Reads incoming datagram packets into a buffer.
   - Forwards datagrams to an upstream target UDP endpoint via `net.DialUDP("udp", nil, targetUDPAddr)` and relays responses back to client endpoints.

4. **Server Lifecycle Management (`pkg/server/server.go`)**:
   - `Server` manages auxiliary TCP and UDP listeners alongside HTTP/HTTPS server loops.
   - Implements graceful shutdown for active TCP socket streams and UDP listener sockets during `Server.Shutdown()`.

## Consequences

- **Positive**: Enables Toron to function as a versatile Layer 4 transport load balancer for TCP and UDP protocol traffic alongside its existing HTTP/2 & Web Control Center features.
- **Modularity**: L4 proxy engines operate independently in `pkg/proxy` without bloating the L7 HTTP parser or router logic.
