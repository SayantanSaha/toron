# TC-140 - Verification Test Cases for Dynamic Upstream Target Logging and Trace Fidelity

## 1. Overview & Test Objectives

Verify that the dynamic upstream target context propagation, route tagging, and telemetry trace ingestion implemented under [`REQ-140`](../requirements/REQ-140.md), [`TASK-163`](../tasks/TASK-163.md), and [`ADR-140`](../architecture/ADR-140.md) correctly resolve and display active backend sockets rather than generic `"gateway"` strings, properly identify matched route prefixes, and maintain thread-safe zero-leak execution.

## 3. Detailed Test Case Specifications

### TC-140-01: Single-Target Upstream Context Injection
- **Preconditions**: A mock HTTP backend listener running on `127.0.0.1:<port>`.
- **Action**: Instantiate `ReverseProxy` pointing to the mock listener. Dispatch `proxy.ServeHTTPWithPrefix(req, res, "")`.
- **Verification**: Check `proxy.GetUpstreamTarget(req.Context())`.
- **Pass Criteria**: Value equals `"127.0.0.1:<port>"`.

### TC-140-02: Multi-Target Load-Balanced Upstream Context Injection
- **Preconditions**: Two mock backend listeners running on ports $P_1$ and $P_2$.
- **Action**: Configure `ReverseProxy` with round-robin load balancing over both targets. Dispatch two consecutive requests.
- **Verification**: Inspect `proxy.GetUpstreamTarget(req.Context())` for each request.
- **Pass Criteria**: First request returns `127.0.0.1:P1`, second request returns `127.0.0.1:P2`.

### TC-140-03: Route Prefix Identification on Subpath Requests
- **Preconditions**: Router registered with prefix route `/kite/api`.
- **Action**: Dispatch request with path `/kite/api/v1/trades/order-123`.
- **Verification**: Check `router.GetMatchedRoute(req.Context())` and `req.Path`.
- **Pass Criteria**: `router.GetMatchedRoute(req.Context())` is `"/kite/api"`, while `req.Path` is `"/kite/api/v1/trades/order-123"`.

### TC-140-04: Static Directory Destination Tagging
- **Preconditions**: Router registered with static route `/assets` pointing to a local directory.
- **Action**: Dispatch request for `/assets/style.css`.
- **Verification**: Check `router.GetDestination(req.Context())`.
- **Pass Criteria**: Returns `static (/assets)` or `static`.

### TC-140-05: In-Process Route Tagging
- **Preconditions**: Built-in `/health` or `/metrics` route.
- **Action**: Dispatch request for `/health`.
- **Verification**: Check `router.GetDestination(req.Context())`.
- **Pass Criteria**: Returns `in-process`.

### TC-140-06: End-to-End Trace Buffer Upstream Recording
- **Preconditions**: Telemetry middleware wrapping router and proxy.
- **Action**: Dispatch GET `/kite/api/test` through the middleware chain.
- **Verification**: Retrieve the latest log entry from `GlobalTraceBuffer.GetRecent(1)`.
- **Pass Criteria**: `entry.Up` is `"127.0.0.1:8080"` (or backend socket), NOT `"gateway"`.

### TC-140-07: Dashboard Route Filtering and Upstream Display
- **Preconditions**: Dashboard loaded with trace logs containing diverse upstreams (`127.0.0.1:8080`, `10.0.1.11:8080`, `static (/assets)`, `in-process`).
- **Action**: Run `lgUpdate(buildDataModel(), true)`. Filter by `state.lroute = 'kite_api'`.
- **Verification**:
  - Upstream column renders `127.0.0.1:8080` (not `"gateway"`).
  - Both `/kite/api` and subpath `/kite/api/v1/orders` appear when route is filtered.
- **Pass Criteria**: Clean table rendering with zero exceptions and accurate socket/route filtering.

### TC-140-08: Topology Leakage Guard (CWE-200)
- **Preconditions**: Live client requesting proxied endpoint.
- **Action**: Inspect serialized client HTTP response headers.
- **Verification**: Verify no `X-Toron-Upstream` or private network IP headers exist in `res.Header`.
- **Pass Criteria**: Zero internal topology leaked to client.

### TC-140-09: Concurrency Race Freedom
- **Action**: Run `go test -race -count=1 ./pkg/proxy/... ./pkg/router/... ./pkg/server/...`.
- **Pass Criteria**: Zero race warnings, exit code 0.
