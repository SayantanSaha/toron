# ADR-054 - Precise Upstream Reverse Proxy Path Rewriting and Target Subpath Preservation

## Context

In an edge gateway architecture, reverse proxy routes commonly map public URL prefixes to upstream microservices that host endpoints at specific subpaths. For example:
- Public route: `/kite/postback`
- Upstream target: `http://127.0.0.1:8082/postback`

Prior to this decision, Toron's path resolution in `pkg/proxy/proxy.go` handled path prefix stripping by coercing any empty stripped remainder (`strings.TrimPrefix(req.Path, prefix)`) into `"/"`. When joined with an upstream target path using Go's standard `singleJoiningSlash(targetPath, relPath)`, this produced an unconditional trailing slash on the upstream request (e.g. `http://127.0.0.1:8082/postback/`).

Strict HTTP routers, microservice web frameworks, and Go's standard library `http.ServeMux` treat `/postback` and `/postback/` as distinct routes. When an upstream service registers an endpoint without a trailing slash, receiving an unsolicited trailing slash leads to HTTP 404 (Not Found).

Industry standard reverse proxies (such as Nginx via `proxy_pass http://upstream/targetPath;`, Envoy, and Caddy) preserve exact target subpath parity without injecting unsolicited trailing slashes unless explicitly present in the incoming request or target URL definition.

## Decision

We decide to:

1. **Introduce Deterministic Proxy Path Joining (`joinProxyPath`)**:
   Refactor proxy path resolution from ad-hoc string concatenation into a dedicated, thoroughly tested helper:
   ```go
   func joinProxyPath(targetPath, reqPath, prefix string, stripPrefix bool) string
   ```

2. **Differentiate Exact Prefix Matches from Root Slashes**:
   When `stripPrefix` is active:
   - If `trimmed == ""` (the client requested the exact prefix without trailing slash, e.g. `/kite/postback`):
     - If `targetPath` has a non-empty subpath (e.g. `/postback`), return `targetPath` exactly as defined, without appending a slash.
     - If `targetPath` is empty or root (`""` or `"/"`), return `"/"`.
   - If `trimmed == "/"` (the client explicitly requested a trailing slash, e.g. `/kite/postback/`):
     - Preserve the trailing slash: if `targetPath` does not end with `/`, return `targetPath + "/"`.
   - If `trimmed` is a nested subpath (e.g. `/orders`), join cleanly via `singleJoiningSlash(targetPath, trimmed)`.

3. **Preserve Compatibility for Target Paths without Subpaths**:
   When upstream targets do not specify subpaths (e.g. `http://127.0.0.1:8080`), continue to map exact prefix hits to `/` and nested paths to their relative remainder.

4. **Preserve `strip_prefix: false` Semantics**:
   When `stripPrefix` is disabled, the full request path is forwarded, joining with any target subpath prefix.

## Consequences

### Positive
- Full parity with Nginx reverse proxy behavior.
- Clean architectural decoupling: microservices do not need alias routes or gateway-specific path prefixes.
- Zero breaking changes to existing routes or services without subpaths.
- Fully compatible with HTTP/1.1, HTTP/2, HTTP/3, and WebSocket proxying.

### Negative / Trade-offs
- Requires rebuilding and redeploying the Toron binary.
