# TC-045 - Custom WAF Regex Rules & Zero-Downtime Hot Reloading Test Cases

## Test Objective

Validate that user-defined regex rules in YAML configuration are properly compiled, scoped to target locations, accurately matched against incoming requests, and can be atomically hot reloaded in memory via `WAFEngine.Reload()` and `ConfigWatcher` with zero downtime, zero data races, and fail-safe error handling.

## Test Scenarios

### Scenario 1: User-Defined Custom Rule Matching Across Locations
- **File**: `pkg/waf/custom_rules_test.go`
- **Setup**: Initialize `WAFEngine` with custom rule `CUSTOM-001` (`category: "bot"`, `pattern: "(?i)(sqlmap|nikto|nmap|acunetix)"`, `score: 10`, `locations: ["headers"]`).
- **Steps**:
  1. Send request with `User-Agent: sqlmap/1.5.2#stable` -> Verify threat detected, score 10, matched rule ID `CUSTOM-001`, blocked in `enforce` mode (`403 Forbidden`).
  2. Send request with `User-Agent: Mozilla/5.0` and URL `/search?q=sqlmap` -> Verify rule does NOT trigger because location is restricted to `headers`.
  3. Initialize custom rule targeting `["body"]` (e.g. `pattern: "(?i)credit_card_leak"`). Send POST request with matching body -> Verify rule triggers.

### Scenario 2: Invalid Regex & Custom Rule Validation
- **File**: `pkg/config/config_test.go` / `pkg/waf/custom_rules_test.go`
- **Setup**: Attempt to initialize `WAFEngine` or validate `AppConfig` with malformed regex `"(?i)[unclosed_regex"`.
- **Expected Result**: Validation returns explicit descriptive error; engine initialization fails gracefully without panicking.

### Scenario 3: Thread-Safe Atomic Rule Reloading Under Traffic
- **File**: `pkg/waf/reload_test.go`
- **Setup**: Spin up 50 concurrent worker goroutines continuously evaluating requests through `WAFEngine.InspectToron()`.
- **Steps**:
  1. Call `WAFEngine.Reload(newConfig)` concurrently with new custom rules, modified anomaly thresholds, and updated IP ACLs.
  2. Perform 5 consecutive reloads during heavy concurrent traffic.
- **Expected Result**: Zero panics, zero data races detected by Go race detector (`go test -race`), and newly added custom rules immediately take effect for subsequent requests.

### Scenario 4: `ConfigWatcher` Dynamic File Modification Hot Reload
- **File**: `pkg/config/config_watcher_test.go`
- **Setup**: Create temporary `config.yaml` with baseline settings. Start `ConfigWatcher`.
- **Steps**:
  1. Overwrite temporary `config.yaml` with new custom rule `CUSTOM-002` (`pattern: "(?i)badactor"`).
  2. Wait for debounced reload callback.
  3. Verify the reload callback receives the new configuration with updated custom rules.
  4. Write malformed YAML to `config.yaml` -> Verify reload is safely rejected with error log and previous configuration state is preserved.
  5. Stop watcher cleanly.
