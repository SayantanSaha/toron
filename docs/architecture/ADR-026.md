# ADR-026 - Prometheus Exposition Metrics & W3C Traceparent Header Propagation Architecture

## Context

Enterprise deployment requires standardized metrics monitoring (Prometheus / Grafana) and distributed tracing (OpenTelemetry / Jaeger / Zipkin) across microservice proxies.

## Decision

1. **Prometheus Metrics Registry (`pkg/metrics/metrics.go`)**:
   - Implements thread-safe counters, gauges, and latency histograms without external third-party dependencies.
   - Exposes metrics in standard Prometheus text format (`text/plain; version=0.0.4`):
     - `toron_http_requests_total{method, status, route}`: Request volume counter.
     - `toron_http_request_duration_seconds{method, route}`: Latency histogram (buckets: `0.005`, `0.01`, `0.025`, `0.05`, `0.1`, `0.25`, `0.5`, `1`, `2.5`, `5`, `10`).
     - `toron_active_quic_streams`: Gauge tracking HTTP/3 active QUIC streams.
     - `toron_circuit_breaker_trips_total{target}`: Circuit breaker trip counter.

2. **W3C Traceparent Context Propagation (`pkg/metrics/tracing.go`)**:
   - Parses incoming `traceparent` headers matching the W3C Trace Context spec: `00-<32_hex_trace_id>-<16_hex_parent_id>-<2_hex_flags>`.
   - If missing, generates a cryptographically random 32-hex character `trace_id` and 16-hex `span_id`.
   - Injects/updates `traceparent` headers on outbound proxy requests to backend targets.

3. **Metrics Endpoint (`/metrics`)**:
   - Built into `router.Router` and served as a standard endpoint accessible to Prometheus scraping agents.

## Consequences

- **Positive**: Native Prometheus / Grafana observability and OpenTelemetry distributed tracing without performance degradation.
- **Interoperability**: Standardized W3C `traceparent` propagation provides end-to-end tracing across heterogeneous microservices.
