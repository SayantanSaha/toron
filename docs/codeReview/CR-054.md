# CR-054 - Code Review of Config-Based Multi-Stream Logging and System Logrotate Integration

## Description

Comprehensive engineering and code review of the multi-stream logging engine (`pkg/logging`), configuration schema extensions (`pkg/config`), routing middleware integration (`pkg/router`), and lifecycle/signal management (`cmd/toron/main.go`).

## Findings

### Finding 1: SIGHUP Reopening and Goroutine Safety
- Severity: Informational
- Location: `pkg/logging/manager.go:440`
- Description: `Reopen()` acquires a read lock to snapshot active sinks and then sequentially invokes `s.Reopen()`, which acquires the sink's mutex. Concurrent log writes wait on the sink mutex during file descriptor recreation without dropping records.
- Status: Verified safe under concurrent writes in `manager_test.go`.

### Finding 2: Safe Fallback for Standalone Router Invocations
- Severity: Informational
- Location: `pkg/router/router.go:578`
- Description: `AccessLoggerMiddleware` safely handles `nil` routers and `nil` log managers, falling back gracefully without panic.

- `TestLogSink_ReopenLogrotate`: Verifies log rotation simulation (rename -> reopen -> verify lines in old vs new files).

- `TestLogManager_JSONFormat`: Verifies structured JSON telemetry serialization.
- `TestLogManager_ConcurrentWrites`: Verifies 50 concurrent worker routines writing 5,000 log records with race detector.

- `TestRouter_AccessLoggerMiddleware_RouteOverrides`: Verifies HTTP access logging middleware with default, custom route, and silenced routes.
- `TestConfig_LoggingConfigAndRouteOverrides`: Verifies configuration parsing for global logging and route overrides.
