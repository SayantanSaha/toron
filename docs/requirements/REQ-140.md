# REQ-140 - Dynamic Upstream Target Resolution, Route Identification, and Live Request Log Telemetry Fidelity

## 1. Description & Problem Statement

### 1.1 Context & Background
The Toron Edge Gateway Control Center dashboard ([`public/app.js`](../../public/app.js)) features a **Live Requests & Logs** section (`#/logs`) and an interactive Trace Waterfall Drawer (`openDrawer('log', id)`). This interface allows system operators to inspect incoming requests in real time, view client IP addresses, response status codes, execution durations, trace IDs, matched routes, and active upstream service destinations.

Under [`REQ-135`](REQ-135.md), Toron established the `GlobalTraceBuffer` ring buffer in [`pkg/server/internal_api.go`](../../pkg/server/internal_api.go) and the `/internal/api/logs` endpoint to stream live request traces to the dashboard. Under [`REQ-137`](REQ-137.md) and [`REQ-138`](REQ-138.md), client IP visibility, datetime formatting, and deterministic multi-level secondary and tertiary sorting were added. Under [`REQ-139`](REQ-139.md), upstream route pool disaggregation and hierarchical subpath metrics aggregation were introduced.

### 1.2 Identified Defects & Root Cause Analysis
During live operational audits of the Control Center dashboard, operators identified that in the **Live Requests & Logs** table, the **Upstream** column (`e.up`) unconditionally displays `"gateway"` for every single request:

1. **Hardcoded Upstream in Telemetry Middleware ([`cmd/toron/main.go`](../../cmd/toron/main.go))**:
   - In [`cmd/toron/main.go`](../../cmd/toron/main.go), the global request tracing middleware captures request telemetry before and after `next(req, res)` executes:
     ```go
     server.GlobalTraceBuffer.RecordTrace(server.TraceLogEntry{
         TS:      time.Now().UnixMilli(),
         Method:  req.Method,
         Path:    req.Path,
         Route:   routeStr,
         Short:   shortStr,
         Status:  res.StatusCode,
         MS:      float64(dur.Microseconds()) / 1000.0,
         Up:      "gateway", // <-- Hardcoded to "gateway"
         Trace:   traceID,
         IP:      req.RemoteAddr,
         Bytes:   bodyBytes,
     })
     ```
   - Because `Up` is statically set to `"gateway"`, every request logged—whether proxied to an upstream backend socket (e.g., `127.0.0.1:8080`), served from a local static assets directory, or handled by an in-process engine handler—is recorded as `"gateway"`.

2. **Missing Upstream Target Propagation in Reverse Proxy ([`pkg/proxy/proxy.go`](../../pkg/proxy/proxy.go))**:
   - When [`pkg/proxy/proxy.go`](../../pkg/proxy/proxy.go) executes `ServeHTTPWithPrefix`, its load balancer (`Balancer.Next(req)`) selects a specific `UpstreamTarget` node (`targetNode`).
   - The selected backend target contains the network address (`targetNode.URL.Host`, e.g., `127.0.0.1:8080` or `10.0.1.11:8080`).
   - However, `ReverseProxy` does not propagate this selected target back to the request context (`req.Context()`) or response object. Consequently, the outer telemetry middleware cannot access the actual upstream socket that handled the request.

3. **Subpath Route Identification Mismatch in Log Entries**:
   - In [`cmd/toron/main.go`](../../cmd/toron/main.go), `TraceLogEntry.Route` is recorded as `req.Path` (e.g., `/kite/api/v1/trades`).
   - In the dashboard ([`public/app.js`](../../public/app.js)), the route filter dropdown (`#lgRoute`) filters entries by comparing `e.route === state.lroute`, where `state.lroute` contains the configured route prefix ID (e.g., `_kite_api` or `/kite/api`).
   - Because `e.route` contains the raw request path rather than the matched route prefix, filtering by route in the dashboard fails to match subpath requests.

4. **Conflation of Static and In-Process Endpoints**:
   - Requests served by static directory handlers (e.g., `/var/www/public`) or internal in-process endpoints (e.g., `/health`, redirects) are not distinguished from proxied upstreams.
   - Static routes should be explicitly tagged with their destination (e.g., `static` or `static (<dir>)`), while direct engine endpoints should be tagged as `in-process` or `gateway`.

## 2. Requirements

### 2.1 Functional Requirements

- **REQ-140.1: Dynamic Upstream Target Propagation in Reverse Proxy**:
  - When `ReverseProxy.ServeHTTPWithPrefix` selects an upstream target node via its load balancer, it MUST attach the selected upstream target host address (`targetNode.URL.Host`, or target host:port) to the request context (`req.Context()`).
  - If upstream target selection fails or the proxy returns 502/503 bad gateway/service unavailable, the attempted target or failure state MUST be clearly reflected.

- **REQ-140.2: Route Context Tagging in Router**:
  - When `Router.ServeHTTP` matches an incoming request to a configured route (whether prefix route, static route, or exact route), it MUST record the matched route prefix, route ID, and route type (`upstream`, `static`, `in-process`) in the request context.
  - For static file routes, the destination MUST indicate `static` or `static (<dir>)`.
  - For unproxied in-process gateway routes (e.g., `/health`, HTTP redirects, metrics), the destination MUST indicate `in-process`.

- **REQ-140.3: Telemetry Middleware Upstream & Route Resolution**:
  - In `cmd/toron/main.go`, the global telemetry middleware MUST inspect the request context after `next(req, res)` completes to extract:
    1. **Upstream Node (`Up`)**: The dynamically resolved upstream socket (e.g., `127.0.0.1:8080`, `10.0.1.11:8080`), static destination, or `in-process`/`gateway`.
    2. **Matched Route (`Route`)**: The matched route prefix or route ID (e.g., `/kite/api` or `_kite_api`), rather than the unindexed subpath.
    3. **Short Label (`Short`)**: The host + matched route prefix (or host + path if no prefix).

- **REQ-140.4: Control Center Dashboard Route Filtering & Upstream Display**:
  - In `public/app.js`:
    - The **Upstream** column (`e.up`) in `lgUpdate()` MUST render the actual resolved upstream socket (e.g., `127.0.0.1:8080`) or destination tag.
    - The Route filter in `lgUpdate()` MUST support matching against both the matched route prefix and subpaths (hierarchical route matching: `e.route === state.lroute || e.path.startsWith(prefix)`).
    - The Trace Waterfall Drawer (`openDrawer('log', id)`) MUST display the real upstream node address in `<dt>Upstream Node</dt><dd><code>${esc(e.up)}</code></dd>`.

### 2.2 Non-Functional & Operational Requirements

- **REQ-140.5: Zero Third-Party Dependencies & Memory Efficiency**:
  - Context key and value storage MUST use standard library `context.Context` without third-party libraries.
  - Context attachment MUST NOT allocate heap memory on hot paths beyond standard context wrapping.

- **REQ-140.6: Concurrency Safety**:
  - Context propagation and trace recording MUST be fully thread-safe and race-clean under concurrent requests (`go test -race ./...`).

- **REQ-140.7: Backward Compatibility**:
  - Existing endpoints (`GET /internal/api/logs` and `GET /internal/api/status`) MUST preserve their JSON response schema (`TraceLogEntry` fields: `id`, `ts`, `method`, `path`, `route`, `short`, `status`, `ms`, `up`, `trace`, `ip`, `bytes`).

- **REQ-140.8: Strictly Relative Links**:
  - All documentation links MUST strictly use relative links. Never use absolute paths (`file:///...`, `/Users/...`, leading slash filesystem paths).

## 3. Acceptance Criteria

- [ ] **Dynamic Upstream Target in Logs**: Requests proxied to backend targets (e.g., `127.0.0.1:8080`) appear in `GET /internal/api/logs` and the dashboard with `up: "127.0.0.1:8080"` (or the respective backend socket), NOT the generic `"gateway"`.
- [ ] **Static Route Upstream Tagging**: Requests served by static directory handlers appear with `up: "static"` or `up: "static (<dir>)"`.
- [ ] **In-Process Handler Upstream Tagging**: Direct gateway responses (e.g., `/health`, HTTP redirects) appear with `up: "in-process"` or `"gateway"`.
- [ ] **Accurate Route Identification**: `TraceLogEntry.Route` reflects the matched route prefix/ID, allowing the dashboard's route dropdown filter (`#lgRoute`) to properly filter both parent and subpath requests.
- [ ] **Trace Drawer Fidelity**: Opening a request in the trace drawer renders the concrete upstream socket under **Upstream Node**.
- [ ] **Race Detector & Regression Testing**: All Go unit and race tests (`go test -race -count=1 ./...`) and dashboard tests pass cleanly with zero regressions.
