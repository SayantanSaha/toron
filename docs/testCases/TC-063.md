# TC-063 - Verification of Shared Cache Isolation, Set-Cookie Stripping, and Authorization Boundaries

## Objective

Verify that the shared HTTP response caching middleware complies with RFC 7234 §8 and §3.2 by stripping `Set-Cookie` headers from all cached response snapshots and isolating authenticated requests from unauthenticated cache consumption.

## Test Cases

### TC-063-01: Set-Cookie Stripping on Cached Responses
- **Input Request 1 (Initial)**: `GET /api/session HTTP/1.1`
- **Upstream Response**: `HTTP/1.1 200 OK`, `Set-Cookie: session=secret_token_12345; Path=/; HttpOnly`, `Set-Cookie2: ...`
- **Expected Outcome 1**: Client receives initial response containing `Set-Cookie` with `X-Cache: MISS`.
- **Input Request 2 (Subsequent)**: `GET /api/session HTTP/1.1`
- **Expected Outcome 2**:
  - Response has `X-Cache: HIT`.
  - Headers `Set-Cookie` and `Set-Cookie2` are strictly absent.

### TC-063-02: Authorization Boundary - Private Response Exclusion
- **Input Request 1**: `GET /api/user/profile HTTP/1.1` with `Authorization: Bearer user1-token`.
- **Upstream Response**: `HTTP/1.1 200 OK`, `{"profile_id": 1}` (no `public` directive in `Cache-Control`).
- **Expected Outcome 1**: Request handled upstream (`X-Cache: MISS`).
- **Input Request 2**: `GET /api/user/profile HTTP/1.1` without `Authorization` header.
- **Expected Outcome 2**:
  - Response must NOT be served from cache (`X-Cache: MISS`).
  - Upstream handler runs again to produce an unauthenticated response.

### TC-063-03: Authorization Boundary - Explicit Public Cache Caching
- **Input Request 1**: `GET /api/public/data HTTP/1.1` with `Authorization: Bearer user1-token`.
- **Upstream Response**: `HTTP/1.1 200 OK`, `Cache-Control: public, max-age=60`, `{"public_id": 1}`.
- **Expected Outcome 1**: Handled upstream (`X-Cache: MISS`).
- **Input Request 2**: `GET /api/public/data HTTP/1.1` with `Authorization: Bearer user1-token`.
- **Expected Outcome 2**:
  - Response served from cache (`X-Cache: HIT`).
  - Handler call count remains 1.

### TC-063-04: Vary Header Safety
- **Input Request**: `GET /api/vary-custom HTTP/1.1`.
- **Upstream Response**: `HTTP/1.1 200 OK`, `Vary: User-Agent, Cookie`.
- **Expected Outcome**:
  - Response with unsupported variance dimensions is bypassed and never stored in the shared cache.
