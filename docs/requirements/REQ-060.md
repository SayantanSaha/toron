# REQ-060 - Forwarding and Preservation of URL Query Parameters in Reverse Proxy across HTTP/1.1, HTTP/2, and HTTP/3

## Description

The Toron edge gateway and reverse proxy shall faithfully preserve and forward all client URL query parameters (`?key=value&...`) to upstream target destinations across all supported ingress protocols (HTTP/1.1, HTTP/2 over TLS, HTTP/3 over QUIC, and Sidecar proxying).

Previously, during HTTP/2 and HTTP/3 protocol adaptation in `pkg/server/server.go` (`http2AdapterHandler`), the internal `httpparser.Request` was instantiated without populating `QueryParams` or preserving `URL.RawQuery`. Consequently, when requests were processed by the reverse proxy in `pkg/proxy/proxy.go`, `outURL.RawQuery = req.QueryParams.Encode()` evaluated to an empty string, completely stripping all query parameters from client requests before forwarding to upstream services.

Toron shall guarantee that query parameters are preserved verbatim across all ingress adapters, merged cleanly with any target-defined query parameters, and logged accurately in access logs.

## Acceptance Criteria

### 1. HTTP/2 and HTTP/3 Query Parameter Forwarding
- Requests received via HTTP/2 (ALPN `h2`) and HTTP/3 (QUIC) shall retain their complete query parameters.
- `req.QueryParams` and `req.URL.RawQuery` shall be populated accurately in `http2AdapterHandler` and `sidecar.ProxyEngine`.

### 2. Verbatim Raw Query Preservation
- Upstream requests shall prefer `req.URL.RawQuery` to preserve client parameter ordering, non-value flags (e.g. `?debug`), and percent-encoding fidelity, falling back to `req.QueryParams.Encode()` only if `RawQuery` is unavailable.

### 3. Upstream Target Query Parameter Merging
- If the upstream `target` URL defined in configuration contains query parameters (e.g. `http://upstream:8080/api?fixed=1`), client query parameters (e.g. `?user=123`) shall be merged cleanly (e.g. `fixed=1&user=123`) without dropping either set.

### 4. WebSocket Query Parameter Forwarding
- WebSocket upgrade requests containing query strings (e.g. `/ws?token=secret`) shall forward the query parameters to the upstream WebSocket backend during handshake connection.

### 5. Access Log Telemetry
- Access logs shall record `req.RequestURI` (including query parameters, e.g. `GET /api/v1/trades?symbol=INFY HTTP/2.0`) in the request line, maintaining full observability.
