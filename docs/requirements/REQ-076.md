# REQ-076 - Bounded Request Body Ingestion in HTTP/2 Adapter Handler

## Description

The Toron HTTP/2 adapter handler (`http2AdapterHandler` in `pkg/server/server.go`) shall enforce strict request body memory allocation bounds matching the server's configured `MaxBodyBytes`, preventing memory exhaustion and Denial of Service (OOM) attacks from oversized or streaming HTTP/2 payloads.

## Acceptance Criteria

### 1. Enforcement of Maximum Body Bytes Limit
- In `http2AdapterHandler()`, the reading of `r.Body` shall be bounded by `s.config.MaxBodyBytes` (default 10 MB or configured value).
- Uncontrolled calls to `io.ReadAll(r.Body)` without an upper size bound shall be prohibited.

### 2. HTTP 413 Payload Too Large Response
- If an incoming HTTP/2 request body exceeds `s.config.MaxBodyBytes`, the adapter shall terminate ingestion and return `HTTP 413 Payload Too Large`.
- The connection shall discard excess data safely without exhausting server memory.

### 3. Normal Request Preservation
- Requests within the allowed payload limit shall be read completely and accurately into `req.Body` for routing and proxying.

## Rationale

HTTP/1.1 enforces `MaxBodyBytes` in `httpparser.ParseRequest`. However, HTTP/2 ingress previously used `io.ReadAll(r.Body)` without bounds. Attackers streaming gigabytes over an HTTP/2 connection could trigger kernel OOM kills.

## Constraints

- Pure Go standard library.
- Compatible with HTTP/2 multiplexing.
