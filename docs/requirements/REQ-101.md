# REQ-101 - Physical TCP Socket Termination Verification in Differential Fuzzer

## 1. Description

To enforce RFC 7230 connection teardown invariants and empirical security guarantees during differential protocol fuzzing (`benchmarks/fuzzer/diff_fuzzer.go`), the test harness shall actively verify that the target server physically terminates the underlying TCP socket upon issuing protocol rejection responses or handling request smuggling vectors.

Prior implementations solely read the initial HTTP status line and terminated inspection, inadvertently marking `connection_closed: false` across all test outputs and failing to verify whether sockets with `ExpectClose: true` were actually torn down.

## 2. Acceptance Criteria

### AC-1: Active Socket Teardown Probe
- Following reception of the HTTP status line, the test harness must execute an active socket verification probe.
- The probe shall drain any unconsumed response bytes under a short bounded deadline ($\le 250\text{ ms}$) and assert socket termination via `io.EOF`, connection reset (`ECONNRESET`), broken pipe (`EPIPE`), or closed connection error.
- If the socket remains open and readable without reaching EOF before deadline expiry, it shall attempt a probe write/read to confirm TCP state. If the connection remains responsive, it is designated as open (`connection_closed = false`).

### AC-2: Invariant Enforcement on `ExpectClose`
- If a `TestCase` defines `ExpectClose: true`, the fuzzer must assert that `connection_closed == true`.
- If the target returns an expected rejection status code (e.g., `400 Bad Request` or `501 Not Implemented`) but leaves the socket open on keep-alive, the test shall be marked as **FAILED** with an explicit failure reason detailing the keep-alive violation.

### AC-3: Measurement Isolation for Fail-Fast Latency
- The recorded `LatencyUs` metric must measure solely the duration up to initial response status line reception.
- Socket teardown draining and probe deadlines must not be added to or inflate the recorded fail-fast rejection latency.

### AC-4: Structured Artifact Reporting
- The JSON report (`benchmarks/results/differential_fuzz_report.json`) must accurately record `"connection_closed": true` when sockets are physically terminated.
- The Markdown report (`benchmarks/results/differential_fuzz_report.md`) must include a dedicated `Conn Closed` column reflecting socket termination state.
- Standard console execution logs must report socket state per vector (e.g., `[conn: closed]` vs `[conn: open]`).

## 3. Constraints & Non-Functional Requirements

- **Zero Third-Party Dependencies**: All socket inspection and draining must use only Go standard library primitives (`net`, `bufio`, `io`, `time`, `errors`, `syscall`).
- **Bounded Timeout**: Verification probes must never hang or block test suite execution, enforcing explicit deadlines.
