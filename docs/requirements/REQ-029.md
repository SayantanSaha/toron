# REQ-029 - Token Bucket Rate Limiting Middleware per Client IP / API Key

## Description

The Toron web server shall support route-level rate limiting using a Token Bucket algorithm to protect backend upstream services from abuse, traffic spikes, and DDoS attacks.

Rate limits shall be configurable in `routes.yaml` per route rule (e.g. `rate_limit: "100/min"`, `rate_limit: "10/sec"`, or `rate_limit: "1000/hour"`). Rate limits shall track request rates per client IP address or API key header (`X-API-Key`). When a client exceeds their rate limit threshold, the server shall respond with HTTP status `429 Too Many Requests`, include a `Retry-After` header, and halt upstream forwarding.

## Acceptance Criteria

- `pkg/config`: `ProxyRouteConfig` supports parsing optional `rate_limit` string parameters (e.g. `"100/min"`, `"10/sec"`, `"1000/hour"`).
- `pkg/router`: Implements thread-safe Token Bucket rate limiter middleware (`RateLimiter`) that tracks client request rates by remote IP or `X-API-Key` header.
- When rate limit is exceeded, server returns `429 Too Many Requests` status, `Retry-After` response header, and JSON error payload (`{"error":"429 Too Many Requests"}`).
- Automated unit and integration tests in `pkg/router` and `pkg/config` pass cleanly without regressions.

## Rationale

Route-level rate limiting ensures application resilience, prevents resource exhaustion on backend microservices, and provides multi-tenant API protection.
