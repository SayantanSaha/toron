# REQ-083 - Automated Performance Benchmarking and Differential Security Fuzzing Testbed

## Description

To support empirical evaluation for academic peer review and artifact evaluation, Toron shall provide an automated, repeatable benchmarking and differential security testing suite in `benchmarks/`. The suite shall include:
1. Repeatable `wrk2` latency and throughput test harnesses with structured reporting.
2. Built-in, zero-dependency fallback load generator reproducing `wrk2` constant-rate concurrency semantics if `wrk2` is unavailable on the test machine.
3. Automated differential security fuzzer suite testing protocol desynchronization, HTTP request smuggling mutations, control characters, path canonicalization, and parameter pollution.

## Acceptance Criteria

### 1. Repeatable Throughput & Latency Benchmarking (`benchmarks/wrk2/`)
- A configurable shell runner (`run_wrk2.sh`) capable of executing parameterized benchmark sweeps (concurrency: 50, 100, 500, 1000; rates: 5,000 to 50,000 RPS).
- Support for wrk Lua scripts for pipelining, varied request headers, and payload bodies.
- A built-in high-performance Go load generator (`loadgen.go`) that executes when `wrk2` binary is absent, capturing p50, p90, p99, and p99.9 tail latencies.
- Export of benchmark results to structured JSON and CSV in `benchmarks/results/`.

### 2. Differential Security Fuzzer Harness (`benchmarks/fuzzer/`)
- A Go-based automated differential fuzzer (`diff_fuzzer.go`) verifying RFC conformance and rejection semantics across:
  - **HTTP Request Smuggling**: Conflicting `Content-Length` and `Transfer-Encoding`, multiple divergent `Content-Length` headers, invalid chunk encodings.
  - **RFC 7230 §3.2.4 Whitespace Invariants**: Spaces/tabs preceding colons, obs-fold continuations, malformed field names.
  - **Control Character Injection**: Raw non-printable ASCII bytes (`0x00-0x1F`, `0x7F`) in request lines, paths, and headers.
  - **Path Traversal Mutations**: Percent-encoded traversal patterns (`%2e%2e`, `%252e%252e`, uppercase encodings) and dot-segment boundary escapes.
  - **HTTP Parameter Pollution**: Target query key collisions and precedence validation.
- The fuzzer shall compare responses against expected fail-fast security invariants (e.g., 400 Bad Request, 501 Not Implemented, immediate connection teardown).
- Export of comprehensive differential security reports in both Markdown and JSON format.

### 3. Unified Runner & Artifact Documentation
- A top-level master runner script (`benchmarks/run_all.sh`) allowing one-click execution of both suites against a local or running Toron instance.
- Comprehensive `benchmarks/README.md` guiding reviewers through execution, hardware configurations, metric interpretation, and artifact reproduction.

## Rationale

Academic conferences (USENIX Security, ACM CCS, EuroSys, SoCC) require verifiable, statistically reproducible experimental results and artifact evaluation packages. Having self-contained, automated benchmarks ensures anyone can reproduce all performance figures and security defense tables.

## Constraints

- Zero external package dependencies outside Go standard library for the Go harness.
- Must execute deterministically on macOS and Linux systems.
