# TC-121 - Test Cases for Multi-Proxy Differential Docker Benchmark Harness

## 1. Overview & Verification Strategy

This document defines the automated validation criteria and verification test procedures for the Multi-Proxy Differential Docker Benchmark Harness ([`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md), [`ADR-121`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-121.md)).

---

## 2. Test Specifications

### TC-121.1: Compose Configuration Validation
- **Objective**: Verify that `docker-compose.compare.yml` contains valid syntax and port bindings.
- **Procedure**: Run `docker compose -f benchmarks/docker-compare/docker-compose.compare.yml config`.
- **Expected Result**: Exit code 0, no validation errors, valid YAML structure.

### TC-121.2: Upstream Origin Service Verification
- **Objective**: Confirm all 4 upstream backends initialize correctly on the Docker bridge network.
- **Endpoints**:
  - `node-origin:9101/health` $\rightarrow$ `HTTP 200`, `runtime: "node"`, `engine: "llhttp"`
  - `python-origin:9102/health` $\rightarrow$ `HTTP 200`, `runtime: "python"`, `engine: "uvicorn/h11"`
  - `go-origin:9103/health` $\rightarrow$ `HTTP 200`, `runtime: "go"`, `engine: "net/http"`
  - `fast-origin:9104/health` $\rightarrow$ `HTTP 200`, `runtime: "fast-echo"`
- **Expected Result**: All 4 backends return HTTP 200 with appropriate payload identifiers.

### TC-121.3: Multi-Proxy Routing Equivalence & Path Preservation
- **Objective**: Verify every proxy correctly strips path prefixes and routes requests to upstream origins.
- **Proxy Matrix**:
  - Toron (`http://127.0.0.1:8881`)
  - NGINX (`http://127.0.0.1:8882`)
  - Traefik (`http://127.0.0.1:8883`)
  - Caddy (`http://127.0.0.1:8884`)
  - HAProxy (`http://127.0.0.1:8885`)
- **Route Matrix**:
  - `GET /node/health` $\rightarrow$ HTTP 200
  - `GET /python/health` $\rightarrow$ HTTP 200
  - `GET /go/health` $\rightarrow$ HTTP 200
  - `GET /fast/health` $\rightarrow$ HTTP 200
- **Expected Result**: 20/20 combinations return HTTP 200 with valid upstream payload.

### TC-121.4: Pre-Flight Automated Health Check Suite
- **Objective**: Ensure the pre-flight verification script verifies connectivity prior to load generation.
- **Procedure**: Run `./benchmarks/docker-compare/run_compare.sh --preflight-only`.
- **Expected Result**: Reports `[PASS]` for all 5 proxies and 4 upstream targets, exiting with code 0.

### TC-121.5: End-to-End Comparative Load Execution & Metrics Generation
- **Objective**: Execute automated load test across all proxies and backends.
- **Procedure**: Run `./benchmarks/docker-compare/run_compare.sh -c 50 -d 5s`.
- **Expected Result**:
  - Outputs `benchmarks/results/docker_compare_report.json` with valid JSON schema.
  - Outputs `benchmarks/results/docker_compare_report.md` containing formatted comparison tables.
  - Generates RPS, Latency (P50, P90, P99, P99.9, Max), and error rates.

### TC-121.6: Docker Container Telemetry Sampling
- **Objective**: Validate CPU and Memory metrics collection during test execution.
- **Procedure**: Check `docker_compare_report.json` contains `cpu_percent` and `memory_rss_mb` per proxy.
- **Expected Result**: Non-zero memory RSS recorded for all active proxy containers.

### TC-121.7: Clean Teardown & Port Release
- **Objective**: Confirm `--down` or exit trap terminates all benchmark containers cleanly.
- **Procedure**: Run `./benchmarks/docker-compare/run_compare.sh --down`, followed by `lsof -iTCP:8881-8885`.
- **Expected Result**: No containers remain running from `compare-net`, and ports 8881-8885 are released.
