# SR-066 - Security Review of Strict CORS Origin Validation and Prohibit Credentialed Wildcards

## Description

Security evaluation of the implementation for `TASK-069` / `SEC-09` (Permissive CORS wildcard reflection with credentials enabled).

## Scope

- Files reviewed:
  - `pkg/router/cors.go`
  - `pkg/config/loader.go`
  - `pkg/router/cors_test.go`
  - `pkg/config/config_test.go`

## Security Evaluation & Analysis

1. **Elimination of Credential Hijacking via Permissive Wildcards (CWE-942)**:
   - Previously, configuring `allow_origins: ["*"]` with `allow_credentials: true` resulted in the server dynamically echoing back the client's `Origin` header in `Access-Control-Allow-Origin` alongside `Access-Control-Allow-Credentials: true`. This effectively allowed any attacker-controlled website to issue credentialed AJAX/fetch requests and read private user data.
   - Fail-closed configuration validation now prevents Toron from loading or booting any route or global configuration containing `allow_credentials: true` and `*` in `allow_origins`.
2. **Runtime Defense-in-Depth**:
   - `isOriginAllowed` explicitly skips wildcard `*` matching when `allowCredentials` is active. Even if an unvalidated configuration were injected at runtime, wildcards will never match, ensuring untrusted origins are not reflected.
3. **Cache Partitioning via Vary: Origin**:
   - Every request evaluating origin emits `Vary: Origin`, preventing intermediate caches, CDNs, or browser caches from poisoning clean responses with permissive cross-origin headers.
4. **Exploit Verification**:
   - Tested that preflights from untrusted origins are blocked with `403 Forbidden`, and simple cross-origin requests do not emit `Access-Control-Allow-Origin`.

## Conclusion

`SEC-09` is completely resolved. Permissive CORS reflection vulnerability is mitigated. The implementation is approved.
