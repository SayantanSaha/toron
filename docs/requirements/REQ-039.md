# REQ-039 - Per-Host Dynamic SNI Certificate Mapping & mTLS Client Authentication in Routing Configuration

## Description

The Toron web server shall support **per-host dynamic SSL/TLS configuration** defined directly within routing rules in `routes.yaml`. This enables multi-tenant virtual hosts to configure distinct X.509 certificate pairs, client certificate verification policies (Mutual TLS / mTLS), and minimum TLS protocol versions mapped by Server Name Indication (SNI).

The per-host TLS subsystem shall:
1. **Per-Host Certificate Mapping via SNI**:
   - Allow individual route rules in `routes.yaml` to specify `tls.cert_file` and `tls.key_file`.
   - Dynamically serve the matching certificate during the TLS handshake based on the client's SNI hostname (`GetCertificate` / `GetConfigForClient`).
   - Support fallback to global certificates or auto dev certs if a host has no custom certificate defined.
2. **Mutual TLS (mTLS) Client Certificate Authentication**:
   - Support `tls.ca_file` and `tls.client_auth` options per host:
     - `no_client_cert`: Do not request client certificate.
     - `request_client_cert`: Request client cert but do not require it.
     - `require_any_client_cert`: Require a client cert but do not verify against CA.
     - `verify_client_cert_if_given`: Verify against `ca_file` if client sends a cert.
     - `require_and_verify`: Strictly mandate and verify a valid client certificate issued by `ca_file`.
3. **Per-Host Minimum TLS Version**:
   - Support `tls.min_version` (`tls1.2` or `tls1.3`) per host.
4. **Configuration in `routes.yaml`**:
   - Capture per-host TLS settings inside `routes[].tls` block in `routes.yaml` and `ProxyRouteConfig`.

## Acceptance Criteria

- When client connects with `ServerName: "hostA.local"`, Toron returns `hostA.local`'s custom certificate.
- When client connects with `ServerName: "secure.internal"`, Toron enforces mTLS requiring valid client certificates signed by the configured CA.
- Clients failing mTLS verification are rejected during the TLS handshake.
- Fallback hostnames receive the default server certificate / auto dev cert.
- All Go unit tests pass cleanly (`go test ./...`).
