# SR-029 - Security Review of Transparent Response Compression Middleware (Gzip & Deflate)

## Scope

Security audit of response compression middleware ([`pkg/router/compression.go`](file:///D:/Work/server/pkg/router/compression.go)), MIME type filters, WebSocket and HTTP/2 Extended CONNECT connection bypass guards, and `sync.Pool` memory boundaries.

## Findings

1. **Protocol Hijacking & Upgrade Safety**: Compression explicitly checks `res.StatusCode == http.StatusSwitchingProtocols` and `res.UpgradedConn != nil`, guaranteeing that active WebSocket tunnels (RFC 6455) and HTTP/2 Extended CONNECT streams are bypassed and not corrupted.
2. **BREACH / CRIME Mitigation & Content-Type Scoping**: Incompressible binary formats and media files (images, audio, video, zip) are excluded from compression via prefix/substring MIME filtering.
3. **Memory Safety & Resource Exhaustion Protection**: Writer instances are recycled using `sync.Pool` without unbounded memory allocations. Compression is bounded by Toron's upstream buffer and max body constraints (`MaxBodyBytes`).
4. **Header Integrity**: Proper setting of `Vary: Accept-Encoding` prevents cache poisoning in downstream intermediate CDNs and shared caching proxies.

## Conclusion

Approved. No security vulnerabilities or unsafe memory patterns identified.
