# ADR-014 - Dual-File Decoupled Configuration Architecture

## Context

Combining infrastructure settings (network ports, worker pool sizes, timeouts, static file directories) and dynamic reverse proxy routing rules into a single `config.yaml` file creates risk during route updates and limits independent configuration management.

## Decision

1. **Dual-File Separation**:
   - `config.yaml`: Infrastructure parameters (`server`, `static`, `logging`).
   - `routes.yaml`: Routing rules (`proxy: enabled: true`, `routes: [...]`).
2. **Flexible Loading Hierarchy**:
   - `LoadFromFiles(configPath, routesPath string)` parses `config.yaml` first, then merges `routes.yaml` into `cfg.Proxy`.
   - If `routesPath` is not explicitly passed, `pkg/config` auto-discovers `routes.yaml` in the directory of `config.yaml` or current working directory.
   - Backward compatibility: If `config.yaml` contains `proxy.routes`, those routes are retained if no `routes.yaml` is found.

## Consequences

- **Positive**: Separates devops infrastructure from traffic routing policy; simplifies CI/CD routing updates.
