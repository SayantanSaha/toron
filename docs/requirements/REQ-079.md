# REQ-079 - Container Ingress Route Scoping and Protected Path Validation

## Description

The Toron container auto-discovery subsystem (`pkg/discovery/parser.go` and `pkg/discovery/manager.go`) shall enforce path validation and namespace scoping on container-declared routes, preventing rogue or untrusted containers from registering the root path (`/`) or shadowing internal administrative endpoints.

## Acceptance Criteria

### 1. Root and Protected Path Blacklisting
- `ParseContainerLabels` shall reject any container route specifying root prefix (`""` or `"/"`) unless explicitly authorized in discovery configuration.
- Containers shall be prohibited from binding to internal management prefixes (`/internal`, `/internal/api`) or critical gateway endpoints.

### 2. Host Requirement for Broad Prefixes
- Any container attempting to bind to top-level prefixes shall be required to declare an explicit, valid non-empty `toron.host` label.

### 3. Graceful Registration Failure
- Containers with invalid, dangerous, or shadowed prefix configurations shall be ignored with an informative warning log, without aborting manager discovery loops.

## Rationale

Without label validation, any container created on the local Docker host with `toron.enable=true` and `toron.prefix=""` immediately steals all gateway ingress traffic, enabling traffic interception and credential theft.

## Constraints

- Pure Go standard library.
- Compatible with existing Docker/Podman Unix socket discovery.
