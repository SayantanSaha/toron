# TC-062 - Verification of Management API Access Control, Subnet Restrictions, and SSRF Hardening

## Objective

Verify that Toron strictly enforces administrative authentication, CIDR subnet allowlisting, and SSRF mitigations on all internal management endpoints (`/internal/api/*`), preventing unauthorized telemetry inspection, network reconnaissance, and loopback privilege escalation.

## Test Cases

### TC-062-01: Mandatory Authentication on Management Routes
- **Input Request**: `GET /internal/api/status HTTP/1.1` without credentials.
- **Precondition**: `AdminAuthEnabled: true` or `AdminToken: "super-secret"`.
- **Expected Outcome**:
  - Response status code is `HTTP 401 Unauthorized`.
  - Response header contains `WWW-Authenticate: Bearer realm="Toron Management", Basic realm="Toron Management"`.
  - Response body contains JSON error message.

### TC-062-02: Invalid Authentication Rejection
- **Input Request**: `GET /internal/api/status HTTP/1.1` with `X-Toron-Admin-Key: invalid-key`.
- **Expected Outcome**:
  - Response status code is `HTTP 401 Unauthorized`.

### TC-062-03: Multi-Scheme Credential Acceptance
- **Input Requests**:
  1. `GET /internal/api/status HTTP/1.1` with header `X-Toron-Admin-Key: <valid-token>`.
  2. `GET /internal/api/metrics HTTP/1.1` with header `Authorization: Bearer <valid-token>`.
  3. `GET /internal/api/routes HTTP/1.1` with header `Authorization: Bearer <secondary-key>`.
  4. `GET /internal/api/status HTTP/1.1` with header `Authorization: Basic <base64-credentials>`.
- **Expected Outcome**:
  - Response status code is `HTTP 200 OK` for all authorized requests.
  - Requested telemetry payload is returned.

### TC-062-04: Subnet Allowlist Enforcement
- **Input Request**: `GET /internal/api/status HTTP/1.1` originating from socket IP `198.51.100.25:52341`.
- **Precondition**: `AdminSubnets: ["127.0.0.1/32", "10.0.0.0/16"]`.
- **Expected Outcome**:
  - Response status code is `HTTP 403 Forbidden`.
  - Response body indicates access denied by administrative subnet policy.

### TC-062-05: Subnet Whitelist Conformance
- **Input Request**: `GET /internal/api/status HTTP/1.1` originating from socket IP `127.0.0.1:49152` or `10.0.4.12:51234`.
- **Precondition**: `AdminSubnets: ["127.0.0.1/32", "10.0.0.0/16"]`.
- **Expected Outcome**:
  - Subnet check passes and response is served (`200 OK`).

### TC-062-06: Proxy-Test SSRF and Path Whitelist Rejection
- **Input Payloads**:
  1. `{"path":"http://evil.com/ssrf","method":"GET"}` (Absolute external URI)
  2. `{"path":"//evil.com/ssrf","method":"GET"}` (Protocol-relative URI)
  3. `{"path":"https://169.254.169.254/latest/meta-data","method":"GET"}` (Cloud metadata)
  4. `{"path":"/secret-admin-area","method":"GET"}` (Non-whitelisted path)
  5. `{"path":"/internal/api/status","method":"GET"}` (Internal route probe)
  6. `{"path":"/health","method":"DELETE"}` (Disallowed method)
- **Expected Outcome**:
  - All payloads rejected with `HTTP 400 Bad Request`.

### TC-062-07: Proxy-Test Privilege Header Injection Prevention
- **Input Payloads**:
  1. `{"path":"/health","method":"GET","headers":{"X-Authenticated-User":"root"}}`
  2. `{"path":"/health","method":"GET","headers":{"X-Admin":"true"}}`
  3. `{"path":"/health","method":"GET","headers":{"x-user":"admin"}}`
- **Expected Outcome**:
  - Request rejected with `HTTP 400 Bad Request` ("Disallowed sensitive header in proxy test request").
  - Hop-by-hop and forwarded headers (`X-Forwarded-For`, `Authorization`) are stripped before probe dispatch.
