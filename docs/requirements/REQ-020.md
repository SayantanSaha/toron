# REQ-020 - Domain-Based HTTP Routing and Proxy Forwarding

## Description

The Toron HTTP server and router shall support domain-based (Host header) request dispatching and proxy forwarding. Routes shall support an optional `host` / `domain` matching parameter (e.g. `host: "api.toron.local"` or `host: "auth.toron.local"`). When a request arrives, the router shall match the incoming `Host` header against registered domain routes before falling back to default catch-all routes.

## Acceptance Criteria

- `ProxyRouteConfig` in `pkg/config` updated with `Host` YAML tag (`host: "domain.name"`).
- Router in `pkg/router` updated to support host matching (`r.GETHost`, `r.ProxyHostWithOptions`).
- `routes.yaml` updated with example domain-based routes (`host: "api.toron.local"`, `host: "auth.toron.local"`).
- Request with matching `Host` header (e.g., `Host: api.toron.local:8080` or `Host: api.toron.local`) is correctly routed to the corresponding domain upstream targets.
- All Go unit tests pass cleanly.

## Rationale

Enables virtual hosting and domain-based microservice gateway routing on a single Toron server port.
