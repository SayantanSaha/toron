# SR-085 - Security Review of SEC-25 Remediation - Service Mesh Sidecar Request Body Limiting & Truncation Rejection

## Security Evaluation Summary

- **Vulnerability Remediated**: **SEC-25** ([CWE-436](https://cwe.mitre.org/data/definitions/436.html), [CWE-400](https://cwe.mitre.org/data/definitions/400.html))
- **Affected Subsystem**: Service Mesh Sidecar Proxy ([`pkg/sidecar`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go))
- **CVSS v3.1 Vector**: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N` (Base Score: 5.3 &rarr; **0.0 Resolved**)
- **Verdict**: **APPROVED & RESOLVED**

## 1. Context & Threat Modeling

In [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go), [`ProxyEngine.proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L192) adapts incoming Go standard library [`http.Request`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L192) instances into Toron internal [`httpparser.Request`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go) instances prior to dispatching traffic to local application containers or remote mesh workloads via [`proxy.NewProxyWithOptions`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go).

Prior to this remediation, request body processing was governed by a hardcoded 10 MB limit and an unhandled over-read condition:
```go
const maxSidecarBody = 10 * 1024 * 1024 // 10 MB limit
bodyBytes, err := io.ReadAll(io.LimitReader(r.Body, maxSidecarBody+1))
if err == nil {
    toronReq.Body = bytes.NewReader(bodyBytes)
    toronReq.ContentLength = int64(len(bodyBytes))
}
```

This legacy implementation introduced two severe security exposures:
1. **Silent Request Body Truncation & Interpretation Conflict ([CWE-436](https://cwe.mitre.org/data/definitions/436.html))**:
   When an incoming payload exceeded 10 MB, `io.LimitReader` truncated the stream at `10 * 1024 * 1024 + 1` bytes without error. The proxy updated `toronReq.ContentLength` to the truncated size and forwarded the mutilated body upstream. Upstream services (databases, object storage, API backends) accepted truncated JSON documents, fragmented multipart uploads, or truncated binary RPC frames without noticing corruption, causing data loss and protocol desynchronization.
2. **Hardcoded Body Limit & Denial of Service Vulnerability ([CWE-400](https://cwe.mitre.org/data/definitions/400.html))**:
   The 10 MB limit was hardcoded in the method body, preventing operators from tuning buffer ceilings in resource-constrained edge environments. Additionally, an attacker sending a stream with an declared oversized `Content-Length` forced the proxy to allocate buffer memory and read 10 MB before truncating, allowing buffer allocation exhaustion attacks.

## 2. Verification of Security Controls

### Control 1: Complete Elimination of Silent Truncation & Resource Exhaustion (CWE-436, CWE-400)
- **Evaluation**: The sidecar proxy engine no longer forwards truncated or partial bodies under any condition. Any payload exceeding the configured threshold is immediately rejected at the ingress perimeter before reaching upstream handlers.
- **Verification**:
  - Validated by [`TestTC086_01_DeclaredContentLengthFastFailRejection`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L224) and [`TestTC086_02_BoundedStreamOverReadRejection`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L293).
  - CWE-436 and CWE-400 are fully remediated.

### Control 2: Elimination of Hardcoded Body Limit via Configurable `SidecarConfig.MaxBodyBytes`
- **Evaluation**:
  - [`SidecarConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L109) in [`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) enables operators to specify custom byte thresholds via YAML, JSON, or programmatic structs.
  - Triple-layer fallback guarantees ensure safe operation if unset or non-positive (`<= 0`):
    1. [`DefaultAppConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L539-L541) initializes `Sidecar.MaxBodyBytes = 10 * 1024 * 1024` (10 MB).
    2. [`validateConfigDefaults`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go#L166-L168) in [`pkg/config/loader.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go) normalizes `<= 0` values to `10 * 1024 * 1024`.
    3. [`NewProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L47-L49) and [`proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L205-L208) in [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go) enforce the 10 MB fallback at construction and runtime.
- **Verification**:
  - [`TestConfig_SidecarMaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config_test.go#L30) validates configuration loading.
  - [`TestTC086_03_Default10MBFallbackEnforcement`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L362) verifies fallback normalization for `0` and `-100`, exact 10 MB acceptance (Subtest 3B), and 10 MB + 1 byte rejection (Subtest 3C).

### Control 3: Fast-Fail Declared `Content-Length` Guard (Prevents Buffer Allocation DoS)
- **Evaluation**:
  - In [`proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L214-L219):
    ```go
    if r.ContentLength > maxBody && r.ContentLength > 0 {
        log.Printf("[SIDECAR] 413 Payload Too Large: %s %s declared Content-Length %d exceeds limit %d", r.Method, r.URL.Path, r.ContentLength, maxBody)
        http.Error(w, fmt.Sprintf("Payload Too Large: request Content-Length %d exceeds limit of %d bytes", r.ContentLength, maxBody), http.StatusRequestEntityTooLarge)
        r.Body.Close()
        return
    }
    ```
  - Incoming mutating requests with declared `Content-Length > maxBody` are rejected immediately prior to reading the stream or allocating byte buffers.
  - Protects the sidecar proxy from memory exhaustion attacks via client-declared giant bodies.
- **Verification**:
  - [`TestTC086_01_DeclaredContentLengthFastFailRejection`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L224) verifies immediate HTTP 413 response, body closure, and zero upstream requests.

### Control 4: Bounded Stream Over-Read Guard (`io.LimitReader(r.Body, maxBody+1)`)
- **Evaluation**:
  - In [`proxyToURL`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L225-L234):
    ```go
    bodyBytes, err := io.ReadAll(io.LimitReader(r.Body, maxBody+1))
    if err != nil {
        http.Error(w, fmt.Sprintf("Bad Request: %v", err), http.StatusBadRequest)
        return
    }
    if int64(len(bodyBytes)) > maxBody {
        log.Printf("[SIDECAR] 413 Payload Too Large: %s %s request body exceeds limit %d", r.Method, r.URL.Path, maxBody)
        http.Error(w, fmt.Sprintf("Payload Too Large: request body exceeds limit of %d bytes", maxBody), http.StatusRequestEntityTooLarge)
        return
    }
    ```
  - For chunked transfer encoding (`Transfer-Encoding: chunked`) or streams with undeclared lengths (`r.ContentLength <= 0`), stream reading is strictly capped at `maxBody + 1` bytes.
  - When the read stream exceeds `maxBody`, reading stops, the body is closed, HTTP 413 is returned, and read bytes are dropped.
  - Total heap allocation is bounded by `maxBody + 1`, preventing memory depletion (CWE-400).
  - Malformed streams trigger HTTP 400 Bad Request, preventing transmission of damaged frames.
- **Verification**:
  - [`TestTC086_02_BoundedStreamOverReadRejection`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L293) verifies chunked transfer rejection at 512-byte limit with zero upstream forwarding.

### Control 5: Zero Payload Leakage to Upstream Targets on Oversized Requests
- **Evaluation**:
  - On both rejection branches (fast-fail declared `Content-Length` and bounded stream over-read), execution returns immediately without invoking `px.ServeHTTP(toronReq, toronRes)`.
  - Upstream backend services never receive partial, truncated, or malformed data frames.
- **Verification**:
  - Confirmed across `TestTC086_01` (counter = 0), `TestTC086_02` (counter = 0), `TestTC086_03` (counter = 0 for Subtest 3C), and `TestTC086_06` (`oversizedLeakCount` = 0 across 50 concurrent oversized requests).

### Control 6: Memory Cleanup and Socket Closure (`r.Body.Close()`)
- **Evaluation**:
  - `defer r.Body.Close()` at [`proxy.go:L211`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L211) ensures connection cleanup across all execution paths.
  - Fast-fail path explicitly executes `r.Body.Close()` at line 217 to ensure instant socket release before returning.
  - The temporary byte slice `bodyBytes` is unreferenced upon return on error paths, permitting prompt garbage collection.

### Control 7: Zero Third-Party Dependencies and Attack Surface Minimization
- **Evaluation**:
  - The security fix is implemented entirely within Go standard library packages: `bytes`, `context`, `crypto/tls`, `fmt`, `io`, `log`, `net`, `net/http`, `strings`, `sync`, `time`.
  - Zero external dependencies were introduced, maintaining a minimal attack surface and eliminating supply chain vulnerabilities.

### Control 8: High-Concurrency & Race-Condition Safety
- **Evaluation**:
  - Mutex locking in [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23) protects state mutations during start/stop lifecycles, while routing and traffic splitter access use read locks.
  - Verified under Go race detector:
    `go test -count=1 -race ./pkg/sidecar/...` passes with zero race conditions or data races.
- **Verification**:
  - [`TestTC086_06_HighConcurrencyRaceSafety`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L688) executed 100 concurrent requests (25 valid POSTs, 25 declared oversized POSTs, 25 chunked oversized POSTs, and 25 GETs) with 100% assertion adherence and zero upstream leaks.
