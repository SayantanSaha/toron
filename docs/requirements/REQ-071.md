# REQ-071 - Client Connection State Integrity for Forwarded Ingress Headers

## Description

The Toron reverse proxy gateway shall derive forwarded protocol and client address headers (`X-Forwarded-Proto`, `X-Forwarded-For`) strictly from verified socket connection states, preventing untrusted clients from spoofing security-sensitive headers to upstream backend services.

Client-supplied headers such as `X-Forwarded-Proto` and `X-Real-IP` shall not be blindly trusted or propagated unless the request originates from a pre-configured trusted proxy IP address.

## Acceptance Criteria

### 1. Trusted Protocol Derivation
- The reverse proxy shall determine `X-Forwarded-Proto` based strictly on whether TLS encryption is active on the incoming client socket (`req.RawConn`), setting `https` only when TLS was negotiated.
- A client connecting over cleartext HTTP shall not be able to force `X-Forwarded-Proto: https` by supplying a crafted header, unless originating from a configured trusted proxy.

### 2. Client IP Derivation from Physical Socket
- The proxy shall populate `X-Forwarded-For` using the verified client IP address extracted from `req.RawConn.RemoteAddr()`.
- Client-supplied `X-Forwarded-For` and `X-Real-IP` headers shall be appended to or replaced, rather than blindly overriding the verified client address.

### 3. Hop-by-Hop Header Stripping
- In accordance with RFC 7230 §6.1, hop-by-hop headers (such as `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Upgrade`) shall be sanitized and not forwarded blindly to upstream microservices on standard HTTP transactions.

### 4. Trusted Proxy CIDR Configuration
- Toron shall provide a `trusted_proxies` configuration list in `config.yaml`. Only connections arriving from IPs in this list shall have their client-supplied `X-Forwarded-*` headers honored.

## Rationale

When reverse proxies forward unverified client headers, attackers can spoof `X-Forwarded-Proto: https` to bypass downstream SSL-only restrictions, or forge `X-Real-IP` to tamper with backend auditing and access control systems.

## Constraints

- Compliance with RFC 7230 §6.1.
- Minimal performance overhead during header transformation.
