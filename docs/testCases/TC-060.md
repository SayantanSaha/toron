# TC-060 - Verification of Query Parameter Forwarding and Preservation Across Protocols

## Objective

Verify that Toron preserves and forwards all URL query parameters to upstream backends across HTTP/1.1 and HTTP/2/3 ingress adapters, merges target-configured query parameters, and records full URIs in access logs.

## Test Cases

### TC-060-01: Standard Query Parameter Forwarding (HTTP/1.1 & HTTP/2)
- **Input Request**: `GET /api/v1/trades?symbol=INFY&status=COMPLETE`
- **Action**: Dispatch through reverse proxy.
- **Expected Outcome**: Upstream backend receives `RawQuery` equal to `symbol=INFY&status=COMPLETE`.

### TC-060-02: HTTP/2 Ingress Adapter Request Conversion
- **Input**: Standard library `*http.Request` with `URL.RawQuery = "page=2&limit=50"`.
- **Action**: Convert via `httpparser.NewRequestFromStd(r)`.
- **Expected Outcome**:
  - `req.QueryParams.Get("page")` is `"2"`.
  - `req.QueryParams.Get("limit")` is `"50"`.
  - `req.URL.RawQuery` is preserved as `"page=2&limit=50"`.

### TC-060-03: Merging Client Query with Upstream Target Query
- **Configuration**: `target: "http://upstream:8080/api?fixed=true"`
- **Client Request**: `GET /api?filter=active`
- **Expected Outcome**: Upstream receives `fixed=true&filter=active`.

### TC-060-04: Verbatim Query String Preservation (Flags & Encodings)
- **Input Request**: `GET /search?q=hello+world&verbose`
- **Expected Outcome**: Upstream receives `q=hello+world&verbose` verbatim without key re-sorting or conversion of `verbose` into `verbose=`.

### TC-060-05: Access Log Telemetry with Query Parameters
- **Action**: Process request with query parameters through `AccessLoggerMiddleware`.
- **Expected Outcome**: Access log entry contains `req.RequestURI` (e.g. `/search?q=hello`).
