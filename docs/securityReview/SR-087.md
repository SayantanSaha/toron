# SR-087 - Security Review of SEC-27 Remediation: Maximum Idle Deadline Enforcement on Upgraded Protocol and WebSocket Connections

## Security Evaluation Summary

- **Vulnerability Remediated**: **SEC-27** ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html))
- **Affected Subsystems**: Core HTTP Server Connection Management ([`pkg/server/server.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go), [`pkg/server/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/config.go), [`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go))
- **CVSS v3.1 Vector**: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:M` (Base Score: 5.3 &rarr; **0.0 Resolved**)
- **Verdict**: **APPROVED & RESOLVED**

---

## 1. Context & Threat Modeling

In [`pkg/server/server.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go), Toron provides bidirectional stream tunneling for HTTP/1.1 protocol upgrades (`101 Switching Protocols` / WebSocket RFC 6455) and HTTP/2 Extended CONNECT streams (RFC 8441).

Prior to this remediation, upgraded connections exhibited critical resource exhaustion vulnerabilities identified in [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392) and [`SR-081 Finding 5`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L142-L150):

1. **Permanent Deadline Stripping**: In [`handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go), when switching protocols, existing deadlines were cleared with `conn.SetDeadline(time.Time{})` and `res.UpgradedConn.SetDeadline(time.Time{})`.
2. **Unbounded Blocking `io.Copy`**: Forwarding relied on unrestricted `io.Copy` loops. If an attacker or silent peer ceased transmitting, both relay goroutines remained blocked indefinitely.
3. **Slowloris File Descriptor & Memory Exhaustion (`EMFILE`)**: Because abandoned connections were never reclaimed, an adversary could open hundreds of idle WebSocket connections, consuming file descriptors until host limits were exceeded, denying service to all gateway traffic.

---

## 2. Security Control Verification

### A. Elimination of Permanent Deadline Clearing
- Unconditional `SetDeadline(time.Time{})` has been completely eliminated.
- Sockets are armed with `UpgradeIdleTimeout` before stream copying begins.

### B. Bidirectional Activity-Refreshed Deadlines (`pkg/server/server.go`)
- The new `relayUpgradedStreams` and `relayStreams` mechanisms refresh read and write deadlines on both client and upstream sockets on every transferred data chunk.
- If bidirectional silence exceeds `UpgradeIdleTimeout`, the stream times out immediately, triggering synchronized teardown via `sync.Once`.
- Verified in [`TestServer_UpgradedConn_IdleTimeout`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go#L705): idle connection terminated cleanly within $150\text{ms} \pm 50\text{ms}$.

### C. HTTP/2 Extended CONNECT Stream Protection
- In [`http2AdapterHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go), `relayHTTP2UpgradedStream` enforces `UpgradeIdleTimeout` via atomic timestamp tracking and watchdog timer.
- Client context cancellation (`r.Context().Done()` / `RST_STREAM`) immediately triggers socket closure.
- Verified in [`TestServer_HTTP2_ExtendedCONNECT_IdleAndCancel`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go#L958).

### D. Heartbeat / Ping-Pong Transparency
- RFC 6455 Ping (`0x9`) and Pong (`0xa`) frames and application heartbeats are transmitted at the transport layer, naturally refreshing deadlines.
- Verified in [`TestServer_UpgradedConn_HeartbeatKeepsAlive`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go#L765): connection preserved for $> 400\text{ms}$ under periodic pings, and cleanly timed out once pings stopped.

### E. Concurrency & Race Freedom
- Validated under `go test -race -count=1 ./pkg/server/... ./pkg/config/...` with 40 concurrent workers across mixed scenarios (heartbeats, idle timeouts, abrupt disconnects, HTTP/2 context cancellations). Zero data races detected.

---

## 3. Security Verdict

**APPROVED & RESOLVED**

Vulnerability [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392) (CWE-400) is fully mitigated. The server is immune to Slowloris attacks on WebSocket and upgraded protocol endpoints.
