# REQ-038 - Native gRPC Health Checking Protocol & HTTP/2 Trailers Gateway Verification

## Description

The Toron edge proxy shall support native **gRPC Health Checking Protocol (`grpc.health.v1.Health`)** and strict **HTTP/2 Trailers preservation** to operate as a production-grade gRPC Edge Gateway.

The gRPC gateway subsystem shall:
1. **gRPC Health Checking Prober (`grpc.health.v1.Health/Check`)**:
   - Implement native binary Protobuf frame generation and response decoding for the standard gRPC health check service.
   - Send HTTP/2 requests with `Content-Type: application/grpc`, `TE: trailers`, and standard 5-byte gRPC framing (`[0x00][4-byte-length][protobuf]`).
   - Decode `HealthCheckResponse` Protobuf varints and verify `ServingStatus == SERVING (1)` and `grpc-status == 0`.
   - Update circuit breaker states and healthy target pools accordingly.
2. **HTTP/2 Trailers Preservation & Passthrough**:
   - Ensure the reverse proxy engine captures and preserves upstream HTTP/2 trailing headers (`grpc-status`, `grpc-message`, `grpc-status-details-bin`).
   - Deliver trailers as terminal HTTP/2 HEADERS frames with `END_STREAM` set.
3. **Route Configuration Extensions**:
   - Extend `routes.yaml` and `pkg/config/config.go` with `health_check_type: "grpc"` and `health_check_service: "<service_name>"`.

## Acceptance Criteria

- `pkg/proxy`: Active health check probes target microservices via `grpc.health.v1.Health/Check` when `health_check_type: "grpc"`.
- Targets returning `SERVING (1)` and `grpc-status: 0` are marked healthy; targets returning `NOT_SERVING` or connection errors are marked unhealthy.
- gRPC client responses preserve `grpc-status` and `grpc-message` trailing headers.
- All Go unit tests pass cleanly (`go test ./...`).
