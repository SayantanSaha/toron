# TC-043 - Route-Level WAF Overrides & CIDR IP Access Lists Verification

## Test Objectives

1. **CIDR Denylist Enforcement**: Verify requests originating from IP addresses matching configured `denied_ips` CIDR blocks (e.g., `198.51.100.0/24`, `203.0.113.5`) are immediately rejected with `403 Forbidden`.
2. **CIDR Allowlist Enforcement**: Verify that when `allowed_ips` is configured (e.g., `10.0.0.0/8`, `192.168.1.0/24`), requests from client IPs outside those subnets return `403 Forbidden`, while client IPs inside the subnets proceed.
3. **IPv4 & IPv6 CIDR Parsing**: Verify correct handling of IPv4 subnets, IPv6 subnets (e.g., `2001:db8::/32`), single IP notations, and graceful handling of malformed CIDR strings.
4. **Client IP Extraction**: Verify client IP resolution from `req.RemoteAddr` (e.g. `127.0.0.1:54321` -> `127.0.0.1`) and `X-Forwarded-For` headers.
5. **Route-Level Rule Disabling**: Verify that a route with `disabled_rules: ["SQLI-001"]` permits payloads matching `SQLI-001` on that specific route without triggering `403 Forbidden`, while another route with default rules blocks the same payload.
6. **Route-Level Detection Mode**: Verify that a route configured with `mode: "detection"` allows threat payloads to pass to the target handler while setting `X-Toron-WAF-Anomaly-Score`, while default routes enforce blocking.
7. **End-to-End Route Dispatching**: Verify route-level WAF binding works seamlessly for both static site routes and upstream proxy routes in `router.go`.
