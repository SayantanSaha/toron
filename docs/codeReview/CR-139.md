# CR-139 - Code Review for Distinct Upstream Route Pool Rendering and Live Telemetry Metric Derivation

## 1. Executive Summary

This code review evaluates the implementation of disaggregated upstream route pool rendering and live telemetry metric derivation in the Toron Edge Gateway Control Center dashboard ([`public/app.js`](../../public/app.js)) and its verification harness ([`tests/dashboard_telemetry_test.js`](../../tests/dashboard_telemetry_test.js)).

The implementation resolves two major operational visibility defects specified in [`REQ-139`](../requirements/REQ-139.md), architected in [`ADR-139`](../architecture/ADR-139.md), decomposed in [`TASK-162`](../tasks/TASK-162.md), and verified by [`TC-139`](../testCases/TC-139.md):
1. **Upstream Route Collapse Anti-Pattern**: Multiple proxy routes targeting the same backend socket (e.g. `/kite/callback`, `/kite/api`, `/kite/broker`, `/kite/auth` routing to `http://127.0.0.1:8080`) were previously conflated into the first declared route, causing subsequent routes to be dropped from the Upstreams view (`#/upstreams`).
2. **Telemetry Field Mismatch & Static Metric Fallbacks**: Lookups against non-existent metric properties (`by_route`, `rate_per_sec`, `latency_p95_ms`, `err_rate`) caused route and pool cards to display hardcoded fallback values (`0.0/s`, `2.5 ms`, `0.0%`), masking live traffic load and backend health status.

---

## 2. Review Scope

The scope of this code review covers all modified and added files:
- **Frontend Controller** ([`public/app.js`](../../public/app.js)):
  - Route-level proportional RPS derivation (`curRPS`) from `rawApiStatus.timeseries.A.rps` and `rawApiStatus.metrics.requests_by_route`.
  - Dynamic route latency derivation (`lat`) from health probe response (`u.latency_ms`) and gateway time-series (`tsA.p95`).
  - Strict route-first probe matching prioritizing `u.route` over raw target socket addresses.
  - Deterministic route-scoped pool key generation (`poolKey = primaryRoute.id`).
  - Distinct instance binding and multidimensional health state classification (`isDown`, `isUp`, `instState`).
  - Exhaustive fallback route loop ensuring unmapped proxy routes are rendered as independent pool cards with passive health checks.
  - Dynamic pool p95 derivation from active instance probe latencies and dynamic error rate calculation from probe history ticks.
  - Instance row latency binding in `poolCard(p)` displaying live probe latency formatted to one decimal place.
  - Visual tone escalation (`ok` $\rightarrow$ `warn` $\rightarrow$ `err`) and circuit breaker status notes.
  - Overview Traffic Flow Sankey diagram disaggregation (`flow()`) routing distinct ribbons from routes to upstream pools.
  - Routes view table parity (`rtUpdate()`) maintaining metric alignment and multi-level column sorting.
- **Automated Verification Suite** ([`tests/dashboard_telemetry_test.js`](../../tests/dashboard_telemetry_test.js)):
  - Headless Node.js DOM sandbox and test harness.
  - Test cases TC-139-01 through TC-139-10 covering functional, edge-case, visual parity, and performance benchmark requirements.

## 4. Detailed Technical Findings

### Finding 1: Upstream Route Disaggregation on Shared Sockets (FR-1, FR-2, FR-3, FR-4)
- **Severity**: Informational / Verified
- **Implementation Detail**:
  In `buildDataModel()`, health check probe matching was refactored to evaluate route labels before examining socket addresses:
  ```javascript
  const routeMatches = routes.filter(r => {
    if (!u.route) return false;
    return r.short === u.route || r.path === u.route || (r.host + r.path) === u.route ||
           r.short.includes(u.route) || (r.host + r.path).includes(u.route) ||
           u.route.includes(r.path) || u.route.includes(r.short);
  });
  ```
  Pool keys are generated using `primaryRoute.id` (sanitized route ID) rather than socket IP/port:
  ```javascript
  const poolKey = primaryRoute ? primaryRoute.id : (u.route ? u.route.replace(/[^a-zA-Z0-9]/g, '_') : targetAddr.replace(/[^a-zA-Z0-9]/g, '_'));
  ```
  Additionally, the exhaustive secondary loop iterates over all configured proxy routes not yet in `poolMap`, guaranteeing that unmapped routes (e.g. `/kite/orders`) render as distinct pool cards with passive health checking.
- **Verification**: Verified by `TC-139-01` and `TC-139-02`. All 4 Kite routes sharing `127.0.0.1:8080` render discrete pool cards with route-specific headers, match paths, and headers summaries.

### Finding 2: Proportional Real-Time Telemetry Rate Derivation (FR-5, FR-6, FR-7)
- **Severity**: Informational / Verified
- **Implementation Detail**:
  Property lookups now correctly align with [`pkg/metrics/metrics.go`](../../pkg/metrics/metrics.go):
  - `requests_by_route` replaces `m.by_route`.
  - `timeseries.A.rps[last]` replaces `m.rate_per_sec`.
  Instantaneous route RPS is calculated proportionally:
  $$\text{curRPS} = \text{total\_rps} \times \left(\frac{\text{route\_cumulative}}{\max(1, \text{total\_requests})}\right)$$
  When cumulative route requests are zero and the gateway has processed requests for other routes, `curRPS` evaluates cleanly to `0.0`. Pool summary Requests metric sums `curRPS` across associated routes.
- **Verification**: Verified by `TC-139-03`. Given 120 req/s total throughput and request shares of 50%, 30%, 20%, and 0%, routes evaluate to exactly 60.0, 36.0, 24.0, and 0.0 req/s with total conservation $\sum \text{curRPS} = 120.0$.

### Finding 3: Dynamic Health Probe Latency & Error Rate Calibration (FR-8, FR-9, FR-10, FR-11, FR-12)
- **Severity**: Informational / Verified
- **Implementation Detail**:
  - In `poolCard(p)`, instance latency directly formats `i.latency` (derived from `/internal/api/upstreams/health` `u.latency_ms`):
    ```javascript
    <span>Latency: <b>${(i.latency && i.latency > 0) ? i.latency.toFixed(1) + ' ms' : fmt.ms(p.p95)}</b></span>
    ```
  - Pool p95 latency dynamically selects `Math.max(...activeProbeLats)` or route average / time-series p95, eliminating the static `2.5 ms` constant when real measurements exist.
  - Instance health state evaluates both probe status strings and HTTP codes:
    ```javascript
    const isDown = u.status === 'UNREACHABLE' || u.status === 'DOWN' || (u.http_code && u.http_code >= 500);
    const isUp = (u.status === 'HEALTHY' || u.status === 'UP') && (!u.http_code || u.http_code < 400);
    const instState = isDown ? 'down' : (isUp ? 'up' : 'warn');
    ```
  - Failing probes trigger `down` status, calculate probe failure ratios from `i.history`, escalate pool tone to `err`, and inject the circuit-breaker alert notice into the card.
- **Verification**: Verified by `TC-139-04`, `TC-139-05`, and `TC-139-06`. Unreachable instances display red status pills, 25.0% error rate, and trigger critical upstream alerts in `D.alerts`.

### Finding 4: Overview Flow Sankey Parity & Route Ribbon Routing (FR-13, FR-14)
- **Severity**: Informational / Verified
- **Implementation Detail**:
  In `flow(host, D)`, pool nodes are derived from `D.pools`, and route matching incorporates route ID and pool membership:
  ```javascript
  let targetPool = poolMap.get(r.id) || poolMap.get(r.pool) || poolNodes.find(p => p.id === r.id || (p.routes && p.routes.some(pr => pr.id === r.id)) || (r.pool && (r.pool.includes(p.id) || p.id.includes(r.pool)))) || poolNodes[0];
  ```
  Ribbons connect from each route node to its specific upstream pool block. When an upstream pool is in error tone, the connecting ribbon carries the corresponding error tone class (`class="rb err"`).
- **Verification**: Verified by `TC-139-08` and `TC-139-09`. SVG contains distinct `<rect>` nodes and link ribbons for `/kite/callback`, `/kite/api`, `/kite/broker`, and `/kite/auth`.

### Finding 5: Automated Verification Suite in Headless DOM Sandbox

It systematically verifies all 10 test cases from [`TC-139`](../testCases/TC-139.md), including edge conditions (cold startup, missing metric objects, division-by-zero guards) and a 100-iteration performance benchmark.
