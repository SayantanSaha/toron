# SR-140 - Security Review for Dynamic Upstream Target Context Propagation, Route Tagging, and Telemetry Trace Fidelity

## 1. Executive Summary

This security review conducts a comprehensive vulnerability assessment and threat modeling analysis of the dynamic upstream target context propagation and route identification features implemented under [`REQ-140`](../requirements/REQ-140.md), [`TASK-163`](../tasks/TASK-163.md), and [`ADR-140`](../architecture/ADR-140.md).

The review focuses on ensuring that propagating internal backend socket addresses (e.g. `127.0.0.1:8080`, internal private VPC IPs) and route metadata does not expose sensitive network topology to external untrusted clients, introduce cross-site scripting risks in the dashboard, or create memory exhaustion attack vectors.

---

## 2. Threat Modeling & CWE Analysis

### 2.1 Information Exposure Through Internal Network Topology (CWE-200)
- **Threat Vector**: If the reverse proxy or telemetry middleware passes the selected upstream backend address (e.g., `127.0.0.1:8080` or internal microservice IPs) in HTTP response headers (such as `X-Toron-Upstream` or `Via`), external adversaries could map internal infrastructure topology, backend hostnames, and service distribution.
- **Mitigation & Verification**:
  - The implementation in [`pkg/proxy/proxy.go`](../../pkg/proxy/proxy.go) and [`pkg/router/router.go`](../../pkg/router/router.go) attaches the upstream target socket strictly to `req.Context()`.
  - No response headers containing upstream sockets or internal topology are ever added to `res.Header` sent over the wire to external clients.
  - Upstream socket visibility is restricted exclusively to authenticated administrators inspecting the Control Center dashboard via `GET /internal/api/logs`.
- **Status**: **VERIFIED SAFE (ZERO WIRE LEAKAGE)**.

### 2.2 Cross-Site Scripting (XSS) Prevention (CWE-79)
- **Threat Vector**: An attacker manipulating route paths or host headers could attempt to inject malicious HTML/JavaScript payloads into `routeStr`, `shortStr`, or `upNode` that would execute when an operator views the **Live Requests & Logs** view or opens the trace drawer.
- **Mitigation & Verification**:
  - In [`public/app.js`](../../public/app.js), all dynamic values rendered in table rows (`e.up`, `e.route`, `e.short`, `e.path`, `e.trace`, `e.ip`) and the trace drawer are passed through the strict contextual HTML escaper `esc()`:
    ```javascript
    <td class="hide-md"><code>${esc(e.up)}</code></td>
    <dt>Upstream Node</dt><dd><code>${esc(e.up)}</code></dd>
    ```
  - Any raw HTML tags or script delimiters are neutralized before DOM insertion.
- **Status**: **VERIFIED SAFE**.

### 2.3 Uncontrolled Resource Consumption & Memory Leaks (CWE-400)
- **Threat Vector**: Recording high-frequency request traces could cause unbounded memory growth, leading to gateway denial-of-service.
- **Mitigation & Verification**:
  - `GlobalTraceBuffer` operates with a strict, fixed-capacity circular ring buffer (`DefaultTraceCapacity = 300`).
  - Ingestion executes in $\mathcal{O}(1)$ time with zero heap allocation per record.
  - Per-request context objects are short-lived and garbage-collected as soon as the client connection completes.
- **Status**: **VERIFIED SAFE**.

### 2.4 Race Conditions & Concurrency Safety (CWE-362)
- **Threat Vector**: Multi-threaded access to request contexts across goroutines during proxying, streaming, or logging could result in data races or memory corruption.
- **Mitigation & Verification**:
  - Context values are written serially on the request goroutine before response serialization.
  - The test suite verified execution under `go test -race -count=1 ./...` with zero race warnings.
- **Status**: **VERIFIED SAFE**.

## 3. Security Review Verdict

| Security Criterion | Assessment | Finding |
|---|---|---|
| **CWE-200 Information Disclosure** | Evaluated | Zero internal topology leaked in client responses |
| **CWE-79 Cross-Site Scripting** | Evaluated | Contextual escaping enforced on all dashboard renders |
| **CWE-400 Resource Consumption** | Evaluated | Fixed-capacity circular buffer with $\mathcal{O}(1)$ insertion |
| **CWE-362 Concurrency Races** | Evaluated | Verified race-clean under `-race` flag |
| **Strictly Relative Links** | Evaluated | No absolute filesystem paths in documentation |

**Overall Verdict: APPROVED WITH ZERO SECURITY DEFECTS.**
