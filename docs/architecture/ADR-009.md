# ADR-009 - Upstream Health Checking and Circuit Breaker Architecture

## Context

To protect reverse proxy workloads from forwarding client requests to degraded or offline upstream backends, Toron requires a circuit breaker pattern coupled with active and passive health checks.

## Decision

1. **Circuit Breaker State Machine**:
   - **`StateClosed` (Healthy)**: Normal request routing. Requests/probes that succeed reset consecutive failure counters.
   - **`StateOpen` (Tripped)**: Reached $N$ consecutive failures. Requests immediately bypass this target without attempting network I/O.
   - **`StateHalfOpen` (Probing Recovery)**: After `cooldown_period` elapses, 1 trial request/probe is permitted. Success resets state to `StateClosed`; failure re-trips state to `StateOpen`.
2. **Active Health Prober**:
   - Each route with `health_check_path` spawns a background ticker probing `targetURL + health_check_path` via HTTP GET.
3. **Load Balancer Integration**:
   - `RoundRobinBalancer.Next()` dynamically filters targets to select only `StateClosed` or `StateHalfOpen` upstreams.
   - If 0 targets are healthy, returns `ErrNoHealthyUpstreamAvailable` resulting in HTTP 503 Service Unavailable / 502 Bad Gateway.

## Consequences

- **Positive**: Prevents cascading failures and isolates offline upstreams.
- **Negative**: Adds background goroutine timers for active health probing per configured route.
