# TC-009 - Reverse Proxy Upstream Request Forwarding Verification

## Description

Verify that `pkg/proxy` forwards client requests to an upstream HTTP server, passes headers and body payloads, injects `X-Forwarded-*` headers, streams the upstream response back to the client, and returns `502 Bad Gateway` when upstream is unreachable.

## Preconditions

- Mock upstream HTTP server started on dynamic port.

## Test Data

- Client GET request to `/proxy/data`.
- Client POST request to `/proxy/submit` with body payload `{"test":true}`.
- Requests to an offline port (`http://127.0.0.1:59999`).

## Steps

1. Start mock upstream server echoing received headers and body.
2. Issue GET request via Toron reverse proxy -> Verify 200 OK and presence of `X-Forwarded-For` and `X-Forwarded-Host` headers at upstream.
3. Issue POST request with body payload -> Verify body received intact at upstream and returned to client.
4. Issue request targeting offline port -> Verify `502 Bad Gateway` returned.

## Expected Results

- Reverse proxy successfully forwards HTTP requests and handles offline upstream failures gracefully.

## Acceptance Criteria

- All integration tests in `pkg/proxy` pass.

## Rationale

Ensures reverse proxy reliability.

## Constraints

- Pure Go integration tests.
