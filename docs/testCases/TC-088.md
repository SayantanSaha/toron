# TC-088 - Verification of Upgraded Connection Idle Deadline Enforcement and Slowloris Protection

## Objective

Verify that the Toron HTTP server engine ([`Server`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go)) enforces configurable maximum idle deadlines and bidirectional activity tracking across all upgraded protocol streams—including HTTP/1.1 protocol upgrades (RFC 6455 WebSockets and raw bidirectional TCP tunnels returning `101 Switching Protocols`) and HTTP/2 Extended CONNECT streams (RFC 8441 WebSockets over HTTP/2). This test suite validates that:
1. Schema configuration and hierarchical fallbacks for [`UpgradeIdleTimeout`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/config.go#L6-L30) function predictably across [`server.Config`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/config.go#L6-L30), [`ServerConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L214-L237), and [`ValidateConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go#L172).
2. Prolonged inactivity on established upgraded connections triggers deterministic socket closure and goroutine termination, releasing operating system socket file descriptors (`FD`s).
3. Active streams exchanging periodic control frames (RFC 6455 Ping/Pong) or application heartbeats continuously refresh their deadlines and remain active indefinitely.
4. Abrupt or graceful peer disconnection by either client or upstream triggers immediate counterpart socket closure.
5. TCP half-close (`CloseWrite()`) is propagated gracefully, permitting response draining up to the idle deadline.
6. HTTP/2 Extended CONNECT streams enforce inactivity timeouts and immediate cancellation upon request context termination (`r.Context().Done()`).
7. All lifecycle mechanisms execute concurrently with zero data races under `go test -race`.

This specification validates the remediation of critical security vulnerability [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html)) and [`SR-081 Finding 5`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L142-L150), preventing Slowloris socket exhaustion and file descriptor starvation (`EMFILE`).

## Test Specifications

### TC-088-01: Configurable Schema & Hierarchical Fallback Validation
- **Objective**: Verify that [`UpgradeIdleTimeout`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/config.go#L6-L30) is correctly defined, initialized, deserialized, validated, and hierarchically mapped:
  1. [`DefaultConfig()`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/config.go#L33-L54) sets `UpgradeIdleTimeout` to `60 * time.Second`.
  2. [`DefaultAppConfig()`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L494-L577) sets `Server.UpgradeIdleTimeout` to `60 * time.Second`.
  3. [`ServerConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L214-L237) correctly unmarshals `upgrade_idle_timeout` from YAML and JSON payloads.
  4. [`ToServerConfig()`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L580-L610) resolves `UpgradeIdleTimeout` according to the 3-tier hierarchy:
     - Tier 1: Explicit `ServerConfig.UpgradeIdleTimeout` when `> 0`.
     - Tier 2: Fall back to `ServerConfig.IdleTimeout` when `UpgradeIdleTimeout <= 0` and `IdleTimeout > 0`.
     - Tier 3: Fall back to `60 * time.Second` when both are `<= 0`.
  5. [`ValidateConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go#L172) rejects negative `UpgradeIdleTimeout` (`< 0`) with a descriptive error.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 1), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§1.1–§1.4), [`TASK-097`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-097.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestConfig_UpgradeIdleTimeoutSchemaAndFallback(t *testing.T)` in [`pkg/config/config_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config_test.go).
- **Setup & Preconditions**:
  - Temporary YAML and JSON configuration files created via `t.TempDir()`.
- **Action**:
  - **Subtest 1A (Default Invariants)**:
    1. Inspect `server.DefaultConfig().UpgradeIdleTimeout`.
    2. Inspect `config.DefaultAppConfig().Server.UpgradeIdleTimeout`.
  - **Subtest 1B (YAML & JSON Deserialization)**:
    1. Write YAML snippet with `server:\n  upgrade_idle_timeout: 45s\n` and parse via `config.LoadFromFile`.
    2. Write JSON snippet with `{"server": {"upgrade_idle_timeout": 30000000000}}` and unmarshal via `json.Unmarshal`.
  - **Subtest 1C (Hierarchical Fallback Resolution)**:
    1. Evaluate `ToServerConfig()` when `Server.UpgradeIdleTimeout = 15s` and `Server.IdleTimeout = 30s`.
    2. Evaluate `ToServerConfig()` when `Server.UpgradeIdleTimeout = 0` and `Server.IdleTimeout = 25s`.
    3. Evaluate `ToServerConfig()` when `Server.UpgradeIdleTimeout = 0` and `Server.IdleTimeout = 0`.
  - **Subtest 1D (Negative Value Rejection)**:
    1. Construct `AppConfig` with `Server.UpgradeIdleTimeout = -5 * time.Second`.
    2. Pass to `config.ValidateConfig(cfg)`.
- **Verifiable Assertions**:
  1. `server.DefaultConfig().UpgradeIdleTimeout` equals `60 * time.Second`.
  2. `config.DefaultAppConfig().Server.UpgradeIdleTimeout` equals `60 * time.Second`.
  3. YAML deserialization yields `cfg.Server.UpgradeIdleTimeout == 45 * time.Second`.
  4. JSON unmarshaling yields `cfg.Server.UpgradeIdleTimeout == 30 * time.Second`.
  5. Fallback Tier 1 resolves to `15s`, Tier 2 resolves to `25s`, and Tier 3 resolves to `60s`.
  6. `ValidateConfig` returns an error containing `"server.upgrade_idle_timeout must be non-negative"`.

### TC-088-02: HTTP/1.1 Upgraded Connection Idle Timeout Teardown
- **Objective**: Verify that [`Server.handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L272-L294) terminates both the client socket and the upstream socket (`res.UpgradedConn`) when an upgraded connection remains idle (zero byte transfer in both directions) for longer than `UpgradeIdleTimeout` (`150ms`). Assert that all relay goroutines terminate cleanly and socket file descriptors are returned to the operating system without resource leakage.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 2, AC 5, AC 6), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§2.1–§2.3, §2.5–§2.6), [`TASK-098`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-098.md), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_UpgradedConn_IdleTimeout(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server running on `127.0.0.1:0` that tracks open socket state and echoes received bytes.
  - Toron server configured with `UpgradeIdleTimeout = 150 * time.Millisecond` and `ReadTimeout = 2 * time.Second`.
  - Route `/ws-idle` registered in router: upon request, dials the mock backend, returns `101 Switching Protocols`, and assigns the backend socket to `res.UpgradedConn`.
  - Server listener started on `127.0.0.1:0`.
  - Record baseline goroutines via `runtime.NumGoroutine()`.
- **Action**:
  1. Client dials server (`net.Dial("tcp", srvAddr)`).
  2. Client transmits HTTP upgrade request:
     ```http
     GET /ws-idle HTTP/1.1\r\nHost: localhost\r\nUpgrade: websocket\r\nConnection: Upgrade\r\n\r\n
     ```
  3. Client reads server response and verifies `HTTP/1.1 101 Switching Protocols`.
  4. Client sends `"hello-handshake"` and receives `"echo: hello-handshake"` to confirm the bidirectional relay is actively operating.
  5. Client ceases all transmissions and upstream backend ceases all transmissions (total bidirectional silence). Record timestamp $T_{\text{idle\_start}}$.
  6. Client issues a blocking read on the socket with a 1-second timeout: `conn.SetReadDeadline(time.Now().Add(1 * time.Second))`.
  7. Client observes read return and records elapsed duration $\Delta T = T_{\text{read\_return}} - T_{\text{idle\_start}}$.
  8. Check mock upstream server socket status.
  9. Allow 50ms for goroutines to drain; measure `runtime.NumGoroutine()`.
- **Verifiable Assertions**:
  1. Client socket read returns `io.EOF` or a closed network connection error.
  2. Socket teardown occurs within the expected timeout window: $140\text{ms} \le \Delta T \le 300\text{ms}$ (enforcing `UpgradeIdleTimeout = 150ms`).
  3. Mock upstream server observes connection closure on its counterpart socket.
  4. Both relay goroutines terminate cleanly; `runtime.NumGoroutine()` returns to baseline ($\pm 1$).
  5. Both client and upstream socket file descriptors are released.

### TC-088-03: HTTP/1.1 Heartbeat / Active Stream Preservation
- **Objective**: Verify that active upgraded connections exchanging periodic traffic (such as RFC 6455 Ping/Pong frames or application-level keep-alives) at intervals shorter than `UpgradeIdleTimeout` continuously refresh their socket deadlines and remain alive indefinitely without premature disconnection. When heartbeats cease, the connection MUST terminate after `UpgradeIdleTimeout`.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 2, AC 4), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§2.2, §4), [`TASK-098`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-098.md), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_UpgradedConn_HeartbeatKeepsAlive(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server on loopback.
  - Toron server configured with `UpgradeIdleTimeout = 150 * time.Millisecond`.
  - Route `/ws-heartbeat` registered returning `101 Switching Protocols` and `res.UpgradedConn`.
- **Action**:
  1. Client dials server and completes the upgrade handshake to `/ws-heartbeat`.
  2. Client enters a heartbeat loop executing for a total duration of `400ms` ($> 2.6 \times \text{UpgradeIdleTimeout}$):
     - Every `50ms` ($< 150\text{ms}$), client sends a ping payload `"ping-<i>"` ($i \in [1, 8]$).
     - Client reads and verifies the echo response `"echo: ping-<i>"`.
  3. Verify that all 8 ping-pong cycles succeed across the 400ms period.
  4. At $T = 400\text{ms}$, client ceases all heartbeat transmissions.
  5. Client attempts a blocking read with a 500ms timeout: `conn.SetReadDeadline(time.Now().Add(500 * time.Millisecond))`.
  6. Measure duration until the connection closes after heartbeats cease.
- **Verifiable Assertions**:
  1. The upgraded connection remains fully operational and connected throughout the entire 400ms heartbeat phase, successfully completing all 8 round-trips without timeout.
  2. Byte transfers in both directions continuously extend read and write deadlines by `UpgradeIdleTimeout`.
  3. Once heartbeats cease at $T = 400\text{ms}$, the connection terminates after the idle window ($150\text{ms} \pm 50\text{ms}$).
  4. The client read returns `io.EOF` or a closed connection error after the idle timeout expires.

### TC-088-04: HTTP/1.1 Peer Disconnect Teardown
- **Objective**: Verify that when either peer (client or upstream backend) abruptly closes its connection or cleanly terminates, the server immediately tears down the counterpart socket via `sync.Once` without waiting for `UpgradeIdleTimeout` to expire.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 2, AC 5), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§2.3, §2.6), [`TASK-098`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-098.md), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_UpgradedConn_PeerDisconnect(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server with support for programmatic socket closure.
  - Toron server configured with a generous `UpgradeIdleTimeout = 5 * time.Second` to prove that teardown is triggered by the peer disconnect rather than timeout expiration.
  - Route `/ws-disconnect` registered in router.
- **Action**:
  - **Subtest 4A (Client Disconnection Triggers Immediate Upstream Closure)**:
    1. Client dials server, completes upgrade handshake, and exchanges initial test payload.
    2. Client immediately invokes `conn.Close()`.
    3. Measure elapsed time until the mock upstream backend's read unblocks with `io.EOF` or socket error.
  - **Subtest 4B (Upstream Disconnection Triggers Immediate Client Closure)**:
    1. Second client establishes an upgraded session.
    2. Mock upstream server forcibly closes its accepted socket (`upstreamConn.Close()`).
    3. Measure elapsed time until the client's read unblocks with `io.EOF` or socket error.
- **Verifiable Assertions**:
  1. In Subtest 4A, upstream backend observes socket closure within $\le 100\text{ms}$ of client disconnect (far below the 5s timeout).
  2. In Subtest 4B, client observes socket closure within $\le 100\text{ms}$ of upstream disconnect (far below the 5s timeout).
  3. Sockets on both ends are closed cleanly via `sync.Once` without double-close errors or panics.
  4. Relay worker goroutines unblock and exit immediately without leaking.

### TC-088-05: HTTP/1.1 Half-Close Propagation
- **Objective**: Verify that when a client half-closes its TCP connection (`CloseWrite()`), the server propagates the half-close to the upstream backend (`CloseWrite()`) while keeping the reverse stream open. The reverse stream MUST continue relaying buffered responses from upstream to client while honoring `UpgradeIdleTimeout` until the upstream backend closes or the idle deadline expires.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 2), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§2.4), [`TASK-098`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-098.md), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_UpgradedConn_HalfClose(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend configured such that upon reading client payload and detecting half-close (`io.EOF` on read):
    1. Pauses for `60ms` to simulate response processing.
    2. Transmits `"final-response-data"` back to the client.
    3. Closes its connection.
  - Toron server configured with `UpgradeIdleTimeout = 300 * time.Millisecond`.
  - Route `/ws-halfclose` registered in router.
- **Action**:
  1. Client dials server and completes upgrade handshake.
  2. Client writes `"query-payload"` to `conn`.
  3. Client casts `conn` to `*net.TCPConn` and invokes `tcpConn.CloseWrite()`.
  4. Client continues to read from `conn` with a 1-second deadline.
  5. Mock upstream reads `"query-payload"`, receives `io.EOF`, waits 60ms, writes `"final-response-data"`, and closes.
- **Verifiable Assertions**:
  1. Mock upstream successfully reads `"query-payload"` followed by `io.EOF`.
  2. Client read does NOT fail prematurely; it successfully receives `"final-response-data"`.
  3. Subsequent client read yields `io.EOF` once upstream completes and closes.
  4. Both directions terminate cleanly without truncated data or hung goroutines.

### TC-088-06: HTTP/2 Extended CONNECT Idle Teardown & Context Cancellation
- **Objective**: Verify that an RFC 8441 HTTP/2 Extended CONNECT stream handled by [`http2AdapterHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L310-L382):
  1. Automatically terminates the upstream connection (`res.UpgradedConn`) and unblocks stream forwarders when no data is transferred across the stream for longer than `UpgradeIdleTimeout` (`150ms`).
  2. Immediately tears down `res.UpgradedConn` when the client cancels the HTTP request context (`r.Context().Done()`) without waiting for `UpgradeIdleTimeout`.
  3. Flushes data frames to the client using `http.Flusher`.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 3, AC 5, AC 6), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§3.1–§3.2), [`TASK-099`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-099.md), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_HTTP2_ExtendedCONNECT_IdleAndCancel(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server on loopback.
  - Toron server configured with `UpgradeIdleTimeout = 150 * time.Millisecond` and `HTTP2Enabled = true`.
  - Router registered with extended CONNECT handler: matches `Method: "CONNECT"` and `:protocol: "websocket"`, returning `StatusCode = http.StatusOK` and `res.UpgradedConn = upstreamConn`.
- **Action**:
  - **Subtest 6A (HTTP/2 Inactivity Timeout)**:
    1. Create an idle mock request: `req = httptest.NewRequest("CONNECT", "/ws-h2", idlePipeReader)`.
    2. Pass `req` and `httptest.NewRecorder()` to `srv.HTTP2AdapterHandler().ServeHTTP` in a background goroutine.
    3. Allow `250ms` ($> 150\text{ms}$) of zero data activity.
    4. Assert that `res.UpgradedConn` was closed by the inactivity monitor.
  - **Subtest 6B (HTTP/2 Context Cancellation Immediate Teardown)**:
    1. Create request with cancellable context: `ctx, cancel := context.WithCancel(context.Background())`.
    2. Create `req = httptest.NewRequest("CONNECT", "/ws-h2", pipeReader).WithContext(ctx)`.
    3. Launch `srv.HTTP2AdapterHandler().ServeHTTP` in a background goroutine.
    4. Immediately invoke `cancel()`.
    5. Assert that `res.UpgradedConn` was closed within $\le 50\text{ms}$ without waiting for the 150ms timeout.
- **Verifiable Assertions**:
  1. In Subtest 6A, inactivity exceeding `UpgradeIdleTimeout` closes `res.UpgradedConn` and terminates stream handling within $150\text{ms} \pm 50\text{ms}$.
  2. In Subtest 6B, context cancellation terminates `res.UpgradedConn` within $\le 50\text{ms}$.
  3. No goroutines are leaked from the HTTP/2 forwarder or watchdog routines.
  4. Teardown is synchronized via `sync.Once`, eliminating double-close races.

### TC-088-07: Concurrency & Race Safety
- **Objective**: Verify that concurrent upgraded HTTP/1.1 connections and HTTP/2 Extended CONNECT streams under high I/O concurrency, periodic heartbeat streams, sudden peer disconnections, and simultaneous idle timeout expirations operate with complete thread safety, zero data races, zero deadlocks, and zero goroutine leaks under `go test -race ./pkg/server/... ./pkg/config/...`.
- **Traceability**: [`REQ-088`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-088.md) (AC 7), [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) (§1–§4), [`TASK-100`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-100.md), [`SEC-27`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L384-L392).
- **Target Function**: `TestServer_UpgradedConn_ConcurrencyRaceSafety(t *testing.T)` in [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server_test.go).
- **Setup & Preconditions**:
  - Mock TCP backend echo server.
  - Toron server configured with `UpgradeIdleTimeout = 100 * time.Millisecond` and `WorkerPoolSize = 64`.
- **Action**:
  1. Launch 30 concurrent client goroutines:
     - **Group 1 (10 goroutines)**: Establish upgraded connection and run an active heartbeat loop (ping every 30ms for 250ms).
     - **Group 2 (10 goroutines)**: Establish upgraded connection and remain completely silent, expecting timeout closure after 100ms.
     - **Group 3 (10 goroutines)**: Establish upgraded connection, send small random payload, and abruptly close or half-close the client socket.
  2. Concurrently execute 10 HTTP/2 extended CONNECT streams with random context cancellations.
  3. Wait for all 40 client routines to complete (with a 5-second test deadline).
  4. Perform server graceful shutdown.
- **Verifiable Assertions**:
  1. The test passes cleanly with zero data race warnings under `go test -v -race`.
  2. Zero deadlocks occur.
  3. All socket file descriptors are returned to the OS.
  4. All worker and relay goroutines terminate cleanly.
