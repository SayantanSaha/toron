## Scope of Review

The review covered all changes across the transport ingress, core request model, and perimeter security subsystems designed to eliminate unauthenticated client IP spoofing in multiplexed HTTP/2 streams and HTTP/3 QUIC datagrams:

1. **Request Model Physical Binding** ([`pkg/httpparser/request.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go)):
   - Addition of exported `RemoteAddr string` field.
   - Robust, panic-safe address resolution helpers `RemoteHost() string` and `RemoteIP() net.IP` handling IPv4, IPv6, port splitting, bracket stripping, whitespace trimming, and seamless fallback to `RawConn.RemoteAddr()`.
   - Preservation of `RemoteAddr` in `NewRequestFromStd(r)`.
2. **Protocol Ingress Adapters** ([`pkg/server/server.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go)):
   - Population of `req.RemoteAddr = conn.RemoteAddr().String()` alongside `req.RawConn = conn` in `handleConn` (HTTP/1.1).
   - Ingress binding in `http2AdapterHandler` (HTTP/2) and `ListenAndServeH3` (HTTP/3).
3. **Perimeter Security Hardening & Trusted Proxy Gating**:
   - **WAF IP ACL** ([`pkg/waf/ip_acl.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go), [`pkg/waf/middleware.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go), [`pkg/waf/waf.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/waf.go)): ExtractClientIP anchors to physical `req.RemoteIP()`; forwarded headers evaluated only when physical peer matches configured `TrustedProxies`; fail-secure default when allowlist is active.
   - **Internal Management API Subnet Gate** ([`pkg/server/internal_api.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go)): Elimination of unverified `RawConn == nil` fallback; client IP anchored to `RemoteIP()`; fail-closed 403 Forbidden on unresolvable or out-of-subnet addresses.
   - **Token Bucket Rate Limiting** ([`pkg/router/rate_limiter.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/rate_limiter.go)): Removal of insecure `peerIsTrusted || req.RawConn == nil` condition; untrusted connections strictly anchored to `ip:<remoteHost>`, neutralizing header rotation attacks.
   - **Reverse Proxy Header Forwarding** ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go)): Untrusted client `X-Forwarded-For` and `X-Real-IP` discarded and replaced with physical `peerIP`; trusted proxy chaining correctly appends `peerIP`.
   - **Structured Access Logging** ([`pkg/logging/manager.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/logging/manager.go)): Anchors client IP extraction to `req.RemoteHost()`, preventing audit log falsification.
4. **Preserved Non-Goal Scope**:
   - Verification that [`pkg/proxy/sticky.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/sticky.go) has 0 diffs, maintaining mobile roaming session persistence under [`REQ-030`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-030.md).

### Finding 2: Protocol Parity across HTTP/1.1, HTTP/2, and HTTP/3 QUIC

- **Severity**: Informational
- **Location**: [`pkg/httpparser/request.go:120-161`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L120-L161), [`pkg/server/server.go:241,318,429`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go)
- **Related Artifact**: [`REQ-092-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L89-L93), [`REQ-092-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L94-L97), [`ADR-087 Section 2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L131-L162)
- **Description**: Physical remote connection metadata is uniformly populated and bound to `req.RemoteAddr` across all ingress protocols:
  - In `handleConn`, `req.RemoteAddr = conn.RemoteAddr().String()` is set alongside `req.RawConn = conn`.
  - In `http2AdapterHandler` and `ListenAndServeH3`, `httpparser.NewRequestFromStd(r)` binds `r.RemoteAddr` directly.
  - Address resolution helper `req.RemoteHost()` safely extracts the host part, falling back to `RawConn` when `RemoteAddr` is empty, while `req.RemoteIP()` handles bracket stripping and IP parsing for both IPv4 and IPv6 without panics (including on nil receivers).
- **Verdict**: Verified and Compliant.

### Finding 3: Trusted Proxy Gating & Fail-Closed Administrative Perimeter

- **Severity**: Informational
- **Location**: [`pkg/waf/ip_acl.go:118-175`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L118-L175), [`pkg/server/internal_api.go:195-242`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go#L195-L242), [`pkg/router/rate_limiter.go:286-335`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/rate_limiter.go#L286-L335), [`pkg/proxy/proxy.go:818-874`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L818-L874)

- **Description**:
  - The dangerous check `if peerIsTrusted || req.RawConn == nil` in [`rate_limiter.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/rate_limiter.go) has been completely eliminated. Untrusted connections anchor to `ip:<socketHost>`, preventing DoS evasion by rotating client headers.
  - In `internal_api.go`, subnet enforcement rejects untrusted clients attempting to spoof internal CIDRs with `403 Forbidden` (`{"error":"403 Forbidden","message":"Access denied by administrative subnet policy"}`). Requests with unresolvable client addresses fail closed.
  - In `proxy.go`, untrusted HTTP/2 and HTTP/3 clients have their incoming `X-Forwarded-For` and `X-Real-IP` discarded and replaced strictly with physical `peerIP`. Trusted proxy requests have `peerIP` safely appended.
  - In `ip_acl.go`, `CheckIP(nil)` fails secure, rejecting access when an allowlist is configured.
- **Verdict**: Verified and Compliant.

## Positive Observations

1. **Clean Decoupling of Transport Descriptor and Network Identity**:
   Exposing `RemoteAddr string` on `httpparser.Request` cleanly decouples network peer identity from physical socket descriptors (`net.Conn`), enabling seamless protocol parity across stream-oriented HTTP/1.1, multiplexed HTTP/2 streams, and datagram-oriented HTTP/3 QUIC.
2. **Zero-Allocation Host Resolution & Standard Library Purity**:
   `RemoteHost()` and `RemoteIP()` utilize `net.SplitHostPort` and string slicing without external dependencies or heavy regex engines, avoiding garbage collection overhead on the request hot path.
3. **Fail-Closed & Fail-Secure Architectural Guarantees**:
   The implementation consistently applies defensive security practices: missing or unresolvable client addresses fail closed with `403 Forbidden` on administrative endpoints, and fail secure on WAF allowlists.
4. **Strict Scope Discipline on Mobile Roaming Non-Goals**:
   The implementation respected architectural boundaries by leaving `pkg/proxy/sticky.go` completely untouched with 0 diffs, guaranteeing that mobile roaming session affinity under [`REQ-030`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-030.md) remains 100% intact.

## Constraints

1. **Standard Library Only**: All modifications strictly use standard library packages (`net`, `net/http`, `strings`, `sync`, `time`, `bytes`). Zero external third-party dependencies.
2. **Immutability Invariant**: `RemoteAddr` is assigned once at request construction and accessed read-only across router middlewares, ensuring thread safety and race freedom.
3. **Preservation of REQ-030**: `pkg/proxy/sticky.go` was excluded from modification and verified clean.
