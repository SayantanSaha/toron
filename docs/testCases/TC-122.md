# TC-122 - Test Cases for Reverse Proxy Upstream Connection Pooling and Transport Optimizations

## 1. Test Specifications

### TC-122.1: Transport Connection Pool Verification
- **Objective**: Verify `NewProxyWithOptions` initializes `http.Transport` with `MaxIdleConnsPerHost >= 1000`.
- **Expected Result**: Unit test confirms `MaxIdleConnsPerHost` is non-default and $\ge 1000$.

### TC-122.2: Hop-by-Hop Response Header Stripping
- **Objective**: Verify that when upstream responds with `Connection: close` or `Keep-Alive: timeout=5`, Toron strips them from `res.Header`.
- **Expected Result**: `res.Header.Get("Connection")` is not contaminated by upstream.

### TC-122.3: Zero-Allocation Response Serialize Verification
- **Objective**: Benchmark `Response.Serialize` and verify zero allocations on status and header writing.
- **Expected Result**: `BenchmarkResponse_Serialize` demonstrates improved nanoseconds/op and reduced allocations.

### TC-122.4: High-Throughput Benchmarking Verification
- **Objective**: Re-run multi-proxy Docker benchmark on `fast`, `go`, and `node` backends.
- **Expected Result**: Toron throughput increases significantly with P50 latency $\le 1\,\text{ms}$.
