# REQ-137: Dashboard Alerts Full Timestamps, Banned IP Creation Dates, and Request Source IP Telemetry

## 1. Problem Statement

Operators monitoring the Toron Edge Gateway dashboard need precise temporal context and source IP provenance across operational alerts, active threat actor bans, and live request streams:
1. **Alerts & Threat Incidents**: Previously displayed relative times (`ago`) without exact calendar dates, making forensic correlation with system logs difficult. Alerts were not guaranteed to be sorted with the latest occurrences at the top.
2. **Banned IP Threat Table**: Did not display the exact date and timestamp when an IP was banned and lacked latest-first sorting.
3. **Live Request Tail & Drawer**: Displayed only time-of-day (`HH:MM:SS`) without the calendar date, and lacked a dedicated visible Source IP column in the primary request table.

## 2. Functional Requirements

### 2.1 Full Datetime Formatting & Latest-First Sorting for Alerts
- Every alert in the Active Alerts list (`#/alerts`) and Overview alerts widget shall display a complete date and timestamp in `YYYY-MM-DD HH:MM:SS` format (with relative elapsed duration).
- Active alerts (WAF security anomalies, banned actors, upstream degradation, high error rates, certificate renewal failures) shall be sorted in strictly descending chronological order (latest event first).

### 2.2 Banned IP Creation Timestamp & Chronological Sorting
- The Banned IP Management Table (`#/alerts`) shall include a dedicated "Created At" column rendering the exact date and timestamp (`YYYY-MM-DD HH:MM:SS`) when the ban was enacted.
- The active ban entries shall be sorted with latest bans first (`created_at` descending).

### 2.3 Requests / Live Logs Table Telemetry
- The Requests table (`#/logs`) shall display the full calendar date and time (`YYYY-MM-DD HH:MM:SS`) in the Time column.
- The Requests table shall include a visible "Source IP" column displaying the client socket IP (`client_ip` / `ip`).
- The Request Details Drawer shall display both the full request datetime and the client IP address.

## 3. Verification Criteria
- `TC-137.1`: Verify alerts render full `YYYY-MM-DD HH:MM:SS` date-times and sort newest first.
- `TC-137.2`: Verify Banned IP table displays ban creation date-times and sorts newest bans first.
- `TC-137.3`: Verify Live Tail table displays `YYYY-MM-DD HH:MM:SS` and Client IP column.
