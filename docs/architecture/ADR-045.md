# ADR-045: Advanced Load Balancing Engine Architecture

## Status
Accepted

## Context
Toron Edge Gateway requires expanded load balancing capabilities to handle heterogeneous cluster capacity, variable request duration, and latency fluctuations across microservices.

## Decision
We implement 5 load balancing algorithms in `pkg/proxy`:
1. **`weighted_round_robin`**: Nginx smooth weighted round-robin algorithm. Maintains `effectiveWeight` and `currentWeight` per node to ensure smooth distribution without burst clustering.
2. **`weighted_random`**: Cumulative weight probability distribution selection using pseudo-random generator.
3. **`least_conn`**: In-flight connection tracking using atomic counters (`atomic.AddInt64`). Selects healthy target with minimal active connections.
4. **`weighted_least_conn`**: Selects healthy target with minimal `float64(ActiveConns) / float64(Weight)`.
5. **`least_latency`**: Exponential moving average (EMA) response time tracking (`alpha = 0.2`). Selects node with lowest average latency.

## Consequences
- **Positive**: Complete support for capacity-aware, load-aware, and latency-aware routing.
- **Negative**: Minor memory overhead per target node (approx. 32 bytes for atomic counters).
- **Compliance**: Maintains 0 external dependencies (Go stdlib `sync/atomic`, `math/rand`, `time`).
