# REQ-010 - Header-Based HTTP Routing and Upstream Dispatching

## Description

The Toron server shall support header-based routing to dispatch incoming HTTP requests to specific route handlers or reverse proxy upstreams based on HTTP request header names and values (e.g., `X-Version`, `X-Environment`, `X-Tenant-ID`).

## Acceptance Criteria

- Router evaluates HTTP request headers when matching routes and reverse proxy targets.
- Supports programmatic header route registration (e.g., `router.GETHeader(path, headerKey, headerVal, handler)`, `router.ProxyHeader(prefix, headerKey, headerVal, targetURL)`).
- Supports configuring header-based proxy routes in `config.yaml` under `proxy.routes[].headers`.
- Header matching is case-insensitive for header names (RFC 7230 compliance).
- When multiple header routes match, the router prioritizes the most specific match (path + header matching before path-only matching).

## Rationale

Enables canary deployments, API versioning (`X-Version: v1` vs `X-Version: v2`), multi-tenant routing, and A/B traffic testing.

## Constraints

- Header name comparisons must use `strings.ToLower`.
