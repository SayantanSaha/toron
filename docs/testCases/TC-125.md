# TC-125 - Test Specification for Conditional Direct Socket Streaming Fast-Path, Transport Timeout Decoupling, and Response Buffer Pooling Architecture

## 1. Test Suite Overview & Architectural Objectives

### 1.1 Executive Summary & Problem Context
Comparative benchmarking across high-throughput reverse proxies in [`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md) and [`REQ-124`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-124.md) demonstrated that Toron delivers throughput (~24.5k RPS) competitive with Traefik (~24.0k RPS) and superior to Caddy (~18.3k RPS). However, Traefik achieved a ~0.19ms lower median latency (P50 0.97ms vs Toron's 1.16ms).

Profiling identified three systemic architectural bottlenecks:
1. **Double In-Memory Payload Buffering**:
   - In [`pkg/proxy/proxy.go:1037`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1037), `io.Copy(res.Body, outResp.Body)` buffered the entire upstream HTTP response payload into an in-memory `*bytes.Buffer`.
   - In [`pkg/httpparser/response.go:97`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/response.go#L97), `res.Serialize(conn)` allocated a secondary `bytes.Buffer`, copied status line, headers, and `res.Body.Bytes()`, and issued `conn.Write(buf.Bytes())`.
   - This incurred two full in-memory body copies and dynamic heap allocations per request, contrasting with Traefik and Caddy which stream bytes directly into the client connection writer without intermediate body buffering.
2. **Monolithic Transport Timeout Aborting Long-Lived Streams**:
   - In [`pkg/proxy/proxy.go:551`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L551) and [`pkg/proxy/proxy.go:654`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L654), `p.Client.Timeout = 10 * time.Second` enforced an aggregate deadline over the entire request lifecycle (dial, TLS handshake, redirects, and reading `Response.Body`).
   - Consequently, any long-lived streaming connection—such as Server-Sent Events (SSE, `text/event-stream`), live telemetry, or chunked transfer streams lasting longer than 10 seconds—was abruptly terminated by `http.Client.Timeout`.
3. **Heap Churn from Unpooled Buffers**:
   - Non-streaming responses repeatedly allocated and garbage-collected `bytes.Buffer` instances for response buffering and serialization, driving GC pauses under high load.

### 1.2 The WebSocket-Aligned Streaming Paradigm
To eliminate intermediate buffering while preventing conflicts with Transparent Response Compression ([`REQ-017`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-017.md) / [`ADR-029`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-029.md)), Response Caching ([`REQ-019`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-019.md) / [`ADR-030`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-030.md)), and Header Rewriting ([`REQ-004`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-004.md)), this test specification validates the architectural pattern defined in [`ADR-125`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-125.md):

> **Core Architectural Principle**: *Server-Sent Events (SSE) and live response streams are handled in the exact same manner as WebSockets (`res.UpgradedConn`).*

In this paradigm:
1. **Immediate Proxy Hand-off**: When streaming eligibility (`canStream`) is met, [`ReverseProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go) sets status and filtered headers, assigns the live upstream stream handle to `res.StreamBody io.ReadCloser`, and returns immediately without blocking on `io.Copy(res.Body, outResp.Body)`.
2. **Middleware Streaming Passthrough**: [`CompressionMiddleware`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go) and [`CacheMiddleware`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go) detect `res.StreamBody != nil` (identically to `res.UpgradedConn != nil` or HTTP 101) and bypass payload buffering, satisfying [`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md).
3. **Server Socket Streaming Relay**: [`Server.handleConnection`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go) serializes status line and headers to the client socket (omitting static `Content-Length`) and delegates stream relaying to a chunk transfer loop with activity-refreshed write deadlines (modeled on [`s.relayUpgradedStreams`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L596) and [`TC-088`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-088.md)).
4. **Clean Resource Teardown**: Server core registers `defer res.StreamBody.Close()`, guaranteeing upstream socket release upon client disconnect, EOF, or write timeout.

## 2. Test Setup, Topology & Environmental Requirements

### 2.1 Subsystem Architecture & Interaction Topology

The execution topology across the streaming test harness is structured as follows:

```
+-----------------------------------------------------------------------------------------+
|                               Downstream Client (TCP / H2)                              |
+-----------------------------------------------------------------------------------------+
                                      |
                      Request Wire Bytes / Frames
                                      v
+-----------------------------------------------------------------------------------------+
|                               Server Engine (pkg/server)                                |
|  - handleConnection (HTTP/1.1): detects res.StreamBody != nil                           |
|  - http2AdapterHandler (HTTP/2): detects res.StreamBody != nil                          |
|  - Activity-refreshed write deadlines (conn.SetWriteDeadline(now + idleTimeout))        |
|  - Stream chunk loop: io.CopyBuffer slab -> conn.Write / flusher.Flush()               |
+-----------------------------------------------------------------------------------------+
                                      |
                           res.StreamBody Pass-Through
                                      v
+-----------------------------------------------------------------------------------------+
|                             Middleware Pipeline (pkg/router)                            |
|  - CompressionMiddleware: if res.StreamBody != nil { return }                          |
|  - CacheMiddleware: if res.StreamBody != nil { res.Header.Set("X-Cache", "MISS"); ret }|
+-----------------------------------------------------------------------------------------+
                                      |
                           res.StreamBody Assignment
                                      v
+-----------------------------------------------------------------------------------------+
|                            ReverseProxy Core (pkg/proxy)                                |
|  - Evaluates canStream eligibility matrix                                               |
|  - Strips RFC 7230 hop-by-hop headers                                                   |
|  - Rewrites 3xx redirects, cookies, sticky session tokens                               |
|  - Hands off upstream outResp.Body -> res.StreamBody (omits outResp.Body.Close())       |
|  - Immediate return (< 0.05ms) without reading body                                     |
+-----------------------------------------------------------------------------------------+
                                      |
                         Client.Do(outReq) (Timeout = 0)
                                      v
+-----------------------------------------------------------------------------------------+
|                          Upstream Origin Server (httptest)                              |
|  - Text/Event-Stream SSE emitter (spaced over 12s)                                      |
|  - Slow header generator (tests ResponseHeaderTimeout)                                  |
|  - Standard JSON backend (tests buffered fallback)                                      |
+-----------------------------------------------------------------------------------------+
```

### 2.2 Environmental Prerequisites & Dependencies
- **Go Toolchain**: Go 1.24+ with CGO enabled for `-race` validation.
- **Dependencies**: Strictly zero third-party Go dependencies outside standard library (`testing`, `net`, `net/http`, `net/http/httptest`, `sync`, `time`, `io`, `bytes`, `strings`, `context`) and existing project packages (`pkg/config`, `pkg/httpparser`, `pkg/router`, `pkg/proxy`, `pkg/server`).
- **Timing & Concurrency Invariants**:
  - `ResponseHeaderTimeout` tests: Upstream header delay $= 150\text{ms}$; transport timeout $= 50\text{ms}$.
  - Long-lived stream tests: Upstream streams 6 SSE chunks over 12 seconds ($2.0\text{s}$ chunk interval), demonstrating resilience beyond default 10-second client timeouts.
  - Slow client write timeout tests: Client stops reading after initial handshake; write timeout triggers within $150\text{ms} \pm 50\text{ms}$.
  - Buffer slabs: 32KB copy slice pool (`sync.Pool`) and 8KB header serialization pool.

### TC-125.1: Config Model & Cascading Verification
- **Identifier**: `TC-125.1`
- **Target Subsystem**: Configuration Model & Transport Defaults ([`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go), [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go))
- **Test Implementation**: `TestConfig_ProxyTransportConfig_StreamResponseAndTimeout` in [`pkg/config/config_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config_test.go)
- **Objective**: Verify that `ProxyTransportConfig` properly defines, serializes, deserializes, sets preset profile defaults, merges, and cascades `StreamResponse *bool` and `ResponseHeaderTimeout time.Duration` across global and route-level configurations.
- **Traceability**: [`REQ-125 §2.1`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-125.md#L90-L103), [`TASK-148 WP-1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-148.md#L95-L129), [`ADR-125 §2.6`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-125.md#L318-L338).
- **Setup & Preconditions**: None. Pure configuration unit test suite.
- **Action**:
  - **Subtest 1A (Preset Profile Defaults)**:
    1. Invoke `DefaultProxyTransportConfig("raw_speed")`. Assert `cfg.StreamResponse != nil`, `*cfg.StreamResponse == true`, and `cfg.ResponseHeaderTimeout == 10 * time.Second`.
    2. Invoke `DefaultProxyTransportConfig("balanced")`. Assert `cfg.StreamResponse != nil`, `*cfg.StreamResponse == false`, and `cfg.ResponseHeaderTimeout == 10 * time.Second`.
  - **Subtest 1B (Hierarchical Merge Logic)**:
    1. Base: `raw_speed` (`StreamResponse = &true`, `ResponseHeaderTimeout = 10s`). Override: `StreamResponse = &false`, `ResponseHeaderTimeout = 5s`. Call `MergeProxyTransportConfig(base, override)`. Assert result has `*StreamResponse == false` and `ResponseHeaderTimeout == 5s`.
    2. Base: `balanced` (`StreamResponse = &false`). Override: `StreamResponse = &true`, `ResponseHeaderTimeout = 0`. Call `MergeProxyTransportConfig(base, override)`. Assert result has `*StreamResponse == true` and `ResponseHeaderTimeout == 10s` (unspecified duration preserves base).
  - **Subtest 1C (Route-Level Cascading & Precedence)**:
    1. Global transport has `stream_response: true` ("raw_speed"). Route 1 defines `stream_response: false`. Resolve route transport: assert Route 1 resolves to `stream_response == false`.
    2. Global transport has `stream_response: false` ("balanced"). Route 2 defines `stream_response: true` and `response_header_timeout: 3s`. Resolve route transport: assert Route 2 resolves to `stream_response == true` and `response_header_timeout == 3s`.
    3. Route 3 defines no transport overrides (`StreamResponse == nil`). Resolve route transport: assert Route 3 inherits global settings verbatim.
  - **Subtest 1D (YAML & JSON Deserialization)**:
    1. Deserialize YAML snippet:
       ```yaml
       stream_response: true
       response_header_timeout: 15s
       ```
       Assert fields unmarshal cleanly.
    2. Deserialize JSON snippet:
       ```json
       {"stream_response": false, "response_header_timeout": 5000000000}
       ```
       Assert fields unmarshal cleanly.
- **Expected Outcomes**:
  - All profile defaults strictly conform to REQ-125 specification.
  - Pointer boolean overrides cascade cleanly without pointer aliasing mutations.
  - Deserialization and validation succeed with zero errors.

### TC-125.2: Transport Timeout Decoupling Verification
- **Identifier**: `TC-125.2`
- **Target Subsystem**: ReverseProxy Upstream Transport Client ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go))
- **Test Implementation**: `TestProxy_Transport_ResponseHeaderTimeoutEnforcement` and `TestProxy_Transport_BodyStreamingDecoupled` in [`pkg/proxy/proxy_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy_test.go)
- **Objective**: Verify that upstream connection dial and response header receipt are bounded by `http.Transport.ResponseHeaderTimeout` and `DialContext` timeout, while response body streaming is completely decoupled from monolithic client timeouts (`p.Client.Timeout = 0`), allowing long-lived response bodies to stream indefinitely.
- **Traceability**: [`REQ-125 §2.1`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-125.md#L100-L103), [`TASK-148 WP-2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-148.md#L131-L154), [`ADR-125 §2.6`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-125.md#L318-L338).
- **Setup & Preconditions**:
  - Mock upstream HTTP server with programmable delays for headers and response bodies.
- **Action**:
  - **Subtest 2A (ResponseHeaderTimeout Enforcement)**:
    1. Configure mock upstream server: receives request, sleeps for $150\text{ms}$ before writing HTTP status code and response headers.
    2. Initialize `ReverseProxy` with `Transport.ResponseHeaderTimeout = 50 * time.Millisecond` and `Client.Timeout = 0`.
    3. Dispatch request `GET /slow-headers`.
    4. Assert proxy operation fails within $\approx 50\text{ms}$ returning an error or HTTP 502/504 Bad Gateway.
    5. Assert the error indicates header timeout (`net/http: timeout awaiting response headers`).
  - **Subtest 2B (Body Streaming Decoupling from Client.Timeout)**:
    1. Configure mock upstream server: writes HTTP 200 OK and headers immediately ($< 2\text{ms}$), then writes chunks slowly (e.g. 3 chunks spaced $100\text{ms}$ apart, total body read duration $300\text{ms}$).
    2. Contrast with old configuration: If `Client.Timeout` were set to $100\text{ms}$, the request would fail mid-stream.
    3. Under the decoupled configuration: `Client.Timeout = 0`, `ResponseHeaderTimeout = 2 * time.Second`.
    4. Dispatch request. Read upstream body via `res.StreamBody`.
    5. Assert all body chunks are read successfully to EOF without client timeout abort.
- **Expected Outcomes**:
  - Slow header receipt is aborted strictly at `ResponseHeaderTimeout`.
  - Body streaming proceeds unconstrained by `http.Client.Timeout`, proving complete decoupling.

  | **Case 3** | `true` | `true` | `false` | `application/json` | (none) | **`false`** | `nil` (buffered for compression) |
  | **Case 4** | `true` | `false` | `true` | `application/json` | (none) | **`false`** | `nil` (buffered for cache) |
  | **Case 5** | `true` | `true` | `true` | `text/event-stream` | (none) | **`true`** | Non-nil (REQ-128 exemption) |

  - When `canStream == false`: `res.StreamBody == nil`, `res.Body.Len() > 0` (payload fully read into buffer).
  - 100% agreement across all 8 matrix permutations.

### TC-125.4: WebSocket-Aligned Stream Hand-off in ReverseProxy
- **Identifier**: `TC-125.4`
- **Target Subsystem**: ReverseProxy Stream Hand-Off Engine ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go), [`pkg/httpparser/response.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/response.go))
- **Test Implementation**: `TestProxy_WebSocketAlignedStreamHandOff` in [`pkg/proxy/proxy_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy_test.go)
- **Objective**: Verify that `ReverseProxy` hands off live streams to `res.StreamBody` in the exact same non-blocking manner as WebSocket upgrades (`res.UpgradedConn`), executing header rewriting, stripping hop-by-hop headers, transferring body ownership without deferring `outResp.Body.Close()`, and returning immediately.
- **Traceability**: [`REQ-125 §2.2`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-125.md#L116-L122), [`TASK-148 WP-3.2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-148.md#L187-L201), [`ADR-125 §2.3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-125.md#L164-L177).
- **Setup & Preconditions**:
  - Mock upstream server emitting SSE stream with custom headers, hop-by-hop headers, 3xx redirect location, and `Set-Cookie` header.
- **Action**:
  - **Subtest 4A (Zero-Copy Non-Blocking Return)**:
    1. Dispatch request to streaming endpoint.
    2. Measure duration of `proxy.ServeHTTPWithPrefix(req, res, prefix)`.
    3. Assert execution returns in $< 0.5\text{ms}$ while upstream body remains completely unread.
    4. Assert `res.StreamBody != nil` and `res.Body.Len() == 0`.
  - **Subtest 4B (RFC 7230 §6.1 Hop-by-Hop Header Stripping)**:
    1. Upstream emits:
       ```http
       Connection: keep-alive, Upgrade
       Keep-Alive: timeout=5
       Proxy-Authenticate: Basic
       Proxy-Authorization: Secret
       TE: trailers
       Transfer-Encoding: chunked
       Upgrade: websocket
       ```

## 5. Invariants & Standards Compliance

1. **RFC 7230 §6.1 Hop-by-Hop Header Stripping**:
   - Stripping of `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Transfer-Encoding`, and `Upgrade` is validated by `TC-125.4` prior to any downstream socket transmission.
2. **RFC 7234 §5.2.2.2 Origin Cache & REQ-128 Invariant**:
   - Validated by `TC-125.5`: Streaming responses (`text/event-stream`, `X-Accel-Buffering: no`) are strictly exempt from cache storage, preventing cache poisoning and stale SSE event replays.
3. **CWE-444 HTTP Request / Response Smuggling Prevention**:
   - Validated by `TC-125.4` and `TC-125.6`: Streaming responses omit static `Content-Length` headers, preventing conflicting framing indicators between proxy and client.
4. **CWE-400 Slowloris Resource Exhaustion Defense**:
   - Validated by `TC-125.7`: Downstream clients that stall reading have their connections severed upon write deadline expiration, releasing upstream sockets immediately.
5. **Zero Third-Party Dependency Invariant**:
   - All tests and implementations rely exclusively on the Go standard library (`net`, `net/http`, `sync`, `io`, `time`).
