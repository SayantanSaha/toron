# CR-141 - Code Review for Native ECMAScript Modules Dashboard Architecture and Feature Parity

## 1. Executive Summary

This code review evaluates the modularization of the Toron Edge Gateway Control Center dashboard from a monolithic 1,663-line script (`public/app.js`) into a clean, layered hierarchy of 17 native browser ECMAScript Modules under `public/js/`.

The implementation fulfills all requirements specified in [`REQ-141`](../requirements/REQ-141.md), architected in [`ADR-141`](../architecture/ADR-141.md), decomposed in [`TASK-164`](../tasks/TASK-164.md), and verified by [`TC-141`](../testCases/TC-141.md):
1. **Native ESM Layering Without Build Tools**: Complete elimination of monolithic script clustering without introducing Node.js bundlers (Webpack/Vite/Rollup) or npm runtime dependencies. The ~15 MB Docker appliance container build remains pristine.
2. **100% Behavioral & Visual Parity**: All 8 views (`overview`, `routes`, `upstreams`, `logs`, `certs`, `modules`, `alerts`, `console`) and 2 slide-out drawers (`route` detail and `trace` waterfall) function identically to the pre-refactor state.
3. **Telemetry Invariant Preservation**: Hierarchical route subpath rollups, external user traffic isolation, trailing 5-point moving average rate smoothing, and disaggregated upstream route pool generation remain 100% mathematically faithful.
4. **Strictly Relative Links**: Zero absolute machine or filesystem paths exist in documentation or module import specifiers.

## 2. Detailed Findings by Architecture Layer

### 2.1 Layer 0: Primitives & State (`public/js/utils.js`, `public/js/state.js`, `public/js/components/icons.js`)
- **Design & Quality**:
  - `utils.js` cleanly exports DOM selection (`$`, `$$`), string escaping (`esc`), numeric/time formatters (`fmt`, `axis`, `dtFmt`, `hms`, `hm`, `ago`), and pure mathematical functions (`clamp`, `sum`, `avg`, `H`, `stCls`).
  - `state.js` centralizes mutable state into a single reactive store (`state`), provides non-leaking theme management (`effTheme`, `themeIcon`, `toggleTheme`), cache controls (`invalidate`, `getCache`, `setCache`, `isForce`), and an event subscription channel (`setOnLiveChange`, `setLive`) for reactive tail pausing.
  - `icons.js` defines vector SVG symbol references and status tone badge generators (`ICON`, `pill`, `TI`, `TONE`, `toneErr`).
- **Code Standards**: Zero globals polluted; strictly typed helper signatures.

### 2.2 Layer 1a: Telemetry Ingestion & Mathematical Modeling (`public/js/api.js`, `public/js/model.js`)
- **Data Polling & Ingestion (`api.js`)**:
  - Employs non-blocking `Promise.allSettled` to fetch all 6 telemetry endpoints (`/internal/api/status`, `routes`, `upstreams/health`, `security/incidents`, `logs`, `security/banned-ips`).
  - Invokes `setUpdateCallback` and `invalidate` to trigger atomic UI refreshes upon successful snapshot retrieval.
- **Model Invariants (`model.js`)**:
  - Implements hierarchical subpath aggregation (`getRouteTotalReqs`), ensuring child requests (e.g. `/kite/api/v1/business`) roll up into parent configured prefixes (`/kite/api`).
  - Isolates internal dashboard polling requests (`/internal/*`) from external request traffic denominators.
  - Preserves 5-point moving average RPS smoothing across the gateway timeseries window.
  - Generates disaggregated pool cards with 48-tick probe health strips for multi-route backends sharing target sockets.

### 2.3 Layer 1b: Visual Components & Drawers (`public/js/components/`)
- **Component Design**:
  - `charts.js`: Renders inline SVG sparklines, canvas/SVG line graphs, and latency distribution histograms without third-party graphing libraries.
  - `sankey.js`: Constructs vector SVG cubic Bezier ribbon geometries for traffic flow visualization.
  - `drawer.js`: Manages slide-over inspector state (`dw`), focus traps, route SLO targets, and request trace waterfall timelines.

### 2.4 Layer 2: Dedicated View Controllers (`public/js/views/`)
- **Standardized View Contract**:
  - All 8 view modules (`overview.js`, `routes.js`, `upstreams.js`, `logs.js`, `certs.js`, `modules.js`, `alerts.js`, `console.js`) adhere to the `{ shell, init, update }` protocol.
  - Views encapsulate their own DOM generation, event listeners, and filtering logic without cross-view coupling.

### 2.5 Layer 3: Application Orchestration & Bootstrap (`public/js/app.js`)
- **Router & Chrome Coordination**:
  - Houses the canonical view registry (`VIEWS`), navigation metadata (`NAV`, `META`), and hash routing engine (`go()`).
  - Coordinates header metadata, time-range selectors, live mode status, mobile drawer navigation, and global keyboard shortcuts.
  - Self-boots on `DOMContentLoaded` and registers the 2000 ms background polling interval.

### 2.6 Entrypoint Integration & Test Compatibility
- `public/index.html` updated to load `<script type="module" src="/internal/dashboard/js/app.js"></script>`.
- `public/package.json` created with `{"type": "module"}` to enable native Node.js dynamic import execution.
- `public/app.js` preserved for backward-compatible fallback.
- `tests/dashboard_telemetry_test.js` updated to verify TC-139, TC-140, and TC-141.
