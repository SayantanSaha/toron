# CR-061 - Code Review of Upstream TLS Certificate Verification in WebSocket Proxy

## Description

Engineering code review of `TASK-065` changes across `pkg/proxy/proxy.go`, `pkg/config/config.go`, `cmd/toron/main.go`, and `pkg/proxy/proxy_test.go`.

## Scope

- Files reviewed:
  - `pkg/proxy/proxy.go`
  - `pkg/config/config.go`
  - `cmd/toron/main.go`
  - `pkg/proxy/proxy_test.go`

## Key Observations & Review Findings

1. **Clean Configuration Propagation**:
   - `ProxyOptions` and `ReverseProxy` struct definitions were augmented with `TLSCACertPool *x509.CertPool` and `InsecureSkipVerify bool`.
   - `ProxyRouteConfig` in `pkg/config/config.go` added optional `InsecureSkipVerify` field.
   - `cmd/toron/main.go` cleanly builds `x509.CertPool` from configured CA certificates and passes verification flags into route proxies.
2. **Proper Transport & Dialer Consistency**:
   - Standard HTTP proxy transport (`http.Transport`) and WebSocket TLS dialer (`tls.Dialer`) share identical TLS verification semantics: both configure `TLSClientConfig` with matching `RootCAs` and `InsecureSkipVerify` settings.
3. **Robust Unit & Integration Test Coverage**:
   - `TestWebSocketProxy_TLSVerification` tests three core scenarios: untrusted cert rejection resulting in HTTP 502, custom CA cert validation succeeding with HTTP 101, and explicit insecure bypass succeeding with HTTP 101.
4. **Standard Library Compliance & Performance**:
   - Zero external dependencies introduced.
   - Dialers use 10-second connect timeouts preventing connection leaks.

## Verdict

Approved. Ready for commit.
