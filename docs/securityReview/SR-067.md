# SR-067 - Security Review of Host Header Validation in Cleartext HTTP-to-HTTPS Redirection

## Description

Security evaluation of the implementation for `TASK-070` / `SEC-10` (Open Redirect via unvalidated Host header in HTTP-to-HTTPS redirection).

## Scope

- Files reviewed:
  - `pkg/server/server.go`
  - `pkg/server/sni.go`
  - `pkg/server/config.go`
  - `pkg/config/config.go`
  - `pkg/router/router.go`
  - `cmd/toron/main.go`
  - `pkg/server/server_test.go`

## Security Evaluation & Analysis

1. **Open Redirect Elimination (CWE-601)**:
   - In `pkg/server/server.go:serveHTTPRedirect`, incoming `Host` values are validated via `s.isRecognizedHost(host)` prior to assembling the redirect destination.
   - The validation checks explicit `AllowedHosts`, `DefaultHost`, `SNIRegistry` domains, route-specific host rules, and loopback addresses.
   - If an unrecognized domain (e.g. `Host: attacker.com`) is provided, the server refuses to reflect it, returning `HTTP 400 Bad Request` or safely falling back to `DefaultHost`.
2. **Preservation of Response Splitting Protections (CWE-113)**:
   - Pre-existing checks verifying that `Host` contains no CRLF characters, spaces, or backslashes (`\r\n\t /\\`) remain active and enforced before host recognition.
3. **Exploit Verification**:
   - Confirmed that sending `Host: attacker.com` does not redirect to `attacker.com`. The request receives `400 Bad Request: Unrecognized Host Header` with zero `Location` header emitted.

## Conclusion

`SEC-10` is completely resolved. Open redirect vulnerability in cleartext HTTP-to-HTTPS redirection is mitigated. The implementation is approved.
