# SR-068 - Security Review of Connection State Integrity and Hop-by-Hop Stripping

## Description

Security evaluation of the implementation for `TASK-071` / `SEC-11` (Connection State Integrity and Hop-by-Hop Stripping for Forwarded Ingress Headers).

## Scope

- Files reviewed:
  - `pkg/proxy/proxy.go`
  - `pkg/config/config.go`
  - `cmd/toron/main.go`
  - `pkg/proxy/proxy_test.go`

## Security Evaluation & Analysis

1. **Hop-by-Hop Header Stripping (RFC 7230 §6.1)**:
   - Evaluated `pkg/proxy/proxy.go:ServeHTTPWithPrefix`. Standard hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailers`, `Transfer-Encoding`, `Upgrade`) are explicitly removed before forwarding upstream.
   - Dynamic connection tokens in the incoming `Connection` header are parsed via comma-separation, trimmed, canonicalized, and stripped from the forwarded request, preventing hop-by-hop header leakage and connection hijacking.
2. **Anti-Spoofing of `X-Forwarded-Proto` and `X-Forwarded-For`**:
   - `X-Forwarded-Proto` is derived from the underlying socket state via `isTLSConnection(req.RawConn)` unless the connecting peer IP matches a configured subnet in `TrustedProxies`. Untrusted clients attempting to forge `X-Forwarded-Proto: https` over cleartext connections are safely overwritten to `http`.
   - `X-Forwarded-For` and `X-Real-IP` are grounded in `req.RawConn.RemoteAddr()`. For untrusted connections, existing headers are overwritten with the verified peer IP, defeating IP spoofing against backend access controls.
3. **Trusted Proxy Subnet Support**:
   - For recognized intermediate proxies (`TrustedProxies` CIDRs or exact IPs), client chains are preserved and the peer address is properly appended to `X-Forwarded-For`.
4. **Exploit Verification**:
   - Verified that client-forged `X-Forwarded-Proto: https` sent by untrusted socket yields `X-Forwarded-Proto: http` at the upstream.
   - Verified that custom hop-by-hop headers specified in `Connection: close, X-Internal-Token` are stripped.

## Conclusion

`SEC-11` is completely remediated. Upstream header spoofing and protocol confusion attacks are mitigated. The implementation is approved.
