# REQ-121 - Local Docker Benchmark Suite Comparing Toron Against NGINX, Traefik, Caddy, and HAProxy with Heterogeneous Upstream Origins

## 1. Description & Problem Statement

### 1.1 Executive Summary & Motivation
To evaluate and demonstrate Toron's performance and efficiency relative to industry-standard edge proxies and reverse proxies, a standardized, reproducible, and isolated local Docker benchmark harness is required. The benchmark must directly compare:
1. **Toron** (Go-based event-driven zero-dependency edge gateway)
2. **NGINX** (C-based asynchronous multi-process reverse proxy, `nginx:alpine`)
3. **Traefik** (Go-based cloud-native edge router, `traefik:v3.1`)
4. **Caddy** (Go-based memory-safe modern web server, `caddy:alpine`)
5. **HAProxy** (C-based event-driven TCP/HTTP load balancer, `haproxy:alpine`)

All proxies must front the **exact same heterogeneous upstream origin runtimes** running in the same Docker network under equivalent networking, connection pooling, and CPU/memory quotas:
- **Node.js 20 LTS** (`node-origin:9101`, C-based `llhttp` parser engine)
- **Python 3.11** (`python-origin:9102`, ASGI `uvicorn/h11` parser engine)
- **Go 1.24** (`go-origin:9103`, Standard library `net/http` parser engine)
- **High-Throughput Fast Echo** (`fast-origin:9104`, minimal latency Go origin to measure raw proxy transit overhead without origin worker saturation)

### 1.2 Benchmark Objectives & Key Metrics
The benchmark suite must execute under identical load profiles (concurrency, request rates, connection reuse, keepalive settings) and collect:
1. **Throughput**: Requests per second (RPS) and data transfer rates (MB/s).
2. **Tail Latency**: Coordinated omission-free latency percentiles: P50, P90, P99, P99.9, and Max latency.
3. **Resource Efficiency**: Peak and average CPU usage (%) and Memory RSS (MB) per proxy container via `docker stats`.
4. **Reliability & Error Accounting**: Non-2xx/3xx HTTP responses, connection resets, timeouts, and socket drops.
5. **Multi-Hop Upstream Parity**: Identical URI path prefixes and upstream routing semantics across all proxies (`/node/*`, `/python/*`, `/go/*`, `/fast/*`).

## 2. Functional Requirements

### REQ-121.1: Standardized Multi-Proxy Docker Compose Infrastructure
- A dedicated Docker Compose specification (`benchmarks/docker-compare/docker-compose.compare.yml`) must define:
  - Heterogeneous upstream services: `node-origin`, `python-origin`, `go-origin`, and `fast-origin`.
  - Target proxies: `toron-proxy`, `nginx-proxy`, `traefik-proxy`, `caddy-proxy`, and `haproxy-proxy`.
  - Isolated bridge network (`compare-net`) with DNS resolution.
  - Consistent port mapping on host (e.g. Toron on 8881, NGINX on 8882, Traefik on 8883, Caddy on 8884, HAProxy on 8885) avoiding occupied ports (8081-8085).
  - Configurable resource reservations and limits (CPU quota and memory limits) to guarantee fair scheduling.

### REQ-121.2: Apples-to-Apples Proxy Configurations
- Each proxy configuration (`toron_config.yaml`/`routes.yaml`, `nginx.conf`, `traefik.yml`, `Caddyfile`, `haproxy.cfg`) must implement:
  - Identical route routing tables:
    - `/node/` -> `http://node-origin:9101/` (strip prefix)
    - `/python/` -> `http://python-origin:9102/` (strip prefix)
    - `/go/` -> `http://go-origin:9103/` (strip prefix)
    - `/fast/` -> `http://fast-origin:9104/` (strip prefix)
  - Upstream persistent connection pooling (keepalive) enabled across all proxies.
  - Standardized timeout thresholds (e.g., 5s connect/read/write timeouts).
  - Equivalent logging level to avoid disproportionate disk I/O penalties during high-throughput benchmarking.

### REQ-121.3: Automated Pre-Flight Health & Semantic Parity Verification
- Before load testing begins, an automated verification probe must confirm that every proxy is operational and correctly routing requests to all 4 backends (`/node/health`, `/python/health`, `/go/health`, `/fast/health`), verifying HTTP 200 responses and backend runtime confirmation headers (`X-Backend-Runtime`).

### REQ-121.4: Multi-Concurrency & Multi-Origin Benchmark Execution Engine
- The benchmark runner (`benchmarks/docker-compare/run_compare.sh` and Go benchmark runner) must support:
  - Benchmark profiles:
    - Quick smoke test (e.g., 50 concurrency, 5s duration)
    - Standard comparative run (e.g., 100 concurrency, 10s duration)
    - Concurrency sweep (e.g., 50, 100, 250, 500 connections)
  - Engine selection:
    - `wrk2` / `wrk` if present on host.
    - Zero-dependency fallback using Toron's high-performance `loadgen.go` HDR histogram engine.
    - Containerized load generator option.

### REQ-121.5: Real-Time Docker Resource Monitoring
- The harness must sample container metrics via `docker stats --no-stream --format "{{.Name}}: {{.CPUPerc}} | {{.MemUsage}}"` before, during, and after each proxy benchmark run.
- Telemetry must be recorded in the final output report.

### REQ-121.6: Dual-Output Reporting & Retention Integration (REQ-119 Compliance)
- Outputs must be generated in both structured formats:
  - JSON artifact: `benchmarks/results/docker_compare_report.json`
  - Markdown summary: `benchmarks/results/docker_compare_report.md`
- Markdown summary must include a formatted comparative matrix ranking proxies by RPS, P99 latency, and Memory footprint per backend.
- Full integration with `benchmarks/archive_run.sh` to record execution in `benchmarks/results/history/manifest.json`.

## 3. Non-Functional Requirements

### REQ-121.7: Port Isolation and Local Machine Port Safety
- Ensure host exposed ports do not conflict with active developer services (ports 8081, 8082, 8084, 8085). Default assigned ports:
  - Toron: `8881`
  - NGINX: `8882`
  - Traefik: `8883`
  - Caddy: `8884`
  - HAProxy: `8885`

### REQ-121.8: Deterministic Teardown and Cleanup
- Traps and CLI flags (`--down`, `--clean`) must ensure all benchmark containers and networks are stopped and removed upon completion or interruption (`SIGINT`/`SIGTERM`).

## 4. Acceptance Criteria

- [ ] `docker compose -f benchmarks/docker-compare/docker-compose.compare.yml config` validates with zero syntax errors.
- [ ] All 5 proxies build or pull clean official images and start up in healthy status.
- [ ] Pre-flight checks pass 100% across all 5 proxies for `/node/*`, `/python/*`, `/go/*`, and `/fast/*`.
- [ ] Automated benchmark script executes end-to-end against all proxies and backends.
- [ ] Valid `docker_compare_report.json` and `docker_compare_report.md` artifacts are created in `benchmarks/results/`.
- [ ] Memory RSS and CPU usage are captured for each proxy container.
- [ ] Master historical archive in `benchmarks/results/history/manifest.json` is updated via `archive_run.sh`.
