# TC-094 - Verification of Kubernetes Ingress Route Table Lifecycle, Atomic Source Replacement, and Multi-Pod Balancing

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's core routing engine ([`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go)), Kubernetes Ingress Controller ([`pkg/ingress/controller.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go)), route translation engine ([`pkg/ingress/translator.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go)), and upstream reverse proxy ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go)) enforce an **atomic, bounded route lifecycle**, eliminating monotonic memory leaks, zombie route persistence, stale endpoint shadowing, pod replica starvation, and background resource leaks.

This test specification validates the complete remediation of critical security vulnerability [`SEC-33`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L449-L457) and security audit finding [`SR-091 Finding 3`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L130-L152) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html), [CWE-670: Use of Incorrect Operator / Control Flow](https://cwe.mitre.org/data/definitions/670.html), [CWE-1059: Incomplete Technical Documentation](https://cwe.mitre.org/data/definitions/1059.html)), confirming that:

1. **Source Isolation & Atomic Replacement**: The router's atomic replacement method [`ReplacePrefixRoutesBySource(source, specs)`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go) isolates mutations strictly to the targeted source subsystem (e.g. `"k8s-ingress"`). Routes originating from other sources (e.g. `"config"`, `"static"`) remain 100% intact and preserve their exact relative ordering.
2. **All-or-Nothing Rollback**: Pre-compilation and validation of route specifications occur prior to acquiring the router's write lock (`r.mu.Lock()`). Any malformed specification triggers an immediate error return, leaving the existing routing table unmodified.
3. **Empty Replacement Pruning**: Supplying an empty replacement slice (`len(specs) == 0`) cleanly evicts and tears down all prefix routes matching `source` without altering routes belonging to other sources.
4. **$O(K)$ Bounded Route Table Invariant**: Given an invariant cluster state with $K$ active Kubernetes Ingress rules, executing repeated synchronization cycles ($N \ge 10$) via periodic 30-second resync or watch events guarantees that the prefix route table contains exactly $K$ routes for source `"k8s-ingress"` ($\text{Count} = K$). Monotonic slice growth is completely eliminated, yielding $O(1)$ memory consumption with respect to sync cycle count.
5. **Zombie Route Elimination**: Deleting an Ingress resource or path from the Kubernetes cluster prunes the route from the routing table on the subsequent sync cycle. Subsequent HTTP requests matching the deleted route immediately return HTTP `404 Not Found`, eliminating unauthorized access and cross-tenant traffic leakage.
6. **Multi-Pod Endpoint Aggregation & Fair Load Balancing**: All pod endpoint IPs sharing a `(Host, Prefix)` routing tuple are consolidated into exactly **one** prefix route configured with a multi-target `RoundRobinBalancer`. Sequential client requests are distributed evenly across all healthy pod replicas ($\approx 1/M$ traffic per replica), eliminating replica starvation and single-pod overload crashes.
7. **Immediate Endpoint Cutover Without Shadowing**: Updating pod endpoint addresses (e.g. during rolling updates or pod restarts) atomically replaces the target upstream proxy. Requests arriving immediately after replacement route exclusively to the updated pod IPs. Zero traffic is shadowed by stale route entries or forwarded to decommissioned IPs.
8. **Reverse Proxy & Health Check Resource Teardown**: Evicting routes during replacement, manual deletion, or router reset invokes [`proxy.Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L596-L600), terminating active background health check ticker goroutines (`StopActiveHealthCheck`) and freeing network socket descriptors.
9. **Zero Third-Party Dependencies Invariant**: All route manipulation, endpoint grouping, synchronization loops, and load balancing algorithms strictly utilize Go standard library packages (`sync`, `net/http`, `net/url`, `time`, `context`, `strings`, `path`, `path/filepath`, `fmt`).
10. **High-Concurrency Race Safety**: Concurrent execution of high-volume HTTP client traffic through `router.ServeHTTP` while the Ingress Controller continuously synchronizes route tables operates with 100% thread safety and zero data races under `go test -race ./pkg/router/... ./pkg/ingress/...`.

- **Preconditions**:

### TC-094-02: Bounded Ingress Route Table Invariant Across Repeated Sync Cycles

- **Objective**: Verify that repeated invocations of [`syncIngresses`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go#L111-L161) (simulating 30-second periodic resync or continuous watch events) maintain a strictly constant route count in `r.prefixRoutes` for an unchanged cluster state ($O(K)$ memory bound), completely eliminating the monotonic slice growth vulnerability ([`SEC-33`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L449-L457)).
- **Traceability**: [`REQ-094-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-094.md#L139-L144), [`ADR-089 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-089.md#L197-L240), [`TASK-117`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-117.md), [`SEC-33`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L449-L457).
- **Target Function**: `TestIngressController_BoundedRouteTable(t *testing.T)` in `pkg/ingress/ingress_test.go`.
- **Preconditions**:
  - Mock Kubernetes API server returning $K = 3$ Ingress resources (e.g. `/app1`, `/app2`, `/app3`) with corresponding Endpoints.
  - Ingress Controller initialized with `IngressClass: "toron"`.
  - Core `router.Router` attached to Controller.
- **Action & Test Steps**:
  1. Initialize mock API server with 3 distinct Ingress definitions:
     - Ingress 1: `host: "app1.cluster.local"`, path: `"/app1"`, service: `"svc-1"` (1 endpoint: `10.244.0.10:8080`)
     - Ingress 2: `host: "app2.cluster.local"`, path: `"/app2"`, service: `"svc-2"` (1 endpoint: `10.244.0.20:8080`)
     - Ingress 3: `host: "app3.cluster.local"`, path: `"/app3"`, service: `"svc-3"` (1 endpoint: `10.244.0.30:8080`)
  2. Also pre-register 1 static route in the router via `RoutePrefix("static", "", "/static", ...)` to ensure non-ingress routes coexist.
  3. Execute 50 consecutive synchronization iterations:
     ```go
     for i := 1; i <= 50; i++ {
         ctrl.syncIngresses(ctx)
         routes := r.GetPrefixRoutes()
         var k8sRoutes int
         for _, rt := range routes {
             if rt.Source == "k8s-ingress" {
                 k8sRoutes++
             }
         }
         if k8sRoutes != 3 {
             t.Fatalf("Iteration %d: expected exactly 3 k8s-ingress routes, got %d", i, k8sRoutes)
         }
     }
     ```
  4. Inspect the total slice length of `r.prefixRoutes`.
- **Verifiable Assertions**:
  1. After iteration 1, `k8s-ingress` route count is exactly 3.
  2. After iteration 10, `k8s-ingress` route count is exactly 3.
  3. After iteration 50, `k8s-ingress` route count is exactly 3.
  4. Total route count is consistently 4 (3 Ingress routes + 1 static route) across all 50 iterations.
  5. Memory footprint invariant: Memory usage is strictly $O(K)$ where $K=3$, and $O(1)$ with respect to sync count $N=50$. Monotonic append behavior is completely eliminated.

### TC-094-03: Zombie Route Elimination on Ingress Deletion

- **Objective**: Verify that when an Ingress resource is removed from the Kubernetes cluster, the Ingress Controller immediately prunes the corresponding route from `r.prefixRoutes` during synchronization, and subsequent HTTP requests to the deleted route return HTTP `404 Not Found` rather than continuing to proxy traffic to obsolete backends.

- **Target Function**: `TestIngressController_ZombieRoutePruning(t *testing.T)` in `pkg/ingress/ingress_test.go`.
- **Preconditions**:
  - Mock Kubernetes API server with dynamic in-memory Ingress store allowing runtime additions and deletions.
  - Active backend HTTP server responding with `200 OK` and `"service-a payload"`.
  - Ingress Controller running and connected to `Router`.
- **Action & Test Steps**:
  1. **Phase 1 (Creation & Active Routing)**:
     - Deploy Ingress for `host: "api.example.com"`, path: `"/service-a"`.
     - Trigger `ctrl.syncIngresses(ctx)`.
     - Send HTTP request: `GET http://api.example.com/service-a`.
     - Assert response status is `200 OK` and body contains `"service-a payload"`.
     - Assert `len(r.GetPrefixRoutes()) == 1`.
  2. **Phase 2 (Ingress Deletion in K8s)**:
     - Remove Ingress `"/service-a"` from the mock Kubernetes API server.
     - Trigger `ctrl.syncIngresses(ctx)`.
  3. **Phase 3 (Zombie Elimination Verification)**:
     - Inspect route table: Assert `len(r.GetPrefixRoutes()) == 0`.

  4. **Phase 4 (Partial Route Deletion with Multiple Ingresses)**:
     - Add Ingress A (`/alpha`) and Ingress B (`/beta`).
     - Sync -> both return 200 OK.
     - Delete Ingress A (`/alpha`) only.
     - Sync -> `/alpha` returns 404 Not Found, `/beta` continues returning 200 OK.
- **Verifiable Assertions**:
  1. Deletion in Kubernetes removes the route entry from `r.prefixRoutes` on the next sync cycle.
  2. Requests dispatched to deleted Ingress paths return HTTP `404 Not Found`.
  3. No zombie routes remain in the router table.
  4. Remaining Ingress routes continue to function normally without disruption.

    - Pod 2: returns `"pod-2"` on GET `/app`
    - Pod 3: returns `"pod-3"` on GET `/app`
  - Ingress rule defined for `host: "lb.example.com"`, path: `"/app"`, pointing to Kubernetes Service `"app-svc"`.
  - Kubernetes Endpoints for `"app-svc"` contains the 3 mock pod IPs/ports.
- **Action & Test Steps**:

  3. Each pod replica receives exactly $33.3\%$ ($10/30$) of total traffic.
  4. Single-pod replica starvation (where replica 1 previously received 100% of traffic) is completely resolved.

## 5. Security, Performance & Architectural Invariants

1. **Strict $O(K)$ Memory Bound Invariant**:
   The memory footprint of Toron's prefix route table MUST be strictly $O(K)$, where $K$ is the number of active Ingress rules defined in the Kubernetes cluster. Monotonic growth across synchronization iterations $N$ is prohibited ($O(1)$ scaling with respect to $N$).
2. **Fail-Closed All-or-Nothing Mutation Invariant**:
   Pre-compilation and validation of replacement routes occur outside the write lock. If any spec is malformed (invalid target type, unparseable rate limit, invalid upstream URL), the mutation fails immediately and the existing route table remains completely unchanged.
3. **Atomic Cutover & Zero Stale Route Shadowing**:
   Route replacement must execute as a single atomic pointer swap under `r.mu.Lock()`. Readers acquiring `r.mu.RLock()` in `ServeHTTP` observe either the complete prior route table or the complete new route table. No request shall observe an intermediate or corrupted state, and updated pod endpoints immediately supersede previous endpoints.
4. **Zero Zombie Route Invariant**:
   Routes removed from the control plane must be pruned from the gateway routing table on the subsequent reconciliation cycle. Client requests matching deleted routes must return HTTP `404 Not Found` rather than continuing to proxy to decommissioned backends.
5. **Horizontal Pod Load Balancing Invariant**:
   Multi-replica pod services must aggregate all healthy pod endpoints into a single load-balanced route (`RoundRobinBalancer`). All replicas must receive proportional traffic shares ($\approx 1/M$), preventing single-pod cascading failure.
6. **Resource Cleanup Invariant (Zero EMFILE / Goroutine Leaks)**:
   Every route eviction or reset MUST invoke `Close()` on the evicted `ReverseProxy`, halting background health check tickers and closing idle network connections.
7. **Zero Third-Party Dependencies Invariant**:
   All routing, synchronization, and balancing implementations must strictly utilize Go standard library packages (`sync`, `net/http`, `net/url`, `time`, `context`, `strings`, `path`, `fmt`).
