# TC-114 - Test Specification for High-Concurrency Adversarial Stress Testing (BMK-04)

## 1. Test Suite Objectives

Verify that Toron edge gateway under high-concurrency saturation (5,000+ RPS sustained background traffic) with concurrent adversarial attack injection (10% malformed protocol probes):
1. Reliably intercepts and blocks 100.0% of malformed protocol probes with $400\text{ Bad Request}$ or $403\text{ Forbidden}$.
2. Eliminates starvation for concurrent legitimate traffic, maintaining bounded tail latencies ($p99 \le 50.0$ ms).
3. Accurately profiles decoupled latency distributions for both legitimate service times and fast-fail rejection times.
4. Generates publication-grade evaluation artifacts (`benchmarks/results/saturation_stress_report.json` and `benchmarks/results/saturation_stress_report.md`).

---

## 2. Test Cases

### TC-114-01: High-Concurrency Constant-Rate Pacing (5,000+ RPS)
- **Target**: `benchmarks/wrk2/loadgen.go`
- **Methodology**: Execute constant-rate load generator with `-rate 5000 -c 50 -d 5s` against Toron edge gateway (`/health`).
- **Expected Outcome**:
  - Achieved request rate $\ge 4,500$ RPS (within 90% of target rate under loopback).
  - 100% of benign requests succeed with $200\text{ OK}$.
  - Zero connection drops or unhandled timeouts.

### TC-114-02: Concurrent Adversarial Attack Vector Injection
- **Target**: `benchmarks/wrk2/loadgen.go`
- **Methodology**: Execute load generator with `-rate 5000 -c 50 -d 5s -attack-ratio 0.10` sampling across attack vectors `ADV-01` through `ADV-08`.
- **Expected Outcome**:
  - Exactly ~10% of total generated requests are malformed attack probes.
  - Workers sample from all 8 attack vectors without thread starvation or deadlocks.

### TC-114-03: Decoupled Telemetry Stream Isolation
- **Target**: `benchmarks/wrk2/loadgen.go`
- **Methodology**: Verify that benign response latencies and adversarial rejection latencies are tracked in distinct, independent buffers without cross-contamination.
- **Expected Outcome**:
  - Benign metrics reflect solely $200\text{ OK}$ service latencies.
  - Adversarial metrics reflect solely $400/403$ rejection latencies.
  - Decoupled percentiles ($p50, p75, p90, p95, p99, p99.9, \text{Max}$) computed accurately for each stream.

### TC-114-04: Zero-Starvation Invariant Verification
- **Target**: `benchmarks/wrk2/loadgen.go`
- **Methodology**: Inspect benign stream tail latencies under 5,000+ RPS load with 10% concurrent attack injection.
- **Expected Outcome**:
  - Benign $p99$ tail latency $\le 50.0$ ms (target $< 10.0$ ms over loopback).
  - Benign request failure rate is strictly $0.0\%$.
  - Proves that active defense evaluation does not lock event loops or starve concurrent connections.

### TC-114-05: 100% Invariant Rejection & Zero Bypass Assertion
- **Target**: `benchmarks/wrk2/loadgen.go`
- **Methodology**: Evaluate status code distributions for the adversarial attack stream.
- **Expected Outcome**:
  - Rejection count equals total attack probes transmitted ($100.0\%$ rejection rate).
  - Zero attack probes return $200\text{ OK}$ (Bypass Count $= 0$).
  - Mean rejection latency remains sub-millisecond.

### TC-114-06: Structured Evaluation Artifact Generation
- **Target**: `benchmarks/results/`
- **Methodology**: Execute test harness and inspect output files `saturation_stress_report.json` and `saturation_stress_report.md`.
- **Expected Outcome**:
  - `saturation_stress_report.json` contains complete machine-readable telemetry (rates, percentiles, attack breakdown, status codes).
  - `saturation_stress_report.md` contains publication-grade Markdown tables for Paper 2.
  - Both files non-empty and valid.
