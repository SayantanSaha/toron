# REQ-078 - Hardening Path Exclusion Logic in Authentication and WAF Middleware

## Description

The Toron authentication middleware (`pkg/router/auth.go`) and WAF middleware (`pkg/waf/middleware.go`) shall harden path exclusion matching to prevent accidental global security bypasses caused by empty (`""`) or root (`"/"`) exclusion entries.

## Acceptance Criteria

### 1. Robust Exclusion Path Normalization
- Empty strings (`""`) in `cfg.Excluded` or `engine.Config().Excluded` shall be ignored and shall never match any request path.
- Root path entries (`"/"`) in `cfg.Excluded` shall require strict exact equality (`req.Path == "/"`) and shall never match as a prefix for subpaths (e.g. `/admin`, `/api`).

### 2. Elimination of Universal Prefix Match Flaw
- The expression `strings.HasPrefix(req.Path, strings.TrimSuffix(p, "/")+"/")` shall not be evaluated when `strings.TrimSuffix(p, "/")` results in an empty string (such as when `p == "/"` or `p == ""`).

### 3. Verification
- Configuring `excluded: ["/"]` shall exempt only the exact root `/` endpoint, while requests to `/admin`, `/internal`, `/api/users` continue to enforce authentication and WAF inspection.

## Rationale

When `p = "/"`, trimming the suffix `"/"` produces `""`. Adding `"/"` produces `"/"`. Checking `strings.HasPrefix(req.Path, "/")` matches every valid URL path, silently disabling all authentication and WAF protections server-wide due to a single configuration entry.

## Constraints

- Pure Go standard library.
- Backward compatibility with legitimate subpath exclusions (e.g. `excluded: ["/public", "/health"]`).
