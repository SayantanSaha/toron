# CR-064 - Code Review of Wire Frame Size Bounding and Buffer Allocation Protection in gRPC Transcoder

## Description

Engineering code review of `TASK-068` changes across `pkg/transcoder/framer.go`, `pkg/transcoder/transcoder.go`, and `pkg/transcoder/transcoder_test.go`.

## Scope

- Files reviewed:
  - `pkg/transcoder/framer.go`
  - `pkg/transcoder/transcoder.go`
  - `pkg/transcoder/transcoder_test.go`

## Key Observations & Review Findings

1. **Pre-Allocation Size Validation**:
   - `DecodeGRPCFrameWithLimit` inspects `binary.BigEndian.Uint32(header[1:5])` against `maxFrameSize` before allocating the payload slice, eliminating heap exhaustion attack vectors.
2. **Backward Compatibility**:
   - `DecodeGRPCFrame(reader io.Reader)` signature is fully preserved as a backward-compatible wrapper calling `DecodeGRPCFrameWithLimit(reader, DefaultMaxGRPCFrameSize)`.
3. **Error Isolation & HTTP Semantics**:
   - `Engine.HandleTranscode` explicitly differentiates `ErrFrameTooLarge` via `errors.Is`, assigning appropriate `502 Bad Gateway` status instead of silently returning empty JSON `{}`.
4. **Concurrency & Zero Race Conditions**:
   - All tests run cleanly under race detection (`go test -race ./pkg/transcoder/...`). No shared mutable state is introduced.

## Verdict

Approved. Ready for commit.
