# TC-073 - Verification of HTTP Header Field-Name Whitespace Rejection (RFC 7230 §3.2.4)

## Objective

Verify that `httpparser.ParseRequest` strictly enforces RFC 7230 §3.2.4 by rejecting any HTTP request containing whitespace (spaces, tabs) between the header field-name and the colon delimiter with `HTTP 400 Bad Request`.

## Test Cases

### TC-073-01: Transfer-Encoding Space Before Colon
- **Setup**: Create raw TCP HTTP request buffer.
- **Action**: Transmit `GET / HTTP/1.1\r\nHost: example.com\r\nTransfer-Encoding : chunked\r\n\r\n`.
- **Expected Outcome**:
  - `ParseRequest` returns an error wrapping `ErrBadRequest`.
  - Server sends `HTTP 400 Bad Request`.
  - Connection is closed without body processing.

### TC-073-02: Header Tab Before Colon
- **Setup**: Raw HTTP request buffer.
- **Action**: Transmit `GET / HTTP/1.1\r\nHost\t: example.com\r\n\r\n`.
- **Expected Outcome**:
  - Request is rejected with `HTTP 400 Bad Request`.

### TC-073-03: Valid Header Whitespace Handling
- **Setup**: Raw HTTP request buffer.
- **Action**: Transmit `GET / HTTP/1.1\r\nHost: example.com\r\nX-Custom:  value with spaces  \r\n\r\n`.
- **Expected Outcome**:
  - Header is accepted without errors; leading/trailing whitespace in field value is trimmed to `"value with spaces"`.
