# TC-097 - Verification of Strict Sidecar Client TLS Validation, System Trust Root Fallback, and Explicit InsecureSkipVerify Opt-In

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's Service Mesh Sidecar Proxy ([`pkg/sidecar/`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/)) enforces **strict, secure-by-default certificate validation** for all outbound egress TLS and mutual TLS (mTLS) connections, completely eliminating the hardcoded insecure verification flaw tracked under vulnerability [`SEC-35`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L474-L482) and audit finding [`SR-091 Finding 5`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L173-L195) ([CWE-295: Improper Certificate Validation](https://cwe.mitre.org/data/definitions/295.html)).

This test specification validates the complete architectural remediation across [`pkg/config/config.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) and [`pkg/sidecar/mtls.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/mtls.go), confirming that:

1. **Secure-by-Default Configuration**: In `SidecarConfig`, the new opt-in field `InsecureSkipVerify` defaults strictly to `false` in both zero-value struct initialization (`SidecarConfig{}`) and `defaultConfig()`.
2. **Elimination of Hardcoded Insecure Verification**: `BuildClientTLSConfig` unconditionally assigns `tlsConfig.InsecureSkipVerify = cfg.InsecureSkipVerify`. Omitting `cfg.CAFile` NEVER sets `InsecureSkipVerify = true`.
3. **Host System Trust Root Fallback**: When `cfg.CAFile == ""` and `cfg.InsecureSkipVerify == false`, `tlsConfig.RootCAs` remains `nil`, enabling Go's runtime to validate certificates against host operating system certificate trust roots. Outbound requests to untrusted, self-signed, or expired certificates are rejected immediately during the TLS handshake.
4. **Custom Certificate Authority (CA) Pool Support**: When `cfg.CAFile != ""`, certificates are loaded into `tlsConfig.RootCAs` while `InsecureSkipVerify` remains `false`. Outbound connections validate against the custom CA, establishing TLS with services signed by that CA and rejecting untrusted endpoints.
5. **High-Visibility Security Audit Warning**: When `cfg.InsecureSkipVerify: true` is explicitly configured, `BuildClientTLSConfig` emits a prominent warning log (`[SIDECAR] WARNING: InsecureSkipVerify is enabled...`) to ensure visibility in security monitoring and SIEM systems.
6. **Egress Client Identity Keypair Loading (mTLS)**: Valid `CertFile` and `KeyFile` paths load into `tlsConfig.Certificates`, enabling the sidecar to authenticate itself to upstream mTLS services independently of certificate verification settings.
7. **Minimum TLS Version Enforcement**: All client TLS configurations strictly enforce `tlsConfig.MinVersion = tls.VersionTLS12`, preventing downgrade attacks to legacy SSL/TLS versions.
8. **High-Concurrency Race Safety**: All client TLS configurations and egress request dispatchers execute with 100% thread safety under `go test -race ./pkg/sidecar/... ./pkg/config/...`.

## 3. Detailed Test Case Specifications

### TC-097-01: Default Configuration Enforces Strict Validation (`InsecureSkipVerify == false`, `RootCAs == nil`)

- **Objective**: Verify that `SidecarConfig.InsecureSkipVerify` defaults to `false` in zero-value initializations and `defaultConfig()`, and that `BuildClientTLSConfig` strictly sets `tlsConfig.InsecureSkipVerify = false` and `tlsConfig.RootCAs = nil` when `CAFile` is empty, completely eliminating the vulnerability of defaulting to insecure verification.
- **Traceability**: [`REQ-097-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md#L102-L109), [`REQ-097-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md#L110-L117), [`ADR-097 §1, §2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-097.md#L112-L192), [`TASK-120 §1, §2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-120.md#L127-L163), [`SEC-35`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L474-L482).
- **Target Function**: `TestBuildClientTLSConfig_DefaultSecure(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - `SidecarConfig` updated with `InsecureSkipVerify bool`.
  - `BuildClientTLSConfig` updated to assign `tlsConfig.InsecureSkipVerify = cfg.InsecureSkipVerify`.
- **Test Scenarios Matrix**:

| Scenario ID | Configuration Input | Expected InsecureSkipVerify | Expected RootCAs | Expected MinVersion |
| :--- | :--- | :--- | :--- | :--- |
| `1.1` (Zero-Value Struct) | `config.SidecarConfig{}` | `false` | `nil` | `tls.VersionTLS12` |
| `1.2` (Default Config) | `config.DefaultConfig().Sidecar` | `false` | `nil` | `tls.VersionTLS12` |
| `1.3` (Egress Mode Omitted CA) | `config.SidecarConfig{Enabled: true, Mode: "egress", CAFile: ""}` | `false` | `nil` | `tls.VersionTLS12` |
| `1.4` (Explicit False) | `config.SidecarConfig{InsecureSkipVerify: false}` | `false` | `nil` | `tls.VersionTLS12` |

- **Action & Test Steps**:
  1. Instantiate `cfg := config.SidecarConfig{}`.
  2. Invoke `tlsConfig, err := BuildClientTLSConfig(cfg)`.
  3. Assert `err == nil`.
  4. Assert `tlsConfig.InsecureSkipVerify == false`.
  5. Assert `tlsConfig.RootCAs == nil`.
  6. Assert `tlsConfig.MinVersion == tls.VersionTLS12`.
  7. Repeat assertions for `config.DefaultConfig().Sidecar` and explicit `InsecureSkipVerify: false`.
- **Verifiable Assertions**:
  1. `InsecureSkipVerify` is `false` by default across all struct initialization patterns.
  2. `RootCAs` is `nil` when no CA file is specified, enabling system trust store fallback.
  3. Minimum TLS version is `tls.VersionTLS12` (0x0303).
  4. Zero hardcoded branches set `InsecureSkipVerify = true`.

### TC-097-02: System Trust Store Fallback Handshake Rejection on Untrusted Server

- **Objective**: End-to-end TLS test verifying that under default settings (`InsecureSkipVerify: false`, `CAFile: ""`), an egress connection to an upstream server presenting an untrusted self-signed certificate fails the TLS handshake with an authority error and terminates the connection.
- **Traceability**: [`REQ-097-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md#L118-L124), [`ADR-097 §3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-097.md#L194-L204), [`TASK-120 §2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-120.md#L143-L163), [`SEC-35`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L474-L482).
- **Target Function**: `TestSidecar_EgressTLS_HandshakeRejection(t *testing.T)` in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Upstream TLS test server running with a freshly generated self-signed certificate (not trusted by the host OS trust store).
  - Sidecar client transport initialized with `BuildClientTLSConfig(SidecarConfig{CAFile: ""})`.
- **Action & Test Steps**:
  1. Launch `upstream := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { w.WriteHeader(http.StatusOK) }))`.
  2. Construct client TLS config: `tlsConfig, err := BuildClientTLSConfig(config.SidecarConfig{})`.
  3. Assert `tlsConfig.InsecureSkipVerify == false` and `tlsConfig.RootCAs == nil`.
  4. Construct `http.Client` with custom `http.Transport{TLSClientConfig: tlsConfig}`.
  5. Attempt HTTP request: `resp, err := client.Get(upstream.URL)`.
  6. Verify outcome:
     - Assert `err != nil`.
     - Assert error message contains `"certificate signed by unknown authority"` or `x509.UnknownAuthorityError`.
     - Assert `resp == nil` (no response data received).
- **Verifiable Assertions**:
  1. Untrusted self-signed certificates are rejected by default.
  2. TLS handshake aborts before transmitting application HTTP payloads.
  3. Handshake error confirms fallback to system certificate roots.
  4. CWE-295 MITM vulnerability is completely mitigated.

### TC-097-03: Custom CA Certificate Pool Validation and Validated Handshake Success

- **Objective**: Verify that when `cfg.CAFile` is provided, `BuildClientTLSConfig` correctly parses the CA certificate into `tlsConfig.RootCAs`, keeps `InsecureSkipVerify == false`, and successfully establishes a TLS connection with an upstream server whose certificate is signed by that custom CA.
- **Traceability**: [`REQ-097-AC-04`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md#L125-L131), [`ADR-097 §4`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-097.md#L206-L215), [`TASK-120 §2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-120.md#L143-L163).
- **Target Functions**:
  - `TestBuildClientTLSConfig_CustomCA(t *testing.T)`
  - `TestSidecar_EgressTLS_HandshakeSuccess_WithCustomCA(t *testing.T)`
  in `pkg/sidecar/sidecar_test.go`.
- **Preconditions**:
  - Temporary directory containing a custom CA certificate PEM file and an upstream TLS server configured with a certificate issued by that CA.
- **Action & Test Steps**:
  1. Generate temporary CA certificate and write to `ca.pem`.
  2. Spin up `httptest.NewTLSServer` using a server certificate signed by `ca.pem`.
  3. Configure sidecar: `cfg := config.SidecarConfig{CAFile: "path/to/ca.pem", InsecureSkipVerify: false}`.
  4. Call `tlsConfig, err := BuildClientTLSConfig(cfg)`.
  5. Assert `err == nil`, `tlsConfig.RootCAs != nil`, and `tlsConfig.InsecureSkipVerify == false`.
  6. Execute HTTPS request using `tlsConfig` against the custom-CA server:
     - Assert `err == nil`.
     - Assert `resp.StatusCode == http.StatusOK`.
  7. Test Invalid CA File Path:
     - Configure `cfg.CAFile = "/nonexistent/ca.pem"`.
     - Call `BuildClientTLSConfig(cfg)`.
     - Assert `err != nil` and error message contains `"failed to read sidecar ca cert"`.
- **Verifiable Assertions**:
  1. `CAFile` populates `tlsConfig.RootCAs` with a non-empty `*x509.CertPool`.
  2. `InsecureSkipVerify` remains `false` when a custom CA is configured.
  3. TLS handshakes succeed against endpoints signed by the custom CA.
  4. Non-existent CA files trigger immediate, descriptive errors.

## 5. Security, Performance & Architectural Invariants

1. **Secure-by-Default Invariant (CWE-295 Remediation)**:
   `InsecureSkipVerify` MUST evaluate to `false` in all standard configurations, default files, and zero-value struct initializations. Bypassing certificate verification MUST require an explicit, intentional opt-in by the operator.
2. **Fail-Closed Security Invariant**:
   When peer certificate verification fails, the sidecar MUST terminate the TLS handshake immediately and return HTTP 502 Bad Gateway to the local application, never falling back to insecure transport.
3. **Mandatory Auditability**:
   Any runtime activation of `InsecureSkipVerify: true` MUST emit a standard log warning to ensure detection by security audit pipelines and SIEM systems.
4. **Cryptographic Protocol Floor**:
   `tlsConfig.MinVersion = tls.VersionTLS12` MUST be unconditionally enforced on all client TLS configurations, preventing protocol downgrade attacks to SSLv3, TLS 1.0, or TLS 1.1.
5. **Zero Third-Party Dependencies Invariant**:
   All cryptographic operations, certificate pool manipulations, and TLS configurations MUST strictly use Go standard library packages (`crypto/tls`, `crypto/x509`, `log`, `fmt`, `os`).
6. **Thread Safety & Race Freedom**:
   The `*tls.Config` constructed by `BuildClientTLSConfig` MUST be safe for concurrent use across high-concurrency request dispatching without race conditions under `go test -race`.
