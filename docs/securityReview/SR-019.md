# SR-019 - Security Review of WebSocket Upgrade and Bi-directional Proxy Tunneling

## Scope

Security review of HTTP/1.1 `Upgrade: websocket` header parsing, connection hijacking, upstream raw socket dialing, and socket deadline management during WebSocket streaming sessions.

## Findings

1. **Header Sanitization**: `IsWebSocketUpgrade()` strictly requires both `Connection` containing `upgrade` and `Upgrade` matching `websocket`, preventing accidental raw socket exposure.
2. **Upstream Handshake Validation**: The proxy verifies that the upstream server returns an explicit `101 Switching Protocols` response line before hijacking client TCP sockets. If the upstream rejects the upgrade or fails, a standard `502 Bad Gateway` response is returned.
3. **Resource Leak & Teardown Guards**: Bi-directional goroutines use dual deferred socket closures (`io.Copy` returns on socket close or `io.EOF`), ensuring socket file descriptors are released cleanly without leaking connection state.

## Conclusion

Approved. No security vulnerabilities or connection leaks identified.
