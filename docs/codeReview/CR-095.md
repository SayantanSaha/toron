# CR-095 - Code Review of Thread-Safe ReverseProxy Caching, Transport Teardown, and Client mTLS Lifecycle Management in Service Mesh Sidecar Proxy (SEC-37)

## Review Summary

- **Components Reviewed**:
  - [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L466-L610): Addition of `TLSClientConfig *tls.Config` to [`ProxyOptions`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L466), attachment of pre-compiled `TLSClientConfig` to `http.Transport` in `NewProxyWithOptions`, and comprehensive idle connection teardown in [`ReverseProxy.Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L601-L610) via `tr.CloseIdleConnections()`.
  - [`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L23-L377): Thread-safe `ReverseProxy` caching in [`ProxyEngine`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L24-L37), single compilation of `clientTLS` via `BuildClientTLSConfig(cfg)` during initialization, canonical origin normalization in `normalizeTargetOrigin` (`scheme://host[:port]`), double-checked locking in `getOrCreateProxy` via `sync.RWMutex`, cached proxy dispatch in `proxyToURL`, and clean lifecycle teardown in `ProxyEngine.Stop()`.
  - [`pkg/proxy/proxy_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy_test.go#L1197-L1228): Unit test verification of `ReverseProxy.Close()` closing idle transport connections (`TC-099-07`).
  - [`pkg/sidecar/sidecar_test.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/sidecar_test.go#L1519-L1877): Automated test suite verifying singleton proxy reuse (`TC-099-01`), multi-origin isolation (`TC-099-02`), high-concurrency race freedom (`TC-099-03`), stop lifecycle teardown (`TC-099-04`), egress client mTLS propagation (`TC-099-05`), and canonical origin normalization (`TC-099-06`).
  - `go.mod` / `go.sum`: Verification of zero third-party dependencies (100% pure Go standard library).
- **Security & Architectural Invariant Verifications**:
  - **Elimination of Per-Request Transport Allocation (CWE-400 / CWE-772)**: Instantiating a new `ReverseProxy`, `http.Client`, and `http.Transport` per request has been replaced with origin-keyed caching in `ProxyEngine.proxies`. Sequential requests reuse existing pooled TCP connections via HTTP keep-alive.
  - **Idle Transport Socket Teardown (CWE-772)**: `ReverseProxy.Close()` invokes `tr.CloseIdleConnections()`, terminating idle TCP sockets and releasing file descriptors (`EMFILE`).
  - **Bounded Memory Footprint ($O(U)$ Bounded Cache)**: `normalizeTargetOrigin` strips path, query, and fragment components, mapping dynamic paths to canonical origin keys and preventing cache key explosion.
  - **Client mTLS Configuration Propagation**: Pre-compiled `clientTLS` is attached to cached proxies via `opts.TLSClientConfig`, ensuring egress HTTPS/mTLS connections present client certificates and validate custom CA roots in compliance with [`REQ-097`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md) / `SEC-35`.
  - **Zero Third-Party Dependencies**: Pure Go standard library (`net/http`, `crypto/tls`, `sync`, `net/url`, `io`, `fmt`, `time`, `strings`).
  - **Concurrency Safety & Race Freedom**: 100% thread safety verified under 50 concurrent workers executing 1,000 requests across multiple backends with zero data races.
- **Verdict**: **APPROVED WITH RECOMMENDATIONS (Status: approved)**.

### Background & Root Cause Analysis (SEC-37 / CWE-400, CWE-772)

During security audit [`SR-091 Finding 7`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md) and vulnerability tracking [`SEC-37`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L492-L500) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html), [CWE-772: Missing Release of Resource after Effective Lifetime](https://cwe.mitre.org/data/definitions/772.html)), a critical performance and resource leak flaw was identified in the sidecar proxy engine ([`pkg/sidecar/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go)).

Previously, `proxyToURL` executed:

```go
// Vulnerable implementation prior to TASK-122
func (p *ProxyEngine) proxyToURL(w http.ResponseWriter, r *http.Request, targetURL string) {
    opts := proxy.ProxyOptions{
        Targets: []string{targetURL},
    }

    px, err := proxy.NewProxyWithOptions(opts) // Failure Mode: Allocated per request!
    ...
    px.ServeHTTP(toronReq, toronRes)
}
```

### Vulnerability Impact

1. **Socket Descriptor Exhaustion & Crash (EMFILE)**:
   Every outbound request allocated a new `*http.Transport` with its own connection pool (`MaxIdleConns: 100`, `IdleConnTimeout: 90s`). Because transports were created per request and never reused or closed, thousands of open TCP sockets accumulated concurrently without connection pooling. Under microservice production loads, this caused rapid file descriptor exhaustion (`EMFILE: too many open files`), heavy GC thrashing, and process crash.
2. **Missing Transport Connection Teardown in `ReverseProxy.Close()`**:
   `ReverseProxy.Close()` only halted load balancer health checks (`p.Balancer.Stop()`), failing to close idle transport connections (`tr.CloseIdleConnections()`).
3. **Egress Client mTLS Disconnect**:
   `proxyToURL` passed an empty `opts.TLS`, failing to propagate client certificates (`CertFile`/`KeyFile`), custom CA bundles (`CAFile`), or `InsecureSkipVerify` settings configured on `SidecarConfig` (tracked under [`REQ-097`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-097.md) / `SEC-35` and [`CR-093 Finding 3`](file:///Users/sneha/.gemini/antigravity-cli/brain/a66ff311-fc9a-4bbc-bb45-70ab388f0c99/CR-093.md)).

### 3. Thread-Safe ReverseProxy Caching via Double-Checked Locking (`pkg/sidecar/proxy.go`)

- **Implementation**:
  [`pkg/sidecar/proxy.go:237-277`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L237-L277):
  ```go
  func (p *ProxyEngine) getOrCreateProxy(targetURL string) (*proxy.ReverseProxy, error) {
      origin, err := normalizeTargetOrigin(targetURL)
      if err != nil {
          return nil, err
      }

      // Fast path: read lock
      p.mu.RLock()
      px, ok := p.proxies[origin]
      p.mu.RUnlock()
      if ok && px != nil {
          return px, nil
      }

      // Slow path: write lock
      p.mu.Lock()
      defer p.mu.Unlock()

      // Double-checked locking
      if px, ok = p.proxies[origin]; ok && px != nil {
          return px, nil
      }

      opts := proxy.ProxyOptions{
          Targets:         []string{origin},
          TLSClientConfig: p.clientTLS,
      }

      newPx, err := proxy.NewProxyWithOptions(opts)
      if err != nil {
          return nil, err
      }

      if p.proxies == nil {
          p.proxies = make(map[string]*proxy.ReverseProxy)
      }
      p.proxies[origin] = newPx
      return newPx, nil
  }
  ```
- **Evaluation against REQ-099-AC-03, AC-05 / ADR-099 §3**:
  - Hot path uses `RLock()`, providing lock-free sub-microsecond cache lookups.
  - Cold path uses `Lock()` with re-checking (`double-checked locking`), preventing race condition duplicate allocations when multiple concurrent requests target an uncached origin simultaneously.
  - `opts.TLSClientConfig` passes `p.clientTLS` to all newly instantiated proxies.
  - Verified by `TestProxyEngine_ProxyCaching_SingletonPerOrigin` (`TC-099-01`) and `TestProxyEngine_HighConcurrency_RaceClean` (`TC-099-03`).
- **Verdict**: **COMPLIANT**.

### 4. Canonical Origin Normalization ($O(U)$ Bounded Memory)

- **Implementation**:
  [`pkg/sidecar/proxy.go:207-235`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L207-L235):
  ```go
  func normalizeTargetOrigin(rawURL string) (string, error) {
      targetURL := strings.TrimSpace(rawURL)
      if targetURL == "" {
          return "", fmt.Errorf("empty target URL")
      }

      lower := strings.ToLower(targetURL)
      if strings.HasPrefix(targetURL, "//") {
          targetURL = "http:" + targetURL
      } else if !strings.HasPrefix(lower, "http://") && !strings.HasPrefix(lower, "https://") {
          targetURL = "http://" + targetURL
      }

      u, err := url.Parse(targetURL)
      if err != nil {
          return "", fmt.Errorf("invalid target URL: %w", err)
      }

      scheme := strings.ToLower(u.Scheme)
      host := strings.ToLower(u.Host)

      if host == "" {
          return "", fmt.Errorf("missing host in target URL: %s", rawURL)
      }

      return fmt.Sprintf("%s://%s", scheme, host), nil
  }
  ```
- **Evaluation against REQ-099-AC-04 / ADR-099 §4**:
  - Normalizes URLs to `scheme://host[:port]`, stripping dynamic paths, queries, and fragments.
  - Defaults scheme to `http` if omitted.
  - Converts scheme and host to lowercase.
  - Memory consumption of `p.proxies` is strictly bounded by $O(U)$ where $U$ is the number of distinct upstream microservices, completely preventing cache key explosion.
  - Validated across all 9 scenarios in `TestProxyEngine_OriginNormalization` (`TC-099-06`).
- **Verdict**: **COMPLIANT**.

## Findings & Recommendations

### Finding 1: Single-Origin Target Assumption in ReverseProxy Instance

- **Severity**: Low (Architectural Documentation / Future Extensibility)
- **Location**: [`pkg/sidecar/proxy.go:263`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L263)
- **Related Artifact**: [`REQ-099-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-099.md#L127-L141), [`ADR-099 §3.3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L236-L248)
- **Description**:
  In `getOrCreateProxy`:
  ```go
  opts := proxy.ProxyOptions{
      Targets:         []string{origin},
      TLSClientConfig: p.clientTLS,
  }
  newPx, err := proxy.NewProxyWithOptions(opts)
  ```
  The cached `ReverseProxy` is instantiated with a single target (`[]string{origin}`). Traffic splitting across multiple backends (canary releases) is handled at the `ProxyEngine.splitters` layer prior to `proxyToURL`.
- **Impact**:
  This design is optimal for sidecar egress routing where traffic splitting selects the destination backend URL before forwarding. However, load-balancer algorithms internal to `ReverseProxy` (e.g. multi-endpoint round-robin) are not exercised because each cached proxy manages a single target origin.
- **Recommendation**:
  Document in `ProxyEngine` architectural comments that traffic splitting occurs upstream in `ProxyEngine.splitters`, while `ReverseProxy` acts as an origin-specific connection-pooled transport.

### Finding 2: Ingress vs Egress Local Forwarding Origin Coexistence

- **Severity**: Low (Operational Clarity)
- **Location**: [`pkg/sidecar/proxy.go:140`](file:///Users/sneha/Developer/toron-research/toron/pkg/sidecar/proxy.go#L140)
- **Related Artifact**: [`REQ-081`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-081.md), [`ADR-099 §5`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-099.md#L298-L322)
- **Description**:
  In `startIngressListener`:
  ```go
  appURL := fmt.Sprintf("http://127.0.0.1:%d%s", p.cfg.AppPort, r.URL.RequestURI())
  p.proxyToURL(w, r, appURL)
  ```
  Both ingress (forwarding to local container `127.0.0.1:AppPort`) and egress (forwarding to external upstreams) utilize the same `p.getOrCreateProxy` cache.
- **Impact**:
  For ingress, the local container is cached as origin `http://127.0.0.1:AppPort`. Because the scheme is `http://`, the attached `p.clientTLS` is ignored by Go's HTTP transport, correctly preserving plaintext forwarding to the local container.
- **Recommendation**:
