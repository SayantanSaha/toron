# SR-078 - Security Review of Case-Insensitive WAF TRAVERSAL-001 Hardening

## Description

Security evaluation of the implementation for `TASK-080` / `SEC-20` (WAF path traversal detection bypass via uppercase percent-encoded sequences in `TRAVERSAL-001`).

## Scope

- Files reviewed:
  - `pkg/waf/rules.go`
  - `pkg/waf/waf_test.go`

## Security Evaluation & Analysis

1. **Elimination of Case-Sensitivity Evasion (CWE-693 / CWE-22)**:
   - Added `(?i)` case-insensitivity flag to rule `TRAVERSAL-001`.
   - Expanded regex to: `(?i)(\.\./|\.\.\\|%2e%2e/|%2e%2e%2f|%2e%2e\\|%2e%2e%5c)`.
   - Traversal sequences containing uppercase hex characters (`%2E%2E/`, `%2E%2E%2F`) or backslashes (`%2E%2E\`, `%2E%2E%5C`) are now detected reliably across all inspection locations (URL, queries, headers, and body).
2. **Exploit Verification**:
   - TC-080-01 verified: Header with `X-Path: %2E%2E/secret.txt` is blocked by `TRAVERSAL-001`.
   - TC-080-02 verified: POST body with `{"file":"%2e%2E%2Fetc/passwd"}` is blocked by `TRAVERSAL-001`.
   - TC-080-03 verified: Query parameter `?file=%2e%2e%5cwindows%5cwin.ini` is blocked by `TRAVERSAL-001`.

## Conclusion

`SEC-20` is fully mitigated. Path traversal casing and backslash evasion vectors against the WAF are eliminated. Approved.
