# SR-112 - Security Review for HTTP/2 Translation Invariant Guards

## 1. Security Evaluation Summary

- **Components**: `pkg/httpparser/request.go`, `pkg/server/server.go`, `pkg/proxy/proxy.go`
- **Reviewed By**: Security Analyst
- **Status**: **APPROVED** (Zero Security Defects Identified)
- **Target Threat Invariants**:
  - CWE-444: Inconsistent Interpretation of HTTP Requests (HTTP Request Smuggling / Cross-Protocol Desynchronization)
  - CWE-113: Improper Neutralization of CRLF Sequences in HTTP Headers ('HTTP Response Splitting')
  - CWE-74: Improper Neutralization of Special Elements in Output Used by a Downstream Component ('Injection')

## 2. Threat Vector Fidelity & Mitigation Verification

| Threat Vector / Attack Scenario | Security Verification & Invariant Analysis | Empirical Security Finding |
| :--- | :--- | :---: |
| **H2.TE Downgrading Smuggling (CWE-444)** | Attackers send HTTP/2 requests with `Transfer-Encoding: chunked`. Upstream HTTP/1.1 proxies misinterpret message framing, leading to backend socket poisoning. | **Mitigated**: RFC 7540 §8.1.2.2 strictly enforced in `ValidateHTTP2Request`; `Transfer-Encoding` is unconditionally rejected with `400 Bad Request`. |
| **H2.CL Framing Discrepancy & Smuggling (CWE-444)** | Duplicate or comma-separated `Content-Length` headers, or payload byte count differing from declared `Content-Length`. | **Mitigated**: `ValidateHTTP2Request` rejects multi-header and comma-separated `Content-Length`. `http2AdapterHandler` verifies that stream payload length matches declared `Content-Length` exactly, blocking H2.CL attacks. |
| **CRLF & NUL Binary Injection (CWE-113, CWE-74)** | Binary HPACK frames containing `\r\n` or `0x00` in pseudo-headers or headers injected into HTTP/1.1 wire streams to forge arbitrary requests. | **Mitigated**: Linear zero-allocation byte scanner validates method, path, query, host, and all header keys/values, rejecting requests containing `\r`, `\n`, or `0x00` with `400 Bad Request`. |
| **Forbidden Hop-by-Hop / Connection Headers** | Attackers transmit `Connection: keep-alive`, `Proxy-Connection`, or `Upgrade` to manipulate downstream socket state. | **Mitigated**: Prohibited connection headers rejected with `400 Bad Request`. Extended CONNECT allowed strictly when `:protocol` is present (RFC 8441). |
| **Upstream Pseudo-Header Smuggling** | Pseudo-headers (`:protocol`, `:path`, etc.) leaking into HTTP/1.1 socket wire requests corrupting backend HTTP/1.1 parsers. | **Mitigated**: `pkg/proxy/proxy.go` strips all colon-prefixed (`:`) headers during HTTP reverse proxying and raw TCP upgrade streaming. |

## 3. Verdict

**APPROVED**. The implementation effectively mitigates James Kettle's Black Hat 2021 HTTP/2 desynchronization attack surface (H2.CL and H2.TE), blocks header and pseudo-header CRLF injection attacks, and establishes complete cross-protocol translation isolation for the Toron edge gateway.
