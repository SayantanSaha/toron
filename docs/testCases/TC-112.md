# TC-112 - Test Specification for HTTP/2 Translation Invariant Guards

## 1. Test Suite Objectives

Verify that `pkg/server/server.go` (`http2AdapterHandler`), `pkg/httpparser`, and `pkg/proxy/proxy.go` enforce RFC 7540 §8.1.2 translation invariants, reject H2.TE and H2.CL smuggling attempts, reject CRLF/NUL injection in headers or pseudo-headers, preserve RFC 8441 extended CONNECT compatibility, and strip all colon-prefixed pseudo-headers before forwarding to HTTP/1.1 backend sockets.

## 2. Test Cases

### TC-112-01: H2.TE Rejection (`Transfer-Encoding` in HTTP/2)
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_TransferEncodingRejected`)
- **Methodology**: Issue an HTTP/2 request with header `Transfer-Encoding: chunked`.
- **Expected Outcome**:
  - Request is rejected with `400 Bad Request`.
  - Request is never forwarded to router or backend origin.

### TC-112-02: H2.CL Multiple / Conflicting Content-Length Rejection
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_MultipleContentLengthRejected`)
- **Methodology**: Issue an HTTP/2 request with duplicate `Content-Length` headers (`Content-Length: 5` and `Content-Length: 10`) or comma-separated values (`Content-Length: 5, 10`).
- **Expected Outcome**:
  - Request is rejected with `400 Bad Request`.

### TC-112-03: H2.CL Payload Length Discrepancy Rejection
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_ContentLengthMismatchRejected`)
- **Methodology**: Issue an HTTP/2 POST request declaring `Content-Length: 20` but transmitting only 5 bytes in stream body before `END_STREAM`.
- **Expected Outcome**:
  - Server detects mismatch between declared `Content-Length` and received payload length.
  - Server responds with `400 Bad Request`.

### TC-112-04: CRLF and NUL Binary Injection Rejection
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_CRLFInjectionRejected`)
- **Methodology**: Issue HTTP/2 requests with:
  1. `\r\n` embedded inside a custom header value (`X-Custom: safe\r\nInjected: evil`).
  2. `\r\n` embedded inside the request path (`/api\r\nGET /admin`).
  3. `\x00` (NUL byte) embedded in a header value.
- **Expected Outcome**:
  - Invariant scanner detects carriage return, newline, or NUL byte.
  - All requests are rejected with `400 Bad Request`.

### TC-112-05: Forbidden Connection Headers Rejection
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_ForbiddenConnectionHeadersRejected`)
- **Methodology**: Issue HTTP/2 requests containing:
  - `Connection: keep-alive`
  - `Keep-Alive: timeout=5`
  - `Proxy-Connection: keep-alive`
  - `Upgrade: websocket` (without extended CONNECT)
- **Expected Outcome**:
  - Server rejects all forbidden connection headers with `400 Bad Request`.

### TC-112-06: RFC 8441 Extended CONNECT Compatibility
- **Target**: `pkg/server/server_test.go` (`TestServer_HTTP2_ExtendedConnectAllowed`)
- **Methodology**: Issue an HTTP/2 `CONNECT` request containing pseudo-header `:protocol: websocket` and `Upgrade: websocket`.
- **Expected Outcome**:
  - Extended CONNECT request passes translation validation without rejection.
  - Upgraded WebSocket stream completes handshake successfully.

### TC-112-07: Upstream HTTP/1.1 Pseudo-Header Stripping
- **Target**: `pkg/proxy/proxy_test.go` (`TestProxy_HTTP2ToHTTP1_PseudoHeaderStripping`)
- **Methodology**: Receive downstream request containing pseudo-headers (`:protocol`, `:authority`, `:path`), proxy request to an HTTP/1.1 upstream mock server, and inspect raw HTTP/1.1 request wire bytes.
- **Expected Outcome**:
  - Zero colon-prefixed (`:`) headers are written to the upstream HTTP/1.1 socket.
  - Normal headers (`Host`, `User-Agent`, etc.) are forwarded cleanly.
