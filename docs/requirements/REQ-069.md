# REQ-069 - Strict CORS Origin Validation and Credentialed Wildcard Mitigation

## Description

The Toron Cross-Origin Resource Sharing (CORS) middleware shall enforce strict origin validation and reject invalid configurations that combine wildcard origin matching (`*`) with credential sharing (`allow_credentials: true`).

The middleware shall ensure that untrusted external origins cannot trigger dynamic origin reflection with credentials enabled, preventing cross-site data theft and credential hijacking (CWE-942).

## Acceptance Criteria

### 1. Rejection of Credentialed Wildcard Origins at Configuration Load
- Configuration validation in `pkg/config` and `pkg/router/cors.go` shall reject configurations where `allow_origins` contains `*` while `allow_credentials` is set to `true`.
- The server shall log an error and refuse to start or apply such configurations during startup or hot reloading.

### 2. Disallow Dynamic Reflection on Wildcards
- In runtime execution, if `allow_credentials` is true, the CORS middleware shall never reflect arbitrary client `Origin` headers into `Access-Control-Allow-Origin` unless the incoming origin explicitly matches a non-wildcard configured allowed origin.
- Unmatched origins shall receive no CORS headers or a forbidden response during preflight OPTIONS checks.

### 3. Proper Vary Header Signaling
- Whenever origin-dependent response headers are emitted, the middleware shall reliably set or append `Vary: Origin` to ensure downstream caching proxies do not serve cross-origin responses to wrong clients.

## Rationale

Browsers prohibit `Access-Control-Allow-Origin: *` when `Access-Control-Allow-Credentials: true`. Bypassing this browser safety check by reflecting the incoming `Origin` value on wildcards allows any third-party website to make credentialed cross-origin requests and read sensitive responses.

## Constraints

- Compliance with W3C / WHATWG Fetch and CORS specifications.
- Support for wildcard subdomain patterns (e.g. `*.example.com`) without opening arbitrary root domains.

## Open Questions

- Should a null origin (`null`) be explicitly disallowed when credentials are true?
