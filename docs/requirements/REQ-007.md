# REQ-007 - Extensible File Configuration and CLI Argument Parsing

## Description

The Toron web server shall support loading server, static asset, and middleware configuration parameters from an external configuration file specified via command-line arguments (`-config <path>`). The configuration loader shall support YAML format initially and be architected via an extensible interface to support future formats (e.g., JSON, TOML).

## Acceptance Criteria

- Command line accepts `-config` (or `-c`) flag pointing to a configuration file.
- YAML configuration file schema defines server networking, timeouts, static file paths, and logging options.
- An extensible `Loader` interface (`pkg/config`) decouples format-specific decoding (YAML, JSON, TOML) from domain config structures.
- Provides fallback to sensible defaults when optional parameters are omitted.
- Validates config fields upon startup and returns informative error messages for invalid formats.

## Rationale

Decouples hardcoded configuration from application source code and provides environment-specific deployment flexibility.

## Constraints

- Default fallback configuration must allow server execution even if no CLI config file is provided.
