# SR-077 - Security Review of Container Route Prefix Scoping and Shadowing Guards

## Description

Security evaluation of the implementation for `TASK-079` / `SEC-19` (Ingress route hijacking and administrative route shadowing via unrestricted container labels).

## Scope

- Files reviewed:
  - `pkg/discovery/parser.go`
  - `pkg/discovery/manager.go`
  - `pkg/discovery/discovery_test.go`

## Security Evaluation & Analysis

1. **Root Hijack Protection (CWE-284)**:
   - Untrusted containers sharing Docker engine can no longer register root ingress (`prefix == ""` or `prefix == "/"`) without supplying an explicit, non-empty `toron.host` label.
   - Prevents rogue containers from capturing gateway-wide HTTP traffic.
2. **Administrative Endpoint Shadowing Prevention**:
   - Containers attempting to register routes under reserved internal namespaces (`/internal`, `/internal/*`, `/api/status`, `/api/status/*`) are automatically rejected by `ParseContainerLabels`.
   - In `pkg/discovery/manager.go`, rejected container route attempts trigger security warning logs for operator visibility.
3. **Exploit Verification**:
   - TC-079-01 verified: unhosted root prefix (`"/"` without host) is rejected `(nil, false)`.
   - Empty prefix without host is rejected `(nil, false)`.
   - TC-079-02 verified: administrative path shadowing (`/internal/api`) is rejected `(nil, false)`.
   - TC-079-03 verified: legitimate scoped routes (`/services/payments`) and host-specific root routes register successfully.

## Conclusion

`SEC-19` is fully mitigated. Container route scoping and namespace isolation are enforced. Approved.
