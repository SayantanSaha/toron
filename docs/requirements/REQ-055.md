# REQ-055: Centralized Version Management & Build Metadata Tracking

## Status
- **State**: APPROVED
- **Type**: Architecture / Core Engineering
- **Created**: 2026-09-01

## Description
Establish a single source of truth (SSOT) for Toron versioning across the entire repository, replacing disparate hardcoded version strings in Go code, CLI binaries, Makefile, auto-installer scripts, and telemetry APIs.

## Requirements
1. **Root `VERSION` File**: Maintain a plain-text `VERSION` file in the repository root containing the canonical semantic version (e.g. `1.5.0`).
2. **Go `pkg/version` Package**: Create a central package `toron/pkg/version` exposing `Version`, `GitCommit`, `BuildDate`, and `Info()`.
3. **Build-Time Linker Injection**: `Makefile` must automatically extract Git commit hash and UTC build timestamps and inject them via Go linker flags (`-ldflags`).
4. **CLI Version Support**: Running `toron -v` or `toron --version` must display full build metadata and exit cleanly.
5. **Installer & Shell Integration**: `install.sh` and `install.bat` must dynamically read version information from the root `VERSION` file.
6. **API Consistency**: All internal APIs (`/internal/api/status`, `/api/status`) must return the central version from `pkg/version`.
