# ADR-008 - Integration Mapping of Proxy Routes to Dummy Web Services

## Context

To demonstrate and validate all routing capabilities (header-based matching, path prefix matching, single-target proxying, and round-robin load balancing) out of the box, `config.yaml` must map each proxy route pattern to dummy services running on ports 9001–9010.

## Decision

Assign dummy service ports to proxy routes as follows:

| Route Prefix | Headers Condition | Algorithm | Target Port(s) | Description |
|---|---|---|---|---|
| `/api` | `X-Version: v2` | `round_robin` | 9001, 9002, 9003 | Header routing v2 with 3-node load balancing |
| `/api` | `X-Version: v1` | - | 9004 | Header routing v1 with single target |
| `/services/cluster` | - | `round_robin` | 9005, 9006, 9007 | Path routing with 3-node load balancing |
| `/services/auth` | - | - | 9008 | Path routing with single target |
| `/services/analytics` | - | `round_robin` | 9009, 9010 | Path routing with 2-node load balancing |

## Consequences

- **Positive**: 100% of dummy service ports (9001–9010) and all proxy routing methods are active and testable from `config.yaml`.
- **Negative**: Requires dummy services running on ports 9001–9010 for backend proxy responses.
