# TC-010 - Header-Based Routing and API Versioning Verification

## Description

Verify that requests with matching HTTP headers (`X-Version: v2`) route to designated handlers or upstream targets, while requests missing the header fall back to default routes.

## Preconditions

- Router configured with:
  - `GET /api` with `X-Version: v2` -> returns `"v2 API"`
  - `GET /api` (default) -> returns `"v1 API"`
  - Proxy route prefix `/service` with `X-Env: staging` -> `http://localhost:9092`

## Test Data

- Request `GET /api` with header `X-Version: v2`.
- Request `GET /api` with no headers.
- Request `GET /service/users` with `X-Env: staging`.

## Steps

1. Issue GET `/api` with `X-Version: v2` -> Verify response body is `"v2 API"`.
2. Issue GET `/api` with no header -> Verify response body is `"v1 API"`.
3. Issue GET `/service/users` with `X-Env: staging` -> Verify routed to staging upstream.

## Expected Results

- Router correctly matches and prioritizes header-conditional routes.

## Acceptance Criteria

- All unit and integration tests for header routing pass.

## Rationale

Ensures header-based routing accuracy.

## Constraints

- Standard unit tests in `pkg/router`.
