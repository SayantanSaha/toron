# ADR-019 - WebSocket Upgrade and Bi-directional Proxy Tunneling Architecture

## Context

WebSockets require upgrading an existing HTTP/1.1 TCP connection (`101 Switching Protocols`) into a persistent, full-duplex binary/text framing protocol stream. The gateway server must handle upgrading local endpoints as well as proxying full-duplex streams to upstream servers.

## Decision

1. **WebSocket Handshake Inspection**:
   - `httpparser.Request.IsWebSocketUpgrade()` checks `Connection: upgrade` and `Upgrade: websocket` headers.
2. **Reverse Proxy Tunneling**:
   - For upstream routes with WebSocket upgrade requests, `ReverseProxy` dials a raw TCP connection (`net.DialTimeout`) to the target host.
   - Forwards the HTTP upgrade request headers to the target upstream.
   - Parses the target's initial HTTP status line and response headers.
   - If upstream responds with `101 Switching Protocols`, `ReverseProxy` serializes the `101` response back to the client socket, marks `Response.Upgraded = true`, and returns `RawConn`.
3. **Server TCP Socket Hijacking & Bi-directional Copying**:
   - `pkg/server.handleConn` detects `res.Upgraded`.
   - Disables socket read/write deadlines (`conn.SetDeadline(time.Time{})`).
   - Launches two concurrent goroutines (`io.Copy(upstreamConn, clientConn)` and `io.Copy(clientConn, upstreamConn)`).
   - Once either socket closes or returns `io.EOF`, both sockets are closed gracefully and `handleConn` exits cleanly.

## Consequences

- **Positive**: Clean HTTP/1.1 connection hijacking with minimal overhead, compatible with standard `net.Conn`, works over plain TCP and TLS listeners.
- **Negative**: Persistent WebSocket connections hold open worker sockets until client or server terminates the session.
