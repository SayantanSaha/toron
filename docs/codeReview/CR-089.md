## Description

This code review evaluates the changes implemented under [`TASK-114`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-114.md) and [`TASK-115`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-115.md) satisfying [`REQ-093`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-093.md), architectural decision [`ADR-088`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-088.md), and test specification [`TC-093`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-093.md).

The change refactors the Toron WAF middleware to eliminate redundant double-invocations of [`ExtractClientIP`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L181-L207) on the request hot path, removes the vulnerable `if ip != nil` guard that previously allowed requests with unidentifiable client IP to bypass allowlists fail-open, enforces strict fail-closed 403 Forbidden rejection when incoming client IP cannot be determined under an active allowlist, and establishes comprehensive unit and end-to-end automated test suites.

## Findings

### Finding 1: Elimination of Redundant Double-Invocation of `ExtractClientIP`

- **Severity**: Informational
- **Location**: [`pkg/waf/middleware.go:58-67`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go#L58-L67)
- **Related Artifact**: [`REQ-093-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-093.md#L102-L109), [`ADR-088 Section 3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-088.md#L131-L153), [`TASK-114 Step 1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-114.md#L62-L75)
- **Description**: Previously, [`NewWAFMiddleware`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go#L19-L195) invoked `ExtractClientIP(req, tp)` twice sequentially on the request hot path: first to format string telemetry `clientIP`, and immediately again inside the IP access check block.
- **Verification**:
  - In the updated code, `clientNetIP := ExtractClientIP(req, tp)` is executed exactly once per request.
  - The parsed `clientNetIP` is stored in a local stack variable.
  - `clientIP` string conversion occurs once (`if clientNetIP != nil { clientIP = clientNetIP.String() }`).
  - `clientNetIP` is passed directly into `acl.CheckIP(clientNetIP)`.
  - `clientIP` string is reused across all subsequent audit logging and metric recording points.
  - Ripgrep analysis confirms exactly one call to `ExtractClientIP` in [`pkg/waf/middleware.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go).
- **Verdict**: Verified and Compliant.

### Finding 2: Unconditional Fail-Closed IP Access Control Enforcement under Active Allowlist

- **Severity**: Informational
- **Location**: [`pkg/waf/middleware.go:65-91`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go#L65-L91), [`pkg/waf/ip_acl.go:81-86`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L81-L86)
- **Related Artifact**: [`REQ-093-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-093.md#L83-L95), [`ADR-088 Section 1 & 4`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-088.md#L88-L120), [`TASK-114 Step 2 & 3`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-114.md#L76-L96), [`SEC-32`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L439-L447)
- **Description**: The vulnerable guard `if ip := ExtractClientIP(req, tp); ip != nil` was completely removed. Now, whenever `acl := engine.IPAccessList(); acl != nil && acl.HasRules()` evaluates to true, `acl.CheckIP(clientNetIP)` is evaluated unconditionally.
- **Verification**:
  - When `clientNetIP == nil` and an allowlist (`allowedSubnets` or `allowedIPs`) is configured:
    - `acl.CheckIP(nil)` returns `allowed: false` with the exact reason `"client IP could not be determined and allowed IP list is enforced"`.
    - The middleware resets the response body, sets `Content-Type: application/json`, sets HTTP status `403 Forbidden`, and writes the standard payload `{"error":"Forbidden","message":"client IP could not be determined and allowed IP list is enforced"}`.
    - Execution is terminated immediately without calling `next(req, res)`.
  - Increments `metrics.DefaultRegistry.RecordWAFBlocked("ip_acl", req.Path)`.
- **Verdict**: Verified and Compliant.

### Finding 3: Preservation of Fail-Open Pass-Through for Denylist-Only Configurations

- **Severity**: Informational
- **Location**: [`pkg/waf/ip_acl.go:81-86`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L81-L86), [`pkg/waf/middleware.go:66-91`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware.go#L66-L91)
- **Related Artifact**: [`REQ-093-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-093.md#L96-L101), [`ADR-088 Section 2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-088.md#L122-L130), [`TASK-114 Step 2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-114.md#L81-L82)
- **Description**: When no allowlist is configured (only denylists or no rules), unidentifiable client IP (`ip == nil`) evaluates to `allowed: true, reason: ""` in `CheckIP`.
- **Verification**:
  - In [`pkg/waf/ip_acl.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L81-L86):
    ```go
    if ip == nil {
        if len(acl.allowedSubnets) > 0 || len(acl.allowedIPs) > 0 {
            return false, "client IP could not be determined and allowed IP list is enforced"
        }
        return true, ""
    }
    ```
  - Unit test `TestIPAccessList_CheckIP_NilIP_DenylistOnly` and middleware test `TestWAFMiddleware_NilClientIP_DenylistOnly` confirm that requests with unresolvable client IP pass through without being blocked, preserving operational availability for internal harnesses or intermediate proxies when denylists only are active.
- **Verdict**: Verified and Compliant.

### Finding 4: Robust Defense-in-Depth Against Malformed IP Headers

- **Severity**: Informational
- **Location**: [`pkg/waf/middleware_test.go:402-483`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/middleware_test.go#L402-L483)

- **Verification**:
  - Middleware test `TestWAFMiddleware_MalformedClientIP_AllowlistEnforced` systematically tests all 9 malformed input variants.
  - Every scenario asserts that `ExtractClientIP` returns `nil`, and the middleware responds with HTTP `403 Forbidden` and the expected JSON message, halting downstream execution with 0 panics.
- **Verdict**: Verified and Compliant.

## Positive Observations

1. **Defensive Security by Default**:
   Enforcing fail-closed semantics on allowlists eliminates any possibility that an attacker can bypass perimeter whitelists by intentionally withholding or corrupting network address headers.
2. **Strict Preservation of Denylist Semantics**:
   The engine correctly distinguishes between allowlist (positive security model: fail-closed) and denylist (negative security model: fail-open for unidentified addresses), avoiding severe false-positive outages for synthetic tests or intermediate proxy traffic.
3. **Optimized Hot-Path Request Execution**:
   Consolidating client IP extraction into a single call at the start of the middleware closure removes duplicate parsing and eliminates unnecessary CPU cycles on high-throughput routes.
4. **Comprehensive Test Suite**:
   The automated tests cover edge cases thoroughly—including corrupt IPv6 colons, non-numeric ports, bare hostnames, nil receivers, metrics registry validation, and concurrency stress testing under the Go race detector.
5. **Zero External Dependencies**:
   The implementation adheres strictly to the Go standard library, maintaining the project's zero-dependency footprint.
