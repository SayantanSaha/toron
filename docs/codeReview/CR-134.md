# CR-134 - Code Review of Host Port Disambiguation in Route Matching and Cache Key Authority Derivation (RFC 9111 Shared Cache Session Boundary Isolation)

## 1. Executive Summary & Review Scope

### 1.1 Executive Summary

A comprehensive, senior-level code quality, correctness, performance, and concurrency review was conducted on the architectural and code changes implemented for [`REQ-134`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-134.md) and [`TASK-157`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-157.md), guided by architectural decisions in [`ADR-134`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-134.md), evaluated from a security perspective in [`SR-134`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-134.md), and verified against the 12 formal test specifications in [`TC-134`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-134.md).

Historically, under [`ADR-015`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-015.md) (*Host Header Domain-Based Virtual Host Routing*), Toron normalized incoming HTTP `Host` headers by unconditionally stripping port numbers via `strings.Index(h, ":")` in [`extractHost`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go). While designed to facilitate domain-level virtual host matching (e.g. allowing `example.com:8080` to match a route registered for `example.com`), reusing this port-stripped host string for in-memory cache key derivation in [`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go) created a critical vulnerability ([CWE-524](https://cwe.mitre.org/data/definitions/524.html)):
- In multi-tenant edge deployments, Kubernetes ingress clusters, and multi-port gateway architectures where distinct services share the same hostname or IP across different network ports (e.g., `service.internal:80` for public catalog listings vs. `service.internal:8080` for restricted administration dashboards), requests to both services collapsed to the identical cache key: `GET:service.internal:/data`.
- An unauthenticated client querying the public port could receive cached administrative payloads from the private port, violating RFC 9110 §4.2 and RFC 9111 §2.
- In `pkg/router/router.go`, naive port stripping rendered explicit port-specific virtual host routes (e.g. `routeHost = "service.internal:8080"`) permanently unreachable, while colon splitting corrupted bracketed IPv6 literals (e.g. `[::1]:8080` was truncated to `"["`).
- Prior documentation ambiguously characterized Toron's caching controls as an autonomous defense against Web Cache Deception (WCD; Gil, 2017), obscuring the RFC 9111 Shared Responsibility Model required between edge transparent proxies and upstream application frameworks.

[`TASK-157`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-157.md) establishes a **Decoupled Dual-Track Processing Architecture**:
1. **Dedicated Cache Authority Extraction (`extractCacheHostPort`)**: In [`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go), authority derivation incorporates explicit ports, trims whitespace, normalizes domain names to lowercase, and safely parses bracketed IPv6 literals (`[::1]:8080`), generating RFC 9111-compliant primary cache keys (`Method:HostPort:URI`).
2. **Disambiguated Route Table Matching (`headersAndHostMatch`)**: In [`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go), route matching distinguishes domain-only wildcard-port routes (`example.com`) from explicit port-qualified routes (`example.com:8080`), enforcing a strict 4-tier precedence hierarchy across exact route maps and specificity sorting across prefix routes.
3. **Hardened IPv6 Sanitization**: In [`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go), `extractHost` is hardened to safely isolate bracketed IPv6 literals (`[::1]:8080` -> `[::1]`), eliminating string corruption.
4. **RFC 9111 Shared Cache Session Boundary Isolation**: Verified absolute protocol isolation: Authorization refusal (RFC 9111 §3.5), dual-stage `Set-Cookie`/`Set-Cookie2` stripping (RFC 9111 §8, CWE-384), directive enforcement (`private`, `no-store`, `no-cache`), and SSE streaming exemptions ([`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md), [`ADR-128`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md)).

### 3.1 `extractCacheHostPort` Implementation ([`pkg/router/cache.go:327-370`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L327-L370))

#### 3.1.1 Function Specification & Correctness
The dedicated authority extraction function implements the algorithmic requirements of ADR-134 §2.2:
```go
func extractCacheHostPort(req *httpparser.Request) string {
    if req == nil {
        return ""
    }
    h := req.Header.Get("Host")
    if h == "" {
        return ""
    }
    h = strings.TrimSpace(h)
    if h == "" {
        return ""
    }

    // Handle bracketed IPv6 literals: [fe80::1] or [::1]:8080
    if strings.HasPrefix(h, "[") {
        closeBracket := strings.Index(h, "]")
        if closeBracket != -1 {
            ipv6 := strings.ToLower(strings.TrimSpace(h[1:closeBracket]))
            normalizedHost := "[" + ipv6 + "]"
            rest := strings.TrimSpace(h[closeBracket+1:])
            if strings.HasPrefix(rest, ":") {
                port := strings.TrimSpace(rest[1:])
                if port != "" {
                    return normalizedHost + ":" + port
                }
            }
            return normalizedHost
        }
        return strings.ToLower(h)
    }

    // Handle IPv4 addresses and standard hostnames
    colonIdx := strings.LastIndex(h, ":")
    if colonIdx != -1 {
        host := strings.ToLower(strings.TrimSpace(h[:colonIdx]))
        port := strings.TrimSpace(h[colonIdx+1:])
        if port != "" {
            return host + ":" + port
        }
        return host
    }

    return strings.ToLower(h)
}
```

#### 3.1.2 Code Analysis:
1. **Nil & Empty Guards**: Properly handles `req == nil`, missing `Host` headers, and whitespace-only `Host` values, returning `""`. For HTTP/1.0 hostless requests, the cache key safely becomes `Method::URI`.
2. **Whitespace Trimming**: Leading and trailing ASCII spaces and tabs are stripped via `strings.TrimSpace`. Internal whitespace around colons (e.g. `"api.toron.local : 9090"`) is handled cleanly via `strings.TrimSpace` on both host and port substrings.
3. **Bracketed IPv6 Literal Parsing**:
   - Accurately checks `strings.HasPrefix(h, "[")` and finds matching `]`.
   - Normalizes the internal IPv6 hexadecimal address to lowercase (`[2001:0DB8::1]` -> `[2001:0db8::1]`).
   - Parses the remainder following the closing bracket. If it begins with `:`, extracts the port.
   - Internal colons in IPv6 addresses never collide with or corrupt the trailing port delimiter.
   - Malformed IPv6 inputs (unclosed `[`) safely fall back to lowercase without index panics.
4. **Standard Hostname & IPv4 Port Preservation**:
   - Uses `strings.LastIndex(h, ":")` to isolate the trailing port.
   - Preserves the explicit port number (`example.com:8080` -> `"example.com:8080"`).
   - Trailing colons with empty port strings (`example.com:`) safely strip the dangling colon and return `"example.com"`.
   - Hostnames without ports return the normalized lowercase hostname.

### 3.3 Disambiguated `headersAndHostMatch` & Port Detection ([`pkg/router/router.go:1002-1077`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L1002-L1077))

#### 3.3.1 Explicit Port Detection Helper (`hasExplicitPort`)
```go
func hasExplicitPort(host string) bool {
    host = strings.TrimSpace(host)
    if strings.HasPrefix(host, "[") {
        idx := strings.Index(host, "]")
        return idx != -1 && strings.Contains(host[idx+1:], ":")
    }
    return strings.Contains(host, ":")
}
```
- Differentiates domain-only host rules (`example.com`, `[::1]`) from port-qualified route rules (`example.com:8080`, `[::1]:8080`).
- For bracketed IPv6, ensures colons inside the brackets do not trigger false positive port detection.

#### 3.3.2 Dual-Mode Host Matching
```go
func headersAndHostMatch(reqHost string, req *httpparser.Request, routeHost string, expectedHeaders map[string]string) bool {
    if routeHost != "" {
        cleanRouteHost := strings.ToLower(strings.TrimSpace(routeHost))
        if hasExplicitPort(cleanRouteHost) {
            // Port-specific route: must match full incoming authority (host and port)
            reqAuthority := extractFullHostPort(req)
            if reqAuthority != cleanRouteHost {
                return false
            }
        } else {
            // Domain-only route: matches port-stripped reqHost (wildcard port)
            if reqHost != cleanRouteHost {
                return false
            }
        }
    }
    for k, expectedVal := range expectedHeaders {
        actualVal := req.Header.Get(k)
        if actualVal != expectedVal {
            return false
        }
    }
    return true
}
```
- **Dual-Mode Behavior**:
  1. *Port-Specific Route* (`example.com:8080`): Matches if and only if the full incoming authority (`extractFullHostPort(req)`) equals `cleanRouteHost`. Requests to port 8443 or omitting the port are strictly rejected.
  2. *Domain-Only Route* (`example.com`): Compares against port-stripped `reqHost`, matching any incoming port (`example.com`, `example.com:80`, `example.com:8080`) as a wildcard port.
- **Header Matching**: Preserved unchanged; all configured key-value pairs must match the request headers.

### 3.4 Precedence Hierarchy & Specificity Sorting

#### 3.4.1 Exact Route Map Precedence ([`pkg/router/router.go:848-880`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L848-L880))
During this review, a subtle route-shadowing bug was identified and resolved (see Finding 1). In `ServeHTTP`, candidate exact route entries are evaluated in strict 4-tier precedence:
1. **Tier 1 (Explicit Port Routes)**: Scans entries where `entries[i].host != "" && hasExplicitPort(entries[i].host)`. If client port matches, dispatches immediately.
2. **Tier 2 (Domain-Only Routes with Host)**: Scans entries where `entries[i].host != "" && !hasExplicitPort(entries[i].host)`. Matches any port on the registered domain.
3. **Tier 3 (Header-Constrained Wildcard Routes)**: Scans entries where `entries[i].host == "" && len(entries[i].headers) > 0`. Evaluates header criteria on hostless routes.
4. **Tier 4 (Wildcard Fallback Route)**: Falls back to `fallbackEntry` (`host == ""` and no headers, e.g. the default `/metrics` endpoint).

#### 3.4.2 Prefix Route Specificity Sorting ([`pkg/router/router.go:216-235`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L216-L235))
In `comparePrefixRoutes` and `comparePrefixRouteSpecs`:
- **Tier 1**: Prefix Length (Longest prefix first).
- **Tier 2**: Host Specificity:
  - Route with host sorts before route without host.
  - If both have hosts, an explicit port route (`hasExplicitPort(host) == true`) sorts **before** a domain-only route (`hasExplicitPort(host) == false`).
- **Tier 3**: Header Specificity (More headers before fewer headers).
- **Tier 4**: Method Specificity (Explicit method before any-method).
- **Tier 5**: Deterministic Tie-Breaking (Alphabetical).

### 3.5 Hardened `extractHost` IPv6 Safety ([`pkg/router/router.go:1037-1052`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L1037-L1052))

```go
func extractHost(req *httpparser.Request) string {
    h := req.Header.Get("Host")
    if h == "" {
        return ""
    }
    h = strings.TrimSpace(h)
    if strings.HasPrefix(h, "[") {
        if idx := strings.Index(h, "]"); idx != -1 {
            return strings.ToLower(h[:idx+1])
        }
    }
    if idx := strings.LastIndex(h, ":"); idx != -1 {
        h = h[:idx]
    }
    return strings.ToLower(strings.TrimSpace(h))
}
```
- Hardened to inspect `strings.HasPrefix(h, "[")` and locate `]`.
- For `[::1]:8080`, returns `"[::1]"` rather than truncating at the first colon into `"["`.
- For standard hostnames, uses `strings.LastIndex` to cleanly strip the port.

### 3.7 RFC 9111 Shared Cache Session Boundary Isolation

The caching middleware in [`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go) was audited for RFC 9111 protocol boundaries:
1. **Authorization Refusal (RFC 9111 §3.5)**:
   In lines 209 and 269: requests bearing `Authorization` headers are refused from cache lookup unless the cached response is `cached.Public`, and refused from storage unless the origin emitted `Cache-Control: public`.
2. **Dual-Stage `Set-Cookie` Stripping (RFC 9111 §8, CWE-384)**:
   - *Stage 1 (Storage Purge)*: Lines 297–307 clone headers while explicitly omitting `Set-Cookie` and `Set-Cookie2`.
   - *Stage 2 (Delivery Purge)*: Lines 217–218 explicitly call `res.Header.Del("Set-Cookie")` and `res.Header.Del("Set-Cookie2")` before serving a cache hit.

## 5. Findings & Architectural Observations

### Finding 1: Exact Route Precedence & Wildcard Route Shadowing Neutralization
- **Severity**: Medium (Resolved during Review)
- **Location**: [`pkg/router/router.go:861-880`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L861-L880)
- **Related Artifact**: [`ADR-134 §2.3.5`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-134.md#L444-L450)
- **Description**: In the initial implementation of exact route dispatching in `ServeHTTP`, Tier 2 evaluated candidates with:
  ```go
  if entries[i].host == "" || !hasExplicitPort(entries[i].host) {
      if headersAndHostMatch(reqHost, req, entries[i].host, entries[i].headers) {
          targetHandler = entries[i].handler
          break
      }
  }
  ```
  Because `router.New()` registers a default wildcard route for `/metrics` (`host == ""` and no headers) as `entries[0]`, any subsequently registered domain-specific route for `/metrics` (e.g. `r.GETHost("api.toron.local", "/metrics", ...)`) was shadowed because `entries[0].host == ""` satisfied Tier 2 immediately.
- **Resolution**: Refined exact route dispatching into four distinct tiers:
  - **Tier 1**: Explicit port routes (`entries[i].host != "" && hasExplicitPort(...)`)
  - **Tier 2**: Domain-only routes with host specified (`entries[i].host != "" && !hasExplicitPort(...)`)
  - **Tier 3**: Header-constrained wildcard routes (`entries[i].host == "" && len(entries[i].headers) > 0`)
  - **Tier 4**: Wildcard fallback route (`fallbackEntry`, no host, no headers)
- **Impact**: Domain-specific routes now consistently take precedence over wildcard routes regardless of registration order. Verified by `TestRouter_HostPortDisambiguation`.
