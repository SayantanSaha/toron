# TC-095 - Verification of Composite Route Key Grouping, Multi-Replica Target Aggregation, and Specificity-Based Route Lifecycle in OCI Discovery Engine

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's OCI container auto-discovery engine ([`pkg/discovery`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery)) and core routing engine ([`pkg/router`](file:///Users/sneha/Developer/toron-research/toron/pkg/router)) enforce a **composite-key grouped, multi-replica aggregated, specificity-ordered, and atomically reconciled route lifecycle**.

This test specification validates the complete architectural remediation of critical security vulnerability [`SEC-34`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L465-L473) and security review finding [`SR-091 Finding 4`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L154-L171) ([CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html), [CWE-284: Improper Access Control](https://cwe.mitre.org/data/definitions/284.html), [CWE-662: Improper Synchronization](https://cwe.mitre.org/data/definitions/662.html), [CWE-775: Resource Leak](https://cwe.mitre.org/data/definitions/775.html)), confirming that:

1. **Model & Label Parsing Expressiveness**: Discovered routes accurately extract HTTP method constraints (`toron.method`), individual header constraints (`toron.header.<Name>`), and grouped header constraints (`toron.headers` in both CSV and JSON formats) with robust whitespace trimming, uppercase normalization, override precedence, and panic-free fallback handling.
2. **Deterministic Composite Route Key**: Routes are partitioned using a 4-dimensional tuple $\text{CompositeRouteKey} = (\text{Host}, \text{Prefix}, \text{Method}, \text{CanonicalHeaders})$, where `CanonicalHeaders` sorts header keys alphabetically to eliminate Go map iteration non-determinism across reconciliation passes.
3. **Multi-Replica Target Aggregation & Fair Load Balancing**: All container replicas sharing an identical `CompositeRouteKey` are consolidated into exactly **one** multi-target `PrefixRouteSpec` configured with Toron's `RoundRobinBalancer`. Incoming traffic is distributed proportionally ($\approx 1/M$ per replica), completely eliminating single-replica starvation and horizontal scaling collapse.
4. **Non-Destructive Partial Scale-Down (Zero-Downtime Guarantee)**: Terminating or stopping 1 replica of an $M$-replica service ($M \ge 2$) removes only that container from the target pool, atomically updating the router via [`ReplacePrefixRoutesBySource("oci-discovery", desiredSpecs)`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L307-L350). Ingress traffic continues forwarding to the remaining $M-1$ healthy replicas with **zero HTTP 404 errors**, zero connection drops, and zero transient downtime.
5. **Distinct Variant Separation (Canary vs Baseline Isolation)**: Containers sharing host and prefix but differing in header or method constraints produce distinct `CompositeRouteKey`s and segregated reverse proxy target pools. Canary traffic (`X-Version: canary`) dispatches exclusively to canary instances, while standard traffic routes to baseline instances without traffic bleeding or cross-talk.
6. **ADR-005 Specificity Ordering & Shadowing Prevention**: Prefix routes are evaluated in strict specificity order (Longest prefix $\to$ Host specificity $\to$ Header constraint count $\to$ Method constraint $\to$ Deterministic tie-break). Specific canary routes are guaranteed to match ahead of generic fallback routes regardless of container discovery arrival or registration order.
7. **Declarative Method Matching Support**: [`PrefixRouteSpec`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L172-L179) includes a first-class `Method string` field. Ingress requests matching path and host but failing method constraint return HTTP `405 Method Not Allowed` or cleanly proceed to method-compatible fallback routes.
8. **Clean Reverse Proxy Teardown**: Evicting routes during scale-down, container removal, or manager shutdown invokes [`proxy.Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L596-L600), immediately halting active health check tickers (`StopActiveHealthCheck`) and closing idle TCP connection sockets, eliminating memory, goroutine, and file descriptor leaks (`EMFILE`).
9. **Zero Third-Party Dependencies Invariant**: All container label parsing, composite key generation, target aggregation, and route specificity sorting strictly use Go standard library packages (`sync`, `net/http`, `net/url`, `sort`, `strings`, `encoding/json`).
10. **High-Concurrency Race Safety**: Concurrent execution of high-volume HTTP client traffic through `router.ServeHTTP` while the OCI discovery manager churns container lifecycle events (`start`, `stop`, `die`, `resync`) operates with 100% thread safety and zero data races under `go test -race ./pkg/discovery/... ./pkg/router/...`.

- **Objective**: Verify that [`ParseContainerLabels`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery/parser.go#L22) extracts `toron.method`, `toron.header.<Name>`, and `toron.headers` (both CSV and JSON formats) into the extended [`DiscoveredRoute`](file:///Users/sneha/Developer/toron-research/toron/pkg/discovery/provider.go) model. - **Traceability**: [`REQ-095-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L117-L122), [`REQ-095-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L123-L132), [`ADR-095 §1`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md#L118-L184), [`TASK-118 §1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-118.md#L134-L186).

### TC-095-02: CompositeRouteKey Generation & Deterministic Header Canonicalization

- **Objective**: Verify that `CompositeRouteKey` constructs a deterministic 4-tuple $(\text{Host}, \text{Prefix}, \text{Method}, \text{CanonicalHeaders})$, where `CanonicalHeaders` sorts header keys alphabetically, guaranteeing identical composite key strings across repeated executions regardless of Go's randomized `map[string]string` iteration order.
- **Traceability**: [`REQ-095-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-095.md#L133-L147), [`ADR-095 §2`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-095.md#L185-L232), [`TASK-118 §2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-118.md#L188-L237).
- **Target Function**: `TestDiscoveryManager_CompositeRouteKeyCanonicalization(t *testing.T)` in `pkg/discovery/discovery_test.go`.
- **Preconditions**:
  - `CompositeRouteKey` struct and canonicalization helper defined in `pkg/discovery/manager.go`.
- **Action & Test Steps**:
  1. **Deterministic Canonicalization Test**:
     - Create a headers map with 5 unsorted pairs:
       ```go
       headers := map[string]string{
           "Z-Header": "val-z",
           "A-Header": "val-a",
           "M-Header": "val-m",
           "X-Env":    "prod",
           "B-Tier":   "gold",
       }
       ```
     - Expected canonical representation:
       `"A-Header=val-a&B-Tier=gold&M-Header=val-m&X-Env=prod&Z-Header=val-z"`
     - Execute canonicalization 100 times in a tight loop.
     - Verify that every single iteration produces the exact same canonical string.
  2. **Empty / Nil Headers Handling**:
     - Test with `headers = nil` and `headers = map[string]string{}`.
     - Assert that `CanonicalHeaders` is `""`.
  3. **CompositeRouteKey Normalization**:
     - Input route: `Host: "  API.Example.COM  "`, `Prefix: "/v1/data/"`, `Method: "  post "`
     - Generated Key:
       - `Host`: `"api.example.com"` (lowercased, trimmed)
       - `Prefix`: `"/v1/data"` (leading slash preserved, trailing slash trimmed)
       - `Method`: `"POST"` (uppercased, trimmed)
  4. **Key Inequality Verification**:
     - Assert that differing any single component (`Host`, `Prefix`, `Method`, or `CanonicalHeaders`) produces distinct composite keys that do not collide in a Go map (`map[CompositeRouteKey]struct{}`).
- **Verifiable Assertions**:
  1. `CanonicalHeaders` sorts keys alphabetically with zero randomness across 100 iterations.
  2. Map iteration non-determinism in Go is 100% eliminated.
  3. Normalization functions correctly handle leading/trailing slashes, whitespace, and letter casing.
  4. Composite keys differentiate variants cleanly without hash collisions.

- **Preconditions**:

- **Action & Test Steps**:

       - `toron.prefix: "/v1"`
       - `toron.method: "GET"`
       - `toron.header.X-Region: "us-east"`
     - Configure C1 target to `127.0.0.1:18001`, C2 to `127.0.0.1:18002`, C3 to `127.0.0.1:18003`.
     - Register all 3 containers with `discovery.Manager`.
  2. **Specification Inspection**:
     - Trigger route reconciliation.
     - Inspect routes in `router`:
       ```go
       routes := r.GetPrefixRoutes()
       ```
     - Assert that exactly **one** prefix route exists for source `"oci-discovery"` matching `host: "api.example.com"`, `prefix: "/v1"`.
     - Confirm that 3 separate routes were NOT created.
  3. **Deduplication Verification**:
     - Simulate a duplicate container C4 reporting the same target URL as C1 (`127.0.0.1:18001`).
     - Trigger reconciliation: assert target count remains exactly 3 (`Targets` deduplicated).
     - Verify `Targets` slice is sorted in ascending alphabetical order.
  4. **Traffic Distribution (Load Balancing)**:

       ```go
       counts := make(map[string]int)
       ```

     - Assert `counts["server-2"] == 10`.
     - Assert `counts["server-3"] == 10`.
- **Verifiable Assertions**:
  1. Multiple container replicas sharing a `CompositeRouteKey` aggregate into exactly 1 prefix route.
  2. Target URLs are deduplicated and sorted deterministically.
  3. `RoundRobinBalancer` distributes requests equally across all 3 backend replicas ($10/30$ each).
  4. Single-instance starvation (where replica 1 received 100% of traffic) is completely eliminated.

### TC-095-04: Non-Destructive Partial Replica Scale-Down (Zero-Downtime Guarantee)

- **Objective**: Verify that when 1 replica of an $M$-replica service ($M \ge 2$) is stopped or terminated, the discovery manager recalculates the surviving $M-1$ replicas and atomically replaces the route via `ReplacePrefixRoutesBySource("oci-discovery", desiredSpecs)` with **zero HTTP 404 errors**, zero connection drops, and zero downtime for traffic served by surviving replicas.

## 5. Security, Performance & Architectural Invariants

1. **Zero-Downtime Scale-Down Invariant (CWE-662 & CWE-284 Remediation)**:
   Terminating, crashing, or restarting an individual container replica MUST NOT wipe or interrupt ingress routing for surviving healthy replicas of that service. Ingress requests MUST continue forwarding to surviving replicas with zero HTTP 404 errors.
2. **Horizontal Scaling & Fair Balancing Invariant (CWE-400 Remediation)**:
   Multi-replica container services MUST aggregate all healthy replica target URLs into a single multi-target reverse proxy configured with `RoundRobinBalancer`. Sequential client requests MUST be distributed evenly ($\approx 1/M$ per replica), completely eliminating single-replica overload crashes.
3. **Canary Variant Isolation Invariant**:
   Containers serving identical host and prefix that differ in HTTP headers (`toron.header.<Name>`, `toron.headers`) or method (`toron.method`) MUST produce distinct `CompositeRouteKey`s and separate `PrefixRouteSpec`s. Target pools MUST remain strictly segregated to prevent pre-release canary code from leaking to normal users.
4. **ADR-005 Specificity Ordering & Route Shadowing Prevention**:
   Prefix routes MUST be evaluated in descending order of specificity:
   $$\text{Prefix Length} \succ \text{Host Specificity} \succ \text{Header Count} \succ \text{Method Specificity} \succ \text{Deterministic Tie-Break}$$
   A generic fallback route CANNOT shadow a more specific or Canary route, regardless of container discovery arrival or registration order.
5. **Deterministic Header Canonicalization**:
   Canonical header string generation MUST sort header keys alphabetically (`sort.Strings`) prior to serialization (`k1=v1&k2=v2`), eliminating Go's randomized map iteration non-determinism across reconciliation cycles.
6. **Resource Teardown Invariant (CWE-775 Remediation)**:
   Every route eviction or manager shutdown MUST invoke `Close()` on evicted reverse proxies, terminating background health check ticker goroutines (`StopActiveHealthCheck`) and closing idle TCP connection sockets, eliminating memory, goroutine, and `EMFILE` socket leaks.
7. **Source-Tagged Isolation Invariant**:
   Reconciliations performed by the OCI discovery manager (`source: "oci-discovery"`) MUST NOT alter, reorder, or disrupt prefix routes belonging to other sources (`"k8s-ingress"`, `"config"`, `"static"`).
8. **Zero Third-Party Dependencies Invariant**:
   All routing, discovery, label parsing, composite key grouping, and load balancing algorithms MUST strictly utilize Go standard library packages (`sync`, `net/http`, `net/url`, `sort`, `strings`, `encoding/json`).
9. **Thread Safety & Race Freedom**:
   All router and manager state mutations MUST be 100% data-race-free under `go test -race ./pkg/discovery/... ./pkg/router/...`.
