# CR-124 - Code Review of Streaming Response Middleware Exemptions and RFC 7234 Origin Cache-Control Enforcement

## 1. Executive Summary

A comprehensive code review was conducted on the implementation of [`TASK-151`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md), addressing [`REQ-128`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md), [`ADR-128`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md), and [`TC-128`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-128.md).

During multi-proxy streaming benchmarks and pipeline audits, two systemic root causes were discovered that corrupted real-time streaming connections (specifically Server-Sent Events / SSE, `text/event-stream`) and dynamic HTTP responses:
1. **RFC 7234 §5.2.2.2 Violation & Cache Freezing**: In [`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go), while `no-store` and `private` were inspected, `resCC.NoCache` was ignored. When an upstream origin returned `Cache-Control: no-cache` without `max-age`, Toron defaulted to `DefaultTTL = 60s`, cloned the initial body snapshot into `ResponseCache`, and served static dead snapshots (`X-Cache: HIT`) to subsequent clients, resulting in Web Cache Deception ([CWE-524](https://cwe.mitre.org/data/definitions/524.html)). Furthermore, `text/event-stream` and `X-Accel-Buffering: no` responses were captured into cache memory.
2. **Transparent Compression Event Starvation**: In [`pkg/router/compression.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go), `DefaultCompressionConfig.Types` included wildcard `"text/"`, matching `text/event-stream`. When clients sent `Accept-Encoding: gzip, deflate, br, zstd`, the compression middleware buffered live streams until connection close, starving clients of real-time events. Furthermore, reverse proxy unbuffered hints (`X-Accel-Buffering: no`) were ignored.
3. **Reverse Proxy `canStream` Disqualification**: On routes with compression or caching enabled, `ReverseProxy` evaluated `canStream = false`, disqualifying SSE feeds from the direct socket streaming fast-path and forcing infinite streaming responses into memory buffers ([CWE-400](https://cwe.mitre.org/data/definitions/400.html)).

[`TASK-151`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md) implements the architectural resolution approved in [`ADR-128`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md):
- Enforces strict RFC 7234 §5.2.2.2 compliance in [`pkg/router/cache.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go): responses with `resCC.NoCache`, `resCC.NoStore`, `resCC.Private`, `text/event-stream`, `X-Accel-Buffering: no`, or `res.StreamBody != nil` unconditionally bypass cache admission, emit `X-Cache: MISS`, omit `Age`, and never allocate cache memory.
- Enforces an early inspection guard in [`pkg/router/compression.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go): responses with `text/event-stream` or `X-Accel-Buffering: no` immediately bypass compressor writer checkout, leaving `Content-Encoding` untouched and preserving raw chunk delivery.
- Refines `canStream` in [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go): streaming MIME and unbuffered responses activate the direct socket fast-path (`canStream = true`) even on routes where compression or caching are globally configured.
- Optimizes header lookup in [`pkg/httpparser/request.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go) via a fast-path switch on canonical rodata strings, guaranteeing zero dynamic heap allocations in header inspection guards.

**Verdict**: **APPROVED** (0 Critical, 0 High, 2 Low findings, 100% test pass rate across all 14 test cases in [`TC-128`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-128.md), zero race conditions under `go test -race`, zero third-party dependencies).

## 3. Findings

### Finding 1: Explicit Grouping Parentheses in `canStream` Compound Boolean Expression

- **Severity**: Low
- **Location**: [`pkg/proxy/proxy.go:1105`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1105)
- **Related Artifact**: [`TASK-151 WP-3.1`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md#L211-L223), [`ADR-128 §2.3`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-128.md#L225-L243)
- **Description**: In [`pkg/proxy/proxy.go:1105`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1105), the streaming eligibility expression is written as:
  ```go
  canStream := p.streamResponse && (!p.routeHasCompression && !p.routeHasCache || isStreamingMIME || isUnbuffered)
  ```
  Under Go operator precedence rules, binary `&&` has precedence level 2 while `||` has precedence level 1. Inside the outer parentheses, `(!p.routeHasCompression && !p.routeHasCache)` binds tighter than the subsequent `|| isStreamingMIME || isUnbuffered`. While the expression executes with 100% mathematical and semantic correctness, human readers can experience cognitive ambiguity regarding whether `&&` or `||` binds to `isStreamingMIME`.
- **Impact**: Zero runtime defect; minor maintainability and readability concern for engineers maintaining the proxy core in future revisions.
- **Recommendation**: Add explicit inner parentheses around the pure proxy check:
  ```go
  canStream := p.streamResponse && ((!p.routeHasCompression && !p.routeHasCache) || isStreamingMIME || isUnbuffered)
  ```

### Finding 2: Inclusion of `"Accept"` / `"accept"` in `canonicalKey` Fast-Path Switch Table

- **Severity**: Low
- **Location**: [`pkg/httpparser/request.go:53-104`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L53-L104)
- **Related Artifact**: [`REQ-128 §3.1`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-128.md#L134-L137), [`TASK-151 §3.2`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-151.md#L324-L325)
- **Description**: In [`pkg/httpparser/request.go:53-104`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L53-L104), `canonicalKey` provides a static rodata switch table for 23 common HTTP headers (`Content-Type`, `X-Accel-Buffering`, `Cache-Control`, `Accept-Encoding`, `Content-Encoding`, `Content-Length`, `Connection`, `Authorization`, `Vary`, `Pragma`, `Host`, `Upgrade`, `Age`, `X-Cache`, etc.). However, the standard HTTP request header `"Accept"` is omitted from the switch table.
- **Impact**: When handlers or reverse proxy routines inspect `req.Header.Get("Accept")` (e.g. checking for `Accept: text/event-stream`), the lookup falls through to `strings.ToLower(s)`, missing the rodata zero-allocation benefit enjoyed by `Accept-Encoding`.
- **Recommendation**: Include `"Accept"` in the fast-path switch:
  ```go
  case "Accept", "accept":
      return "accept"
  ```

## 4. Detailed Review by Architecture & Requirement Area

### 4.1 RFC 7234 §5.2.2.2 Origin `Cache-Control: no-cache` Enforcement (`pkg/router/cache.go`)

- **Audit Target**: Verify that responses containing origin `Cache-Control: no-cache` are strictly excluded from proxy cache admission.
- **Implementation Analysis in [`pkg/router/cache.go:261-265`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L261-L265)**:
  ```go
  // Evaluate response Cache-Control headers (RFC 7234 §5.2.2.2 Enforcement)
  resCC := ParseCacheControl(res.Header.Get("Cache-Control"))
  if resCC.NoStore || resCC.NoCache || resCC.Private {
      return
  }
  ```
- **Technical Observations**:
  1. **Compliance with RFC 7234 §5.2.2.2**: RFC 7234 §5.2.2.2 states: *"The no-cache response directive indicates that the response MUST NOT be used to satisfy a subsequent request without successful validation on the origin server."* Because Toron does not implement conditional background revalidation (conditional GETs with `If-None-Match` or `If-Modified-Since`), treating `no-cache` as an absolute bar to cache storage is strictly compliant and prevents stale cache serving.
  2. **Precedence Over `max-age`**: If an origin emits `Cache-Control: no-cache, max-age=3600`, line 263 returns immediately, completely bypassing line 288 (`ttl = *resCC.MaxAge`). `no-cache` strictly overrides `max-age`, as verified by `TestCache_OriginNoCache_WithMaxAge_Bypass` (`TC-128.2`).
  3. **Zero Heap Allocation**: `res.Header.Get("Cache-Control")` hits the `canonicalKey` rodata fast-path, and `ParseCacheControl` parses directives in-place.

### 4.2 Streaming MIME & Reverse Proxy Directive Cache Exemption

- **Audit Target**: Ensure responses with `Content-Type: text/event-stream` and `X-Accel-Buffering: no` never enter cache storage.
- **Implementation Analysis in [`pkg/router/cache.go:246-250`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L246-L250)**:
  ```go
  // Streaming MIME or unbuffered responses must never be cached (REQ-128)
  if strings.HasPrefix(strings.ToLower(res.Header.Get("Content-Type")), "text/event-stream") || strings.EqualFold(res.Header.Get("X-Accel-Buffering"), "no") {
      return
  }
  ```
- **Technical Observations**:
  1. **Parameterized MIME Handling**: Using `strings.HasPrefix(..., "text/event-stream")` properly accommodates parameterized MIME types such as `text/event-stream; charset=utf-8` without requiring complex media-type parsing.
  2. **Case Insensitivity**: `strings.ToLower` handles uppercase variants such as `TEXT/EVENT-STREAM`. `strings.EqualFold` handles case variations of `X-Accel-Buffering: no`, `No`, and `NO`.
  3. **Short-Circuit Evaluation**: If `text/event-stream` matches, the second clause `strings.EqualFold(res.Header.Get("X-Accel-Buffering"), "no")` is not evaluated, saving CPU cycles.
  4. **Active Stream Exemption**: Active WebSocket-aligned streams (`res.StreamBody != nil`) are already caught at line 242:
     ```go
     if res.StatusCode == http.StatusSwitchingProtocols || res.UpgradedConn != nil || res.StreamBody != nil {
         return
     }
     ```
     Providing layered defense-in-depth even if headers were omitted.

### 4.3 Cache Bypass Response Semantics (`X-Cache: MISS` & `Age` Omission)

- **Audit Target**: Verify that bypassed responses emit `X-Cache: MISS`, omit `Age`, and never clone bodies into RAM.
- **Implementation Analysis in [`pkg/router/cache.go:238-240`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L238-L240)**:
  ```go
  // Execute downstream handler
  next(req, res)

  res.Header.Set("X-Cache", "MISS")
  res.Header.Del("Age")
  ```
- **Technical Observations**:
  1. **Clean Default State**: Every response executing the downstream handler receives `X-Cache: MISS` and has any existing `Age` header explicitly deleted.
  2. **Zero Cache Retention**: When early returns trigger on `no-cache`, `text/event-stream`, or `X-Accel-Buffering: no`, lines 309-320 (`bodySnapshot := make([]byte, res.Body.Len())`, `cache.Set(...)`) are never executed. Cache registry size remains strictly zero (`store.Len() == 0`).
  3. **Mitigation of CWE-524**: Live streaming tokens, trading updates, or private SSE notifications are never captured in shared cache memory, completely mitigating shared cache information exposure.

### 4.4 Transparent Compression Exemption (`pkg/router/compression.go`)

- **Audit Target**: Guarantee that `text/event-stream` and `X-Accel-Buffering: no` bypass compression, eliminating event starvation.
- **Implementation Analysis in [`pkg/router/compression.go:135-139`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go#L135-L139)**:
  ```go
  // Streaming MIME or unbuffered responses must not be compressed (REQ-128)
  if strings.HasPrefix(strings.ToLower(res.Header.Get("Content-Type")), "text/event-stream") || strings.EqualFold(res.Header.Get("X-Accel-Buffering"), "no") {
      return
  }
  ```
- **Technical Observations**:
  1. **Early Guard Placement**: Placed strictly before `res.Body.Len() < cm.config.MinLength`, `Content-Encoding` checks, and `isMIMECompressible`.
  2. **Escaping Wildcard `"text/"`**: In `DefaultCompressionConfig.Types`, `"text/"` matches text assets. The early guard intercepts `text/event-stream` before `isMIMECompressible` can evaluate it as compressible, preventing the stream from being trapped in compression accumulators.
  3. **Zero Pool Contention**: Compressor writers (`cm.gzipPool`, `cm.zstdPool`, `cm.brotliPool`, `cm.deflatePool`) are never acquired, eliminating mutex contention and allocations.
  4. **Payload Integrity**: `Content-Encoding` remains empty and `res.Body` (or `res.StreamBody`) is relayed in raw text format.

### 4.5 Content-Aware Reverse Proxy Fast-Path Activation (`pkg/proxy/proxy.go`)

- **Audit Target**: Ensure reverse proxy activates direct socket streaming (`canStream = true`) for SSE feeds on compression/cache enabled routes.
- **Implementation Analysis in [`pkg/proxy/proxy.go:1102-1106, 1161-1164`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1102-L1164)**:
  ```go
  contentType := strings.ToLower(outResp.Header.Get("Content-Type"))
  isStreamingMIME := strings.HasPrefix(contentType, "text/event-stream")
  isUnbuffered := strings.EqualFold(outResp.Header.Get("X-Accel-Buffering"), "no")
  canStream := p.streamResponse && (!p.routeHasCompression && !p.routeHasCache || isStreamingMIME || isUnbuffered)
  ...
  if canStream {
      res.StreamBody = outResp.Body
      return
  }
  ```
- **Technical Observations**:
  1. **Stream Eligibility Matrix**:
     - When `p.streamResponse == true`:
       - Pure proxy route (`!p.routeHasCompression && !p.routeHasCache`): `canStream = true`.
       - Middleware route with SSE / unbuffered: `isStreamingMIME || isUnbuffered` triggers `canStream = true`.
       - Middleware route with standard asset (`application/json`, `text/html`): `canStream = false` (buffered via pooled slab into `res.Body` to permit downstream compression/caching).
  2. **Non-Blocking Immediate Handoff**: When `canStream == true`, ownership of `outResp.Body` is transferred directly to `res.StreamBody`. `ServeHTTPWithPrefix` returns immediately in $< 0.05\text{ms}$ without blocking.
  3. **Leak-Free Resource Teardown**: In [`pkg/server/server.go:345, 487`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L345), `Server.handleConnection` registers `defer res.StreamBody.Close()`, ensuring the upstream socket is reaped upon EOF, client disconnect, or network error.

### 4.6 Zero-Allocation Header Inspection Optimization (`pkg/httpparser/request.go`)

- **Audit Target**: Ensure header inspection guards execute with zero dynamic heap allocations.
- **Implementation Analysis in [`pkg/httpparser/request.go:53-104`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L53-L104)**:
  ```go
  func canonicalKey(s string) string {
      s = strings.TrimSpace(s)
      switch s {
      case "Content-Type", "content-type":
          return "content-type"
      case "X-Accel-Buffering", "x-accel-buffering":
          return "x-accel-buffering"
      case "Cache-Control", "cache-control":
          return "cache-control"
      case "Accept-Encoding", "accept-encoding":
          return "accept-encoding"
      ...
      }
      return strings.ToLower(s)
  }
  ```
- **Technical Observations**:
  1. **Rodata String Return**: Matching against string constants returns immutable rodata literals, completely bypassing `strings.ToLower` heap allocation during map lookups.
  2. **Empirical Verification**: `TestCache_ZeroAllocations_HeaderGuards` verified that executing `res.Header.Get("Content-Type")`, `strings.ToLower(...)`, `strings.HasPrefix(...)`, and `strings.EqualFold(...)` resulted in **`allocs == 0.0`** under `testing.AllocsPerRun(1000)`.

### 4.7 Backward Compatibility & Regression Protection for Standard Assets

- Standard cacheable HTTP responses (`Cache-Control: public, max-age=60`, `application/json`) continue to be stored in `ResponseCache` and served with `X-Cache: HIT` and `Age: N` on subsequent requests (`TestCache_StandardResponses_StillCached`, `TC-128.5`).
- Standard compressible MIME types (`text/plain`, `text/html`, `application/json`) continue to be compressed normally according to route configuration (`TestCompression_StandardText_Compressed`, `TC-128.9`).
- Standard non-streaming API endpoints on compression-enabled routes buffer into `res.Body` via pooled copy slabs (`TestProxy_StandardJSON_RouteBuffering`, `TC-128.12`).

## 7. Positive Observations

1. **Layered Defense-in-Depth**: Streaming response protection is implemented at three complementary layers:
   - **Reverse Proxy Layer**: `canStream` activates direct socket streaming (`res.StreamBody != nil`).
   - **Compression Layer**: Checks `res.StreamBody != nil`, `text/event-stream`, and `X-Accel-Buffering: no` prior to compressor writer acquisition.
   - **Cache Layer**: Checks `res.StreamBody != nil`, `text/event-stream`, `X-Accel-Buffering: no`, and `resCC.NoCache` prior to cache admission.
2. **Deterministic Memory Hygiene**: `ResponseCache.Len()` and `NewCacheMiddlewareWithStore` allow whitebox testing to verify that cache entries count remains strictly 0 for non-cacheable responses.
3. **Rodata Header Fast-Path**: The `canonicalKey` optimization in `pkg/httpparser/request.go` provides zero-allocation lookup for high-frequency headers, improving hot-path latency across the entire server pipeline.
