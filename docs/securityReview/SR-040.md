# SR-040 - Security Review of Custom WAF Regex Rules & Zero-Downtime Hot Reloading

## Summary

The Security Analyst has conducted an in-depth security threat modeling and vulnerability assessment of the user-defined custom WAF regex rules engine, regular expression pre-compilation, target location bitmasks, and background `fsnotify` atomic hot reloading implemented in Prototype 35 (`TASK-045`, `REQ-045`, `ADR-040`).

## Threat Modeling & Security Controls

### 1. Regular Expression Denial of Service (ReDoS) Mitigation
- **Threat**: Attackers or misconfigured operator rules providing pathological exponential regex patterns causing CPU starvation.
- **Control**: All user-defined regex patterns are pre-compiled at configuration load time and validated during `-t` syntax validation. Go's standard `regexp` engine is based on RE2 (linear-time execution guaranteeing $O(N)$ matching against input size $N$), eliminating catastrophic backtracking vulnerabilities by design.
- **Control**: Body inspection remains strictly bounded by `max_inspect_body_size` (default 64 KB), preventing unbounded memory allocations on large payload scans.

### 2. Location Scoping Integrity
- **Threat**: Attackers injecting benign keywords into headers or queries to cause false positives, or rules leaking inspection across unintended request segments.
- **Control**: Granular location bitmasks (`InspectURL`, `InspectQuery`, `InspectHeaders`, `InspectBody`) ensure custom rules only evaluate their designated input scopes (e.g. `locations: ["headers"]` only inspects HTTP headers, ignoring query strings).

### 3. Fail-Safe Hot Reloading
- **Threat**: Malformed configuration edits or invalid regex patterns deployed in production crashing the edge server or leaving the gateway without WAF protection.
- **Control**: `ConfigWatcher` and `WAFEngine.Reload` pre-compile and validate all custom regexes and IP ACL subnets *prior* to taking the write lock. If an invalid pattern or syntax error is encountered, the hot reload is safely rejected with an error log, and the active in-memory rule set remains fully operational.

### 4. Concurrency & Race Conditions
- **Threat**: Data races between active client request evaluations (`Inspect` / `InspectToron`) and background hot reload operations.
- **Control**: All field reads within `Inspect` / `InspectToron` are protected by `sync.RWMutex` read locks (`e.mu.RLock()`), while `Reload` takes `e.mu.Lock()`. Validated with Go race detector (`go test -race`).

## Review Outcome

**Verdict**: **APPROVED WITHOUT REQUIRED CHANGES**  
The implementation meets enterprise security standards for virtual patching and zero-downtime threat rule administration.
