# CR-051 - Code Review of HTTP/3 Protocol Engine & QUIC Listener Integration

## Description

This code review evaluates the implementation of the HTTP/3 protocol engine and QUIC transport listener integration across [`pkg/server/server.go`](file:///Users/sneha/Developer/toron/pkg/server/server.go), [`cmd/toron/main.go`](file:///Users/sneha/Developer/toron/cmd/toron/main.go), and [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron/pkg/server/server_test.go).

The review assesses concurrency and thread safety around the HTTP/3 server pointer, error propagation and shutdown handling, idiomatic Go conventions, `Alt-Svc` header generation and edge-case behavior, and regression test coverage under the Go race detector (`go test -race`).

## Technical Evaluation

### 1. Concurrency and Thread Safety (`Server.mu` Locking)

- **Field Protection**: The `h3Server *http3.Server` field in `Server` is correctly synchronized via `s.mu sync.RWMutex`.
- **Atomic Pointer Updates**:
  - `SetH3Server` acquires `s.mu.Lock()` with deferred unlock, ensuring safe injection during testing or runtime initialization.
  - `H3Server` acquires `s.mu.RLock()` with deferred unlock, ensuring thread-safe reads for callers and external inspectors.
- **Lock Scoping in Lifecycle Methods**:
  - In `ListenAndServeH3`, `s.h3Server` is instantiated and assigned while holding `s.mu.Lock()`. A local copy `h3 := s.h3Server` is retained, and `s.mu.Unlock()` is invoked **before** entering the blocking `h3.ListenAndServe()` call. This prevents lock starvation and ensures other goroutines can inspect or shut down the server concurrently.
  - In `Shutdown(ctx context.Context)`, `s.mu.Lock()` is acquired only long enough to extract `h3 := s.h3Server`. The lock is released **before** calling `h3.Close()`, ensuring that network teardown and connection draining do not cause deadlocks or block other server operations.

### 2. Clean Error Propagation & `ErrServerClosed` Handling

- **Sentinel Definition**: `var ErrServerClosed = reactor.ErrServerClosed` establishes unified shutdown semantics across TCP reactor and QUIC listeners.
- **Mapping in `ListenAndServeH3`**: When `h3.Close()` terminates the QUIC server, `quic-go` returns standard Go `http.ErrServerClosed`. `ListenAndServeH3` explicitly catches this with `errors.Is(err, http.ErrServerClosed)` and translates it into `ErrServerClosed`.
- **Suppression in `cmd/toron/main.go`**: The entrypoint goroutine filters both exact equality (`err != server.ErrServerClosed`) and wrapped errors (`!errors.Is(err, server.ErrServerClosed)`), ensuring that expected termination during graceful shutdown does not generate false-alarm error logs or abort process termination.
- **Graceful Teardown**: `Shutdown(ctx)` safely handles cases where `s.h3Server` is nil (e.g. when HTTP/3 is disabled) without nil-pointer dereferences.

### 3. Idiomatic Go Conventions & Test Quality

- **Handler Adaptation**: `http2AdapterHandler()` cleanly bridges Go standard library `http.Handler` semantics to Toron's native `httpparser.Request` / `httpparser.Response` pipeline, facilitating 100% router middleware reuse (WAF, rate limiting, auth, logging, recovery) across HTTP/1.1, HTTP/2, and HTTP/3.
- **WebSocket & Extended CONNECT**: The adapter preserves RFC 8441 Extended CONNECT pseudo-headers (`:protocol`) and maps HTTP 101 Switching Protocols to HTTP 200 OK as required by HTTP/2 and HTTP/3 specs.
- **Test Ergonomics**: Tests in `pkg/server/server_test.go` utilize standard Go subtests (`t.Run`), clear assertions, and zero arbitrary `time.Sleep()` delays, executing deterministically in milliseconds. Dependency injection via `SetH3Server` allows shutdown verification without requiring privileged UDP socket operations.

### 4. `Alt-Svc` Header Formatting & Edge Cases

- **Header Generation**: Both `handleConn` (HTTP/1.1) and `http2AdapterHandler` (HTTP/2 / HTTP/3) construct the `Alt-Svc` header:
  ```go
  if s.config.HTTP3Enabled && s.config.HTTP3AltSvcHeader {
      if res.Header.Get("Alt-Svc") == "" {
          h3Port := s.config.HTTP3Port
          if h3Port <= 0 {
              h3Port = 8443
          }
          res.Header.Set("Alt-Svc", fmt.Sprintf(`h3=":%d"; ma=2592000`, h3Port))
      }
  }
  ```
- **RFC 7838 Compliance**: The header strictly formats the alternative service identifier (`h3=":%d"`) and specifies a 30-day freshness parameter (`ma=2592000`).
- **Edge-Case Resilience**:
  - Negative or zero port values fallback gracefully to standard port `8443`.
  - The `res.Header.Get("Alt-Svc") == ""` guard ensures pre-existing `Alt-Svc` headers set by upstream backends or route handlers are preserved without clobbering.
  - Integer formatting (`%d`) prevents CRLF injection vulnerabilities (CWE-113).

### 5. Regression Test Coverage & Absence of Data Races

- **Race Detector Execution**:
  - `go test -v -race ./pkg/server/...` passed with **0 race condition warnings**.
  - `go test -race ./...` passed across all 16 workspace packages with **0 failures and 0 race warnings**.
- **Coverage**:

  - `TestServer_HTTP2Adapter_AltSvcHeader`: 4 subtests verifying default port 8443, custom port 9443, disabled advertising, and pre-existing header preservation.
  - `TestServer_HTTP3_Shutdown`: Subtests verifying active server close (`ServeQUICConn` returning `http.ErrServerClosed`) and nil safety.

## Findings

### Finding 1: Concurrent `s.config` Field Mutation During Startup

- **Severity**: Informational
- **Location**: [`pkg/server/server.go:398-402`](file:///Users/sneha/Developer/toron/pkg/server/server.go#L398-L402), [`pkg/server/server.go:89-95`](file:///Users/sneha/Developer/toron/pkg/server/server.go#L89-L95)
- **Related Artifact**: `TASK-027`, `REQ-027`
- **Description**: In `ListenAndServeH3` and `ListenAndServeTLS`, `s.config.TLSCertFile` and `s.config.TLSKeyFile` are modified from the function arguments without holding `s.mu`. In `cmd/toron/main.go`, both methods are invoked concurrently in separate goroutines. While both functions write identical string values from `appCfg.Server.TLS`, unsynchronized writes to struct fields represent a theoretical concurrency risk if differing parameters were ever supplied.
- **Impact**: None in current production code because identical string values are assigned at startup.
- **Recommendation**: Avoid mutating `s.config` during listener initialization, or protect configuration mutations under `s.mu`.

### Finding 2: `Shutdown()` Error Handling for HTTP/3 Server Close

- **Severity**: Informational
- **Location**: [`pkg/server/server.go:129-131`](file:///Users/sneha/Developer/toron/pkg/server/server.go#L129-L131)
- **Related Artifact**: `TASK-027`, `ADR-022`
- **Description**: In `Server.Shutdown(ctx context.Context)`, the error returned by `h3.Close()` is ignored (`_ = h3.Close()`). While `h3.Close()` primarily closes UDP socket listeners and terminates active sessions, capturing the error and joining it with `s.reactor.Shutdown(ctx)` via `errors.Join` (filtering expected `http.ErrServerClosed`) would enhance observability during abnormal socket teardown.
- **Impact**: Minimal; socket closure rarely produces unhandled actionable errors during shutdown.
- **Recommendation**: For defense-in-depth, consider aggregating errors using `errors.Join(errH3, errReactor)` when `errH3 != nil && !errors.Is(errH3, http.ErrServerClosed)`.

## Positive Observations

1. **Robust Concurrency Architecture**: `Server.mu` locking pattern correctly decouples pointer management from blocking I/O (`ListenAndServe`, `Close`), avoiding potential deadlocks.
2. **Unified Routing Architecture**: Reusing `http2AdapterHandler` allows HTTP/3 QUIC requests to seamlessly flow through Toron's core router, preserving full middleware support (WAF, Rate Limiting, CORS, Security Headers, Auth).
3. **Clean Teardown and Signal Integration**: `cmd/toron/main.go` cleanly coordinates OS interrupt signals with context timeouts, filtering `ErrServerClosed` to prevent false positive shutdown logs.
4. **RFC 7838 Compliance**: Alt-Svc header formatting correctly complies with HTTP/3 specifications and incorporates defense against header overwrites and parameter injection.
5. **Fast, Deterministic Tests**: The test suite executes in milliseconds without fragile sleeps or network dependencies.
