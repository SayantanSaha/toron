# REQ-102 - Path Traversal Test Oracle Hardening and Deterministic Canary Enforcement

## 1. Description

To ensure rigor in empirical security evaluations and eliminate false-positive test oracle pass conditions, the differential protocol security fuzzer (`benchmarks/fuzzer/diff_fuzzer.go`) shall strictly reject HTTP 404 (Not Found) as an acceptable defensive response for path traversal test cases (`TRAVERSAL-001..003`).

Accepting HTTP 404 conflates non-existent filesystem paths with active defensive mitigation, potentially allowing vulnerable servers that lack path traversal guards to falsely pass security audits. The fuzzer test oracle must enforce that traversal attempts are actively intercepted and rejected deterministically with strictly HTTP 400 (Bad Request) or HTTP 403 (Forbidden), verified against a known canary file outside the route root.

## 2. Acceptance Criteria

### AC-1: Elimination of False-Positive 404 Oracle
- In `benchmarks/fuzzer/diff_fuzzer.go`, test cases `TRAVERSAL-001`, `TRAVERSAL-002`, and `TRAVERSAL-003` must define `ExpectedStatus: []int{400, 403}`.
- Any server response yielding HTTP 404 for these vectors shall cause the test case to be flagged as **FAILED** with an explicit failure reason.

### AC-2: Deterministic Canary Configuration
- A verified canary file (`canary_traversal.txt`) shall be configured outside the static document root (`./public`), containing unique non-sensitive validation content.
- Traversal payloads in `diff_fuzzer.go` shall explicitly target this canary file. If a vulnerable server permits traversal, the canary file would be returned with HTTP 200 OK (failing the security invariant), whereas a protected server will actively block traversal with HTTP 400 or HTTP 403.

### AC-3: Automated Test Oracle Verification
- Automated unit tests in `benchmarks/fuzzer/diff_fuzzer_test.go` must verify that:
  1. A mock server returning HTTP 404 for traversal attempts is evaluated as FAILED.
  2. A mock server returning HTTP 403 or HTTP 400 is evaluated as PASSED.
  3. A mock server returning HTTP 200 (leaking the canary) is evaluated as FAILED.

### AC-4: Zero-Dependency & Race Safety
- All modifications must strictly adhere to the Go standard library and maintain 100% race-clean execution under `go test -race`.
