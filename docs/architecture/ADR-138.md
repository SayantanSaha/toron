# ADR-138 - Deterministic Multi-Level Sorting Pipeline for Real-Time Dashboard Streams

## Status

Approved

## Context

When dashboard users view high-velocity log tails, automated threat alerts, and security bans, records frequently share identical timestamp granularity (e.g. within the same second or millisecond when events arrive in batch). Non-deterministic sorting causes visual jitter during live polling cycles.

## Decision

We implement a deterministic cascading comparator architecture across the client-side UI:

### 1. Alert Multi-Level Ordering
- Primary: Numeric timestamp descending: `(b.timestamp || 0) - (a.timestamp || 0)`
- Secondary: Lexicographical IP ascending: `(a.ip || '').localeCompare(b.ip || '')`

### 2. Banned IP Table Ordering
- Primary: Ban creation timestamp descending: `new Date(b.created_at || 0).getTime() - new Date(a.created_at || 0).getTime()`
- Secondary: Lexicographical IP ascending: `(a.ip || '').localeCompare(b.ip || '')`

### 3. Request Log Ordering
- Primary: Request timestamp descending: `(b.ts || 0) - (a.ts || 0)`
- Secondary: Lexicographical Client IP ascending: `(a.ip || a.client_ip || '').localeCompare(b.ip || b.client_ip || '')`
- Tertiary: Lexicographical Request Path ascending: `(a.path || '').localeCompare(b.path || '')`

## Consequences

- **Determinism**: Identical data payloads always render in the identical visual order across render cycles, eliminating UI jumpiness.
- **Performance**: Standard JavaScript `Array.prototype.sort()` using `localeCompare` runs in $O(N \log N)$ time and takes negligible execution time on typical arrays ($N \le 1000$).
- **Zero Dependencies**: Requires no external library or polyfill.
