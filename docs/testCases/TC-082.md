# TC-082 - Verification of Mandatory JWT Expiration Enforcement

## Objective

Verify that `VerifyJWT` requires an `exp` claim when configured to enforce expiration, rejecting non-expiring tokens.

## Test Cases

### TC-082-01: Token Lacking exp Claim Rejection
- **Setup**: Sign a JWT without an `exp` claim using `SignJWT`. Configure `RequireExpiration: true`.
- **Action**: Call `VerifyJWT(token, secret, "", "")`.
- **Expected Outcome**:
  - Verification fails with an error indicating missing `exp` claim.

### TC-082-02: Valid Future exp Claim Acceptance
- **Setup**: Sign a JWT with `exp` set to 1 hour in the future.
- **Action**: Call `VerifyJWT(token, secret, "", "")`.
- **Expected Outcome**:
  - Verification succeeds; claims are returned.

### TC-082-03: Expired Token Rejection
- **Setup**: Sign a JWT with `exp` set to 1 hour in the past.
- **Action**: Call `VerifyJWT(token, secret, "", "")`.
- **Expected Outcome**:
  - Verification fails with `"token has expired"`.
