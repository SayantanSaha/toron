# TC-040 - CORS Policies & Enterprise Security Headers Verification

## Test Objectives

1. Verify CORS preflight `OPTIONS` request with valid `Origin` and `Access-Control-Request-Method` returns `204 No Content` with appropriate `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, and `Access-Control-Max-Age`.
2. Verify CORS preflight from disallowed `Origin` returns `403 Forbidden` or does not attach allow headers.
3. Verify CORS wildcard origin `*` correctly sets `Access-Control-Allow-Origin: *`.
4. Verify CORS credentials `allow_credentials: true` sets `Access-Control-Allow-Credentials: true` and echoes the specific request `Origin` rather than `*`.
5. Verify actual request (e.g. `GET /api`) with `Origin` header receives `Access-Control-Allow-Origin` and `Vary: Origin`.
6. Verify Security Headers middleware attaches `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`, and `Permissions-Policy` to outgoing responses.
7. Verify full test suite passes cleanly (`go test ./...`).
