# ADR-020 - HTTP/2 Extended CONNECT Protocol Architecture for RFC 8441 WebSockets

## Context

RFC 8441 specifies how to bootstrap WebSocket connections over HTTP/2 using an extended CONNECT request. Rather than switching connection protocols (`101 Switching Protocols`), WebSockets over HTTP/2 run multiplexed over an individual HTTP/2 stream initiated via `:method = CONNECT` and pseudo-header `:protocol = websocket`.

## Decision

1. **HTTP/2 Engine Configuration**:
   - `http2.Server` instances in `pkg/server/server.go` explicitly enable `EnableExtendedConnectProtocol: true`.
   - The server emits `SETTINGS_ENABLE_CONNECT_PROTOCOL` (0x8 = 1) in initial HTTP/2 SETTINGS frame.

2. **Request Parsing & Identification**:
   - `httpparser.Request.IsHTTP2WebSocketUpgrade()` detects requests where `Method == "CONNECT"` and `:protocol` header equals `websocket` (or `IsWebSocketUpgrade()` is extended to recognize RFC 8441 requests).

3. **HTTP/2 Adapter & Reverse Proxy Integration**:
   - In `http2AdapterHandler`, when an extended CONNECT request is processed, the response status line is set to `200 OK` (as required by RFC 8441 instead of `101 Switching Protocols`).
   - Flush headers immediately to establish stream state (`w.(http.Flusher).Flush()`).
   - Perform full-duplex copy between `r.Body` / `w` and upstream socket or handler.

## Consequences

- **Positive**: Full compliance with RFC 8441, enabling WebSockets over HTTP/2 without opening separate TCP connections.
- **Backward Compatibility**: Standard HTTP/1.1 `Upgrade: websocket` requests continue to work unchanged.
