# AN-002: Root Cause Analysis - Native Browser Username/Password Prompt on Dashboard Load

## 1. Problem Statement & Observed Behavior

When navigating to `https://sayantansaha.in/internal/dashboard/` in a web browser, the user is immediately presented with a browser-native authentication dialog:
> *"The server sayantansaha.in requires a username and password. The server says: Toron Management."*

The user is prompted for a **Username** and **Password** rather than being able to enter the generated Admin Token (`a4c423d684e210ab962e335278d0e0d9`) into the newly designed in-page web modal (`authModal.js`).

---

## 2. Investigation & Evidence

1. **Endpoint Probing**:
   - Request: `GET https://sayantansaha.in/internal/api/status` (unauthenticated)
   - Response Headers:
     ```http
     HTTP/2 401 Unauthorized
     content-type: application/json
     www-authenticate: Bearer realm="Toron Management", Basic realm="Toron Management"
     ```
2. **Client Call Flow**:
   - `https://sayantansaha.in/internal/dashboard/` loads `public/index.html` (HTTP 200).
   - `public/js/app.js` initializes and calls `startPolling()`.
   - `public/js/api.js` executes `authenticatedFetch('/internal/api/status')`.
   - Since no token is yet stored in `sessionStorage`, the request has no authentication headers.
   - The server responds with `401 Unauthorized` and header:
     `WWW-Authenticate: Bearer realm="Toron Management", Basic realm="Toron Management"`
3. **Browser Network Engine Behavior**:
   - RFC 7235 / W3C Fetch specification dictates that when a browser receives an HTTP 401 response containing a `Basic realm="..."` challenge, the browser's native credential manager intercepts the response and halts JavaScript execution until the user completes or dismisses the native Username/Password dialog.
   - The server only has `admin_auth: token: "..."` configured; there are no configured username/password credentials.
   - Dismissing the native dialog causes the JavaScript fetch promise to fail, but background polling (every 2 seconds) immediately triggers another unauthenticated request, repeatedly popping up the native dialog.
   - The custom in-page modal (`authModal.js`) is blocked or superseded by the browser's native prompt.

---

## 3. Root Cause

In `pkg/server/internal_api.go` (line 385):
```go
res.Header.Set("WWW-Authenticate", `Bearer realm="Toron Management", Basic realm="Toron Management"`)
```
The inclusion of `Basic realm="Toron Management"` forces modern browsers to trigger the native HTTP Basic Auth prompt.

Because Toron Control Center is designed as a modern Single Page Application relying on Bearer token / Admin API Key authentication, the challenge header should advertise `Bearer realm="Toron Management"` (or omit `Basic` when Basic Auth is not explicitly required). Browsers do not intercept Bearer challenges, allowing `fetch()` to return the 401 status cleanly to `api.js`, which then smoothly displays the custom HTML/CSS authentication modal.

---

## 4. Impact Analysis

- **Affected Components**:
  - `pkg/server/internal_api.go`: `wrapHandler` middleware challenge header.
  - `pkg/server/internal_api_test.go`: Unit test assertions for 401 responses.
- **Side Effects / Backward Compatibility**:
  - Server validation logic in `validateAdminAuth()` continues to accept `X-Toron-Admin-Key`, `Authorization: Bearer <token>`, and `Authorization: Basic <base64>` for programmatic clients (e.g. curl or scripts).
  - Removing `Basic` from the unauthenticated challenge header prevents browser modal interception without breaking any API clients that supply credentials proactively.
- **Security Implications**:
  - Positive security impact: Eliminates native browser modal lock-in and allows the SPA's defense-in-depth token authentication modal to function as designed.

---

## 5. Recommended Actions

1. **Code Modification**:
   - In `pkg/server/internal_api.go`, update line 385 to emit:
     ```go
     res.Header.Set("WWW-Authenticate", `Bearer realm="Toron Management"`)
     ```
2. **Verification**:
   - Run Go unit tests with `-race`.
   - Recompile `toron-linux-amd64`.
   - Deploy binary to remote host `sayantansaha.in` and restart `toron.service`.
   - Verify `curl -sk -i https://sayantansaha.in/internal/api/status` returns `WWW-Authenticate: Bearer realm="Toron Management"`.
   - Verify browser opens the custom in-page Auth Modal cleanly without any browser native prompt.
