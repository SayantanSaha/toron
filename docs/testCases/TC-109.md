# TC-109 - Test Specification for Header Field-Name Token Grammar Validation

## 1. Test Suite Objectives

Verify that Toron's HTTP parser strictly rejects non-token characters in HTTP header field-names in accordance with RFC 7230 §3.2 and §3.2.6, ensuring immunity against parser differential attacks and header injection vulnerabilities.

## 2. Test Cases

### TC-109-01: RFC 7230 §3.2.6 Delimiter Rejection
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_HeaderFieldNameTokenGrammar`)
- **Methodology**: Parse HTTP requests containing each RFC 7230 delimiter within the header field-name:
  `@`, `(`, `)`, `,`, `/`, `;`, `<`, `=`, `>`, `?`, `[`, `\`, `]`, `{`, `}`, `"`
- **Expected Outcome**:
  - `httpparser.ParseRequest` returns non-nil error.
  - Error wraps `httpparser.ErrBadRequest`.
  - Error message indicates `invalid header field-name token grammar`.

### TC-109-02: ASCII Control Character Rejection
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_HeaderFieldNameTokenGrammar`)
- **Methodology**: Parse HTTP requests containing ASCII control characters within the header field-name:
  - NUL (`0x00`)
  - BEL (`0x07`)
  - ESC (`0x1B`)
  - DEL (`0x7F`)
- **Expected Outcome**:
  - Request is rejected with an error wrapping `httpparser.ErrBadRequest`.

### TC-109-03: High-Bit and Non-ASCII Byte Rejection
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_HeaderFieldNameTokenGrammar`)
- **Methodology**: Parse HTTP requests containing non-ASCII bytes (e.g. `0x80`, `0xC2`, `0xFF`) within the header field-name.
- **Expected Outcome**:
  - Request is rejected with an error wrapping `httpparser.ErrBadRequest`.

### TC-109-04: Valid RFC 7230 Complex Header Field-Names
- **Target**: `pkg/httpparser/parser_test.go` (`TestParseRequest_HeaderFieldNameTokenGrammar`)
- **Methodology**: Parse HTTP requests containing valid RFC 7230 `tchar` symbols in header field-names:
  - `X-Custom_Header.1!#$%&'*+-.^_`|~`
  - Standard headers: `Content-Type`, `Accept-Encoding`, `User-Agent`, `X-Forwarded-For`
- **Expected Outcome**:
  - Request parses successfully without error (`err == nil`).
  - Header values are accessible via `req.Header.Get(...)`.

### TC-109-05: Nanosecond In-Process Rejection Microbenchmark
- **Target**: `pkg/httpparser/parser_test.go` (`BenchmarkParseRequest_InvalidTokenRejection`)
- **Methodology**: Execute `testing.B` benchmark measuring rejection latency of header with invalid delimiter (`X-Invalid@Header: test`).
- **Expected Outcome**:
  - Sub-50ns rejection execution.
  - Zero heap allocations (`0 B/op`, `0 allocs/op`).
