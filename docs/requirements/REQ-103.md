# REQ-103 - RFC 7234 Shared Cache Session Boundary Isolation Test Vectors in Differential Fuzzer

## 1. Description

To ensure rigorous session boundary isolation and prevent cross-tenant data leaks during empirical research evaluations, the differential protocol security fuzzer (`benchmarks/fuzzer/diff_fuzzer.go`) shall include automated test vectors evaluating RFC 7234 shared caching compliance over raw TCP sockets.

Specifically, the fuzzer test harness must actively verify that:
1. **Web Cache Deception (CWE-524)**: Authenticated responses with `Cache-Control: private` are never cached or served to unauthenticated subsequent requests.
2. **`Set-Cookie` Stripping (CWE-384 / Session Fixation, CWE-524)**: Any response containing a `Set-Cookie` or `Set-Cookie2` header has these headers stripped prior to cache storage, ensuring cached responses never leak session cookies to another client.
3. **`Authorization` Refusal (RFC 7234 §3.2)**: Responses to requests containing an `Authorization` header are never cached or reused unless explicitly marked with `Cache-Control: public`.

## 2. Acceptance Criteria

### AC-1: Sequential Multi-Stage Payload & Header Assertion Engine
- `benchmarks/fuzzer/diff_fuzzer.go` shall support sequential multi-stage request execution (`SequentialPayloads []string`) within a single test case run.
- The fuzzer must parse HTTP response headers for verification probes and support header assertions, including forbidden response headers (`ForbiddenHeaders []string`) and required response headers (`RequiredHeaders map[string]string`).

### AC-2: `CACHE-001` (Web Cache Deception Prevention)
- Initial request transmits an authenticated request with `Cache-Control: private`.
- Subsequent request transmits an unauthenticated request for the same resource.
- The fuzzer asserts that the unauthenticated response receives `X-Cache: MISS` (or is not served from cache) and does not leak private user payload data.

### AC-3: `CACHE-002` (`Set-Cookie` Header Stripping)
- Initial request fetches an endpoint that sets a cookie (`Set-Cookie: session=xyz`).
- Subsequent request retrieves the cached response (`X-Cache: HIT`).
- The fuzzer asserts that `Set-Cookie` and `Set-Cookie2` headers are strictly absent from the cached response.

### AC-4: `CACHE-003` (`Authorization` Refusal Invariant)
- Initial request transmits an authenticated request lacking `public` directive (`Authorization: Bearer ...`).
- Subsequent request fetches the resource without credentials.
- The fuzzer asserts that the second response receives `X-Cache: MISS`, proving the unshared private response was not stored.

### AC-5: Zero Third-Party Dependencies & Race Safety
- All enhancements must utilize pure Go standard library networking and run race-clean under `go test -race`.
