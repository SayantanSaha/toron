# TC-003 - HTTP Router Path Dispatching and Middleware Execution Verification

## Description

Verify that registered routes correctly match incoming request paths/methods, execute attached middleware in sequence, return 404 for unknown routes, and return 405 for mismatched HTTP methods.

## Preconditions

- Router instantiated with routes `GET /api/v1/resource` and `POST /api/v1/resource`.
- Custom tracking middleware registered.

## Test Data

- Matching request: `GET /api/v1/resource`
- Unmatched route request: `GET /unknown`
- Method mismatch request: `DELETE /api/v1/resource`

## Steps

1. Dispatch `GET /api/v1/resource` -> Verify route handler invoked and middleware tracking flag executed.
2. Dispatch `GET /unknown` -> Verify `404 Not Found` response code returned.
3. Dispatch `DELETE /api/v1/resource` -> Verify `405 Method Not Allowed` response code returned.

## Expected Results

- Router dispatches correctly and runs middleware in defined order.

## Acceptance Criteria

- All routing conditions (200, 404, 405) behave as specified.

## Rationale

Ensures robust URL routing and middleware execution.

## Constraints

- Table-driven unit tests in `pkg/router`.
