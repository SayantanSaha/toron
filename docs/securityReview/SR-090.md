# SR-090 - Security Review of SEC-30 Remediation: Direct Parameterized Subpath Routing & Denial of Service Elimination in REST-to-gRPC Transcoder

## Security Evaluation Summary

- **Vulnerability Remediated**: **SEC-30** ([CWE-284: Improper Access Control](https://cwe.mitre.org/data/definitions/284.html), [CWE-400: Uncontrolled Resource Consumption / Denial of Service](https://cwe.mitre.org/data/definitions/400.html))
- **Affected Subsystems**: REST-to-gRPC Transcoder Engine ([`pkg/transcoder/transcoder.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go)) & Edge Router ([`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go))
- **CVSS v3.1 Vector**: `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:M` (Base Score: 5.3 &rarr; **0.0 Resolved**)
- **Verdict**: **APPROVED & RESOLVED**

---

## 1. Threat Modeling & Vulnerability Context

In [`pkg/transcoder/transcoder.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go), Toron provides RESTful API translation to backend gRPC microservices. REST APIs inherently rely on URI path parameters (e.g. `/v1/users/:id`).

Prior to remediation, [`Engine.registerRoutes`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L68) registered an upstream reverse proxy with empty options (`ProxyOptions{}`) on the literal prefix of parameterized paths, while registering the transcoder handler only on the exact prefix string:
1. **Denial of Service via Subpath Interception (CWE-400)**:
   Any request with a path parameter (e.g. `/v1/users/usr-777`) failed the exact route check, matched the empty prefix proxy, and immediately returned `502 Bad Gateway: No upstream target available`. All parameterized endpoints were rendered completely unusable.
2. **Missing Security Verification**:
   The existing unit test suite in `pkg/transcoder` directly invoked `engine.HandleTranscode` while bypassing `router.ServeHTTP`, masking this critical routing flaw.
3. **Route Shadowing / Collision (CWE-284)**:
   Without method and pattern gating on prefix routes, endpoints sharing prefixes risked colliding or returning 502.

---

## 2. Security Analysis of Remediation

### A. Elimination of Empty Upstream Proxy
- In [`Engine.registerRoutes`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L68), `_ = e.router.RoutePrefix("upstream", ...)` with empty targets was completely deleted.
- Zero dummy or empty upstream proxies exist in the routing table.

### B. Method-Aware In-Process Prefix Handlers
- [`Router.HandlePrefix`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L246) and [`Router.HandlePrefixWithMatcher`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L251) enable direct in-process dispatching for prefix routes.
- In [`Router.ServeHTTP`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go#L453), incoming requests verify `pr.method`. If the method does not match, the route is bypassed and `405 Method Not Allowed` is returned if no candidate matches, adhering to HTTP standards and preventing unauthorized method bypass.

### C. Precise Path Pattern Matching (`MatchPathPattern`)
- [`MatchPathPattern`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L335) enforces segment count integrity and literal equality.
- Subpaths with segment count mismatches (e.g. `/v1/users` or `/v1/users/usr-777/extra`) return `404 Not Found` without invoking upstream gRPC services.
- Multi-level routes (e.g. `/v1/users/:id` and `/v1/users/:id/orders/:orderId`) are segregated with zero route shadowing.

### D. Direct Dispatch Validation through `router.ServeHTTP`
- Validated via `TestTranscoder_ParameterizedSubpathDispatch` (TC-091-01), fulfilling Missing Security Test 5 in [`SR-081`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L221).
- Outgoing gRPC requests reach upstream backends with exact parameters and return `200 OK`.

### E. Race Safety & Zero Dependencies
- Validated under `go test -race ./...` with 50 concurrent requests. Zero data races detected.
- Strictly pure Go standard library (zero 3rd-party dependencies).

## 3. Final Security Verdict

**APPROVED & RESOLVED**. Vulnerability [`SEC-30`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L411-L419) is completely remediated. Parameterized REST-to-gRPC endpoints route reliably and securely through the edge gateway.
