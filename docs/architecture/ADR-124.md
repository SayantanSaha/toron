# ADR-124 - Configurable Distributed Tracing Architecture in Reverse Proxy Transport

## 1. Context & Problem Statement

Under [`REQ-031`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-031.md) and [`ADR-026`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-026.md), Toron implemented automated W3C distributed tracing context propagation. The reverse proxy engine unconditionally invokes [`EnsureW3CTraceparent`](file:///Users/sneha/Developer/toron-research/toron/pkg/metrics/tracing.go#L12) on every outbound request:
```go
incomingTrace := req.Header.Get("traceparent")
outReq.Header.Set("traceparent", metrics.EnsureW3CTraceparent(incomingTrace))
```

When client requests do not supply an incoming `traceparent` header (which is typical for external traffic and benchmark harnesses), `EnsureW3CTraceparent` generates a cryptographically random 128-bit trace ID and 64-bit span ID via two calls to `crypto/rand.Read`.

In the multi-proxy differential benchmark ([`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md)), Toron achieved ~24.5k RPS. At this scale, unconditional tracing generation executes **~49,000 OS CSPRNG system calls per second** (`getrandom` / `/dev/urandom`), causing global runtime mutex contention and kernel context switches. This accounts for an observable latency penalty (~0.19ms P50 latency higher than Traefik, which defaults tracing off).

## 2. Decision

### 2.1 Pointer Boolean Field in `ProxyTransportConfig`
Extend [`ProxyTransportConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) with a pointer boolean named `tracing`:
```go
type ProxyTransportConfig struct {
    ...
    Tracing *bool `yaml:"tracing,omitempty" json:"tracing,omitempty"`
}
```
Using a pointer boolean (`*bool`) allows distinguishing between an explicit `false`, an explicit `true`, and an omitted field that inherits from the preset profile or global configuration.

### 2.2 Profile-Based Defaults
In `DefaultProxyTransportConfig(profile string)`:
1. **`raw_speed` profile**:
   - `Tracing: &false`
   - Bypasses `EnsureW3CTraceparent` and eliminates all CSPRNG system calls by default.
2. **`balanced` profile**:
   - `Tracing: &true`
   - Enables full automated W3C Trace Context generation and child span creation for enterprise observability.

### 2.3 Conditional Proxy Execution Lifecycle
In [`pkg/proxy/proxy.go:ServeHTTPWithPrefix`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1019-L1022):
- Resolve `tracingEnabled`:
  ```go
  tracingEnabled := false
  if p.TransportConfig.Tracing != nil {
      tracingEnabled = *p.TransportConfig.Tracing
  }
  ```
- **When `tracingEnabled == true`**:
  - Unconditionally invoke `metrics.EnsureW3CTraceparent(incomingTrace)`.
  - If `incomingTrace` is valid, parse and generate child span ID. If missing, generate new trace ID and span ID.
- **When `tracingEnabled == false`**:
  - If `incomingTrace != ""`, pass it through to the upstream request verbatim (`outReq.Header.Set("traceparent", incomingTrace)`).
  - If `incomingTrace == ""`, do NOT set `traceparent` and do NOT call `crypto/rand.Read`.

### 2.4 Hierarchical Cascading
Route-level configuration (`routes.yaml` `routes[].transport.tracing`) overrides the global configuration (`config.yaml` `proxy.transport.tracing`), which in turn overrides the default profile preset.

## 3. Consequences

### Positive
- **Eliminates ~49,000 CSPRNG system calls/sec** under saturation loads (24.5k RPS).
- Reduces median latency by ~0.10ms–0.15ms and tightens tail latency percentiles (P90/P99).
- Fully backward-compatible: operators who require distributed tracing can set `tracing: true` or use `profile: "balanced"`.
- Zero third-party dependencies (`go.mod` invariant).

### Negative / Trade-Offs
- Upstream backends will not receive a `traceparent` header when `tracing: false` and the client did not supply one. This is expected and identical to NGINX and Traefik standard behavior.
