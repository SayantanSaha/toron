## 2. Threat Pattern Analysis

Examination of the remote access log (`/var/log/toron/access.log`) reveals 64 distinct HTTP GET requests issued sequentially. The request paths exhibit five distinct malicious behavioral signatures:

### 2.1. Known Public Web Shell Artifacts
The client systematically probed for known pre-compiled PHP web shells and remote administration tools (RATs):
- `/alfa.php` — **Alfa Team Web Shell** (Alfa Rex v4.x), a widely used command execution and database manipulation web shell.
- `/foxv10.php` — **Fox WSO v10 Web Shell**, an obfuscated remote management shell.
- `/coffexium.php` — **Coffexium Web Shell**, designed for server privilege escalation.
- `/0xD.php` — **0xDark Shell**, classic backdoor script.
- `/sallu.php` — Common mass-defacement / web shell tool.

### 2.2. WordPress Backdoor & Plugin Exploits
The client attempted to locate backdoors dropped into WordPress directories or exploit vulnerable file management plugins:
- `/wp-content/plugins/hellopress/wp_filemanager.php` — Known arbitrary file upload / RCE exploit target.
- `/wp-update.php`, `/wp_blog_footer.php`, `/wp-9xay.php`, `/wp-fcar.php` — Pseudonymous filenames frequently deployed by automated WordPress malware injectors.

### 2.3. Parameterized Stager & Eval Probes
Multiple requests appended the `?p=` query parameter:
- `/1.php?p=`
- `/sss.php?p=`
- `/z60.php?p=`
- `/Callback.php?p=`
These represent password-protected one-line webshell stagers (e.g. `eval($_POST['p'])` or `assert($_GET['p'])`), where scanners attempt to verify if a backdoor is listening for commands.

### 2.4. WAF / Normalization Evasion Syntax
The attacker dispatched requests with double-slash prefixes:
- `//aa.php`
- `//av.php`
This is a standard evasion technique intended to bypass poorly configured path-matching filters or web application firewalls that perform strict prefix checks without URL canonicalization.

### 2.5. Programmatically Generated / Wordlist Filenames
High-entropy alphanumeric filenames characteristic of automated brute-force dictionaries:
- `/3PJcpMFsD8B.php`, `/4PJcpMFsD8B.php`
- `/BDKR28WP.php`
- `/pJPoKA.php`, `/hndkzla.php`, `/jybkxer.php`

## 4. Root Cause: Why Toron WAF Did Not Auto-Ban

1. **Rule Mismatch**: Toron's default OWASP rules inspect for active SQLi, XSS, Path Traversal, and RCE command payloads in headers/query/body. The existing custom rule `CUSTOM-002` only matched specific high-value files (`.env`, `.git`, `.aws`, `.ssh`, `wp-config.php`, `id_rsa`, `/etc/passwd`).
2. **Missing Rule for Shell Probing**: Simple HTTP GET requests for non-existent `.php` files (without execution commands in the URI) did not trigger the anomaly score threshold (configured at 5 in `config.yaml`).
3. **Gateway Protection**: Toron handled all requests safely at layer 7, returning `404 Not Found` in under 0.15ms with zero backend impact.
