# SR-061 - Security Review of Rate Limiter Capacity Bounding, TTL Eviction, and Anti-Spoofing

## Description

Security evaluation of the implementation for `TASK-064` / `SEC-04` (Unbounded memory allocation in rate limiter and client IP spoofing).

## Scope

- Files reviewed:
  - `pkg/router/rate_limiter.go`
  - `pkg/router/rate_limiter_test.go`

## Security Evaluation & Analysis

1. **Denial-of-Service & Memory Exhaustion Mitigation (CWE-400)**:
   - In `pkg/router/rate_limiter.go`, the bucket store is strictly bounded by `maxBuckets` (default: 10,000).
   - An attacker attempting to flood the server with randomized client identifiers or headers cannot expand memory consumption beyond the configured cap; when the limit is reached, older buckets are evicted via LRU doubly linked list.
   - Background sweeping and opportunistic per-request cleanup evict idle buckets that have exceeded `IdleTTL`, returning memory resources.
2. **Anti-Spoofing & Client Key Anchoring**:
   - `extractClientKeyInternal` anchors client identity directly to the physical TCP socket address (`req.RawConn.RemoteAddr()`).
   - Client-supplied forwarded headers (`X-Forwarded-For`) are ignored for direct untrusted connections, neutralizing rate-limit evasion via rotated headers.
   - Forwarded client identity is only evaluated when the physical connection peer belongs to an explicitly authorized CIDR in `TrustedProxies`.
3. **Exploit Verification**:
   - Verified that a client rotating randomized `X-Forwarded-For` IPs across multiple requests on a single socket is throttled with `429 Too Many Requests` once the physical connection threshold is reached.

## Conclusion

`SEC-04` is completely mitigated. The implementation is approved.
