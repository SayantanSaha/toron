# ADR-016 - Configuration Syntax Testing and Dry-Run CLI Architecture

## Context

Operators require a safe way to test new or modified `config.yaml` and `routes.yaml` files before deploying or restarting the live server instance.

## Decision

1. **CLI Flag Interface**: `-test-config` (alias `-t`).
2. **Validation Pipeline (`ValidateConfig`)**:
   - YAML structural deserialization check.
   - Server port range validation ($1 \le \text{port} \le 65535$).
   - Static asset directory existence check.
   - Upstream URL schema validation (`http://` or `https://` required).
   - Load balancing algorithm validation (`round_robin`, `random`).
3. **Execution Control**:
   - If `-test-config` is passed, validation runs immediately after loading.
   - The application prints validation results and terminates before instantiating the reactor or binding network listeners (`os.Exit(0)` for success, `os.Exit(1)` for failure).

## Consequences

- **Positive**: Prevents server startup failures due to typos or invalid target URLs.
