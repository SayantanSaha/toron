# ADR-023 - Dynamic Zero-Downtime Route Hot Reloading Architecture

## Context

Modifying routes (static asset locations, domain hosts, version headers, upstream load balancer backends) previously required restarting the Toron server binary, interrupting active client connections.

## Decision

1. **File Watching & Event Debouncing (`pkg/config/watcher.go`)**:
   - Utilize `github.com/fsnotify/fsnotify` to monitor filesystem events on `routes.yaml`.
   - Implement a debounce timer (100ms) to coalesce multiple write/truncate file events into a single reload action.

2. **Validation Guard**:
   - Before applying updates, the file watcher invokes `ReloadRoutesFromFile(filePath)`.
   - If the new `routes.yaml` file contains syntax errors or invalid fields, the reload attempt is rejected, an error log is emitted, and the existing active route table remains untouched.

3. **Atomic Thread-Safe Route Swapping (`pkg/router/router.go`)**:
   - Protect `router.routes` slice using `sync.RWMutex`.
   - Provide `ResetRoutes()` and `UpdateRoutes(newRoutes)` methods allowing instantaneous atomic replacement of route rules without closing open socket streams.

4. **Lifecycle Integration (`pkg/server/server.go`)**:
   - Optional `RouteWatcher` instance created during server initialization if a valid route file path is supplied.
   - `RouteWatcher` stopped cleanly during `Server.Shutdown()`.

## Consequences

- **Positive**: Zero-downtime configuration updates in production; zero dropped client TCP/UDP/QUIC connections during route updates.
- **Resilience**: Malformed `routes.yaml` files cannot crash or break running server operations.
