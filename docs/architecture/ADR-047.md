# ADR-047: Two-Way Prefix Translation & Dynamic Redirect/Cookie Rewriting

## Status
Approved

## Context
When an edge gateway proxies requests using a path prefix (e.g. `/api` -> `http://backend:9001`), the gateway strips the prefix before dispatching upstream. However, upstream applications often issue relative redirects (e.g. `Location: /login`) or set session cookies with `Path=/`. Without gateway interception, client browsers follow redirects to `/login` (missing the prefix and triggering 404s) and associate cookies with the entire domain.

## Decision
1. **Inbound Context Injection**: Always inject `X-Forwarded-Prefix: <prefix>` and `X-Forwarded-Proto` on inbound forwarded requests so modern prefix-aware backends can construct correct URLs.
2. **Outbound 3xx Location Interception**: Intercept 3xx redirect responses when `rewrite_redirects` is true:
   - Rewrite relative paths to prepend the route prefix (`/login` -> `/api/login`).
   - Rewrite internal target URLs (`http://127.0.0.1:9001/dashboard`) to the public gateway URL using the client's `Host` / `X-Forwarded-Host` header.
   - Preserve third-party external redirects (OAuth/SSO/CDN) verbatim.
3. **Outbound Cookie Path Scoping**: Intercept `Set-Cookie` headers when `rewrite_cookie_path` is true and rewrite `Path=/` to `Path=<prefix>`.
4. **Configurable Passthrough**: Provide `strip_prefix: false` and `rewrite_redirects: false` for native prefix-aware backends.

## Consequences
- **Positive**: Off-the-shelf legacy applications, admin consoles, and microservices work behind subpath prefixes out of the box without code changes.
- **Negative**: Adds lightweight string/header parsing overhead on 3xx responses and Set-Cookie headers.
