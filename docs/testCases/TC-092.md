# TC-092 - Test Suite for Physical RemoteAddr Binding & Security Perimeter Anti-Spoofing across HTTP/1.1, HTTP/2, and HTTP/3

## 1. Test Suite Objectives

Verify that Toron Edge Gateway establishes an immutable, tamper-proof binding to the client's physical remote network address across all supported ingress protocols (HTTP/1.1, HTTP/2, HTTP/3), strictly gating client-supplied forwarded headers (`X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`) behind verified `trusted_proxies` configurations.

This test specification validates the complete remediation of critical vulnerability [`SEC-31`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L428-L436) and audit finding [`SR-091 Finding 1`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-091.md#L78-L99) ([CWE-290: Authentication Bypass by Spoofing](https://cwe.mitre.org/data/definitions/290.html), [CWE-345: Insufficient Verification of Data Authenticity](https://cwe.mitre.org/data/definitions/345.html), [CWE-693: Protection Mechanism Failure](https://cwe.mitre.org/data/definitions/693.html)), verifying that:

1. [`httpparser.Request`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L58-L70) binds the physical transport address in `RemoteAddr` and provides robust parsing helpers ([`RemoteHost`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go), [`RemoteIP`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go)) supporting IPv4, IPv6, port splitting, bare IPs, IPv6 bracket stripping, and safe fallback to [`RawConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L68).
2. All protocol ingress adapters—[`handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L240) (HTTP/1.1), [`NewRequestFromStd`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L124) / [`http2AdapterHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L313) (HTTP/2), and [`ListenAndServeH3`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L406) (HTTP/3)—accurately populate `RemoteAddr` from the physical transport connection or QUIC UDP datagram peer.
3. Perimeter security controls—WAF IP ACL ([`pkg/waf/ip_acl.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go)), Internal Management API Subnet Gate ([`pkg/server/internal_api.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go)), Token Bucket Rate Limiting ([`pkg/router/rate_limiter.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/rate_limiter.go)), Reverse Proxy Header Sanitization ([`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go)), and Structured Access Logging ([`pkg/logging/manager.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/logging/manager.go))—strictly anchor client network identity to the verified physical peer IP, completely rejecting spoofed client headers from untrusted connections.
4. Client-supplied forwarded headers are only evaluated when the physical peer is explicitly verified against configured `trusted_proxies` subnets.
5. In accordance with architectural non-goals in [`REQ-092`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md) and [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md), mobile roaming session affinity under [`REQ-030`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-030.md) in [`pkg/proxy/sticky.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/sticky.go) remains 100% preserved with zero code regressions.
6. Multi-protocol request execution is completely thread-safe and race-clean under `go test -race ./...`.

Verify full coverage for IPv4, IPv6, port splitting, bare IPs, IPv6 bracket stripping, fallback to [`RawConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L68), whitespace handling, and fail-safe handling of malformed or empty inputs.
- **Traceability**: [`REQ-092-AC-01`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L81-L88), [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L90-L129), [`TASK-111`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-111.md#L58-L73).
- **Target Function**: `TestRequest_RemoteHostAndIP_Parsing(t *testing.T)` in `pkg/httpparser/request_test.go`.
- **Preconditions**:

- **Test Data Matrix**:

### TC-092-02: Ingress Protocol RemoteAddr Population

- **Objective**: Verify that client physical remote address is consistently and accurately bound to `req.RemoteAddr` across all ingress pathways: native HTTP/1.1 reactor ([`handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L240)), standard library request conversion ([`NewRequestFromStd`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L124)), HTTP/2 stream adapter ([`http2AdapterHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L313)), and HTTP/3 QUIC listener ([`ListenAndServeH3`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/server.go#L406)).
- **Traceability**: [`REQ-092-AC-02`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L89-L93), [`REQ-092-AC-03`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L94-L97), [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L131-L162), [`TASK-111`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-111.md#L74-L87).
- **Target Functions**:
  - `TestRequest_NewRequestFromStd_RemoteAddr(t *testing.T)` in `pkg/httpparser/request_test.go`
  - `TestServer_Ingress_RemoteAddrPopulation_H1(t *testing.T)` in `pkg/server/server_anti_spoofing_test.go`
  - `TestServer_Ingress_RemoteAddrPopulation_H2(t *testing.T)` in `pkg/server/server_anti_spoofing_test.go`
- **Preconditions**:
  - Mock [`net.Conn`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L68) with configurable remote address.
  - Initialized gateway server instance.
- **Action & Test Steps**:
  - **Subtest 2A: `httpparser.NewRequestFromStd`**:
    1. Create standard `http.Request` with `r.RemoteAddr = "192.0.2.10:44300"`.
    2. Convert via `req := httpparser.NewRequestFromStd(r)`.
    3. Assert `req.RemoteAddr == "192.0.2.10:44300"`.
  - **Subtest 2B: HTTP/1.1 Reactor `handleConn`**:
    1. Construct mock client socket `mockConn` with `RemoteAddr()` returning TCP address `"198.51.100.20:55555"`.
    2. Feed valid HTTP/1.1 request bytes (`GET / HTTP/1.1\r\nHost: example.com\r\n\r\n`) through `handleConn`.
    3. Capture the routed `httpparser.Request`.
    4. Assert `req.RawConn == mockConn` AND `req.RemoteAddr == "198.51.100.20:55555"`.
  - **Subtest 2C: HTTP/2 Stream Adapter `http2AdapterHandler`**:
    1. Set up test HTTP/2 handler via `s.http2AdapterHandler()`.
    2. Pass standard `http.Request` representing an HTTP/2 stream with `r.RemoteAddr = "198.51.100.30:60000"`, `r.Proto = "HTTP/2.0"`.
    3. Route request to capturing handler.
    4. Assert downstream receives `req.RemoteAddr == "198.51.100.30:60000"` and `req.RawConn == nil`.
- **Verifiable Assertions**:
  1. `req.RemoteAddr` is strictly populated across all ingress protocols.
  2. Protocol parity is established: physical connection identity is available irrespective of whether `req.RawConn` is present (HTTP/1.1) or nil (HTTP/2 multiplexed streams).

### TC-092-03: HTTP/2 WAF IP Access Control Anti-Spoofing

- **Objective**: Verify that WAF IP Access Control ([`pkg/waf/ip_acl.go:ExtractClientIP`](file:///Users/sneha/Developer/toron-research/toron/pkg/waf/ip_acl.go#L112-L164)) binds strictly to the physical remote connection address (`req.RemoteAddr`) on HTTP/2 requests, rejecting client-supplied spoofed headers (`X-Forwarded-For`, `X-Real-IP`). Verify that blacklisted clients cannot bypass ACLs, unlisted clients cannot bypass allowlists, and forwarded headers are evaluated if and only if the physical peer matches a configured `trusted_proxies` CIDR.
- **Traceability**: [`REQ-092-AC-04`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L98-L108), [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L168-L173), [`TASK-112`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-112.md#L70-L76), [`TASK-113`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-113.md#L80-L86), [`SEC-31`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L428-L436).
- **Target Functions**:
  - `TestServer_H2_WAF_SpoofingRejected(t *testing.T)` in `pkg/server/server_anti_spoofing_test.go`
  - `TestWAF_IPACL_AntiSpoofing(t *testing.T)` in `pkg/waf/ip_acl_test.go`
- **Preconditions**:
  - Toron server running with WAF enabled.
  - Gateway configured with IP Blacklist: `["198.51.100.99/32"]`.
  - Route `/secure/data` protected by WAF IP ACL middleware.
  - Gateway configured without trusted proxies (`trusted_proxies = nil`).
- **Action & Test Steps**:
  - **Subtest 3A: Blacklist Evasion Attempt via Spoofed `X-Forwarded-For`**:
    1. Attacker establishes HTTP/2 connection from physical IP `198.51.100.99:50000` (blacklisted).
    2. Attacker transmits HTTP/2 request: `GET /secure/data` with header `X-Forwarded-For: 203.0.113.1` (whitelisted/benign IP).
    3. Dispatch request through `http2AdapterHandler`.
  - **Subtest 3B: Blacklist Evasion Attempt via Spoofed `X-Real-IP`**:
    1. Attacker sends HTTP/2 request from physical IP `198.51.100.99:50000` with header `X-Real-IP: 203.0.113.1`.
  - **Subtest 3C: Allowlist Bypass Attempt**:
    1. Gateway configured with Allowlist: `["10.0.0.0/8"]`.
    2. External client connects from physical IP `203.0.113.50:45000` (unauthorized).
    3. Client sends `GET /secure/data` with `X-Forwarded-For: 10.1.2.3`.
  - **Subtest 3D: Trusted Proxy Delegation**:
    1. Gateway configured with `trusted_proxies: ["172.16.0.0/16"]`.
    2. Connection arrives from trusted proxy physical IP `172.16.1.1:40000`.
    3. Request carries `X-Forwarded-For: 198.51.100.99` (blacklisted client behind trusted CDN).
- **Verifiable Assertions**:
  1. In Subtest 3A, response status is `403 Forbidden`. The request is blocked because physical client `198.51.100.99` is blacklisted. The spoofed `X-Forwarded-For` is ignored.
  2. In Subtest 3B, response status is `403 Forbidden`. The spoofed `X-Real-IP` is ignored.
  3. In Subtest 3C, response status is `403 Forbidden`. External client cannot bypass allowlist by injecting internal IP headers.
  4. In Subtest 3D, response status is `403 Forbidden`. Client IP `198.51.100.99` is parsed from trusted proxy header and correctly blocked.
  5. Security audit finding `SEC-31` is verified resolved for WAF IP access control.

### TC-092-04: HTTP/2 Internal Management API Subnet Enforcement

- **Objective**: Verify that the Internal Management API security guard ([`pkg/server/internal_api.go:wrapHandler`](file:///Users/sneha/Developer/toron-research/toron/pkg/server/internal_api.go#L194-L224)) enforces administrative CIDR subnet policies against the physical remote address (`req.RemoteIP()`) on HTTP/2 requests. Untrusted clients attempting to spoof administrative IPs via `X-Forwarded-For` must be rejected with `403 Forbidden`.
- **Traceability**: [`REQ-092-AC-04`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L102-L105), [`REQ-092-AC-06`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L128-L131), [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L174-L179), [`TASK-112`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-112.md#L77-L83), [`TASK-113`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-113.md#L87-L93), [`SEC-31`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L428-L436).
- **Target Function**: `TestServer_H2_InternalAPI_SubnetEnforcement(t *testing.T)` in `pkg/server/server_anti_spoofing_test.go`.
- **Preconditions**:
  - Internal management API registered with admin subnet restriction: `AdminSubnets: ["10.50.0.0/16"]`.
  - Admin auth configured (`AdminToken: "admin-secret-token"`).
  - Target endpoint: `GET /internal/api/v1/health` or `GET /internal/api/v1/metrics`.
- **Action & Test Steps**:
  - **Subtest 4A: Untrusted External Client Spoofing Admin Subnet**:
    1. Client connects via HTTP/2 from external physical address `198.51.100.44:54321` (or loopback `127.0.0.1:54321`, outside `10.50.0.0/16`).
    2. Client sends valid admin token: `Authorization: Bearer admin-secret-token`.
    3. Client injects spoofed admin IP: `X-Forwarded-For: 10.50.1.1` and `X-Real-IP: 10.50.1.1`.
    4. Issue request through `http2AdapterHandler`.
  - **Subtest 4B: Legitimate Internal Admin Client**:
    1. Client connects from physical address `10.50.2.15:43210` (inside `10.50.0.0/16`).
    2. Client provides valid admin token: `Authorization: Bearer admin-secret-token`.
    3. Issue request through `http2AdapterHandler`.
  - **Subtest 4C: Trusted Proxy Forwarding Admin Traffic**:
    1. Server configured with `trusted_proxies: ["172.16.0.0/12"]`.
    2. Client connects from trusted proxy physical IP `172.16.0.10:30000`.
    3. Client sends header `X-Forwarded-For: 10.50.3.4` with valid admin credentials.
  - **Subtest 4D: Fail-Closed Default on Unresolvable Address**:
    1. Synthetic request with `req.RemoteAddr = ""` and `req.RawConn = nil`.
    2. Client sends header `X-Forwarded-For: 10.50.1.1`.
- **Verifiable Assertions**:
  1. In Subtest 4A, response code is `403 Forbidden` (`{"error":"403 Forbidden","message":"Access denied by administrative subnet policy"}`). Physical remote IP is evaluated; spoofed headers are disregarded.
  2. In Subtest 4B, response code is `200 OK` (access granted to verified internal physical subnet).
  3. In Subtest 4C, response code is `200 OK` (trusted proxy verified, forwarded client IP within admin CIDR).
  4. In Subtest 4D, response code is `403 Forbidden` (fail-closed invariant: missing/unresolvable addresses are denied access).

### TC-092-05: HTTP/2 Rate Limiter Anti-Spoofing & Single Bucket Containment

- **Objective**: Verify that Token Bucket Rate Limiting ([`pkg/router/rate_limiter.go:extractClientKeyInternal`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/rate_limiter.go#L286-L325)) eliminates the insecure `peerIsTrusted || req.RawConn == nil` vulnerability. For untrusted HTTP/2 connections, the client key must anchor strictly to `"ip:" + req.RemoteHost()`, containing attackers within a single rate limit bucket regardless of rotating `X-Forwarded-For`, `X-API-Key`, or `Authorization` headers.
- **Traceability**: [`REQ-092-AC-05`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-092.md#L109-L117), [`ADR-087`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-087.md#L180-L192), [`TASK-112`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-112.md#L84-L95), [`TASK-113`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-113.md#L94-L100), [`SEC-31`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L428-L436).
- **Target Functions**:
  - `TestServer_H2_RateLimiter_AntiSpoofing(t *testing.T)` in `pkg/router/rate_limiter_test.go`
  - `TestServer_H2_RateLimiter_Integration(t *testing.T)` in `pkg/server/server_anti_spoofing_test.go`
- **Preconditions**:
  - Route `/api/v1/search` protected by Token Bucket rate limiter with `Rate: 5 req/sec`, `Burst: 5`.
  - Trusted proxies not configured (`trusted_proxies = nil`).
- **Action & Test Steps**:
  - **Subtest 5A: Header Rotation Attack via `X-Forwarded-For`**:
    1. Single attacker on physical connection `req.RemoteAddr = "198.51.100.88:51000"` (HTTP/2, `RawConn == nil`).
    2. Attacker issues 10 rapid requests within 50ms, rotating `X-Forwarded-For` on each request:
       - Request 1: `X-Forwarded-For: 10.0.0.1`
       - Request 2: `X-Forwarded-For: 10.0.0.2`
       - ...
       - Request 10: `X-Forwarded-For: 10.0.0.10`
    3. Route through rate limiter middleware.
  - **Subtest 5B: Header Rotation Attack via `X-API-Key`**:
    1. Single attacker on `req.RemoteAddr = "198.51.100.88:51000"`.
    2. Attacker issues 10 rapid requests rotating `X-API-Key: user_1`, `X-API-Key: user_2`, etc.

## 5. Security & Architectural Invariants

1. **Physical Binding Invariant**:
   Client network identity in security-critical components is anchored to the physical network connection (`req.RemoteAddr` / `req.RemoteIP()`) established at transport listener ingress.
2. **Strict Trusted Proxy Gating**:
   Client-supplied forwarded headers (`X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`) are untrusted by default and MUST ONLY be evaluated if the physical client IP matches an explicitly configured `trusted_proxies` CIDR.
3. **Fail-Closed Default**:
   If client network identity cannot be extracted or verified, administrative endpoints MUST deny access with `403 Forbidden`, and WAF allowlists MUST fail closed.
4. **Architectural Separation Invariant**:
   Security authorization (`waf`, `internal_api`, `rate_limiter`, `proxy`, `logging`) enforces physical binding. Application traffic steering ([`pkg/proxy/sticky.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/sticky.go)) preserves client-level headers for mobile session resilience under [`REQ-030`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-030.md).
5. **Standard Library Only**:
   Strictly zero third-party dependencies; standard library packages only (`testing`, `net`, `net/http`, `sync`, `time`, `strings`).
