# REQ-024 - WebSocket Protocol Upgrade and Reverse Proxy Tunneling Support

## Description

The Toron web server shall support HTTP/1.1 WebSocket protocol upgrades (RFC 6455). This includes detecting `Upgrade: websocket` and `Connection: Upgrade` headers, performing 101 Switching Protocols handshakes, and providing transparent bi-directional TCP socket stream forwarding between clients and upstream microservice targets.

## Acceptance Criteria

- `pkg/httpparser`: `Request` exposes `IsWebSocketUpgrade()` to detect WebSocket handshake headers (`Connection: Upgrade`, `Upgrade: websocket`).
- `pkg/proxy`: `ReverseProxy` supports WebSocket tunneling by establishing a raw TCP connection to the upstream target, forwarding the upgrade request, verifying `101 Switching Protocols`, and performing bi-directional TCP stream copy (`io.Copy`).
- `pkg/server`: `Server.handleConn` detects upgraded connection responses and handles TCP socket hijacking without enforcing HTTP request deadlines during active WebSocket sessions.
- Upstream load balancing and health checking apply to WebSocket initial upgrade handshakes.
- All Go unit tests pass cleanly.

## Rationale

Modern real-time applications (web chats, live data feeds, dashboards, interactive gaming, and notification services) require persistent, low-latency, full-duplex WebSocket connections multiplexed or proxied through the API gateway.
