# TC-137: Test Cases for Dashboard Datetime Formatting, Alert/Ban Ordering, and Request Telemetry

## TC-137.1: Active Alerts Datetime Rendering and Latest-First Sorting
- **Given**: Multiple alerts exist across categories (security incidents, banned actors, certificate warnings, upstream degradation).
- **When**: Navigating to `#/alerts` or viewing the Overview active alerts widget.
- **Then**:
  - Alerts are rendered in descending chronological order (most recent at top).
  - Each alert displays the full formatted date and timestamp (e.g. `2026-09-22 07:50:12`).

## TC-137.2: Banned IP Creation Date and Ordering
- **Given**: Banned IPs exist in `/internal/api/security/banned-ips` with differing `created_at` timestamps.
- **When**: Navigating to `#/alerts` (Threat Defense Table).
- **Then**:
  - The table contains a "Created At" column displaying `YYYY-MM-DD HH:MM:SS`.
  - The rows are ordered with the most recently created ban at the top.

## TC-137.3: Live Requests Table Datetime and Source IP
- **Given**: Request log entries exist in `rawApiLogs` / live tail.
- **When**: Navigating to `#/logs` (Live Requests & Logs).
- **Then**:
  - The "Time" column displays the full date and time (`YYYY-MM-DD HH:MM:SS`).
  - The "Source IP" column displays the client IP address (e.g. `136.67.240.107`).
  - Clicking any request row opens the drawer displaying the full datetime and Client IP.
