# TC-069 - Verification of Strict CORS Origin Validation and Prohibit Credentialed Wildcards

## Objective

Verify that CORS configuration validation rejects the dangerous combination of `allow_credentials: true` with wildcard origins (`*`), that runtime origin matching prohibits wildcard matching when credentials are enabled, and that `Vary: Origin` is consistently appended whenever origin-based CORS evaluation takes place.

## Test Cases

### TC-069-01: Configuration Validation of Credentialed Wildcards
- **Setup**: Define a CORS configuration with `allow_credentials: true` and `allow_origins: ["*"]`.
- **Action**: Pass configuration to `ValidateCORSConfig` and `ValidateConfig`.
- **Expected Outcome**:
  - Validation fails returning `ErrInsecureCORSCredentialsWildcard` or descriptive error message.
  - Server startup/configuration reload is rejected.

### TC-069-02: Runtime Disallowance of Credentialed Wildcard Matching
- **Setup**: Construct CORS middleware with `allow_credentials: true` and `allow_origins: ["*"]`.
- **Action**:
  - Send preflight OPTIONS request with `Origin: https://evil.com`.
  - Send GET request with `Origin: https://evil.com`.
- **Expected Outcome**:
  - Preflight request is rejected with `403 Forbidden` and `Vary: Origin`.
  - GET request does not reflect `Origin` in `Access-Control-Allow-Origin`.

### TC-069-03: Consistent Vary: Origin Emission
- **Setup**: Send requests with `Origin` header present (both preflight and simple requests, allowed and disallowed).
- **Action**: Evaluate response headers.
- **Expected Outcome**:
  - `Vary` header contains `Origin` in all cases, preserving cache safety.
