# ADR-114 - High-Concurrency Saturation Stress Testing Harness Architecture (BMK-04)

## 1. Context & Problem Statement

In academic peer review of Paper 2, reviewers raised significant methodological critiques regarding Toron's performance under adversarial saturation (`AER-002` lines 288–291, `MSR-002` lines 239–245 & 298–301):

1. **The Sequential Single-Socket Evaluation Flaw**:
   Prior invariant security benchmarking (`diff_fuzzer.go`) evaluated test cases sequentially across single sockets. While effective for functional invariant validation, single-socket probing cannot induce concurrency contention, socket queueing, or event loop saturation.
2. **Tail Latency Masking & Coordinated Omission**:
   Table 3 in the manuscript reported only mean rejection latency (~298 $\mu$s), omitting high-order tail percentiles ($p95, p99, p99.9$). In high-performance edge gateways, mean latencies obscure long-tail latency spikes induced by lock contention or expensive regex evaluations.
3. **Event Loop Starvation Risk**:
   Reviewers questioned whether active defense mechanisms—such as deep header token validation (RFC 7230 §3.2), WAF scanning, and fail-fast transport socket terminations (`REQ-107`)—starve concurrent legitimate requests or exhaust reactor worker pools (`REQ-111`).

---

## 2. Decision

We establish an automated **High-Concurrency Saturation Stress Testing Harness** based on `benchmarks/wrk2/loadgen.go` embodying the following architectural principles:

```

                        │      High-Precision Rate Pacer (Ticker / Channel)      │
                        │               Target: 5,000+ Req / Sec                 │
                        └──────────────────────────┬─────────────────────────────┘
                                                   │
                                                   ▼
                        ┌────────────────────────────────────────────────────────┐
                        │       Concurrent Load Generator Worker Pool (N=50)     │
                        └───────────┬────────────────────────────────┬───────────┘
                                    │                                │
                     (1 - α) = 90%  │                                │  α = 10%
                     Benign Traffic │                                │  Adversarial Injection

                        ┌────────────────────────┐      ┌────────────────────────┐

                        │  (RFC 7230 Compliant)  │      │    through ADV-08      │
                        └───────────┬────────────┘      └────────────┬───────────┘
                                    │                                │
                                    └────────────────┬───────────────┘
                                                     │
                                                     ▼
                                        ┌────────────────────────┐
                                        │   Toron Edge Gateway   │
                                        │  (Port 8080 / Reactor) │
                                        └────────────┬───────────┘

                        └────────────────────────┘      └────────────────────────┘
```

### 2.1 Decoupled Dual-Stream Telemetry
To prevent conflating $400\text{ Bad Request}$ fast-fail rejection times with legitimate $200\text{ OK}$ service times, telemetry is strictly partitioned into two independent measurement pipelines:
- **Benign Stream ($S_{\text{benign}}$)**:
  - Tracks round-trip service latencies for legitimate traffic.
  - Measures sample distribution: Min, Mean, $p50, p75, p90, p95, p99, p99.9, \text{Max}$.
  - Computes throughput (requests/second and MB/s).
- **Adversarial Stream ($S_{\text{attack}}$)**:
  - Tracks rejection latencies for malformed protocol probes.
  - Asserts that 100.0% of attack probes are intercepted with status $400, 403$, or $413$.
  - Asserts that bypass count is strictly `0`.

### 2.2 Constant-Rate Pacing & Coordinated Omission Mitigation
The harness utilizes a centralized token ticker (`time.NewTicker(time.Second / targetRate)`) coordinating all worker goroutines. When the server experiences transient latency spikes, request attempts accumulate deterministically, ensuring that tail latency measurements reflect true queueing delay rather than artificially throttled request generation.

### 2.3 Adversarial Attack Catalog
Workers probabilistically select an attack vector from a curated catalog when assigned an adversarial slot:
1. `ADV-01`: Conflicting `Content-Length` and `Transfer-Encoding: chunked` (CWE-444 / CL.TE).
2. `ADV-02`: Obfuscated whitespace preceding colon in `Transfer-Encoding : chunked` (RFC 7230 §3.2.4).
3. `ADV-03`: Non-token character in header name (`X-Header@Bad: val`, RFC 7230 §3.2).
4. `ADV-04`: CRLF injection in header value (`X-Custom: val\r\nInjected: evil`).
5. `ADV-05`: Duplicate conflicting `Content-Length` headers (`5` and `10`).
6. `ADV-06`: Path traversal probe attempting canary escape (`GET /../../canary_traversal.txt`).
7. `ADV-07`: Oversized request header block exceeding 8 KB limit.
8. `ADV-08`: Null byte injection in URI path (`GET /health%00evil`).

### 2.4 Zero-Starvation Invariant Bound
Under sustained 5,000+ RPS with 10% concurrent attack injection:
- The benign $p99$ tail latency must remain bounded: $p99 \le 50.0$ ms (target $< 10.0$ ms over local loopback).
- Legitimate request error rate must be $0.0\%$.

## 3. Consequences & Invariants

- **Zero External Dependencies**: Implemented strictly in pure Go standard library.
- **Publication Artifacts**: Auto-generates `saturation_stress_report.json` and `saturation_stress_report.md`.
- **Thread Safety**: All sample collections utilize thread-confined worker buffers, aggregated post-run without lock contention.
- **Academic Rigor**: Formally refutes the wire-rate overhead critique in `AER-002` lines 288–291 and `MSR-002` lines 239–245.
