# SR-079 - Security Review of Request Body Preservation in Sidecar Proxy Engine

## Description

Security evaluation of the implementation for `TASK-081` / `SEC-21` (Request payload dropping in sidecar proxy engine for mutating requests).

## Scope

- Files reviewed:
  - `pkg/sidecar/proxy.go`
  - `pkg/sidecar/sidecar_test.go`

## Security Evaluation & Analysis

1. **Restoration of Request Payload Integrity (CWE-436)**:
   - Previously, `httpparser.NewRequestFromStd(r)` initialized `toronReq.Body` with an empty reader, causing `proxyToURL` to forward empty payloads on POST, PUT, and PATCH operations.
   - Refactored `proxyToURL` in `pkg/sidecar/proxy.go` to read `r.Body` using `io.LimitReader` bounded by a safe 10 MB payload limit.
   - Assigned `toronReq.Body = bytes.NewReader(bodyBytes)` and set `toronReq.ContentLength = int64(len(bodyBytes))`.
2. **Resource Exhaustion & Leak Prevention**:
   - Closed `r.Body` promptly with `defer r.Body.Close()`.
   - Capped memory ingestion to prevent heap exhaustion attacks through the sidecar proxy.
3. **Exploit Verification**:
   - TC-081-01 verified: JSON POST body (`{"account":"123","amount":500}`) is forwarded intact to upstream targets.
   - TC-081-02 verified: Empty GET requests execute without unnecessary buffer allocations.

## Conclusion

`SEC-21` is fully mitigated. Request body dropping in the sidecar proxy is resolved. Approved.
