# REQ-059 - Upstream Reverse Proxy Path Rewriting and Subpath Target Preservation

## Description

The Toron edge gateway and reverse proxy shall accurately map and rewrite client request paths when proxying to upstream target URLs that contain explicit subpaths (e.g. `http://127.0.0.1:8082/postback` or `http://upstream-svc:8080/v1/api`).

Currently, when `strip_prefix: true` is enabled on a route whose `target` defines a subpath without a trailing slash, requesting the exact prefix unintentionally causes a trailing slash to be appended to the upstream request path (e.g. `/postback/` instead of `/postback`), causing strict REST frameworks and Go standard library `http.ServeMux` handlers to reject the request with HTTP 404.

Toron shall cleanly preserve exact path parity without unsolicited trailing slashes, while preserving client-provided trailing slashes and correctly joining subpaths.

## Acceptance Criteria

### 1. Exact Prefix Match to Subpath Target
- When an upstream route defines a prefix (e.g. `prefix: "/kite/postback"`) and an upstream target containing a path without a trailing slash (e.g. `target: "http://127.0.0.1:8082/postback"`), an incoming client request matching the exact prefix (`POST /kite/postback`) with `strip_prefix: true` shall forward to the upstream target path verbatim (`POST /postback`), without appending a trailing slash.

### 2. Client Trailing Slash Preservation
- If the incoming client request explicitly contains a trailing slash (`POST /kite/postback/`), the proxy shall forward the request with the trailing slash (`POST /postback/`).
- If the upstream target URL was explicitly defined with a trailing slash in configuration (e.g. `target: "http://127.0.0.1:8082/postback/"`), the proxy shall preserve the trailing slash regardless.

### 3. Nested Subpath Append
- When a client requests nested subpaths under the prefix (e.g. `GET /kite/postback/status`), the trimmed relative path (`/status`) shall be joined cleanly to the target path without duplicate or missing slashes (`/postback/status`).

### 4. Root & Non-Subpath Target Parity
- Upstream targets without subpaths (e.g. `http://127.0.0.1:8080` or `http://127.0.0.1:8080/`) shall continue to forward exact prefix hits to `/` (or relative paths) without regressions.
- When `strip_prefix: false` is configured, the full original request path shall be forwarded to the upstream target, joining cleanly with any target subpath.

### 5. WebSocket and HTTP/2/3 Compatibility
- All path rewriting rules shall apply identically across HTTP/1.1, HTTP/2, HTTP/3, and WebSocket upgrade proxying.
