# REQ-063 - Shared HTTP Response Cache Security, Session Cookie Isolation, and Authorization Boundaries

## Description

The Toron in-memory HTTP response caching middleware shall strictly adhere to RFC 7234 shared caching security boundaries to prevent cross-user session cookie leakage, credential caching, and cache poisoning.

The cache engine shall guarantee that private credentials, session identifiers, and user-specific authenticated payloads are never saved in shared memory or served to different clients.

## Acceptance Criteria

### 1. Exclusion of `Set-Cookie` from Cached Responses
- In compliance with RFC 7234 §8, the response cache shall strip all `Set-Cookie` response headers before caching a response snapshot.
- No cached response returned on a cache hit (`X-Cache: HIT`) shall ever emit a `Set-Cookie` header to downstream clients.

### 2. Authorization Boundary Enforcement
- Requests bearing an `Authorization` request header shall not be satisfied by a cached response unless the upstream response explicitly declares `Cache-Control: public` (per RFC 7234 §3.2).
- Responses to requests containing `Authorization` headers shall not be stored in the shared cache unless explicit public cache directives are present.

### 3. Cache Key Partitioning & RFC Directives
- The cache key shall incorporate all necessary variance dimensions.
- The cache shall strictly honor `Cache-Control: private`, `no-store`, and `no-cache` directives from upstream servers, discarding the response immediately upon detecting private directives.

### 4. Vary Header Honoring
- If an upstream response declares a `Vary` header (e.g. `Vary: Accept-Encoding` or `Vary: Origin`), the cache shall either incorporate the requested header value into the cache key or refrain from caching the response.

## Rationale

Shared caches that blindly clone all response headers risk saving `Set-Cookie` session tokens, leading to session hijacking and account takeover when a second user requests the same resource.

## Constraints

- Compliance with RFC 7234 §3.2 and §8.
- Zero-allocation memory snapshots where possible.

## Open Questions

- Should an option be provided to cache user-specific responses keyed by user ID for specific routes?
