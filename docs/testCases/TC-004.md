# TC-004 - Security Limits & Timeout Handling Verification

## Description

Verify that requests exceeding maximum header size (8KB) or body size (4MB) are rejected with appropriate HTTP error status codes, and connection read timeouts terminate idle connections.

## Preconditions

- Server configured with MaxHeaderBytes = 8192, MaxBodyBytes = 4194304, ReadTimeout = 100ms.

## Test Data

- Oversized Header Request (9KB header string).
- Oversized Payload Request (5MB payload body).
- Slowloris request (sending 1 byte per 200ms).

## Steps

1. Send request with 9KB header -> Verify response is `400 Bad Request` or `431 Request Header Fields Too Large`.
2. Send request with 5MB body -> Verify response is `413 Payload Too Large`.
3. Open connection and delay sending bytes beyond ReadTimeout -> Verify connection is closed by server timeout guard.

## Expected Results

- Oversized payloads and slow clients are rejected or timed out without crashing server or consuming unallocated memory.

## Acceptance Criteria

- All security limits enforced as expected.

## Rationale

Verifies defense against DoS and memory exhaustion attacks.

## Constraints

- Integration test in `pkg/server`.
