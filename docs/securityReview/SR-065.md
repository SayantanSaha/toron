# SR-065 - Security Review of Wire Frame Size Bounding and Buffer Allocation Protection in gRPC Transcoder

## Description

Security evaluation of the implementation for `TASK-068` / `SEC-08` (Unbounded memory allocation in gRPC wire frame decoder).

## Scope

- Files reviewed:
  - `pkg/transcoder/framer.go`
  - `pkg/transcoder/transcoder.go`
  - `pkg/transcoder/transcoder_test.go`

## Security Evaluation & Analysis

1. **Denial-of-Service & Uncontrolled Memory Allocation Mitigation (CWE-789)**:
   - Previously, `DecodeGRPCFrame` trusted the 4-byte `uint32` wire length directly and called `make([]byte, length)`. A malicious or corrupted upstream service sending `length = 0xFFFFFFFF` could allocate 4 GB, triggering an OOM kill or process crash.
   - Now, `DecodeGRPCFrameWithLimit` inspects `length` before any allocation. If `length > maxFrameSize` (defaulting to 4 MB `DefaultMaxGRPCFrameSize`), the function immediately aborts with `ErrFrameTooLarge`.
2. **Graceful Upstream Error Propagation**:
   - In `pkg/transcoder/transcoder.go`, when an upstream service returns an oversized payload, the engine intercepts `ErrFrameTooLarge`, sets HTTP status to `502 Bad Gateway`, and writes an explicit error payload, keeping the server responsive without panic.
3. **Exploit Verification**:
   - Tested frame header declaring 4 GB payload: was rejected instantly with `ErrFrameTooLarge` with zero memory allocation.
   - Tested upstream proxy sending 10 MB payload against default 4 MB cap: was rejected cleanly with `502 Bad Gateway`.

## Conclusion

`SEC-08` is completely resolved. gRPC wire frame allocation denial-of-service vulnerability is mitigated. The implementation is approved.
