# REQ-075 - Stored Cross-Site Scripting (DOM XSS) Elimination in Security Control Center

## Description

The Toron Security Control Center frontend web interface (`public/app.js`) shall eliminate unsafe HTML rendering and prevent Stored DOM-based Cross-Site Scripting (DOM XSS / CWE-79) when displaying security incident audit logs and dynamic route metadata.

## Acceptance Criteria

### 1. Secure Contextual Encoding & DOM Text Nodes
- In `public/app.js`, all user-controlled incident fields (`inc.path`, `inc.client_ip`, `inc.rule_id`, `inc.timestamp`) shall be rendered using safe DOM APIs (such as `Node.textContent` or explicit HTML entity sanitization).
- Raw string interpolation into `tbody.innerHTML` containing unsanitized request URIs or client IP addresses shall be completely eliminated.

### 2. Route Label and Metadata Sanitization
- Discovered container route fields (`r.container_name`, `r.prefix`, `r.host`) rendered in dynamic UI lists shall be sanitized or escaped prior to DOM insertion.

### 3. Attack Verification
- Transmitting attack payloads (e.g. `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`, `javascript:`) that trigger WAF audit events shall render harmlessly as literal text in the incident table without executing JavaScript.

## Rationale

The administrative dashboard displays real-world attack traffic logged by the WAF. If unescaped, an attacker can intentionally trigger a WAF alert containing an XSS payload, resulting in execution in the browser of any security administrator inspecting the dashboard.

## Constraints

- Zero external frontend dependencies; vanilla JavaScript.
- Retain existing Tailwind CSS layout and visual presentation.
