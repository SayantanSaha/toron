# REQ-084 - K8s Ingress Controller Watch Stream Concurrency, Event Processing, and Deadlock Prevention

## Description

The native Kubernetes Ingress Controller (`pkg/ingress`) MUST maintain robust, non-blocking concurrency across HTTP streaming watch connections (`?watch=true`), continuously process Ingress lifecycle events (`ADDED`, `MODIFIED`, `DELETED`), and guarantee fail-safe cancellation during server shutdown, eliminating the channel deadlock and goroutine leak vulnerabilities identified in `SEC-23`.

## Problem Statement

In `pkg/ingress/controller.go`, `Controller` creates a buffered channel `events: make(chan K8sWatchEvent, 100)` and invokes `WatchIngresses` on the client. However:
1. No worker goroutine reads from `c.events`.
2. When more than 100 events are received from the Kubernetes API server, `WatchIngresses` blocks indefinitely on the naked send `events <- evt`.
3. Because context cancellation is only checked at the head of the read loop, cancelling the context cannot unblock the stuck send.
4. During shutdown, `Controller.Stop()` hangs indefinitely in `c.wg.Wait()`, causing severe Denial of Service on server reload/stop.
5. Ingress lifecycle changes occurring in the cluster are never processed reactively.

## Acceptance Criteria

1. **Non-Blocking / Cancellable Event Transmission (`pkg/ingress/client.go`)**:
   - `WatchIngresses` MUST NOT perform naked channel sends (`events <- evt`).
   - Every send to `events` MUST be wrapped in a `select` statement that listens on `<-ctx.Done()` to guarantee immediate cancellation and prevent producer goroutine freezing.

2. **Dedicated Event Consumer Loop (`pkg/ingress/controller.go`)**:
   - `Controller.Start` MUST launch a dedicated consumer worker (`consumeEventsWorker`) tracked in `c.wg`.
   - The consumer worker MUST continuously drain `c.events` and trigger route synchronization (`syncIngresses`) upon receiving lifecycle events (`ADDED`, `MODIFIED`, `DELETED`).
   - The consumer worker MUST implement a debounce mechanism (e.g., 25ms–50ms) to coalesce rapid bursts of Ingress watch events into efficient batch synchronization, preventing thundering-herd route table updates.

3. **Graceful Shutdown & Zero-Deadlock Teardown**:
   - Calling `Controller.Stop()` MUST cleanly terminate both the watch producer worker (`watchWorker`) and the event consumer worker (`consumeEventsWorker`).
   - `c.wg.Wait()` MUST return within a strict timeout (less than 100ms) even when the watch stream is receiving high-frequency events or the channel buffer is saturated (>100 events).
   - No goroutine or network socket leaks are permitted upon controller termination.

4. **Backward Compatibility & Invariants**:
   - Existing Ingress translation, prefix routing, and zero-dependency guarantees MUST remain fully intact.
   - All tests in `pkg/ingress` and across the entire repository MUST pass race-clean (`go test -race`).
