# REQ-089 - Bounded Request Body Ingestion and 413 Payload Too Large Rejection in REST-to-gRPC Transcoder

## Description

The Toron REST-to-gRPC Transcoding Engine ([`Engine`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L24)) MUST enforce strict, configurable upper bounds on incoming HTTP request bodies across all REST-to-gRPC transcode routes. When an incoming request body exceeds the configured maximum byte ceiling—either via an oversized declared `Content-Length` header or via continuous streaming/chunked body transfer—the transcoder MUST fast-fail and reject the request immediately with `HTTP 413 Payload Too Large` in JSON format. The transcoder MUST abort further reading, prevent heap allocation and JSON unmarshaling, and ensure zero payload leakage to the upstream gRPC backend. This completely remediates vulnerability [`SEC-28`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L393-L401) ([CWE-400](https://cwe.mitre.org/data/definitions/400.html), [CWE-770](https://cwe.mitre.org/data/definitions/770.html)), eliminating Denial-of-Service (DoS) and Out-Of-Memory (OOM) crash vectors.

## Problem Statement

As documented in [`SEC-28`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L393-L401) and [`SR-081 Finding 6`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L151-L160), [`Engine.HandleTranscode`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L89) in `pkg/transcoder/transcoder.go` performs unbounded request body reads without size ceilings:

### 1. Unbounded Ingestion via `io.ReadAll` ([`pkg/transcoder/transcoder.go:L93-L103`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L93-L103))
```go
// 1. Parse JSON body if present
if req.Body != nil {
    bodyBytes, err := io.ReadAll(req.Body)
    if err == nil && len(bodyBytes) > 0 {
        var bodyMap map[string]interface{}
        if err := json.Unmarshal(bodyBytes, &bodyMap); err == nil {
            for k, v := range bodyMap {
                payloadMap[k] = v
            }
        }
    }
}
```
- When a client sends a multi-megabyte or multi-gigabyte payload (or an endless trickle stream), `io.ReadAll(req.Body)` repeatedly grows internal slice buffers on the Go heap without upper bounds.
- If the host system or container memory limit (cgroup) is exceeded, the operating system kernel terminates the Toron process via `SIGKILL 9` (OOM Killer), inducing a full denial-of-service outage across all listeners, proxy routes, and edge gateway services.

### 2. Multiplicative Heap Pressure via `json.Unmarshal`
- Once unbounded bytes are read into memory, `json.Unmarshal` instantiates recursive maps and arbitrary interface allocations (`map[string]interface{}`), increasing heap consumption by 3x to 5x beyond the raw payload size.

### 3. Missing `Content-Length` Header Fast-Fail Guard
- [`httpparser.Request`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/request.go#L58) already parses and populates `req.ContentLength int64`. If a client sends an explicit oversized header (e.g. `Content-Length: 10737418240` - 10 GB), [`HandleTranscode`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L89) fails to inspect this value before attempting to ingest the body.

### 4. Missing Configuration Schema & Default Limits
- [`TranscoderConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L130-L133) in `pkg/config/config.go` lacks a `MaxBodyBytes` field. While [`SidecarConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) (10 MB, [`SEC-25`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L366-L374)) and [`ServerConfig.MaxBodyBytes`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) (4 MB) enforce limits elsewhere, the REST-to-gRPC transcoder has zero configurable ceilings.

### 5. Asymmetry with Downstream Frame Decoding
- Downstream gRPC response decoding is protected by [`DefaultMaxGRPCFrameSize`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/framer.go#L11) (`4 MB`, remediated in `SEC-08`), but upstream REST body ingestion has no matching limit.

## Acceptance Criteria

### 1. Configurable Transcoder Request Body Limit Schema (`MaxBodyBytes`)
- [`TranscoderConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L130-L133) in `pkg/config/config.go` MUST include:
  - `MaxBodyBytes int64` (`yaml:"max_body_bytes,omitempty" json:"max_body_bytes,omitempty"`).
- Helper method `GetMaxBodyBytes() int64` MUST be provided on `TranscoderConfig`:
  - If `MaxBodyBytes > 0`, return `MaxBodyBytes`.
  - Otherwise, return default limit of `4 * 1024 * 1024` (4 MB / 4,194,304 bytes), aligning with [`DefaultMaxGRPCFrameSize`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/framer.go#L11).
- [`DefaultAppConfig()`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) MUST initialize `Transcoder.MaxBodyBytes = 4 * 1024 * 1024` (4 MB).
- [`Engine`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L24) struct in `pkg/transcoder/transcoder.go` MUST store `maxBodyBytes int64`. In `NewEngine()`, if `cfg.GetMaxBodyBytes() <= 0`, default to `4 * 1024 * 1024`.
- [`pkg/config/loader.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/loader.go) MUST validate that `cfg.Transcoder.MaxBodyBytes >= 0`. If negative, config loading MUST return a descriptive validation error.

### 2. Fast-Fail Rejection on Declared `Content-Length`
- In [`Engine.HandleTranscode`](file:///Users/sneha/Developer/toron-research/toron/pkg/transcoder/transcoder.go#L89), prior to reading `req.Body`:
  - If `req.ContentLength > maxBodyBytes && req.ContentLength > 0`:
    - The server MUST immediately reject the request with `http.StatusRequestEntityTooLarge` (HTTP 413).
    - The response header `Content-Type` MUST be set to `application/json`.
    - The response body MUST contain:
      `{"error":"Payload Too Large: request Content-Length %d exceeds limit of %d bytes"}` (formatted with actual values).
    - If `req.Body` implements `io.Closer`, it MUST be closed.
    - Execution MUST return immediately.
    - Zero gRPC requests MUST be sent to the upstream backend.

### 3. Bounded Stream Over-Read Protection & 413 Rejection
- For chunked transfers or requests where `Content-Length` is omitted, zero, or within declared limits but actual stream bytes exceed the limit:
  - Reading MUST be bounded using `io.LimitReader(req.Body, maxBodyBytes+1)`.
  - If the bytes read from the limited reader exceed `maxBodyBytes`:
    - The server MUST immediately reject the request with `http.StatusRequestEntityTooLarge` (HTTP 413).
    - The response header `Content-Type` MUST be set to `application/json`.
    - The response body MUST contain:
      `{"error":"Payload Too Large: request body exceeds limit of %d bytes"}`.
    - The read bytes MUST NOT be passed to `json.Unmarshal`.
    - Execution MUST return immediately.
    - Zero gRPC requests MUST be sent to the upstream backend.

### 4. Non-Mutating Requests and Full-Fidelity In-Limit Body Forwarding
- Requests with `req.Body == nil` or empty bodies (e.g. `GET`, `DELETE` with path parameters) MUST continue to be handled without error.
- Requests with body size $\le \text{maxBodyBytes}$ MUST be read, parsed as JSON, encoded into the 5-byte gRPC wire frame, and forwarded to the upstream gRPC target without corruption or byte alteration.

### 5. Memory Safety & Resource Cleanup
- Over-read checks MUST NOT allocate more than `maxBodyBytes + 1` bytes into memory during rejection, completely preventing memory explosion under gigabyte-scale attack streams.
- Any opened socket or body reader associated with rejected requests MUST be cleanly closed or discarded to prevent connection leaks.

### 6. Zero Third-Party Dependencies & Concurrency Safety
- Implementation MUST use strictly the Go standard library (`io`, `net/http`, `encoding/json`, `fmt`, `sync`).
- Must be 100% race-clean and verified under `go test -race ./pkg/transcoder/...`.
