# REQ-009 - Reverse Proxy and Upstream Request Forwarding

## Description

The Toron server shall provide reverse proxy functionality to forward incoming HTTP requests matching specified path prefixes to designated upstream backend servers (`http://host:port`), returning the upstream response back to the client.

## Acceptance Criteria

- `ReverseProxy` handler created in `pkg/proxy` (and exposed via `router.Proxy(prefix, targetURL)`).
- Forwards HTTP method, request URI, query parameters, headers, and request body to upstream target server.
- Injects standard reverse proxy HTTP headers: `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Real-IP`.
- Supports configuring reverse proxy routes in `config.yaml` (`proxy.routes`).
- Enforces configurable upstream connection timeouts to prevent proxy hangs.
- Sanitizes sensitive proxy headers and handles upstream connection errors gracefully (`502 Bad Gateway`).

## Rationale

Allows Toron to act as an edge gateway / reverse proxy, routing client traffic to backend microservices.

## Constraints

- Must handle HTTP streaming bodies without buffering unbounded payloads in memory.
