# TC-068 - Verification of Wire Frame Size Bounding and Buffer Allocation Protection in gRPC Transcoder

## Objective

Verify that `DecodeGRPCFrame` and `DecodeGRPCFrameWithLimit` enforce an upper bound on incoming gRPC wire frame payload lengths before allocating memory buffers, preventing Out-Of-Memory (OOM) heap exhaustion and denial-of-service crashes from malicious or corrupted upstream frames.

## Test Cases

### TC-068-01: Default Maximum Frame Size Rejection
- **Setup**: Construct a synthetic 5-byte gRPC wire frame header declaring a payload length of `0xFFFFFFFF` (4 GB).
- **Action**: Invoke `DecodeGRPCFrame(reader)`.
- **Expected Outcome**:
  - `DecodeGRPCFrame` returns `ErrFrameTooLarge` immediately.
  - Zero payload memory buffers are allocated.
  - No OOM crash or memory panic occurs.

### TC-068-02: Configurable Frame Limit Validation
- **Setup**: Encode a legitimate frame with an 11-byte payload.
- **Action**:
  - Call `DecodeGRPCFrameWithLimit(reader, 5)` (limit < payload size).
  - Call `DecodeGRPCFrameWithLimit(reader, 100)` (limit >= payload size).
- **Expected Outcome**:
  - Call 1 returns `ErrFrameTooLarge`.
  - Call 2 successfully extracts and returns the payload bytes.

### TC-068-03: Transcoder Upstream Oversized Frame Handling
- **Setup**: Configure a transcoder route pointing to an upstream gRPC server mock that emits an oversized wire frame header (10 MB > 4 MB default).
- **Action**: Dispatch HTTP client request to transcoded endpoint.
- **Expected Outcome**:
  - Transcoder detects `ErrFrameTooLarge`.
  - Returns `HTTP 502 Bad Gateway` with JSON error structure.
  - Gateway remains operational and uncorrupted.
