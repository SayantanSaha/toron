# ADR-025 - Sticky Session Load Balancing Architecture (sticky_cookie & ip_hash)

## Context

Stateful web applications require sticky sessions (session affinity) so that requests from a specific user or client device consistently hit the same backend server.

## Decision

1. **Algorithm Expansion (`pkg/proxy/proxy.go`)**:
   - Add `AlgorithmStickyCookie Algorithm = "sticky_cookie"`
   - Add `AlgorithmIPHash Algorithm = "ip_hash"`

2. **Cookie-Based Session Affinity (`StickyCookieBalancer`)**:
   - Computes a deterministic target identifier hash for each backend (e.g., MD5/SHA256 truncated hash of target URL).
   - Inspects client `Cookie` header for `TORON_STICKY=<target_hash>` (or custom configured `sticky_cookie_name`).
   - If cookie matches a healthy target (`StateClosed` or `StateHalfOpen`), selects that target.
   - If cookie is missing or target is unhealthy (`StateOpen`), selects next available target via round-robin, and instructs `ReverseProxy` to attach `Set-Cookie: <cookie_name>=<target_hash>; Path=/; HttpOnly` to response headers.

3. **Client IP Hash Affinity (`IPHashBalancer`)**:
   - Hashes client IP address using FNV-1a hash algorithm: `hash(clientIP) % len(healthyTargets)`.
   - Ensures consistent target selection without relying on HTTP cookies.

4. **Health Check & Circuit Breaker Interoperability**:
   - Sticky balancers filter candidates against `target.GetState()`. Unhealthy nodes are bypassed automatically until they recover (`HalfOpen` -> `Closed`).

## Consequences

- **Positive**: Full support for stateful web apps, shopping carts, and persistent user sessions; graceful fallback when pinned backend servers fail.
- **Flexibility**: Supports both cookie-based affinity for HTTP web traffic and IP hashing for cookie-less/L4 clients.
