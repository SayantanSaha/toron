# SR-034 - Security Review of Per-Host Dynamic SNI Certificate Mapping & mTLS Client Auth

## Scope

Security audit of dynamic SNI host profile lookup, Mutual TLS (mTLS) client certificate verification (`RequireAndVerifyClientCert`), `CertPool` integrity, and per-host TLS 1.3 protocol enforcement in [`pkg/server/sni.go`](file:///D:/Work/server/pkg/server/sni.go) and [`pkg/server/tls.go`](file:///D:/Work/server/pkg/server/tls.go).

## Findings

1. **Strict Mutual TLS Enforcement**: When `client_auth: "require_and_verify"` is configured on a host, `GetConfigForClient` dynamically injects `tls.RequireAndVerifyClientCert` and the dedicated `*x509.CertPool`. Clients lacking valid certificates signed by the configured CA are rejected during the TLS handshake prior to any HTTP payload transmission.
2. **Untrusted Client Rejection**: Tested and verified that untrusted client certificates signed by invalid root keys are strictly rejected with TLS handshake failure.
3. **Thread Safety**: `SNIRegistry` utilizes `sync.RWMutex` to protect profile read/write access during dynamic hot reloads (`RouteWatcher`), preventing race conditions.
4. **SNI Sanitization**: Hostnames are trimmed and normalized to lowercase before lookup, preventing case-mismatch bypasses.

## Conclusion

Approved. Zero security vulnerabilities identified.
