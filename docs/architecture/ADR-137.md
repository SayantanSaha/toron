# ADR-137: Dashboard Temporal Ordering, Full Datetime Formatting, and Request Source IP Exposure

## Context

Operators navigating between Toron's web dashboard and backend audit logs (`/var/log/toron/security.log`, `/var/log/toron/access.log`) require consistent calendar dates and client IP provenance across views.

## Decisions

1. **Centralized Datetime Formatting Utility**:
   Implement `dtFmt(d)` in `public/app.js` that normalizes strings, numbers, or `Date` objects into ISO standard local strings: `YYYY-MM-DD HH:MM:SS`.

2. **Unified Alert Timestamping & Sort Invariant**:
   Ensure all alert records synthesized in `buildDataModel()` (`incidents`, `bannedIps`, `upstreams`, `routes`, `certs`) compute a normalized millisecond `timestamp`. Sort `D.alerts` descending by `timestamp`:
   ```javascript
   alerts.sort((a, b) => (b.timestamp || 0) - (a.timestamp || 0));
   ```

3. **Banned IP Table Enhancement**:
   Add `<th>Created At</th>` to the banned IP table header and render `dtFmt(b.created_at)`. Pre-sort the ban array by `created_at` descending before rendering.

4. **Live Tail Request Table Enhancement**:
   - Add `<th>Source IP</th>` to the table header in `lgShell()`.
   - In `lgUpdate()`, render `<td class="tm">${dtFmt(e.ts)}</td>` and `<td class="hide-sm"><code>${esc(e.ip || e.client_ip || '127.0.0.1')}</code></td>`.
   - Update request details drawer to display `dtFmt(e.ts)`.

## Consequences

- **Positive**: Operators can immediately cross-reference incidents with server logs by date and timestamp, identify top offending client IPs directly from the requests table, and see latest alerts and bans at a glance.
- **Negative**: Adds a column to the requests table; mitigated by responsive `.hide-sm` styling on narrow viewports.
