# REQ-128 - Streaming Response Middleware Exemptions and RFC 7234 Origin Cache-Control Enforcement

## 1. Description & Problem Statement

### 1.1 Problem Context
During end-to-end architectural audits of Toron's reverse proxy and middleware pipeline, two severe root causes were identified that corrupt real-time streaming connections (e.g. Server-Sent Events / SSE) and dynamic HTTP endpoints:

1. **Root Cause 2: In-Memory Cache Ignores Origin `Cache-Control: no-cache` and `text/event-stream` (RFC 7234 §5.2.2.2 Violation)**:
   - In [`pkg/router/cache.go:245`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/cache.go#L245), `CacheMiddleware` inspects response directives:
     ```go
     resCC := ParseCacheControl(res.Header.Get("Cache-Control"))
     if resCC.NoStore || resCC.Private {
         return
     }
     ```
   - While `no-store` and `private` are checked, **`resCC.NoCache` is completely ignored**.
   - Under RFC 7234 §5.2.2.2, `Cache-Control: no-cache` explicitly mandates that the response must not be used to satisfy subsequent requests without successful revalidation with the origin server. Because Toron does not perform conditional cache revalidation, storing responses marked `no-cache` directly violates RFC 7234.
   - When an upstream origin responds with `Cache-Control: no-cache` (the standard specification for SSE and dynamic APIs) without `max-age`, Toron falls back to `ttl := cfg.DefaultTTL` (default: 60 seconds). Toron clones the body snapshot into `ResponseCache`, freezing the live stream.
   - Any subsequent client connecting to the streaming endpoint receives a frozen, dead snapshot with `X-Cache: HIT` and `Age: N`, breaking real-time updates and causing severe cache deception.
   - Furthermore, `CacheMiddleware` does not inspect `Content-Type: text/event-stream` or `X-Accel-Buffering: no`, allowing streaming responses to be captured as static cached entries.

2. **Root Cause 3: Transparent Compression Traps `text/event-stream` via Wildcard `text/*`**:
   - In [`pkg/router/compression.go:42`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go#L42) and [line 155](file:///Users/sneha/Developer/toron-research/toron/pkg/router/compression.go#L155), `DefaultCompressionConfig.Types` includes `"text/"`.
   - In `isMIMECompressible(contentType, allowedTypes)`, `strings.HasPrefix(ct, "text/")` matches `text/event-stream`.
   - When a client sends standard browser headers (`Accept-Encoding: gzip, deflate, br, zstd`), `CompressionMiddleware` intercepts the live stream, buffers the streaming payload in RAM until stream completion, compresses it into a single zstd/gzip block, and updates `Content-Length` and `Content-Encoding`.
   - This completely destroys streaming delivery: clients experience event starvation and receive no events until the stream terminates or disconnects.
   - Additionally, upstream responses signaling `X-Accel-Buffering: no` (the standard reverse proxy directive requesting unbuffered streaming) are ignored and subjected to buffering and compression.

### 1.2 Prior Requirements & Standards Cross-Audit (Conflict Analysis)

A cross-audit against existing requirements and architectural decisions was conducted:

1. **Alignment with [`REQ-034`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-034.md) & [`ADR-029`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-029.md) (Transparent Response Compression)**:
   - ADR-029 established transparent compression for static assets and REST API bodies. It explicitly excluded streaming tunnels (`101 Switching Protocols` / `UpgradedConn != nil`).
   - Exempting `text/event-stream` and `X-Accel-Buffering: no` directly upholds ADR-029's core architectural principle of preserving live streaming semantics.
2. **Alignment with [`REQ-035`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-035.md) & [`ADR-030`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-030.md) (In-Memory Response Caching)**:
   - ADR-030 states as an explicit goal: *"strict adherence to RFC 7234 HTTP caching specifications."*
   - Omitting `no-cache` on response evaluation was an implementation defect that violated ADR-030's stated goal. Enforcing cache bypass on `resCC.NoCache` and streaming MIME types directly fulfills ADR-030 and prevents cache freezing.
3. **Synergy with [`REQ-125`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-125.md) (Conditional Direct Socket Streaming Fast-Path)**:
   - Under REQ-125, direct socket streaming requires knowing whether downstream compression or caching will intercept the response.
   - By establishing that `text/event-stream` and `X-Accel-Buffering: no` unconditionally bypass caching and compression, `ReverseProxy` can immediately activate the direct socket streaming fast-path for streaming responses even on routes where caching and compression are globally enabled.

### 1.3 Safe Non-Conflicting Path
1. **RFC 7234 Origin `no-cache` Enforcement**: When origin response `Cache-Control` specifies `no-cache`, `CacheMiddleware` must never store the response in `ResponseCache` and must emit `X-Cache: MISS`.
2. **Streaming Response Cache Exemption**: Any response with `Content-Type: text/event-stream` (case-insensitive) or `X-Accel-Buffering: no` (case-insensitive) must be strictly excluded from cache storage.
3. **Streaming Response Compression Exemption**: Any response with `Content-Type: text/event-stream` or `X-Accel-Buffering: no` must bypass `CompressionMiddleware`, ensuring raw uncompressed chunks are emitted immediately with zero intermediate buffering.

## 2. Functional Requirements

### 2.1 Cache Middleware Exemption & RFC 7234 §5.2.2.2 Enforcement (`pkg/router/cache.go`)
1. In `pkg/router/cache.go`, during downstream response cacheability evaluation:
   ```go
   contentType := strings.ToLower(res.Header.Get("Content-Type"))
   isEventStream := strings.HasPrefix(contentType, "text/event-stream")
   isUnbuffered := strings.EqualFold(res.Header.Get("X-Accel-Buffering"), "no")
   resCC := ParseCacheControl(res.Header.Get("Cache-Control"))
   
   // RFC 7234 §5.2.2.2: no-cache responses must not be stored without revalidation.
   // Streaming and unbuffered responses must never be stored in cache.
   if resCC.NoStore || resCC.NoCache || resCC.Private || isEventStream || isUnbuffered {
       return
   }
   ```
2. Any response matching `resCC.NoCache == true`, `isEventStream == true`, or `isUnbuffered == true`:
   - Shall **never** be cloned into `ResponseCache`.
   - Shall have `X-Cache: MISS` emitted in response headers.
   - Shall never emit an `Age` header.
3. Client request cache bypass: client requests sending `Cache-Control: no-cache` or `Pragma: no-cache` shall continue to bypass cache lookups.

### 2.2 Compression Middleware Exemption for Streaming Payloads (`pkg/router/compression.go`)
1. In `pkg/router/compression.go`, inspect response headers prior to evaluating MIME compressibility or acquiring compressor writers:
   ```go
   contentType := strings.ToLower(res.Header.Get("Content-Type"))
   isEventStream := strings.HasPrefix(contentType, "text/event-stream")
   isUnbuffered := strings.EqualFold(res.Header.Get("X-Accel-Buffering"), "no")
   
   if isEventStream || isUnbuffered {
       return
   }
   ```
2. When `isEventStream == true` or `isUnbuffered == true`:
   - `CompressionMiddleware` shall immediately pass through the response without modifying `res.Body`.
   - No compression writer (Zstd, Brotli, Gzip, Deflate) shall be acquired or executed.
   - `Content-Encoding` shall remain untouched.
   - Payload bytes shall not be buffered or concatenated into memory blocks.

## 3. Non-Functional Requirements

### 3.1 Performance & Allocation Invariant
- Cache and compression exemption guards must execute with **zero dynamic heap memory allocations**, utilizing zero-alloc string comparisons and prefix checks.
- Event delivery latency for streaming connections must be $< 1\text{ms}$ upon origin emission.

### 3.2 Standards Compliance & Security
- Strict compliance with RFC 7234 §5.2.2.2 (no-cache response directive).
- Prevention of cache deception and session leakage across client connections consuming real-time feeds.

### 3.3 Zero Third-Party Dependencies
- All checks must use Go standard library packages exclusively (`strings`, `net/http`).

## 4. Acceptance Criteria

1. **`pkg/router/cache.go`**:
   - Responses containing origin `Cache-Control: no-cache` are never stored in `ResponseCache`.
   - Responses containing `Content-Type: text/event-stream` are never stored in `ResponseCache`.
   - Responses containing `X-Accel-Buffering: no` are never stored in `ResponseCache`.
   - Responses bypassed per these rules always emit `X-Cache: MISS` and never emit an `Age` header.
2. **`pkg/router/compression.go`**:
   - Responses containing `Content-Type: text/event-stream` pass through uncompressed, even when `Accept-Encoding: gzip, deflate, br, zstd` is sent by the client.
   - Responses containing `X-Accel-Buffering: no` pass through uncompressed.
   - Standard compressible text responses (e.g. `text/html`, `text/plain`, `text/css`, `application/json`) continue to be compressed normally according to configuration.
3. **Automated Unit & Integration Tests**:
   - Unit tests in `pkg/router/cache_test.go` assert that `Cache-Control: no-cache` and `text/event-stream` responses return `X-Cache: MISS` on repeated identical requests and are not retained in cache memory.
   - Unit tests in `pkg/router/compression_test.go` assert that `text/event-stream` and `X-Accel-Buffering: no` responses do not receive `Content-Encoding` and retain raw uncompressed payloads.
   - Reverse proxy integration tests assert that SSE streams routed through cache-enabled and compression-enabled routes deliver live chunks directly without buffering or caching.
4. **Race Safety**:
   - All tests pass cleanly under `go test -race ./pkg/router/... ./pkg/proxy/...`.
