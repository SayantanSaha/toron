# TC-138 - Verification Test Cases for Multi-Level Sorting on Alerts and Requests

## Test Scenarios

### TC-138-01: Alerts Multi-Level Sort (Timestamp -> Client IP)
- **Input**:
  - Alert 1: `timestamp: 1000`, `ip: '192.168.1.50'`
  - Alert 2: `timestamp: 2000`, `ip: '10.0.0.1'`
  - Alert 3: `timestamp: 1000`, `ip: '10.0.0.2'`
- **Expected Output Order**:
  1. Alert 2 (timestamp: 2000)
  2. Alert 3 (timestamp: 1000, ip: 10.0.0.2)
  3. Alert 1 (timestamp: 1000, ip: 192.168.1.50)

### TC-138-02: Banned IPs Table Multi-Level Sort (Created At -> Client IP)
- **Input**:
  - Ban 1: `created_at: '2026-09-22T08:00:00Z'`, `ip: '198.51.100.20'`
  - Ban 2: `created_at: '2026-09-22T08:00:00Z'`, `ip: '198.51.100.5'`
  - Ban 3: `created_at: '2026-09-22T08:05:00Z'`, `ip: '203.0.113.1'`
- **Expected Output Order**:
  1. Ban 3 (`2026-09-22T08:05:00Z`)
  2. Ban 2 (`2026-09-22T08:00:00Z`, `198.51.100.5`)
  3. Ban 1 (`2026-09-22T08:00:00Z`, `198.51.100.20`)

### TC-138-03: Requests Live Tail 3-Tier Sort (Timestamp -> Client IP -> Request Path)
- **Input**:
  - Req 1: `ts: 5000`, `ip: '1.1.1.1'`, `path: '/b'`
  - Req 2: `ts: 5000`, `ip: '1.1.1.1'`, `path: '/a'`
  - Req 3: `ts: 5000`, `ip: '0.0.0.0'`, `path: '/z'`
  - Req 4: `ts: 6000`, `ip: '9.9.9.9'`, `path: '/c'`
- **Expected Output Order**:
  1. Req 4 (`ts: 6000`, `/c`)
  2. Req 3 (`ts: 5000`, `ip: 0.0.0.0`, `/z`)
  3. Req 2 (`ts: 5000`, `ip: 1.1.1.1`, `/a`)
  4. Req 1 (`ts: 5000`, `ip: 1.1.1.1`, `/b`)

### TC-138-04: Graceful Fallbacks on Missing IP or Path
- **Input**: Entries missing `ip` or `path` properties.
- **Expected Behavior**: Safe handling using `''` fallbacks without throwing `TypeError` or `undefined` comparison errors.
