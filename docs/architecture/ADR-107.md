# ADR-107 - Response-Driven Transport Teardown on Security Rejections

## 1. Context & Problem Statement

Toron utilizes an event-driven reactor model (`pkg/reactor`) with connection worker loops in `pkg/server/server.go`. Currently, the server's decision to maintain or terminate persistent TCP connections (`keep-alive`) relies entirely on the client's request header (`Connection: close`).

When security components (WAF middleware in `pkg/waf/middleware.go`, protocol integrity checkers, or route-level path traversal guards in `pkg/router/router.go`) intercept malicious attacks, they write an HTTP error response (`400`, `403`, `413`) but omit `Connection: close`. Consequently, `server.go` leaves the socket open on the reactor loop, exposing the server to Slowloris connection exhaustion and pipelined HTTP desynchronization.

## 2. Decision

We adopt **Response-Driven Transport Teardown**:

1. **Downstream Security Filters Set `Connection: close`**:
   Whenever a security boundary is violated—including IP ACL denials, protocol integrity violations, OWASP Layer 7 threat detections, and filesystem path traversal attempts—the intercepting filter MUST explicitly set `res.Header.Set("Connection", "close")`.
2. **Server Egress Connection Header Inspection**:
   In `pkg/server/server.go` (`handleConn`), after routing and response serialization (`res.Serialize(conn)`), the loop checks both ingress and egress connection headers:
   ```go
   outConnHeader := strings.ToLower(res.Header.Get("Connection"))
   if connHeader == "close" || outConnHeader == "close" {
       return nil
   }
   ```
   Exiting `handleConn` returns execution to `Reactor.processConn`, which executes `defer conn.Close()`, physically closing the socket.
3. **Preservation of Benign Keep-Alive**:
   Benign requests (`200 OK`, valid upstream proxies) continue to default to `Connection: keep-alive` unless the client explicitly requested closure.

## 3. Considered Alternatives

- **Alternative 1: Passing error sentinels from Router to Server**:
  Rejected because Go HTTP handler signatures (`func(*httpparser.Request, *httpparser.Response)`) do not return errors. Altering handler signatures would require massive refactoring across all middlewares.
- **Alternative 2: Directly closing `req.RawConn` inside WAF middleware**:
  Rejected because closing the socket mid-middleware prevents the server from serializing and sending the structured JSON error body back to the client, leading to abruptly reset connections (`RST`) without informative error reporting.

## 4. Consequences

- **Positive**:
  - Deterministic fail-fast physical socket closure on all security rejections.
  - Zero-cost inspection without modifying middleware interface signatures.
  - Clean client notification: client receives full JSON error body and `Connection: close` before the socket closes.
  - 100% compliance with RFC 7230 §6.1 and academic review task `SRC-01`.
- **Negative / Operational Considerations**:
  - Rejection tests in `diff_fuzzer.go` that previously asserted `ExpectClose: false` on WAF rejections must be updated to expect `ExpectClose: true`.
