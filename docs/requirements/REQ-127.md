# REQ-127 - Explicit Client Socket TCP_NODELAY Configuration and Serialization Buffer Recycling

## 1. Description & Problem Statement

### 1.1 Problem Context
In the multi-proxy differential benchmark ([`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md)), NGINX achieved ~34.1k RPS and HAProxy achieved ~32.3k RPS, compared to Toron's ~24.5k RPS.

Detailed configuration and socket inspection revealed two optimization gaps:
1. **Implicit TCP Socket Options**: Toron accepts inbound client sockets via `ln.Accept()` without explicitly configuring socket options (`TCP_NODELAY`, TCP keep-alive probes, or read/write buffer hints). NGINX explicitly enforces `tcp_nodelay on` and `tcp_nopush on` to eliminate Nagle packet buffering delays and prevent latency spikes.
2. **Response Serialization Heap Allocations**: In [`pkg/httpparser/response.go:70`](file:///Users/sneha/Developer/toron-research/toron/pkg/httpparser/response.go#L70), `res.Serialize(conn)` dynamically allocates a fresh `bytes.Buffer` (`buf.Grow(256 + r.Body.Len())`) on every request to format status lines and headers before socket transmission. At 24.5k RPS, this allocates ~24,500 temporary heap objects per second, increasing GC pressure.

Furthermore, socket profiling revealed that `TCP_NODELAY` is **mission-critical for real-time streaming architectures** (such as Server-Sent Events / SSE):
- By default, TCP sockets run Nagle's algorithm, which buffers small outgoing TCP segments until an acknowledgment (ACK) is received for earlier segments or until a full Maximum Segment Size (MSS, ~1460 bytes) is accumulated.
- In SSE (`text/event-stream`), updates are pushed as small text event frames (e.g. `data: {"id":123,"status":"running"}\n\n`), often only 20 to 200 bytes in size.
- When paired with modern operating systems' TCP Delayed ACK implementation (RFC 1122 §4.2.3.2, which delays sending ACKs by 40ms to 200ms), Nagle's algorithm stalls delivery of successive event frames by 40ms–200ms, severely degrading real-time stream fidelity.
- Additionally, persistent streaming connections frequently endure quiet intervals between event emissions. If a client drops offline abruptly (e.g., WiFi disconnection, sleep state, or silent NAT drop), the socket enters a half-open state. Without explicit TCP keep-alive configuration (`SetKeepAlive(true)` and `SetKeepAlivePeriod(60s)`), the server reactor cannot detect dropped connections during quiet streaming intervals, pinning worker goroutines and upstream proxy handles indefinitely.

### 1.2 Prior Requirements & Standards Cross-Audit (Conflict Analysis)

A conflict audit was conducted against Toron's existing architecture:

   - Immediate dispatch of small frames is essential for direct streaming fast-paths and activity-refreshed write deadlines.

## 2. Functional Requirements

### 2.1 Explicit TCP Socket Tuning (`pkg/reactor`, `pkg/server`)
1. Upon accepting a socket from `net.Listener`, inspect if `conn` implements `*net.TCPConn`:
   ```go
   if tcpConn, ok := conn.(*net.TCPConn); ok {
       _ = tcpConn.SetNoDelay(true)
       _ = tcpConn.SetKeepAlive(true)
       _ = tcpConn.SetKeepAlivePeriod(60 * time.Second)
   }
   ```
2. **Mission-Critical `TCP_NODELAY` Enforcement**:
   - Setting `SetNoDelay(true)` disables Nagle's algorithm immediately on all accepted TCP sockets.
   - For real-time streaming responses (e.g. SSE `text/event-stream`), this guarantees that small individual event frames (e.g., `data: ...\n\n`) are emitted to the wire immediately without incurring the 40ms–200ms delayed-ACK packet stall.
   - For standard HTTP microservice transactions, small JSON payloads and health checks are delivered with minimal latency.
3. **Half-Open Connection Detection via Keep-Alive**:
   - Setting `SetKeepAlive(true)` and `SetKeepAlivePeriod(60 * time.Second)` enables the kernel to send periodic TCP keep-alive probes across long-lived streaming connections during quiet periods when no events are actively being written.
   - When a client disappears without an orderly TCP FIN/RST handshake, the keep-alive probes will detect connection failure within the probe interval, prompting the reactor to abort the socket and cleanly release associated worker goroutines and upstream proxy pipelines.

### 2.2 Serialization Buffer Memory Recycling (`sync.Pool`)
1. In `pkg/httpparser/response.go`, implement a package-level buffer pool:
   ```go
   var responseBufPool = sync.Pool{
       New: func() any {
           b := make([]byte, 0, 4096)
           return &b
       },
   }
   ```
2. In `res.Serialize(w io.Writer)`:
   - Acquire a slice buffer from `responseBufPool`.
   - Format HTTP status line and headers into the pooled buffer.
   - Write headers to `w`.
   - Write `r.Body` directly to `w`.
   - Reset the slice buffer and return it to `responseBufPool`.
3. Eliminate all dynamic heap allocations for response headers and status lines.

## 3. Non-Functional Requirements

### 3.1 Allocation & Latency Stabilization
- Achieve near-zero heap allocations in `res.Serialize` for responses with bodies $< 4\text{ KB}$.
- Eliminate TCP Nagle packet delays on small payloads, stabilizing P90 and P99 latency distributions.
- Eliminate 40ms–200ms inter-event latency spikes in real-time streaming connections (SSE).

### 3.2 Thread-Safety & Race Cleanliness
- The buffer pool must be strictly thread-safe and verified under `-race`.
- Reused buffers must be cleanly reset to avoid cross-request data leaks.

### 3.3 Zero Third-Party Dependencies
- Implemented strictly with standard library `net` and `sync`.

## 4. Acceptance Criteria

1. **`pkg/reactor` & `pkg/server`**:
   - Accepted TCP sockets explicitly have `SetNoDelay(true)`, `SetKeepAlive(true)`, and `SetKeepAlivePeriod(60s)` configured immediately following accept.
   - Unit tests verify that TCP sockets carry `TCP_NODELAY` and keep-alive configuration flags.
2. **Real-Time Streaming Delivery Assertion**:
   - Integration tests assert that small SSE frames (`data: ...\n\n`) are transmitted with immediate wire delivery without incurring 40ms–200ms Nagle buffering delays.
   - Silent client disconnections during quiet streaming intervals are detected by TCP keep-alive probes, releasing server resources.
3. **`pkg/httpparser`**:
   - `res.Serialize` utilizes `responseBufPool` for header serialization, eliminating dynamic buffer creation.
   - Headers and payload write correctly to `io.Writer` with zero output corruption.
4. **Race Safety**:
   - Passes cleanly under `go test -race ./pkg/reactor/... ./pkg/httpparser/... ./pkg/server/...`.
