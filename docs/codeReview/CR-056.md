# CR-056 - Code Review of Query Parameter Forwarding and Ingress Adapter Normalization

## Description

Code review of query parameter preservation and ingress adapter normalization across `pkg/httpparser`, `pkg/server`, `pkg/sidecar`, `pkg/proxy`, and `pkg/router`.

## Scope

- Files reviewed:
  - `pkg/httpparser/request.go`
  - `pkg/httpparser/parser_test.go`
  - `pkg/server/server.go`
  - `pkg/sidecar/proxy.go`
  - `pkg/proxy/proxy.go`
  - `pkg/proxy/proxy_test.go`
  - `pkg/router/router.go`

## Key Observations & Review Findings

1. **Adapter Standardization**:
   - `httpparser.NewRequestFromStd` eliminates fragmented stdlib-to-Toron request adaptation across HTTP/2 (`h2` over TLS), HTTP/3 (QUIC), and sidecar interception.
   - `r.URL.Query()` and `r.URL.RawQuery` are consistently extracted and populated.

2. **Verbatim Query Preservation**:
   - In `pkg/proxy/proxy.go`, `clientQuery` prefers `req.URL.RawQuery` when available, falling back to `QueryParams.Encode()` only if `RawQuery` is missing. This preserves original query order, percent-encoding, and non-valued flags (e.g. `?debug`).
   - Cleanly merges `targetURL.RawQuery` with `clientQuery` using `&` when upstream targets define fixed query parameters.

3. **Telemetry & Observability**:
   - `AccessLoggerMiddleware` now logs `req.RequestURI` (falling back to `req.Path`), ensuring query parameters appear in `/var/log/toron/access.log` for debugging and analytics.

4. **Test Verification**:
   - Added `TestReverseProxy_QueryParametersForwarding` and `TestReverseProxy_QueryParametersMergeWithTarget` in `pkg/proxy/proxy_test.go`.
   - Added `TestNewRequestFromStd` and `TestRequest_QueryLazy` in `pkg/httpparser/parser_test.go`.
   - All tests pass with zero race conditions (`go test -race ./...`).

## Verdict

Approved. The code is ready for production deployment.
