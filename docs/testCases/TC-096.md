# TC-096 - Verification of Composite Route Key Grouping, Multi-Pod Target Aggregation, and Specificity-Based Route Lifecycle in Kubernetes Ingress Controller

## 1. Test Suite Objectives & Scope

Verify that Toron Edge Gateway's Kubernetes Ingress Controller ([`pkg/ingress/controller.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/controller.go)), route translation engine ([`pkg/ingress/translator.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/ingress/translator.go)), and core routing engine ([`pkg/router/router.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/router/router.go)) enforce an **annotation-driven, composite-key grouped, multi-pod aggregated, variant-isolated, and specificity-ordered route lifecycle**.

This test specification validates the complete remediation of critical routing dimension blindness, canary traffic contamination, route shadowing, and resource leakage ([CWE-284: Improper Access Control](https://cwe.mitre.org/data/definitions/284.html), [CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html), [CWE-662: Improper Synchronization](https://cwe.mitre.org/data/definitions/662.html), [CWE-775: Resource Leak](https://cwe.mitre.org/data/definitions/775.html)), confirming that:

1. **Ingress Annotation Parsing**: Ingress resources accurately extract HTTP method constraints (`toron.io/method`), individual header constraints (`toron.io/header.<Name>`), grouped header constraints (`toron.io/headers` in CSV and JSON formats), and industry-standard Ingress-NGINX Canary annotations (`nginx.ingress.kubernetes.io/canary*`).
2. **Deterministic Composite Route Key**: Pod routes are partitioned using a 4-dimensional tuple $\text{CompositeRouteKey} = (\text{Host}, \text{Prefix}, \text{Method}, \text{CanonicalHeaders})$, where `CanonicalHeaders` sorts header keys alphabetically to eliminate Go map iteration non-determinism across 30-second reconciliation cycles.
3. **Multi-Pod Target Aggregation & Fair Load Balancing**: All pod endpoint IPs sharing an identical `CompositeRouteKey` are consolidated into exactly **one** multi-target `PrefixRouteSpec` configured with Toron's `RoundRobinBalancer`. Traffic is distributed proportionally ($\approx 1/M$ per pod replica), completely eliminating single-pod replica starvation.
4. **Strict Canary vs Baseline Target Segregation**: Ingress resources sharing host and path prefix but differing in header annotations (e.g. Canary vs Baseline) produce distinct `CompositeRouteKey`s and separate reverse proxy target pools. Canary traffic (`X-Version: canary`) dispatches exclusively to Canary pods, while standard traffic routes to Baseline pods without traffic bleeding.
5. **ADR-005 Specificity Ordering & Shadowing Prevention**: Route specifications are sorted by specificity (Longest prefix $\to$ Host specificity $\to$ Header constraint count $\to$ Method constraint $\to$ Deterministic tie-break). Specific Canary routes are guaranteed to match ahead of generic Baseline fallback routes, eliminating route shadowing caused by arbitrary Kubernetes API discovery ordering.
6. **Declarative Method Matching Support**: Ingress routes with `toron.io/method` populate `PrefixRouteSpec.Method`. Mismatched HTTP verbs return HTTP `405 Method Not Allowed` or cleanly proceed to method-compatible fallback routes.
7. **Non-Destructive Scale-Down & Clean Eviction Teardown**: Pod scaling events update the target list without dropping routes or connections to healthy pods. Deleting Ingress resources purges routes and invokes [`proxy.Close()`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L596-L600), stopping active health check tickers (`StopActiveHealthCheck`) and releasing sockets.
8. **Zero Third-Party Dependencies Invariant**: All annotation parsing, key generation, pod aggregation, and specificity sorting strictly use Go standard library packages (`sync`, `net/http`, `net/url`, `sort`, `strings`, `encoding/json`, `path`).
9. **High-Concurrency Race Safety**: Continuous route synchronization and pod churn executing concurrently with high-volume HTTP client traffic operates with 100% thread safety and zero data races under `go test -race ./pkg/ingress/... ./pkg/router/...`.
