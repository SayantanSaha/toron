# TC-103 - Verification Suite for RFC 7234 Shared Cache Boundary Isolation Test Vectors

## 1. Test Suite Objectives

Verify that `benchmarks/fuzzer/diff_fuzzer.go` properly supports multi-stage sequential request execution, parses and verifies HTTP response headers, and implements RFC 7234 shared cache session boundary isolation test vectors (`CACHE-001..003`) to detect Web Cache Deception (CWE-524), `Set-Cookie` leakage (CWE-384), and unauthorized cached retrieval (RFC 7234 §3.2).

## 2. Test Cases

### TC-103-01: Sequential Execution & Response Header Parsing
- **Objective**: Verify that `executeRawTest` executes all payloads in `SequentialPayloads` sequentially and successfully extracts headers (`http.Header`) from the probe response.
- **Expected Outcome**: `res.Passed == true`, all sequential requests delivered over TCP, and probe headers correctly parsed into `res.ResponseHeaders`.

### TC-103-02: CACHE-001 (Web Cache Deception Prevention Invariant)
- **Objective**: Execute a 2-stage sequence where Request 1 fetches an authenticated resource with `Cache-Control: private`, and Request 2 is an unauthenticated probe for the same URL.
- **Expected Outcome**: Probe request receives `X-Cache: MISS` (or is not served from cache), `res.Passed == true`. If a vulnerable mock server returns `X-Cache: HIT`, `res.Passed == false`.

### TC-103-03: CACHE-002 (Set-Cookie Stripping Invariant)
- **Objective**: Execute a 2-stage sequence where Request 1 triggers a public cacheable response with `Set-Cookie: session=secret123`, and Request 2 retrieves the cached entry (`X-Cache: HIT`).
- **Expected Outcome**: Probe response receives `X-Cache: HIT`, but `Set-Cookie` and `Set-Cookie2` headers are strictly absent from the response. `res.Passed == true`. If a vulnerable mock server preserves `Set-Cookie` on hit, `res.Passed == false`.

### TC-103-04: CACHE-003 (Authorization Refusal Invariant)
- **Objective**: Execute a 2-stage sequence where Request 1 includes `Authorization: Bearer xyz` without `Cache-Control: public`, and Request 2 is an unauthenticated probe.
- **Expected Outcome**: Probe response receives `X-Cache: MISS`, `res.Passed == true`. If a vulnerable mock server returns `X-Cache: HIT`, `res.Passed == false`.

### TC-103-05: Forbidden Header Assertion Failure Oracle
- **Objective**: Verify that when `ForbiddenResponseHeaders` contains a header present in the server's response, `res.Passed` is marked `false` with a descriptive `FailureReason`.
- **Expected Outcome**: `res.Passed == false`, `res.FailureReason` contains `"Forbidden header"`.

### TC-103-06: Required Header Assertion Failure Oracle
- **Objective**: Verify that when `RequiredResponseHeaders` specifies a key/value not matched by the server's response, `res.Passed` is marked `false` with a descriptive `FailureReason`.
- **Expected Outcome**: `res.Passed == false`, `res.FailureReason` contains `"Required header"`.
