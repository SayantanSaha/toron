## Findings

### SEC-147-01: Plaintext Token Disclosure in Rate Limiting Telemetry ClientIP
- **Severity**: Medium
- **Category**: Telemetry Privacy / Sensitive Information Disclosure (CWE-200 / CWE-532)
- **Location**: `pkg/router/rate_limiter.go:389-409`
- **Related artifacts**: `../requirements/REQ-147.md` (FR-147-4), `../architecture/ADR-147.md` (Section 4.2)
- **Evidence**:
  In `pkg/router/rate_limiter.go` lines 389–409:
  ```go
  if al := limiter.AuditLogger(); al != nil {
      clientIP := clientKey
      if strings.HasPrefix(clientIP, "ip:") {
          clientIP = strings.TrimPrefix(clientIP, "ip:")
      }
      var method, reqPath string
      if req != nil {
          method = req.Method
          reqPath = req.Path
      }
      al.LogEvent(waf.SecurityEvent{
          Event:          "rate_limit_drop",
          Action:         "throttled",
          Category:       "rate_limit",
          ClientIP:       clientIP,
          Method:         method,
          Path:           reqPath,
          AnomalyScore:   0,
          RuleID:         "rate_limit",
          PayloadSnippet: fmt.Sprintf("Rate limit exceeded: retry after %d seconds", retrySecs),
      })
  }
  ```
  In `pkg/router/rate_limiter.go` lines 327–358 (`ExtractClientKey`), requests authenticated via `X-API-Key` or `Authorization` return keys formatted as `"key:" + apiKey` or `"auth:" + auth`.
  While `strings.TrimPrefix(clientIP, "ip:")` strips `"ip:"` prefixes, keys with `"key:"` or `"auth:"` are retained verbatim.
  For example, a request with header `X-API-Key: secret_live_key_99` logs:
  ```json
  {"timestamp":"...","event":"rate_limit_drop","client_ip":"key:secret_live_key_99", ...}
  ```
  This was verified during Go test execution where `TestRateLimiter_AuditLogger_MemoryBounding` emitted:
  ```json
  {"timestamp":"2026-09-29T06:11:42Z","event":"rate_limit_drop","client_ip":"key:same-client","method":"GET","path":"/drop","category":"rate_limit",...}
  ```
- **Description**: The route-level rate limiter records `clientKey` into the `ClientIP` field of `waf.SecurityEvent`. When rate-limiting relies on authentication headers (common on machine-to-machine API routes), raw credential values are saved into the audit logger's circular memory buffer, written to disk/stdout security log sinks in plaintext, and returned to client browsers via `GET /internal/api/security/incidents`.
- **Impact**: Operators or audit log consumers viewing security incidents on `#/alerts` or reviewing log archives can view plaintext client credentials. Furthermore, clicking "Copy Client IP" or "Ban Client IP" in `public/js/components/drawer.js` copies or attempts to firewall-ban the string `key:<token>`, which is not a valid network IP address.
- **Recommendation**:
  1. Sanitize or hash non-IP client keys before populating `SecurityEvent.ClientIP`. If `strings.HasPrefix(clientKey, "key:")` or `"auth:"`, hash the credential using SHA-256 (e.g. `key:sha256(token)[:12]`) or redact the secret value (e.g. `key:****[last4]`).
  2. Alternatively, record the client's actual remote socket address (`req.RemoteIP()`) in `ClientIP`, and store a separate, sanitized client identity field.
- **Required action**: Non-blocking for initial rollout because internal dashboard access requires administrative authentication (`cfg.AdminAuth`). Track for credential sanitization in the next patch release.

### SEC-147-02: Telemetry Ring Buffer Churn & Synchronous I/O Contention Under Volumetric 429 Traffic
- **Severity**: Low
- **Category**: Telemetry Denial-of-Service / Forensic Buffer Exhaustion (CWE-400 / CWE-770)
- **Location**: `pkg/router/rate_limiter.go:389-410`, `pkg/waf/audit.go:119-130`
- **Related artifacts**: `../requirements/REQ-147.md` (NFR-147-4), `../architecture/ADR-147.md` (Section 4.4, Section 7)
- **Evidence**:
  In `pkg/waf/audit.go` lines 119–130:
  ```go
  l.mu.Lock()
  defer l.mu.Unlock()

  l.recentEvents = append(l.recentEvents, event)
  if len(l.recentEvents) > l.maxEvents {
      l.recentEvents = l.recentEvents[len(l.recentEvents)-l.maxEvents:]
  }

  if l.writer != nil {
      _, _ = l.writer.Write(append(data, '\n'))
  }
  ```
  Every HTTP 429 response synchronously invokes `al.LogEvent()`, which locks `l.mu` and writes to `l.writer`.
- **Description**:
  1. **Buffer Churn**: The in-memory circular buffer retains a maximum of 50 events (`maxEvents: 50`). During a volumetric DDoS attack against a rate-limited route, an adversary sending 500 requests/second will generate 500 rate limit drop events per second. Within 100 milliseconds, all 50 slots in the circular buffer will be overwritten with identical `rate_limit_drop` events, completely displacing critical OWASP WAF alerts (e.g., SQLi, XSS, Path Traversal) before human operators can inspect them in the Control Center.
  2. **Lock Contention**: `l.mu.Lock()` is held while writing to `l.writer`. If the security log sink is a physical file or pipe subject to I/O pressure or disk write latency, router worker goroutines processing 429 drops can contend on `l.mu`, creating backpressure on gateway request throughput.
- **Impact**: Potential loss of real-time forensic visibility for high-severity WAF violations during traffic surges, and potential lock contention under extreme volumetric loads. Memory consumption itself remains strictly bounded (50 events, 128-char snippets), preventing out-of-memory panics.
- **Recommendation**:
  1. Implement client-level or route-level event logging sampling/throttling in `RateLimiter` (e.g., emit at most 1 `rate_limit_drop` audit event per client IP every 5 seconds).
  2. Asynchronously decouple `l.writer.Write()` using a non-blocking buffered channel or worker pool rather than writing synchronously under `l.mu`.
- **Required action**: Non-blocking; documented as an accepted architectural design trade-off in `ADR-147 §4.4` and `ADR-147 §7`.

### SEC-147-03: Unescaped Dynamic Parameter in Upstream Navigation Attribute
- **Severity**: Low
- **Category**: Cross-Site Scripting (XSS / CWE-79) / Attribute Injection Defense-in-Depth
- **Location**: `public/js/components/drawer.js:22`
- **Related artifacts**: `../requirements/REQ-141.md`, `../architecture/ADR-146.md`
- **Evidence**:
  In `public/js/components/drawer.js` line 22:
  ```javascript
  <dt>Upstream</dt><dd><button class="linkbtn" data-go="upstreams:${r.pool}">${esc(r.pool)}</button></dd>
  ```
- **Description**: While the button body `${esc(r.pool)}` is properly escaped with `esc()`, the HTML attribute `data-go="upstreams:${r.pool}"` directly interpolates `r.pool` without `esc()`. If an upstream pool identifier configured in the gateway contains double quotes or JavaScript pseudo-protocols (e.g. `pool" onfocus="alert(1)`), this could lead to attribute breakout.
- **Impact**: Low. Route and upstream pool names are defined in server-side configuration (`toron.yaml`) by trusted administrators, not by unauthenticated clients. However, defensive engineering standards require unconditional escaping of all dynamic parameters inside HTML attribute strings.
- **Recommendation**: Wrap `r.pool` in `esc()` inside the attribute string:
  ```javascript
  <button class="linkbtn" data-go="upstreams:${esc(r.pool)}">${esc(r.pool)}</button>
  ```
- **Required action**: Non-blocking defense-in-depth hardening for the next frontend maintenance pass.

## Core Security Verification Analysis

### 1. Cross-Site Scripting (XSS) Prevention & Output Encoding Analysis
- **Operational Alerts Card (`public/js/views/alerts.js:192-196`)**:
  Operational alert rows are rendered using template literals. All external dynamic fields are strictly passed through `esc()`:
  ```javascript
  <li class="al-op-item click" data-go="${esc(target)}" tabindex="0" role="link">
    <span class="${isCrit ? 't-err' : 't-warn'}">${ICON(isCrit ? 'i-x' : 'i-alert')}</span>
    <div style="min-width:0;flex:1">
      <div class="al-t"><b>${esc(a.title || 'Operational Alert')}</b></div>
      <div class="al-d" style="color:var(--ink-2);font-size:12px;margin-top:2px">${esc(a.desc || '')}</div>
    </div>
    <button class="btn sm" data-go="${esc(target)}" style="margin-right:8px;font-size:11px">Investigate</button>
    <span class="mut num" style="white-space:nowrap;font-size:12px">${esc(dtFmt(a.timestamp))}</span>
  </li>
  ```
  Because `esc()` replaces `&`, `<`, `>`, `"`, and `'` with their respective HTML entities, any hostile HTML tags or attribute-breakout sequences injected via alert titles, descriptions, or navigation targets are neutralized.
- **Incidents Feed Item Rendering (`public/js/views/alerts.js:228-234`)**:
  All incident metadata (`category`, `title`, `method`, `path`, `rule_id`, `client_ip`, `location`, `timestamp`) are passed through `esc()`. Action badges are resolved via `getActionMeta()`, which returns hardcoded CSS classes (`s5`, `s4`) and labels (`Blocked`, `Banned`, `Throttled`, `Logged`), preventing arbitrary class or label injection.
- **Forensic Drawer (`public/js/components/drawer.js:40-54`)**:
  Attack payloads captured by the WAF or rate limiter are displayed inside `<pre class="cs-pre">${esc(inc.payload_snippet || '')}</pre>`. Because `esc()` is applied, real-world attack strings (e.g. `<script>alert(document.cookie)</script>` or SQL injection payloads) are rendered safely as inert text without browser script execution.
- **Toast Notifications & Modals**:
  Toast messages (`showToast`) and confirmation modal targets (`openUnbanModal`) use `.textContent` assignment (`t.textContent = msg; el.textContent = ip;`), eliminating DOM injection vulnerabilities.

### 2. Rate Limiting Telemetry Denial-of-Service, Buffer Churn & Memory Bounds Analysis
- **Circular Ring Buffer Bounding (`pkg/waf/audit.go:47-48, 122-125`)**:
  `AuditLogger` enforces a strict fixed-size buffer:
  ```go
  l.recentEvents = append(l.recentEvents, event)
  if len(l.recentEvents) > l.maxEvents {
      l.recentEvents = l.recentEvents[len(l.recentEvents)-l.maxEvents:]
  }
  ```
  `maxEvents` is initialized to `50`. Memory consumption is bounded regardless of total requests processed.
- **Payload Truncation (`pkg/waf/audit.go:110-112`)**:
  ```go
  if len(event.PayloadSnippet) > 128 {
      event.PayloadSnippet = event.PayloadSnippet[:128] + "..."
  }
  ```
  `PayloadSnippet` is clamped to 128 bytes, preventing heap exhaustion from oversized request bodies or headers.
- **Buffer Churn Trade-off**:
  Under volumetric attacks, rate-limiting drop events will rotate the 50-event buffer rapidly. However, persistent logging (`cfg.Output`) ensures that events are written to persistent storage (stdout, stderr, or dedicated security log file) where external SIEM systems can collect complete audit records.

### 3. Nil Pointer Safety & Concurrency Analysis
- **Audit Logger Nil Dereference Guarding**:
  - In `pkg/router/rate_limiter.go:389`:
    `if al := limiter.AuditLogger(); al != nil { ... }` safely inspects if an audit logger is configured before attempting telemetry construction.
  - In `pkg/router/rate_limiter.go:394-398`:
    `if req != nil { method = req.Method; reqPath = req.Path }` prevents nil pointer panics on synthetic or malformed requests where `req` may be nil.
  - In `pkg/waf/audit.go:101-103, 134-136`:
    Both `LogEvent` and `GetRecentEvents` begin with explicit `if l == nil` guards, safely returning empty slices or no-ops if invoked on uninitialized logger instances.
- **Concurrency & Race Conditions**:
  - `RateLimiter.auditLogger` is guarded by `rl.mu.Lock()` on read and write.
  - `Router.auditLogger` is guarded by `r.mu.Lock()` on write and `r.mu.RLock()` on read.
  - `AuditLogger.recentEvents` is guarded by `l.mu.Lock()`.
  - Comprehensive race detection was executed: `go test -race ./pkg/router/...`, `go test -race ./pkg/waf/...`, and `go test -race ./pkg/server/...`. All packages passed with zero race conditions detected.

### 4. Structured Audit Logging & Log Injection Defense Analysis
- **CRLF & Log Injection Immunity (CWE-117)**:
  `AuditLogger.LogEvent` serializes events via `json.Marshal(event)`. In Go's standard library `encoding/json`, all control characters (including ASCII `\r`, `\n`, `\t`, and bell characters `0x07`) are escaped into Unicode escape sequences (e.g. `\u000d\u000a` or `\r\n`).
  The output is appended with a single newline: `l.writer.Write(append(data, '\n'))`.
  An attacker attempting to inject fake audit log lines via request path (e.g., `GET /api\r\n{"event":"admin_login","action":"granted"}`) cannot forge new log records; the entire input is safely contained within the escaped `"path"` JSON attribute.

---

### 5. Client-Side vs Server-Side Authorization Invariant Analysis
- **Server-Side Authorization Enforcement (`pkg/server/internal_api.go:345-405`)**:
  All management API endpoints (`/internal/api/security/ban`, `/internal/api/security/unban`, `/internal/api/security/incidents`, `/internal/api/security/banned-ips`) are wrapped with `wrapHandler`.
  `wrapHandler` enforces two independent layers of security:
  1. **Subnet Policy Check**: Validates that the client IP belongs to an authorized CIDR block (`cfg.AdminSubnets`). Rejects unauthorized networks with HTTP 403 Forbidden.
  2. **Administrative Authentication**: When authentication is enabled (`cfg.AdminAuth.Enabled`), `validateAdminAuth(req, cfg)` validates the session token or bearer key against `cfg.AdminAuth.Token`. Rejects unauthenticated requests with HTTP 401 Unauthorized.
- **Client-Side SPA Integrity**:
  The dashboard UI uses `authenticatedFetch()`, ensuring `credentials: 'same-origin'` and attaching required authentication headers. Client-side state manipulation cannot bypass server-side authorization guards.

---

### 6. Telemetry Privacy & Sensitive Credential Sanitization Analysis
- **Client Key Token Disclosure**:
  As identified in **SEC-147-01**, `RateLimiter.ExtractClientKey` keys token buckets by `X-API-Key` or `Authorization` when requests originate from trusted proxies or when socket host is absent.
  Because the rate limiter forwards `clientKey` directly to `SecurityEvent.ClientIP` without stripping or hashing `key:` and `auth:` prefixes, raw credentials are recorded in security telemetry.
  While access to internal API telemetry is restricted to authenticated administrators, defense-in-depth principles dictate that API keys and bearer tokens must never appear in plaintext telemetry feeds or dashboard views.

## Positive Observations

1. **Robust CRLF Log Injection Prevention (`CWE-117` Defense)**:
   By standardizing on `json.Marshal(event)` in `AuditLogger.LogEvent`, log line forgery via HTTP method, path, or headers is impossible. All control characters are escaped automatically.
2. **Strict Memory Bounding (`CWE-400` / `CWE-770` Defense)**:
   The circular buffer is capped at exactly 50 events, and payload snippets are hard-clamped to 128 characters. Even under prolonged edge operation with millions of requests, in-memory telemetry storage cannot cause heap exhaustion.
3. **Comprehensive Nil-Pointer Defenses**:
   All paths in `rate_limiter.go`, `router.go`, `main.go`, and `audit.go` feature defensive nil checks (`limiter.AuditLogger() != nil`, `req != nil`, `l == nil`).
4. **Decoupled Architecture Eliminating Alert Suppression**:
   Separating operational health alerts into a dedicated card permanently resolves the visibility flaw where high-priority operational emergencies were masked by routine WAF blocks.
5. **Deterministic Multi-Action Badging**:
   Categorizing defense actions into `Blocked`, `Banned`, `Throttled`, and `Logged` eliminates ambiguity for operators, preventing misidentification of auto-ban quarantines or rate-limiting drops.
6. **Zero-Dependency Native ESM Compliance (`NFR-147-1` / `NFR-147-2`)**:
   All frontend code is vanilla ES2022+ without external runtime packages or build steps, strictly maintaining the project footprint budget under 120.0 KB (122,874 bytes).

## Residual Risk

1. **Plaintext Credential Exposure in Rate Limit Telemetry**:
   Until credential masking or hashing is implemented for `key:` and `auth:` client keys in `rate_limiter.go`, API keys and bearer tokens could be viewed by authorized dashboard operators or written to log files. Access is mitigated by gateway admin authentication and subnet restrictions.
2. **Forensic Telemetry Rotation During Volumetric Attacks**:
   Under sustained DDoS attacks, high-frequency 429 drops can rapidly overwrite older security events in the 50-event in-memory ring buffer. For complete historical investigation, operators must configure a persistent file-based security log sink (`SecurityLog`).
3. **Client-Side Session Storage Token**:
   Administrative tokens stored in browser `sessionStorage` could be accessed if a script injection vulnerability were ever introduced elsewhere in the web application. Mitigated by comprehensive `esc()` encoding and single-origin scoping.

## Open Questions

1. **Credential Masking Pattern**:
   Should client keys derived from `X-API-Key` or `Authorization` be masked using SHA-256 truncation (e.g. `key:sha256(key)[:12]`) or prefix-suffix masking (e.g. `key:sk_...1234`)?
   *(Recommendation: Truncated SHA-256 provides deterministic collation without leaking any portion of the secret).*
2. **Rate Limit Telemetry Sampling**:
   Should high-frequency 429 drops be sampled (e.g. max 1 event per 5 seconds per client IP) to protect the in-memory circular buffer from being flooded during volumetric attacks?
   *(Recommendation: Implement an optional sampling rate for rate-limiting telemetry in a future release).*

## Conclusion & Verdict

The implementation of the Alerts Control Center Dual-Card Separation, Multi-Action Status Badging, and Rate-Limiting Telemetry adheres to secure software development practices. Output encoding is consistently applied to untrusted telemetry data, memory bounds and snippet truncation are strictly enforced in the circular buffer, nil safety is validated across middleware and router dispatch, and administrative authorization is enforced at the server gateway layer.

Non-blocking findings (SEC-147-01 through SEC-147-05) have been identified and documented for defense-in-depth credential sanitization, attribute escaping, and future security test suite expansion.
