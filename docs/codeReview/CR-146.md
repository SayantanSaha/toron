## Findings

### Finding CR-146-F01: Frontend Uncompressed Bundle Footprint Margin Near Budget Ceiling
- **Severity**: Low
- **Category**: Maintainability & Performance Budget
- **Location**: [`public/js/`](../../public/js/) (cumulative across 18 ESM modules)
- **Related artifacts**: [`docs/requirements/REQ-146.md`](../requirements/REQ-146.md), [`docs/tasks/TASK-174.md`](../tasks/TASK-174.md), [`docs/architecture/ADR-146.md`](../architecture/ADR-146.md), [`docs/testCases/TC-146.md`](../testCases/TC-146.md)
- **Evidence**:
  The uncompressed byte count across all 18 JavaScript files in `public/js/` totals 122,544 bytes:
  - `public/js/views/alerts.js`: 23,639 bytes
  - `public/js/model.js`: 17,061 bytes
  - `public/js/views/logs.js`: 13,350 bytes
  - `public/js/components/drawer.js`: 9,056 bytes
  - `public/js/app.js`: 8,485 bytes
  - Remaining 13 modules: 50,953 bytes
  - **Total**: 122,544 bytes ($\le 122,880\text{ bytes}$ / $120\text{ KB}$ budget). Remaining headroom is 336 bytes.
  - Furthermore, [`TASK-174 §4 AC-174-9`](../tasks/TASK-174.md#4-acceptance-criteria) noted a $100\text{ KB}$ target, whereas [`TC-146-09`](../testCases/TC-146.md#tc-146-09) and the verification suite establish the budget at $\le 120\text{ KB}$.
- **Description**: While the current codebase strictly passes the $\le 120\text{ KB}$ budget constraint verified by `TC-146-09`, future feature expansions under `public/js/` could inadvertently exceed the 120 KB threshold unless common UI helpers (e.g. pagination controls, toast dialogs) are further deduplicated or minified.
- **Impact**: Non-blocking. Current implementation passes `TC-146-09`.
- **Recommendation**: Document the 120 KB baseline across all artifacts and consider factoring common pagination templating into a shared component if additional dashboard views are introduced in future tasks.
- **Required action**: None for this release; maintain awareness in subsequent frontend tasks.

### Finding CR-146-F02: Fallback Operational Alert Inspection in Drawer Context
- **Severity**: Informational
- **Category**: Robustness & UX Edge Cases
- **Location**: [`public/js/views/alerts.js`](../../public/js/views/alerts.js#L193), [`public/js/components/drawer.js`](../../public/js/components/drawer.js#L30-L31)
- **Related artifacts**: [`docs/requirements/REQ-146.md`](../requirements/REQ-146.md), [`docs/tasks/TASK-174.md`](../tasks/TASK-174.md), [`docs/architecture/ADR-146.md`](../architecture/ADR-146.md)
- **Evidence**:
  In [`public/js/views/alerts.js`](../../public/js/views/alerts.js#L193):
  ```javascript
  const incs = (model.incidents && model.incidents.length > 0) ? model.incidents : (model.alerts || []);
  ```
  When `model.incidents` is empty (`length === 0`), `incs` falls back to `model.alerts`. Each item rendered attaches a click handler invoking `openDrawer('incident', item.dataset.incId)`.
  In [`public/js/components/drawer.js`](../../public/js/components/drawer.js#L30-L31):
  ```javascript
  const incs = (D.incidents && D.incidents.length > 0) ? D.incidents : (rawApiIncidents || []);
  const inc = incs.find(...) || incs[0] || {};
  ```
  `openDrawer('incident')` queries `D.incidents` or `rawApiIncidents`, but does not inspect `D.alerts`.
- **Description**: Under the rare edge case where zero WAF incidents exist but an operational alert (e.g. failing upstream pool instance) is active, clicking that alert row in `#/alerts` opens `#drawer` with blank/default forensic telemetry rather than routing to the target pool or displaying operational alert details.
- **Impact**: Minimal / Informational. In production workloads, operators investigate operational alerts via Overview (`#/overview`) and direct navigation links (`a.go`), while `#/alerts` is primarily focused on threat defense and active WAF audit trails.
- **Recommendation**: In a future enhancement, check if the clicked item is an operational alert with an `a.go` property (or ID prefix `upstream_`, `route_`, `cert_`) and navigate directly to the target subsystem, or allow `renderIncidentDrawer` to display operational alert details if not found in `D.incidents`.
- **Required action**: None for this release; preserve as potential UX polish.

## Positive Observations

1. **Clean Separation of Concerns**: By eliminating the synthetic `ban_${i}` push in `public/js/model.js`, operational alerts (`D.alerts`), WAF events (`D.incidents`), and active firewall bans (`D.bannedIps`) are cleanly separated, eliminating visual duplication and badge count distortion across the dashboard.
2. **Deterministic Tie-Breaking Collation**: Sorting in `public/js/views/alerts.js` strictly respects [`REQ-138`](../requirements/REQ-138.md) and [`ADR-138`](../architecture/ADR-138.md), using numeric IP collation (`localeCompare(..., { numeric: true })`) to resolve secondary ties deterministically.
3. **Hardened Security Observability**: Exposing OWASP rule IDs, anomaly scores, parameter locations, and inspectable payload snippets inside `<pre class="cs-pre">` transforms the alerts view into an operational security cockpit without requiring operators to switch to terminal logs.
4. **Ergonomic Responsive UI**: Relocating the manual ban form into a decoupled action card resolves header wrapping on sub-1200px screens. Mobile breakpoint CSS down to 320px ensures responsive presentation on tablet and handheld viewports.
5. **Zero DOM Freezing & Full Thread Liveness**: Unban confirmation and toast feedback operate entirely through non-blocking asynchronous DOM overlays, guaranteeing uninterrupted background telemetry polling and real-time chart animations.

## Residual Risk

- **Operator Expectation on Navigation Badge**: As noted in [`ADR-146 §7`](../architecture/ADR-146.md#consequences), operators accustomed to seeing banned IPs counted in the navigation alert badge will observe lower numbers. This is technically correct as quarantined actors are mitigated states rather than active unmitigated failures.
- **In-Memory Buffer Horizon**: Backend `AuditLogger` maintains a 50-incident ring buffer. Operators requiring audit investigation beyond 50 events should use disk log inspection or the live request tailing cockpit at `#/logs`.
