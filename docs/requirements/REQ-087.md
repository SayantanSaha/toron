# REQ-087 - Bounded Concurrency, Socket Reuse, and Idle Deadline Enforcement in Layer 4 TCP and UDP Proxies

## Description

The Toron Layer 4 transport proxies—[`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L14-L23) and [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L13-L22)—MUST enforce bounded concurrency, connection limits, upstream socket/session reuse, datagram buffer pooling, and bidirectional idle deadline tracking. These mechanisms remediate vulnerability [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383) (CWE-400), preventing denial of service, memory exhaustion (OOM), ephemeral port starvation, and socket file descriptor exhaustion (`EMFILE`) under Layer 4 high-frequency packet floods and idle Slowloris connection patterns.

## Problem Statement

As documented in [`SEC-26`](file:///Users/sneha/Developer/toron-research/toron/SECURITY_AUDIT.md#L375-L383) and [`SR-081 Finding 4`](file:///Users/sneha/Developer/toron-research/toron/docs/securityReview/SR-081.md#L130-L140), both the Layer 4 UDP and TCP proxy implementations lack resource bounds, lifecycle tracking, and deadline protections:

### 1. UDP Proxy Deficiencies ([`pkg/proxy/udp.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go))
- **Unbounded Goroutine Spawning**: In [`UDPProxy.Serve`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L57-L78), every incoming datagram spawns a new goroutine (`go p.handleDatagram(...)`) without concurrency limits or backpressure. Under a high-volume UDP flood, hundreds of thousands of goroutines are scheduled simultaneously, causing CPU saturation and memory exhaustion (OOM).
- **Per-Packet Socket Allocation**: In [`handleDatagram`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L80-L108), `net.DialUDP("udp", nil, targetUDPAddr)` is invoked on **every single datagram**. Each dial requests a fresh ephemeral port and OS socket file descriptor. High packet rates immediately exhaust host ephemeral ports (`bind: address already in use`) and trigger file descriptor starvation (`socket: too many open files` - `EMFILE`).
- **Unpooled Buffer Churn**: A new 64 KB response slice (`make([]byte, 65535)`) is heap-allocated on every datagram in [`handleDatagram`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L101), generating massive garbage collection pressure and latency spikes.
- **Untracked Lifecycle & Leaked Sockets on Close**: In [`UDPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L111-L126), active goroutines and dialed outbound UDP sockets are neither tracked nor terminated. Existing packet handlers continue executing until their internal timeouts expire.

### 2. TCP Proxy Deficiencies ([`pkg/proxy/tcp.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go))
- **Unbounded Connection Acceptance**: In [`TCPProxy.Serve`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L58-L76), `l.Accept()` loops unconditionally without concurrency limits or active connection tracking. An attacker can exhaust system socket file descriptors by opening unlimited TCP connections.
- **Missing Idle Deadlines (Slowloris Vulnerability)**: Neither `clientConn` nor `upstreamConn` has read or write deadlines set during stream copying. In [`handleConn`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L78-L109), both `io.Copy(upstreamConn, clientConn)` and `io.Copy(clientConn, upstreamConn)` block indefinitely when an established connection stops sending data. An attacker can hold thousands of connections open with 0 bytes transferred, permanently leaking file descriptors and worker goroutines.
- **Unterminated Connections on Shutdown**: In [`TCPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L112-L127), only the listener is closed. Active client connections and upstream sockets are neither tracked nor closed. Existing `io.Copy` goroutines remain blocked indefinitely until remote peers terminate them.

## Acceptance Criteria

1. **Declarative Route Configuration Schema (`ProxyRouteConfig`)**:
   - [`ProxyRouteConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L253-L290) in `pkg/config/config.go` MUST be extended with the following configurable Layer 4 attributes:
     - `MaxConnections int` (`yaml:"max_connections,omitempty" json:"max_connections,omitempty"`): Maximum number of concurrent active TCP connections. If unset or `<= 0`, the proxy MUST default to `10000`.
     - `IdleTimeout time.Duration` (`yaml:"idle_timeout,omitempty" json:"idle_timeout,omitempty"`): Maximum allowable idle duration without bidirectional data transfer before terminating a TCP connection or UDP session. If unset or `<= 0`, the proxy MUST default to `60 * time.Second`.
     - `MaxWorkers int` (`yaml:"max_workers,omitempty" json:"max_workers,omitempty"`): Maximum number of concurrent worker goroutines / datagram processing tasks for UDP proxying. If unset or `<= 0`, the proxy MUST default to `1024`.
   - Helper methods on [`ProxyRouteConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go#L253-L290) (`GetMaxConnections() int`, `GetIdleTimeout() time.Duration`, `GetMaxWorkers() int`) MUST return the configured values or fallback to their respective defaults.
   - Main gateway initialization in [`cmd/toron/main.go`](file:///Users/sneha/Developer/toron-research/toron/cmd/toron/main.go#L390-L429) MUST propagate these route parameters when instantiating [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L15-L23) and [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L14-L22).

2. **Bounded TCP Connection Concurrency & Over-Capacity Handling (`TCPProxy`)**:
   - [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L15-L23) MUST atomically track the count of currently active client connections.
   - When a new TCP connection is accepted in [`TCPProxy.Serve`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L58-L76):
     - If the number of active connections is greater than or equal to `MaxConnections`, the incoming connection MUST be closed immediately without proxying data or dialing upstream.
     - The proxy MUST log a warning indicating that the maximum connection capacity has been reached.
     - Rejected connections MUST NOT be added to active tracking or leak resources.
   - When an active connection terminates (clean close, reset, error, or idle timeout), the active connection count MUST be decremented immediately.

3. **Bidirectional TCP Idle Deadlines & Slowloris Mitigation (`TCPProxy`)**:
   - All bidirectional stream transfers between `clientConn` and `upstreamConn` MUST enforce `IdleTimeout`.
   - The proxy MUST NOT rely on unbounded `io.Copy` blocking calls without deadlines.
   - Both client and upstream socket deadlines MUST be refreshed upon data transfer activity. If no data is read or written in either direction for the duration of `IdleTimeout`, both sockets MUST be closed, terminating the proxy stream and unblocking all associated goroutines.
   - Half-closed connection states (e.g., EOF received in one direction) MUST continue to honor `IdleTimeout` on the surviving direction until completion or timeout.

4. **Bounded UDP Datagram Concurrency & Buffer Pooling (`UDPProxy`)**:
   - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L14-L22) MUST bound concurrent datagram processing to `MaxWorkers` (default `1024`).
   - Unthrottled per-datagram goroutine creation (`go p.handleDatagram(...)`) MUST be eliminated and replaced with a bounded worker pool or concurrency-limiting semaphore pattern.
   - If the worker pool or processing capacity is saturated under extreme packet bursts, excess datagrams MUST be dropped or rejected fail-safe rather than spawning unbounded goroutines or leaking memory.
   - Datagram read and response buffers (64 KB / 65,535 bytes) MUST be recycled using `sync.Pool`, eliminating per-datagram heap allocations and garbage collection thrashing.

5. **Upstream UDP Session Caching, Socket Reuse & Expiration (`UDPProxy`)**:
   - [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L14-L22) MUST NOT invoke `net.DialUDP` on every datagram.
   - The proxy MUST maintain a thread-safe session registry mapping client addresses (`net.UDPAddr` or string endpoint key) to active upstream UDP sockets (`*net.UDPConn`).
   - Subsequent datagrams from an existing client session MUST reuse the established upstream UDP socket, eliminating ephemeral port exhaustion and socket descriptor starvation (`EMFILE`).
   - Upstream replies MUST be read from the cached upstream socket and relayed back to the corresponding client address.
   - Inactive UDP sessions MUST be cleaned up and their upstream sockets closed after `IdleTimeout` of inactivity (via periodic sweeping or deadline-based session eviction).

6. **Active Connection & Session Tracking with Deterministic Shutdown (`Close`)**:
   - Both [`TCPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L15-L23) and [`UDPProxy`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L14-L22) MUST maintain thread-safe registries of all currently active connections, sockets, and sessions.
   - Calling [`TCPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/tcp.go#L112-L127) MUST:
     a. Close the listening socket to reject new incoming connections.
     b. Close all tracked active client and upstream TCP connections, interrupting pending read/write operations.
     c. Wait for or ensure rapid termination of all active forwarding goroutines without hangs or resource leaks.
   - Calling [`UDPProxy.Close`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/udp.go#L111-L126) MUST:
     a. Close the inbound listening UDP socket.
     b. Close all cached upstream session UDP sockets.
     c. Terminate and drain all worker goroutines and background session cleaner routines.

7. **Runtime Observability & Diagnostic Logging**:
   - The Layer 4 proxy engines MUST emit clear diagnostic log entries using standard prefixes (`[TCPProxy]` and `[UDPProxy]`):
     - Log connection rejections when `MaxConnections` is exceeded.
     - Log connection / session terminations triggered by `IdleTimeout`.
     - Log packet drop occurrences when the UDP worker pool is saturated.
   - Logging MUST NOT print raw packet payloads to protect user privacy and avoid denial-of-service via log flooding.

8. **Regression Invariants, Race Freedom & Zero External Dependencies**:
   - Implementation MUST be strictly implemented using Go standard library packages (`net`, `sync`, `sync/atomic`, `time`, `io`, `log`, `errors`). Zero third-party packages may be introduced.
   - Existing Layer 4 proxy forwarding semantics (round-robin target load balancing, backend health status, single vs. multi-target dispatch) MUST remain backward compatible.
   - All connection tracking, session tables, buffer pools, and shutdown mechanisms MUST execute completely race-clean and pass `go test -race ./pkg/proxy/... ./pkg/config/...` without race conditions, deadlocks, or socket leaks.

9. **Performance Monitoring, Benchmark Testing & Low-Overhead Alternative Evaluation**:
   - Automated performance benchmark tests MUST be implemented in `pkg/proxy/tcp_test.go` and `pkg/proxy/udp_test.go` (`BenchmarkTCPProxy_Forwarding`, `BenchmarkUDPProxy_Forwarding`, testing throughput and memory allocations with `b.ReportAllocs()`).
   - The hardened implementation MUST minimize synchronization contention and heap allocations (reusing buffers via `sync.Pool` and minimizing lock hold times).
   - If performance testing reveals significant degradation compared to baseline throughput, alternate low-overhead implementations (e.g., sharded session mutexes, `sync.Map`, atomic fast-paths) MUST be explored and evaluated.

## Rationale

Without bounded concurrency and idle deadlines, Layer 4 TCP and UDP proxies are vulnerable to low-cost DoS attacks (Slowloris and UDP flooding) that can crash the entire Toron edge gateway through socket FD exhaustion or memory starvation. Introducing worker bounds, socket reuse, buffer pooling, and idle timeouts guarantees deterministic resource consumption and resilience in production Kubernetes and bare-metal environments.
