# REQ-067 - Upstream Path Canonicalization and Directory Traversal Prevention in Proxy Routing

## Description

The Toron reverse proxy routing engine shall perform strict URL path canonicalization on incoming request paths before prefix route matching and path resolution in `JoinProxyPath`.

Path traversal sequences (such as `/..` or `/./`) shall be resolved or rejected before target path synthesis, preventing clients from escaping configured route prefixes or reaching unauthorized backend microservice endpoints.

## Acceptance Criteria

### 1. Pre-Routing Path Canonicalization
- Incoming `req.Path` shall be canonicalized (e.g. via `path.Clean`) before evaluating prefix route matches in `Router.ServeHTTP` and `MatchPrefixRoute`.
- Uncleaned dot segments (e.g. `/api/../admin` or `//admin`) shall not be matched against prefix rules prior to normalization.

### 2. Upstream Path Traversal Mitigation in `JoinProxyPath`
- `JoinProxyPath` shall verify that the synthesized destination path does not escape the configured `targetPath` boundary through dot-segment traversal.
- Slashes and directory separators shall be resolved deterministically without allowing relative escapes.

### 3. Rejection of Ambiguous or Malformed Paths
- Requests with malformed relative paths that cannot be safely normalized or that attempt to traverse above root (`/..`) shall be normalized to `/` or rejected with HTTP `400 Bad Request`.

### 4. Preservation of Query Strings and Suffixes
- Path canonicalization shall preserve legitimate trailing slashes and query parameters while stripping dangerous relative path sequences.

## Rationale

If uncleaned request paths containing `/..` are matched against prefix rules, an attacker can match an authorized prefix (e.g. `/public/../admin`) and have the proxy join the relative path to an internal target, breaking namespace isolation on backend services.

## Constraints

- Compliance with RFC 3986 §5.2.4 (Remove Dot Segments).
- Minimal memory allocation impact during request dispatching.

## Open Questions

- Should double-slashes (`//`) be collapsed automatically to single slashes across all proxy routes?
