# REQ-072 - HTTP Parameter Pollution (HPP) Mitigation in Target Query Merging

## Description

The Toron reverse proxy query forwarding engine shall enforce parameter collision guards when merging client-supplied URL query strings with pre-configured upstream target query parameters.

When an upstream route configuration defines fixed query parameters in its target URL (e.g. `target: "http://upstream:8080/api?role=guest"`), client-supplied query parameters shall not be permitted to override or pollute those target-enforced constraints.

## Acceptance Criteria

### 1. Target Query Parameter Precedence
- Any query parameter key explicitly configured in the route's `target` URL shall remain immutable and take precedence over conflicting client query parameters.
- If a client supplies a query parameter key that matches a key in the target URL (e.g. client sends `?role=admin` against a target configured with `?role=guest`), the proxy shall strip or sanitize the client's conflicting key.

### 2. Elimination of Duplicate Key Pollution
- Query string synthesis shall avoid generating duplicate query keys (such as `role=guest&role=admin`) that could trigger HTTP Parameter Pollution (HPP) vulnerabilities in downstream microservices that select the last parameter occurrence.

### 3. Non-Conflicting Query Parameter Preservation
- All non-conflicting client query parameters shall continue to be forwarded verbatim, preserving parameter ordering and percent-encoding fidelity per REQ-060.

## Rationale

Different web application frameworks handle duplicate query parameters differently (e.g. first value, last value, or array concatenation). If Toron appends client query strings after target query strings, an attacker can override gateway-enforced security constraints by exploiting parameter precedence behaviors on downstream backends.

## Constraints

- Seamless integration with `pkg/proxy/proxy.go` query merging logic introduced in REQ-060.
- High-efficiency query string parsing without excessive memory allocations.

## Open Questions

- Should conflicting query parameter attempts be logged to the security log as potential tampering events?
