# REQ-043 - Route-Level WAF Overrides and CIDR IP Blocklists

## Description

The Toron web server and edge reverse proxy shall extend its native Web Application Firewall (`pkg/waf`) to support granular per-route security posture overrides and fast, zero-allocation CIDR-based IP allow/deny access control lists (ACLs).

The system shall provide:

1. **CIDR-Based IP Access Control Lists (ACLs)**:
   - **Allowed IPs (`allowed_ips`)**: Configurable list of IPv4 and IPv6 CIDR blocks (e.g. `10.0.0.0/8`, `192.168.1.0/24`) or single IP addresses. When configured, requests originating from client IPs outside these ranges shall be immediately rejected with HTTP `403 Forbidden` (`{"error":"Forbidden","message":"IP address not in allowed list"}`).
   - **Denied IPs (`denied_ips`)**: Configurable list of IPv4 and IPv6 CIDR blocks (e.g. `198.51.100.0/24`, `203.0.113.50/32`) or single IP addresses. When matched, requests shall be immediately rejected with HTTP `403 Forbidden` (`{"error":"Forbidden","message":"IP address denied by access control list"}`).
   - **Fast-Path O(1) Pre-Inspection**: IP access checking shall execute before deep regex scanning, query string decoding, or payload body buffering.
   - **Client IP Extraction**: Extract remote client IP safely from `req.RemoteAddr` (stripping port) and optional trusted proxy header `X-Forwarded-For` if configured.

2. **Per-Route WAF Configuration & Overrides (`routes.yaml`)**:
   - Allow any static route or upstream proxy route in `routes.yaml` to define a dedicated `waf:` configuration block overriding global settings:
     - `enabled`: Toggles WAF inspection on or off for that specific route.
     - `mode`: Overrides mode (`enforce` vs `detection`) for the route (e.g., allow staging endpoints to log anomalies without blocking).
     - `anomaly_threshold`: Overrides score threshold for the route.
     - `disabled_rules`: Allows disabling specific OWASP rule IDs (e.g., `SQLI-001`, `XSS-002`) on individual microservice routes without weakening global edge protection.
     - `allowed_ips` / `denied_ips`: Route-specific IP allowlists and blocklists.
     - `max_inspect_body_size`: Route-specific inspection payload boundary.

3. **Global & Route Configuration Hierarchy**:
   - Global `server.waf` settings in `config.yaml` serve as the gateway baseline.
   - Route-level `routes[].waf` configurations in `routes.yaml` take precedence for traffic matching that route prefix or virtual host.

## Acceptance Criteria

- Requests from IP addresses matching `denied_ips` return HTTP `403 Forbidden`.
- When `allowed_ips` is defined, requests from IP addresses not in the allowlist return HTTP `403 Forbidden`.
- A route with `disabled_rules: ["SQLI-001"]` permits payloads matching `SQLI-001` on that route while other routes block with HTTP `403 Forbidden`.
- A route configured with `mode: "detection"` allows matching threats to pass to upstream backends while attaching `X-Toron-WAF-Anomaly-Score`.
- Global IP ACLs and route-level IP ACLs execute cleanly with zero performance degradation on benign traffic.
- All Go unit tests pass cleanly across all packages (`go test ./...`).
