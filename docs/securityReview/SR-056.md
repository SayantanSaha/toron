# SR-056 - Security Review of Upstream Reverse Proxy Path Rewriting and Target Subpath Preservation

## Description

Security assessment of upstream path resolution and rewriting logic in `pkg/proxy/proxy.go`. The review examines potential path traversal vulnerabilities, SSRF risks, URL canonicalization anomalies, prefix bypass risks, and header injection concerns.

## Scope

- Files reviewed:
  - `pkg/proxy/proxy.go`
  - `pkg/proxy/proxy_test.go`

## Security Evaluation & Analysis

1. **Path Traversal & Directory Climbing**:
   - `JoinProxyPath` joins target and client paths using `singleJoiningSlash` or prefix-based substring operations.
   - HTTP path parsing (`httpparser`) cleans and standardizes paths prior to router dispatch (`path.Clean`).
   - Slashes are strictly joined without interpreting relative segment escapes (`..`), preventing path escape from designated upstream targets.

2. **Server-Side Request Forgery (SSRF) & Host Header Pollution**:
   - Upstream destinations are statically defined in `routes.yaml` (or `config.yaml`).
   - `JoinProxyPath` strictly modifies the URL path component (`outURL.Path`) and does not alter the destination hostname, port, or protocol scheme.
   - Host isolation is preserved.

3. **Prefix Confusion & Routing Boundary Bypass**:
   - The route prefix match in `pkg/router/router.go` requires exact prefix match or prefix followed by `/`.
   - `strings.TrimPrefix(reqPath, prefix)` cannot trim beyond the registered prefix boundary.

4. **WAF & Security Logging Integrity**:
   - WAF inspection and security log interceptors execute in the router middleware pipeline *prior* to proxy forwarding.
   - Any malicious payloads directed at subpath endpoints (e.g. SQL injection or scanner signatures in headers or query strings) continue to be trapped and recorded to `security.log`.

## Conclusion

No security vulnerabilities identified. The implementation is approved.
