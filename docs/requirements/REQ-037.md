# REQ-037 - Next-Generation HTTP Response Compression (Brotli `br` & Zstandard `zstd`)

## Description

The Toron web server compression engine shall be extended to support high-efficiency, modern compression algorithms: **Brotli (`br`)** (RFC 7932) and **Zstandard (`zstd`)** (RFC 8878), alongside existing Gzip and Deflate support.

The enhanced compression pipeline shall:
1. **Multi-Encoding Negotiation**:
   - Parse client `Accept-Encoding` header supporting `zstd`, `br`, `gzip`, `deflate`, and wildcard `*` with quality factor weighting (`q=`).
   - Default priority preference order: `zstd` > `br` > `gzip` > `deflate`.
2. **Zero-Allocation Object Pooling**:
   - Reuse encoder/writer instances (`brotli.Writer`, `zstd.Encoder`, `gzip.Writer`, `flate.Writer`) using `sync.Pool` to maintain high QPS with minimal GC pressure.
3. **MIME & Protocol Protections**:
   - Compress only textual and structured data MIME types (`text/*`, `application/json`, `application/javascript`, `application/xml`, `image/svg+xml`).
   - Bypass incompressible binary payloads (JPEG, PNG, WebP, MP4, zip) and WebSocket upgrades (`101 Switching Protocols`).
   - Enforce configurable `min_length` threshold (default 512 bytes).
4. **Header Synchronization**:
   - Set matching `Content-Encoding` (`zstd`, `br`, `gzip`, `deflate`).
   - Ensure `Vary: Accept-Encoding` is always preserved.
   - Adjust `Content-Length` to reflect compressed payload size.

## Acceptance Criteria

- When client sends `Accept-Encoding: br`, response is compressed with Brotli and headers include `Content-Encoding: br`.
- When client sends `Accept-Encoding: zstd`, response is compressed with Zstandard and headers include `Content-Encoding: zstd`.
- Quality weights in `Accept-Encoding` (e.g. `gzip;q=1.0, br;q=0.5`) are respected.
- `sync.Pool` is used for Brotli and Zstandard encoders.
- All Go unit tests pass cleanly (`go test ./...`).
