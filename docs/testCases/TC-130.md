# TC-130 - Test Specification for Multi-Tier Duration Stress Testing (5s, 60s, 300s), Go Runtime GC Telemetry Capture, and Differential Reverse Proxy Benchmarking

## 1. Test Suite Overview & Architectural Objectives

### 1.1 Executive Summary & Problem Context
During high-throughput saturation benchmarks, memory boundedness evaluations, and comparative systems audits of Toron's reverse proxy engine against industry-standard reverse proxies (**NGINX**, **Traefik**, **Caddy**, and **HAProxy**) under [`REQ-130`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-130.md), [`TASK-153`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-153.md), and [`ADR-130`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-130.md), three critical methodological and empirical blindspots were identified in the existing benchmarking harnesses:

1. **The 5-Second Short-Duration Evaluation Blindspot**:
   - Existing default benchmark runs in [`benchmarks/run_all.sh`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/run_all.sh#L135-L140), [`benchmarks/wrk2/run_saturation_stress.sh`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/wrk2/run_saturation_stress.sh#L17), and [`benchmarks/docker-compare/run_compare.sh`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/docker-compare/run_compare.sh#L20) executed for only **5 to 10 seconds**.
   - While a 5-second burst is optimal for rapid pre-commit continuous integration sanity checks, it introduces severe scientific distortions:
     - **Transient Startup Bias**: Socket connection pool ramp-up, initial thread scheduling, CPU frequency scaling, and Go runtime netpoller priming dominate the measurement window.
     - **Garbage Collector Masking**: Go's concurrent mark-and-sweep garbage collector (GC) triggers only 0 to 2 times under zero-allocation routing, completely masking Stop-The-World (STW) pauses, mark-assist CPU overhead, and heap expansion dynamics.
     - **Invisible Memory Leaks & Heap Drift**: Memory bloat, buffer pool reference retention (`sync.Pool` retaining slabs), goroutine leaks, and socket descriptor leaks (`EMFILE`, [CWE-775](https://cwe.mitre.org/data/definitions/775.html)) cannot be detected during a transient 5-second run, preventing empirical validation of constant $O(1) \le 32\text{ KB}$ memory boundedness ([`REQ-129`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-129.md) / [`ADR-129`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-129.md)).
2. **Absence of Go Runtime GC Telemetry (`GODEBUG=gctrace=1`)**:
   - Toron and its Go-based competitors (**Traefik** and **Caddy**) rely on automatic heap management. In contrast, **NGINX** and **HAProxy** are implemented in C with explicit manual memory management (`malloc`/`free`).
   - In prior runs, Toron ran with default environment variables, completely omitting runtime GC tracing. Researchers could not observe GC CPU overhead, frequency of STW pauses, max STW pause, or post-GC live heap baseline under saturation.
3. **Single-Snapshot Resource Skew and Lack of Soak Longevity Testing**:
   - In [`benchmarks/docker-compare/runner.go`](file:///Users/sneha/Developer/toron-research/toron/benchmarks/docker-compare/runner.go), proxies were evaluated for 5 seconds per backend, and container resource utilization was sampled only once after benchmark completion via `docker stats --no-stream`.
   - Post-run snapshots capture memory RSS after connections close and idle sweep occurs, obscuring peak working sets, memory fragmentation, and long-term memory growth trajectories across proxies.

To establish publication-grade empirical rigor, [`REQ-130`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-130.md), [`ADR-130`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-130.md), and [`TASK-153`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-153.md) formalize a **Multi-Tier Duration Benchmark Architecture** spanning:
- **Tier 1: Quick Smoke (`quick`, 5 seconds)**: Rapid pre-merge CI regression verification.
- **Tier 2: Steady-State & GC Observation (`medium` / `steady`, 60 seconds)**: Deep observation of Go runtime GC cycles, mark/pause clock times, and steady-state tail latencies ($p95, p99, p99.9$).
- **Tier 3: Long-Term Soak & Memory Stability (`soak`, 300 seconds / 5 minutes)**: Extended soak testing validating $O(1)$ memory boundedness, zero memory drift, connection pool longevity, and proxy resilience under sustained saturation.
- **Tier 4: Comprehensive All-Tiers Sweep (`all`, 5s + 60s + 300s)**: Full sequential evaluation matrix for scientific publication.

### 1.2 Core Architectural Objectives & The 4 Non-Negotiable Invariants

```
+--------------------------------------------------------------------------------------------------+
│                                  THE 4 NON-NEGOTIABLE INVARIANTS                                 │
│                                                                                                  │
│  1. UNCOMPROMISED DUAL-STREAM TELEMETRY & 4-TIER CLASSIFICATION (ADR-114, ADR-117):              │
│     Across all durations (5s, 60s, 300s), benign (90%) and adversarial (10%) streams remain      │
│     strictly decoupled. Adversarial probes evaluated under strict 4-tier taxonomy (Tier 1:       │
│     Active Defense, Tier 2: Route Miss, Tier 3: Attack Bypass, Tier 4: Unhandled). 0% 404 credit.│
│                                                                                                  │
│  2. CONSTANT O(1) MEMORY BOUNDEDNESS UNDER 300s SOAK (ADR-129):                                  │
│     Under continuous 300-second saturation, Toron post-GC live heap shall remain strictly        │
│     bounded with Ordinary Least Squares (OLS) linear regression heap growth slope <= 1.0 MB/min, │
│     confirming zero memory leaks and strict O(1) per-stream memory bounds.                       │
│                                                                                                  │
│  3. ZERO MEASUREMENT DISTORTION & BOUNDED LOG OVERHEAD:                                          │
│     GC telemetry parsing shall occur post-run or asynchronously, imposing < 0.5% CPU overhead.   │
│     GC trace logs shall be cleanly segregated to stderr, bounded, and indexed in manifest.       │
│                                                                                                  │
│  4. COMPLETE BACKWARD COMPATIBILITY:                                                             │
│     Existing CI invocations (e.g. run_all.sh without flags) shall execute default quick 5s tier  │
│     without breaking existing test automation or regression pipelines (< 60s total suite).       │
+--------------------------------------------------------------------------------------------------+
```

### 6.1 The 4 Non-Negotiable Invariants Verification

   - Across all duration tiers (5s, 60s, 300s), benign (90%) and adversarial (10%) streams remain strictly segregated.
   - Adversarial probes are evaluated under the 4-tier taxonomy.
   - **Assertion Oracle**: $0\%$ defense credit awarded for HTTP `404` Route Misses.
2. **Invariant 2: Constant $O(1)$ Memory Boundedness Soak ([`ADR-129`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-129.md))**:
   - Under continuous 300-second saturation ($1.5\text{M}$ transactions), Toron post-GC live heap shall remain bounded.
   - **Assertion Oracle**: $\text{HeapGrowthSlope} \le 1.0\text{ MB/min}$ and $\text{FinalLiveHeapMB} \le 32.0\text{ MB}$.
3. **Invariant 3: Zero Measurement Distortion & Bounded Log Overhead**:
   - GC trace parsing executes asynchronously or post-run, imposing $< 0.5\%$ CPU overhead during benchmark measurement.
   - GC trace log size is bounded ($< 5\text{ MB}$ over 300s) and segregated to stderr.
4. **Invariant 4: Complete Backward Compatibility**:
   - Standard invocations without flags default to `quick` (5s) tier, completing the master test suite in $< 60$ seconds.
