# REQ-124 - Configurable Distributed Tracing and Conflict Analysis of Latency Optimizations

## 1. Description & Problem Statement

### 1.1 Problem Context
In the multi-proxy differential benchmark ([`REQ-121`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-121.md)), Toron outperformed Traefik and Caddy in throughput across high-performance backends (Toron: ~24.5k RPS vs Traefik: ~24.0k RPS vs Caddy: ~18.3k RPS; and on Node.js, Toron reached 20.4k RPS vs Traefik's 16.3k RPS, +25.1% higher).

However, latency analysis revealed that Traefik achieved a ~0.19ms lower median latency (P50 0.97ms vs Toron's 1.16ms) and tighter tail latency. Code profiling identified that on every proxied request in [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1021), Toron unconditionally invokes:
```go
incomingTrace := req.Header.Get("traceparent")
outReq.Header.Set("traceparent", metrics.EnsureW3CTraceparent(incomingTrace))
```

Under [`REQ-031`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-031.md) and [`ADR-026`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-026.md), when requests lack a `traceparent` header (the standard case in high-throughput microbenchmarks and client traffic), `EnsureW3CTraceparent` calls `crypto/rand.Read` twice per request to generate a cryptographically secure 128-bit trace ID and 64-bit span ID. At 24.5k RPS, this generates **~49,000 cryptographic system calls per second (`getrandom` / `/dev/urandom`)**, introducing kernel context switches, global runtime lock contention, and heap allocations.

In comparison, Traefik and Caddy only generate tracing contexts when distributed tracing middleware (OpenTelemetry / Jaeger) is explicitly configured.

### 1.2 Objective
1. Make W3C distributed tracing context generation and propagation configurable under the field name `tracing` at both the global server transport level (`config.yaml`) and the per-route transport level (`routes.yaml`), allowing operators to disable trace generation for raw speed or enable it for enterprise observability.
2. Conduct a formal conflict audit on the other three proposed latency optimizations:
   - Proposal 2: Direct socket streaming vs double-copy response buffering
   - Proposal 3: Eliminating / relaxing per-request deadline syscalls (`SetReadDeadline` / `SetWriteDeadline`)
   - Proposal 4: Socket options (`TCP_NODELAY` and write buffer recycling)

## 2. Conflict Audit of Proposed Latency Optimizations Against Previous Requirements

### 2.1 Proposal 2: Direct Socket Streaming vs. Double-Copy Response Buffering
* **Description**: Stream upstream response bytes directly to the client connection `net.Conn` without intermediate buffering in `httpparser.Response.Body` (`bytes.Buffer`).
* **Audit Against Previous Requirements**:
  1. **Conflict with [`REQ-017`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-017.md) / [`ADR-017`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-017.md) (Transparent Response Compression)**:
     - `CompressionMiddleware` (`pkg/router/compression.go`) inspects `res.Body.Len()`, evaluates compressibility, reads `res.Body.Bytes()`, compresses the body using Zstd, Brotli, Gzip, or Deflate, and replaces `res.Body`.
     - *Conflict*: If `ReverseProxy` streams bytes directly to `net.Conn`, `CompressionMiddleware` cannot compress the body or update `Content-Length`.
  2. **Conflict with [`REQ-019`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-019.md) / [`ADR-019`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-019.md) (In-Memory Response Caching)**:
     - `CacheMiddleware` (`pkg/router/cache.go`) inspects `res.Body.Len()` and captures `res.Body.Bytes()` to cache eligible responses in memory.
     - *Conflict*: If `ReverseProxy` streams bytes directly to `net.Conn`, `CacheMiddleware` cannot capture payloads for caching.
  3. **Conflict with [`REQ-004`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-004.md) / [`ADR-004`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-004.md) (Header & Redirect Rewriting)**:
     - If bytes are streamed to the wire before headers are finalized, downstream cookie path rewriting or redirect rewriting is impossible.
* **Resolution**:
  - **Unconditional streaming directly to `net.Conn` CONFLICTS with `REQ-017` and `REQ-019`.**
  - **Approved Non-Conflicting Path**:
    - Preserve `res.Body` buffering for routes where compression or caching is active.
    - Implement a conditional streaming bypass *only* when compression and caching are disabled on the route or globally.
    - Alternatively, introduce a recycled memory pool (`sync.Pool`) for response buffers to eliminate heap allocation overhead without breaking the middleware contract.

### 2.2 Proposal 3: Eliminating / Relaxing Per-Request Deadline Syscalls
* **Description**: Avoid calling `conn.SetReadDeadline` and `conn.SetWriteDeadline` on every request in the keep-alive loop.
* **Audit Against Previous Requirements**:
  1. **Direct Conflict with [`REQ-005`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-005.md) §2 (Security Controls & Input Protection)**:
     - Mandates: *"Enforces strict read, write, and idle connection timeouts to prevent Slowloris/slow-client resource exhaustion."*
  2. **Direct Conflict with [`TASK-004`](file:///Users/sneha/Developer/toron-research/toron/docs/tasks/TASK-004.md) §3 (Security Guards & Connection Timeouts)**:
     - Mandates: *"Set socket read and write deadlines per connection to prevent Slowloris attacks."*
  3. **Direct Conflict with [`ADR-083`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-083.md) & Security Verifications [`TC-087`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-087.md) / [`TC-088`](file:///Users/sneha/Developer/toron-research/toron/docs/testCases/TC-088.md)**:
     - Removing `SetWriteDeadline` enables Slow Read attacks (CWE-400), where slow clients consume server worker goroutines indefinitely.
     - Removing `SetReadDeadline` exposes the server to classic Slowloris connection pool starvation.
* **Resolution**:
  - **Completely removing deadlines CONFLICTS with `REQ-005` and compromises core DoS security defenses.**
  - **Approved Non-Conflicting Path**:
    - Maintain default deadline enforcement for production safety.
    - Toron already supports zero timeouts (`read_timeout: 0`, `write_timeout: 0`) in `config.yaml` for trusted benchmark environments to eliminate syscalls without modifying core safety invariants.
    - Architectural optimization: Only update `SetReadDeadline` when transitioning to the idle state between requests, avoiding redundant resets during active parsing.

### 2.3 Proposal 4: Socket Options (`TCP_NODELAY` and Recycled Write Buffers)
* **Description**: Explicitly set `TCP_NODELAY = true` on accepted TCP sockets and recycle serialization buffers using `sync.Pool`.
* **Audit Against Previous Requirements**:
  1. **Compliance with [`REQ-001`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-001.md) / [`ADR-001`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-001.md)**:
     - Toron's `Reactor` already leverages `sync.Pool` for connection read buffers (`bufferPool`). Expanding this to serialization aligns with existing architecture.
  2. **Compliance with [`REQ-021`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-021.md) / [`ADR-021`](file:///Users/sneha/Developer/toron-research/toron/docs/architecture/ADR-021.md)**:
     - Layer 4 TCP proxying already manages socket options without conflict.
* **Resolution**:
  - **ZERO conflicts.**

## 3. Functional Requirements for Configurable Tracing

### 3.1 Transport Configuration Extension (`ProxyTransportConfig`)
1. Extend [`ProxyTransportConfig`](file:///Users/sneha/Developer/toron-research/toron/pkg/config/config.go) with a pointer boolean named `tracing`:
   ```go
   Tracing *bool `yaml:"tracing,omitempty" json:"tracing,omitempty"`
   ```
2. Support configuration at both global transport (`config.yaml`: `proxy.transport.tracing`) and per-route transport (`routes.yaml`: `routes[].transport.tracing`).

### 3.2 Preset Profile Integration
1. In `DefaultProxyTransportConfig(profile)`:
   - **`profile: "raw_speed"`**: Defaults `Tracing = &false`. Bypasses `EnsureW3CTraceparent` and eliminates all CSPRNG system calls by default.
   - **`profile: "balanced"`**: Defaults `Tracing = &true`. Preserves automated W3C distributed tracing context generation and propagation for enterprise observability.
2. In `MergeProxyTransportConfig(base, override)`:
   - If `override.Tracing != nil`, override the base setting.

### 3.3 Proxy Request Dispatch Behavior
In [`pkg/proxy/proxy.go:ServeHTTPWithPrefix`](file:///Users/sneha/Developer/toron-research/toron/pkg/proxy/proxy.go#L1019-L1022):
1. When `Tracing` resolves to `true`:
   - Invoke `EnsureW3CTraceparent(incomingTrace)` as established in `REQ-031` / `ADR-026`.
   - Update child span ID or generate new trace/span IDs if missing.
2. When `Tracing` resolves to `false`:
   - If the incoming client request already includes a `traceparent` header, propagate it verbatim without invoking `crypto/rand` to re-generate IDs.
   - If the client request lacks a `traceparent` header, do NOT generate one and do NOT call `crypto/rand`.
   - Outbound request proceeds with zero CSPRNG system calls and zero crypto lock contention.

### 3.4 Backward Compatibility & Security Invariants
1. Default behavior when transport configuration is omitted or defaulted to `"raw_speed"` eliminates CSPRNG overhead.
2. If `tracing` is explicitly set to `true`, 100% full compliance with W3C Trace Context Level 1 and [`REQ-031`](file:///Users/sneha/Developer/toron-research/toron/docs/requirements/REQ-031.md) is preserved.
3. Zero third-party dependencies (`go.mod` invariant).

## 4. Acceptance Criteria

1. **`pkg/config`**:
   - `ProxyTransportConfig` includes `Tracing *bool` with YAML/JSON tags `yaml:"tracing,omitempty" json:"tracing,omitempty"`.
   - `DefaultProxyTransportConfig("raw_speed")` sets `Tracing = &false`.
   - `DefaultProxyTransportConfig("balanced")` sets `Tracing = &true`.
   - `MergeProxyTransportConfig` correctly inherits and overrides `Tracing`.
   - `(p *ProxyRouteConfig) ResolveTransport(global)` correctly resolves route-level `tracing` overrides over global defaults.
2. **`pkg/proxy`**:
   - `ProxyTransportConfig` in `pkg/proxy` mirrors the configuration with `Tracing *bool`.
   - `ServeHTTPWithPrefix` respects `tc.Tracing`:
     - When `false`, missing incoming traceparent results in NO outbound `traceparent` header and zero calls to `crypto/rand.Read`.
     - When `true`, missing incoming traceparent generates a valid W3C header.
3. **Automated Unit Tests**:
   - Automated tests in `pkg/config/config_test.go` verify defaults, inheritance, and route overrides for `tracing`.
   - Automated tests in `pkg/proxy/proxy_test.go` verify traceparent generation when `tracing: true` and complete suppression of generation when `tracing: false`.
4. **Zero Regressions & Race Safety**:
   - All tests in `toron/pkg/config` and `toron/pkg/proxy` pass cleanly under `go test -race`.
