# SR-030 - Security Review of In-Memory HTTP Response Caching Middleware & Cache-Control Engine

## Scope

Security review of in-memory response cache storage ([`pkg/router/cache.go`](file:///D:/Work/server/pkg/router/cache.go)), RFC 7234 `no-store`/`private` directive handling, WebSocket bypass safety, memory boundary enforcement, and cache key namespace isolation.

## Findings

1. **Information Disclosure Prevention**: Cache accurately respects `Cache-Control: no-store` and `Cache-Control: private`, preventing confidential or user-specific payloads from being cached and served to other clients.
2. **WebSocket & Hijacked Socket Safety**: Verified that WebSocket handshakes (`101 Switching Protocols` / `UpgradedConn != nil`) are never captured in cache.
3. **Memory Exhaustion & DoS Resistance**: Memory usage is strictly bounded by `max_entries` (default 1000 items) and `max_payload_size` (default 1 MB), preventing malicious clients from inducing Out-Of-Memory (OOM) panics via large responses or unbounded URI permutations.
4. **Cache Poisoning Resistance**: Cache key includes HTTP method, Host header, and full Request URI path + query string. Requests with non-idempotent methods (POST, PUT, DELETE) are never cached.

## Conclusion

Approved. No security vulnerabilities identified.
