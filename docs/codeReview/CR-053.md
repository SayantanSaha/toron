# CR-053 - Code Review of HTTP-to-HTTPS Redirection and Route-Level Exemption Overrides

## Description

This code review assesses the implementation of cleartext HTTP-to-HTTPS redirection and route-level redirect exemption overrides across [`pkg/config/config.go`](file:///Users/sneha/Developer/toron/pkg/config/config.go), [`pkg/config/loader.go`](file:///Users/sneha/Developer/toron/pkg/config/loader.go), [`pkg/proxy/proxy.go`](file:///Users/sneha/Developer/toron/pkg/proxy/proxy.go), [`pkg/router/router.go`](file:///Users/sneha/Developer/toron/pkg/router/router.go), [`pkg/server/config.go`](file:///Users/sneha/Developer/toron/pkg/server/config.go), [`pkg/server/server.go`](file:///Users/sneha/Developer/toron/pkg/server/server.go), and [`cmd/toron/main.go`](file:///Users/sneha/Developer/toron/cmd/toron/main.go).

The review examines:
1. **Architectural Conformance**: Full alignment with [`ADR-052`](file:///Users/sneha/Developer/toron/docs/architecture/ADR-052.md) and fulfillment of requirements in [`REQ-057`](file:///Users/sneha/Developer/toron/docs/requirements/REQ-057.md) and [`TASK-057`](file:///Users/sneha/Developer/toron/docs/tasks/TASK-057.md).
2. **Code Quality & Idiomatic Go**: Nil safety on pointer booleans, clean configuration mapping, and zero allocations on routing lookups.
3. **Concurrency & Thread Safety**: Shared usage of `*router.Router` across TLS and cleartext HTTP listeners governed by read-locks (`r.mu.RLock()`).
4. **Lifecycle Coordination**: Graceful termination of both the primary TLS server and the auxiliary HTTP redirect server without leaked goroutines or abandoned TCP sockets.
5. **Test Coverage**: Automated test suites in [`pkg/config/config_test.go`](file:///Users/sneha/Developer/toron/pkg/config/config_test.go), [`pkg/router/router_test.go`](file:///Users/sneha/Developer/toron/pkg/router/router_test.go), and [`pkg/server/server_test.go`](file:///Users/sneha/Developer/toron/pkg/server/server_test.go).

## Detailed Code Audit

### 1. Configuration Layer (`pkg/config/config.go`, `pkg/config/loader.go`, `pkg/server/config.go`)
- `HTTPRedirectConfig` (`Enabled bool`, `Port int`) is cleanly modeled in `ServerConfig` and properly converted to `server.Config` in `ToServerConfig()`.
- Default port `80` is established when `HTTPRedirect.Enabled` is `true` and `Port <= 0`.
- In `ProxyRouteConfig`, `RedirectHTTP *bool` and `HTTPSRedirect *bool` provide clean pointer semantics, allowing `nil` to represent inherited default redirection while `false` represents explicit cleartext exemption.
- Helper method `ShouldRedirectHTTP()` returns `false` only if explicitly disabled.

### 2. Router Protocol Policy Evaluation (`pkg/router/router.go`)
- `prefixRoute` stores `redirectHTTP *bool`.
- `ShouldRedirectHTTP(req *httpparser.Request) bool` evaluates incoming HTTP requests against configured prefix routes under `r.mu.RLock()`.
- If a route matches and has `redirectHTTP != nil && !*redirectHTTP`, it returns `false`, signaling that cleartext HTTP is allowed.
- Otherwise, it returns `true`, triggering the default HTTPS redirect.

### 3. Server Redirect Handling (`pkg/server/server.go`)
- In `handleConn`, when `s.config.HTTPRedirectEnabled` is active, requests are tested with `s.router.ShouldRedirectHTTP(req)`.
- If exempt, the request executes normally via `s.router.ServeHTTP(req, res)` over cleartext HTTP.
- If not exempt, `s.serveHTTPRedirect(req, res)` emits an `HTTP/1.1 301 Moved Permanently` response.
- Strict input validation prevents Host header injection, CRLF injection, and Open Redirects (CWE-601).
- Port numbers in the `Host` header are cleanly stripped using `net.SplitHostPort`.

### 4. Application Bootstrap & Lifecycle Management (`cmd/toron/main.go`)
- The auxiliary HTTP redirect server is created when `appCfg.Server.TLS.Enabled && appCfg.Server.HTTPRedirect.Enabled`.
- Reuses the shared `*router.Router` instance without duplicated route tables.
- `stopCtx` is allocated prior to shutdown invocations, and both `redirectSrv` and `srv` are closed gracefully within the 5-second context timeout.
